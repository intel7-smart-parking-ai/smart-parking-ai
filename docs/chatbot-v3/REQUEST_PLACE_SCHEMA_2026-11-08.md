# 요청별 장소 후보 제한 · 복구 후 신규 구현

이 변경은 dbb9fe0 백업에서 출발해 새로 구현했다. 8cc7fd4의 코드를 복원한 것으로 간주하지 않는다.
기존 모델 응답 형식·사용량 보존 코드를 유지하면서 요청별 lot_id 허용 범위를 줄인다.

## 동작

- 카탈로그 이름, 별칭, 유형, 관련 장소, 목적, 등록 예문에서 실제 질문과 맞는 표현만 후보 근거로 사용한다.
- 단어 시작/조사 경계를 확인해 비→비용, 시→시간, 공항→김포공항 같은 부분 문자열 오인식을 막는다.
  띄어쓰기 변형과 등록된 -기 목적의 -러 활용(영화 보기→영화 보러)은 제한적으로 허용한다.
- 말고/아니라/아니고/제외/빼고/싫고/안 가고 등 지원하는 부정 표현 뒤에서는 해당 장소를 제외한다.
  명시적 다른 장소가 없고 정해진 '거기/그곳/그 주차장' 참조 형태일 때만 확정 문맥을 허용한다.
- 미등록 장소 복합어와 카탈로그의 모호한 표현은 후보를 비운다. 오타 사전이나 근사 문자열 교정은 추가하지 않았다.
- ConversationService가 만든 allowed_place_ids를 OpenRouterModel이 함수 스키마 lot_id의 enum에 적용한다.
  후보가 없으면 null만 허용한다. 다른 필드의 required/additionalProperties=false 계약은 유지한다.
- 공급자가 스키마를 무시해도 로컬 검증에서 거절한다. 모의/사용자 모델이 이를 우회해도 서비스 경계에서 다시 거절한다.
  값을 정상 후보로 바꾸지 않고 도구 실행과 문맥 갱신을 차단한다. 실패 사용량과 요청 재실행 방지도 유지한다.
- null 장소의 availability가 오타 질문을 전체 주차장 조회로 바꾸지 못하게 한다.
  전체 조회는 '전체/모든 주차장 빈자리 알려줘' 같은 명시적 전체 조회 문형에서만 허용한다.

## 검증 의미

새 시험은 정상 별칭/목적/부정/정정/문맥, 신새계·신새게, 다른 실존 장소, 부분 문자열,
스키마 전송 내용, 공급자의 후보 외 출력, 사용자 모델의 우회, null의 전체 조회 확대,
실패 뒤 도구 미실행/문맥 미변경/동일 요청 재실행 방지를 검사한다. HTTP 응답은 MockTransport로 제공한다.
34문항 중 기대 lot_id가 명시된 11문항 모두 그 장소가 후보에 포함되는 것도 검사한다.
이 11/11은 후보 포함률이며 34문항 모델 정답률·합격·반복 검증 결과가 아니다.

## 한계와 다음 검토

- 범위가 정해진 한국어 표현 처리다. 모든 활용·띄어쓰기·부정 범위를 이해하는 자연어 분석기가 아니다.
  미등록 동의어, '거긴?'처럼 참조 문형에 없는 표현, 장소가 생략된 '빈자리'는 과도하게 확인 질문할 수 있다.
- 여러 양성 후보는 그대로 남는다. 복합 요청·문맥과 목적의 충돌(기존 Q12 등)은 여전히 모델의 clarify 판단이 필요하다.
  후보를 허용했다는 사실은 모델이 올바른 후보/의도를 골랐다는 증거가 아니다.
- 이 변경은 lot_id 제한이다. destination_id 및 차량 kind/value의 후속 역사적 변경을 복원하지 않는다.
- ConversationService를 통하지 않는 직접 OpenRouterModel 호출은 allowed_place_ids를 전달해야 요청 제한이 적용된다.
  서비스 경로에서는 매 요청 새로 계산하며 전역 Decision 스키마를 변경하지 않는다.
- 공급자 실제 strict 스키마 수용성, 실제 한국어 의미 성능, 지연/비용은 검증하지 않았다.
  fixture를 유지했고 유료 모델 호출 및 Langfuse 외부 전송은 하지 않았다.

기존 차량 검증 시험 2개는 질문에 없는 B 장소를 주입하던 모의 Decision의 lot_id를 null로 수정했다.
차량 번호 오선택 방어의 기존 검증 목적은 유지한다. 기존 설정집 시험의 read_text는 Windows에서 UTF-8을 명시했다.
