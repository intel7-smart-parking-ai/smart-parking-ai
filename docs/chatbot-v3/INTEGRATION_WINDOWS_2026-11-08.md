## 통합 결정

- 공급자용 vehicle_identifier={kind,value} union을 먼저 생성하고 그 스키마의 lot_id에 요청 후보 enum을 적용한다. 내부 Decision/fixture/평가 형식은 유지한다.
- 두 버전의 장소 문형 검사를 중첩하면 정상 참조와 목적 표현이 다시 차단될 수 있어, 후보 산출과 실행 근거 검증이 동일한 후보 규칙을 사용하도록 통합했다.
- 신 세 계처럼 카탈로그 이름 내부 띄어쓰기, 그곳 빈자리 좀 확인해줘, 그/이 주차장, 등록 목적의 제한적 활용을 보존한다.
- 명시적 이름은 이전 장소를 정정할 수 있지만, 단순 목적 표현이 확정 장소와 충돌하면 확인한다. 부정된 장소와 미등록 오타를 정상값으로 고치지 않는다.
- 전체/모든/각 주차장, 주차장 전체/모두/별 등 기존 정상 범위 표현은 보존하되, 전체 조회 요청 문형 전체를 확인해 추가 미확인 장소가 붙은 입력을 전체 조회로 확대하지 않는다.
- 모의 공급자 시험도 신규 typed 계약에 맞춰 수정했다. 잘못된 kind/value나 후보 밖 장소를 허용하도록 검증을 완화하지 않았다.
- Windows에서 asyncio 대기 종료와 단조 시계 deadline의 미세한 차이로 늦은 후속 조회가 한 번 재현됐다. 응답 timeout 시 Event를 설정하고 작업의 다음 budget 검사에서 차단한다. 이미 시작한 요청을 강제로 취소하거나 동일 요청을 재실행하지 않는다.
