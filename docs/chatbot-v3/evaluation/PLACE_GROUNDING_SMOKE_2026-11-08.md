## 해석

새 근거 경계는 두 오타를 차단했다. 저장된 Decision을 서비스에 주입해 최종 상태 clarify와 문맥 오염 없음을 확인했다.

모델은 등록되지 않은 오타를 자동 보정하려는 경향이 남아 있다.
다음 설계 후보는 요청별로 허용할 장소 후보를 카탈로그/문맥 근거에서 정하고 공급자 스키마와 실행 검증을 일치시키는 것이다.
다만 후보 계산이 의미 별칭·부정·정정·문맥을 과도하게 제한할 수 있어 변경 전 오프라인 반례 검증이 필요하다.
서버 경계가 차단한 경우 장소 확인을 명시하는 UX도 별도 검토할 수 있다.
현재도 등록되지 않은 정상 재표현을 차단할 수 있고 보편적 프롬프트 주입 해결을 뜻하지 않는다.
