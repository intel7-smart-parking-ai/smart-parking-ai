# 34문항 첫 평가 이후 오프라인 보완

기준 결과는 RUN_2026-11-08_COORDINATOR_1.md의 22/34, 실행 해결률 58.8%다.
이번 작업에서는 모델/API/Langfuse를 호출하지 않았다. 기존 점수와 기대값을 변경하지 않았다.

## 변경

- Coordinator 프롬프트와 Decision 필드 설명에 ASCII 두 자리 sticker/네 자리 plate_suffix,
  선행 0 보존, 주차장 없는 차량 조회 허용, 01/전각 숫자 재확인 규칙을 명시했다.
- 추천에는 선택한 주차장의 facilities 목록 facility_id를 destination_id로 복사하도록 했다.
  문맥의 주차장에 시설이 없거나 장소가 모호하면 clarify로 처리하도록 지시했다.
- 복합 비교를 전체 현황 조회로 바꾸지 않도록 지시하고 facilities(시설 위치/목록)와
  guidance(층/지하/높이/진출입)의 차이를 명시했다. 미확인 높이 값은 생성하지 않는다.
- 실행 의도와 question이 동시에 있는 Decision은 조회 전 차단한다. Q14의 관측 응답은
  이 경계로 차단된다. question=null로 잘못 분류하는 모든 복합 요청까지 감지하는 것은 아니다.
- 차량번호 앞뒤 경계와 새 번호 탐색에서 Unicode 숫자도 감지한다. ASCII 하위 문자열 매칭과
  이전 차량 문맥으로의 우회를 막되, 실제 조회 식별자는 ASCII 문자열로만 허용한다.
  예: 이전 23 문맥에서 １23을 입력해도 23으로 조회하지 않는다. 전각 숫자를 변환하지 않는다.
- 전체 주차장 현황을 위한 lot_id=null의 기존 실행 경로는 유지했다. 모든 의미 오분류를
  규칙 파서로 재해석하는 방식으로 전환하지 않았다.

## 검증

- 관측된 잘못된 Decision 9개를 주입해 API 실행 없음/문맥 오염 없음/동일 요청 재실행 없음을 확인.
- 정상 sticker/plate_suffix/추천/전체 현황 인자가 유지되는지 확인.
- guidance의 로컬 가상 정보 표시와 미확인 높이를 만들지 않는 동작 확인.
- 전각·혼합 숫자가 이전 차량을 재사용하지 못하며 '그 차 요금'은 정상 문맥을 사용하는지 확인.
- chatbot_v3 관련 7파일: **71 passed, 13 warnings / 11.39초**.
  경고는 기존 Starlette/httpx 사용 중단 예고다. 전체 저장소 회귀 결과가 아니다.

테스트는 명시적으로 주입한 Decision과 MockTransport를 사용한다. 프롬프트가 실제 모델의
오분류를 해결했다는 증거가 아니다. 다음 유료 평가에서 새 프롬프트 SHA/코드 기준으로
같은 34문항을 재실행해야 점수 개선을 판단할 수 있다. 추가 호출은 이번 작업에서 하지 않았다.
