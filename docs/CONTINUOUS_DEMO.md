# 연속 시연 모드

시연 서버의 비공개 환경 설정에 `PARKING_MODE=demo`와
`PARKON_CONTINUOUS_DEMO=1`을 지정한다. Docker Compose에서는 시연 전용
프로젝트와 볼륨을 사용하고 API를 한 프로세스로 실행한다.

```sh
docker compose -p parkon-rehearsal up -d --build
```

Docker 없이 실행할 때도 같은 플래그와 `SMART_PARKING_DB_PATH`를 지정하고
`python -m backend.app.main`으로 시작한다. DB 경로는 비어 있는 새 파일이나
가상 이력을 넣었던 시연 DB의 백업 복사본을 사용한다. 운영 DB와 연결하는
공용 볼륨이나 경로를 피한다. 처음 시작할 때 과거 이력을 생성하므로 부팅이
평소보다 오래 걸릴 수 있다.

- 최초 시각과 2026-11-13 00:00 KST 중 이른 시각까지 2025-01-01부터
  A·B·C·D 이력을 한 번 생성한다. 첫 실행 시점이 시연 기간 안이라면 그
  시점 이후는 실시간 기록으로 이어간다. 이미 시연 이력이 들어간 DB의
  과거 이력과 표시 제한은 유지한다.
- C·D는 첫 실행에 자동 시작한다. 이후에는 DB에 저장된 시작·정지 설정을
  유지한다. 출차가 관측되면 주차 요금표를 적용해 모의 결제를 기록한다.
  결제 또는 취소 이력이 있는 세션은 자동으로 다시 결제하지 않는다.
- 15초마다 실행 시각을 기록한다. 재시작하면 그 시각부터 재개 시각까지
  켜져 있던 C·D의 가상 이력을 통계용으로 한 번 생성한다. 정상 종료는
  종료 시각을 기록한다. 갑작스러운 종료에서는 마지막 기록과 실제 종료
  사이에 최대 약 15초의 오차가 생길 수 있다. 재시작 간격이 짧거나 수요가
  없는 시간에는 가상 입출차가 0건일 수 있다.
- 중단 구간을 가로질러 주차된 차량의 자리는 보충 생성에서 제외한다.
- 재시작하면 C·D(실행 중인 주차장)는 재시작 전 차량으로 복구하지 않는다. 남아 있던 가상 차량은
  재시작 직후 서버 관측 경로로 출차 처리되고(세션 종료 + 자동 모의 결제), 대신 같은 요일 유형
  (평일 / 주말·공휴일)·같은 시간대의 과거 평균 점유율(15~85%)만큼 빈 칸을 골라 새 가상 차량을 둔다.
  새 차량도 시뮬레이션 관측을 서버가 확정해야 세션이 생긴다. 첫 시작 때도 같은 방식으로 채운다.
  A·B는 실물 카메라 관측으로만 상태를 맞춘다.
  보충 기록을 실시간 점유 엔진으로 보내지 않는다. A·B는 최초 과거 이력
  이후 실물 관측으로만 기록하며, 추적된 중단 시간은 이용률 집계에서 뺀다.
- 관리자 매출 화면과 CSV에는 가상 이력이 포함됐다는 표시가 붙는다.
  DB 파일은 시연 서버의 볼륨에 보관한다.
