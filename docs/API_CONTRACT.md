# API 계약 v0.1 (제안 / 11월 2일 팀 합의 후 확정)

- 기본 경로 `/api/v1`
- JSON UTF-8, 필드 `snake_case`, 날짜 ISO 8601(타임존 포함), 금액 원(KRW) 정수
- `car_id`(실물 미니카 스티커)는 `"10"`~`"99"` 두 자리 숫자 문자열, `00`~`09`는 사용하지 않음, 미인식 `null` (2026-11-03 PM 결정)
- 가상 C/D 차량은 번호판(예: `17가1724`)이 기준 값이며, 화면에는 **뒤 4자리**(`1724`)만 표시하고 상세 조회·관리에서 전체 번호판을 보여준다 (2026-11-03 PM 결정). 필드명(`plate_number` 제안)과 검색 API는 박해준과 확정 예정. 합성 번호이며 실제 번호판이 아님
- `lot_id`: 실물 A/B, 가상 C/D (내부 코드). 화면 표시 이름은 아래 표의 주차장 이름(개발원·부산역·북항·라 미정)
- `space_id`: **각 주차장 도면의 칸 번호**(`A-01`, `B-06` …, A·B는 주차장 안의 구역). 주차장끼리 같은 번호가 있을 수 있으므로 항상 `(lot_id, space_id)`로 식별하고, 화면·챗봇은 "가 주차장 B-06"처럼 주차장 이름과 함께 표시한다. `space_id`의 A·B는 `lot_id`와 무관
- API 계약 변경 시 PM 김한별과 박해준 협의

### 주차장·칸 구성 (2026-11-03 PM 결정, 도면 기준)

여러 곳에 떨어져 있는 주차장을 한 시스템으로 운영하는 컨셉이다. 칸 번호는 주차장마다 독립적이다.

| 순서 | 주차장 이름 | `lot_id` | 종류 | 도면 | 칸 수 | 칸 번호 | 전기차 전용 | 장애인 전용 |
| --- | --- | --- | --- | --- | :-: | --- | --- | --- |
| 가 | **개발원주차장** | `A` | 실물 | 기본형 | 12 | A-01~A-06, B-01~B-06 | A-05, A-06 | B-06 |
| 나 | **부산역주차장** | `B` | 실물 | 사선형 | 16 | A-01~A-08, B-01~B-08 | A-07, A-08 | B-07, B-08 |
| 다 | **북항주차장** | `C` | 가상 | 일방순환형 | 12 | A-01~A-06, B-01~B-06 | A-05, A-06 | B-06 |
| 라 | (김채린 지정 예정) | `D` | 가상 | **대형 4구역** | **64** | A-01~A-16, B-01~B-16, C-01~C-16, D-01~D-16 | **D-01~D-08** (8) | **C-13~C-16** (4) |

- 합계 **104칸** (실물 28 / 가상 76). 미니카는 최대 24대이므로 실물 만차 시연은 가상 주차장으로 대신한다
- 라 주차장 도면은 2026-11-03 PM 제공 이미지(가상 주차장 · 64면) 기준: 4구역(A·B 상단, C·D 하단) 각 16칸(8칸×2줄), 하단 중앙 보행자 출입구, 입구 좌하단·출구 우하단. 이전 L자 10칸 도면은 폐기
- 라 주차장 칸 번호의 C·D는 **주차장 안 구역**이며 `lot_id` `C`(북항)·`D`와 무관 — 항상 `(lot_id, space_id)`로 식별 (예: `lot_id=D, space_id=C-13` = 라 주차장 C구역 13번, 장애인 전용)
- 주차장 이름: 가·나·다는 PM 확정(2026-11-03), 라는 김채린이 지정 예정. `lot_id`(A~D)는 그대로 유지하고 화면·챗봇에는 이름을 표시한다
- 전기차·장애인 전용 칸은 **별도 관리**하며 일반 차량은 주차할 수 없다 (PM 결정). 칸 종류 필드(`space_type`: `general`/`ev`/`accessible` 제안)와 위반 처리 방식은 박해준과 확정 예정

### 차량 종류 (2026-11-03 PM 결정)

- 실물 미니카 번호 스티커는 **무작위 두 자리 번호**, 스티커 **색으로 차량 종류**를 구분한다: **초록 = 전기차**, **파랑 = 장애인 차량**, **흰 바탕 = 일반 차량**. 빨강·주황·분홍 계열은 LED 오탐 때문에 쓰지 않는다
- 번호 인식 모델은 번호와 함께 스티커 색으로 차량 종류를 관측한다 → 필드 `vehicle_type`: `general` / `ev` / `accessible` (불확실하면 `null`)
- 가상 차량의 종류는 시뮬레이터가 지정한다

### DB (2026-11-03 PM 결정)

- 팀 서버 DB는 **SQLite + SQLAlchemy**로 개발·시연한다. 모델은 SQLAlchemy로 작성해 PostgreSQL로 전환 가능한 구조만 준비한다(전환은 선택 과제)
- 프론트 데모 서버(`dev/parkon-api`)의 PostgreSQL은 데모 전용이며 팀 DB와 별개

### 세션 상태 (2026-11-03 PM 결정)

- 세션 = 차량 한 대의 입차부터 출차까지의 주차 기록. 상태는 **`active`(주차 중) / `closed`(출차 완료)** 로 통일한다. 화면·챗봇은 한글로 표시

### 요금 견적 `quote_id` (2026-11-03 PM 결정: 채택)

- 요금 조회 응답이 `quote_id`와 만료 시각을 함께 준다. 결제 요청은 `quote_id`를 보내고, 서버는 **요금 화면에 표시된 견적 금액으로 결제**한다
- 견적이 만료되면 결제를 거절하고(재조회 안내), 화면은 일정 시간이 지나면 요금 화면을 초기 화면으로 되돌린다. 유효 시간은 담당자(윤명수·김채린)가 정한다
- 금액은 여전히 서버가 계산·보관하며 클라이언트가 금액을 보내지 않는다
