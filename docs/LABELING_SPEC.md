## 1. 최종 목표에서 거꾸로 — 모델이 내야 하는 것

모델은 **관측(evidence)만** 낸다 (규칙 2). 서버로 가는 vision-event 필드가 곧 라벨이 맞춰야 할 출력이다.

| 모델 (D-27 담당) | 서버 이벤트 | 모델이 채우는 필드 | 라벨로 가르칠 것 |
| --- | --- | --- | --- |
| **EPIC 01 칸 점유** (김한별·박해준) | `vehicle_observed` / `space_empty_observed` | `space_id`(ROI에서), `confidence` | 칸 사진 → `occupied` / `empty` / `unusable` |
| **EPIC 02 번호 스티커 + 색** (우지원·김채린) | 같은 `vehicle_observed`에 함께 (D-30) | `car_id`(`"10"`~`"99"`/null), `vehicle_type`(`general`/`ev`/`accessible`/null) | 스티커 위치, 두 자리 번호, 바탕색, 읽을 수 있는지 |
| **EPIC 03 LED 모의 화재** (윤명수·서정범) | `mock_fire_led_observed` | `lot_id`, `bbox_xyxy`, `confidence` | LED 위치·켜짐/꺼짐, 빨간 물체 오탐 |

**서버가 요구하는 조건 (API_CONTRACT 3장) → 라벨 설계 이유**
- `min_confidence` **0.8** 미만은 `uncertain` → confidence가 **믿을 만해야** 함 → 애매한 사진을 억지로 occupied/empty로 넣지 않는다
- **가림·끊김 중 `space_empty_observed` 금지** (가짜 출차) → 가림을 **empty로 라벨하면 안 됨** → `unusable`
- 번호를 못 읽으면 `car_id: null` (점유는 유지) → 번호는 **추측 라벨 금지**, `unreadable`로

## 3. 모델별 라벨 기준

### 3-1. EPIC 01 칸 점유 (D-32 B안)

- **단위:** 원본 프레임 → ROI(`roi_version`)로 자른 **칸 사진 1장 = 라벨 1개** (가 12칸·나 16칸 → 프레임 1장에서 12~16장)
- **클래스 (3개)**

| 클래스 | 기준 | 예 |
| --- | --- | --- |
| `occupied` | 미니카 차체가 칸 안에 **판단 가능할 만큼** 보임 | 정상 주차, 선을 조금 밟은 차 |
| `empty` | 칸 바닥이 **충분히 보이고** 차가 없음 | 빈칸, 작은 그림자만 |
| `unusable` | **판단 불가** — 손·물체 가림, 흐림, 화면 밖, 심한 반사·검은 화면 | 손으로 가린 칸 |

- **헷갈리는 경우**
  - 차가 **두 칸에 걸침** → 두 칸 모두 `occupied` (+ 3-4 `placement`)
  - **반쯤 들어오는 중** → 차체 절반 이상이면 `occupied`, 아니면 `unusable` (입차 중 프레임은 학습에서 빼도 됨)
  - 미니카가 아닌 물체(종이·손) → `unusable` (empty 아님)
- **대량 카메라 자동 라벨 (D-45):** 빈 기준 사진 비교(A안)로 `label_source=auto_A` 초안 → **사람이 최소 10% 표본 확인**, 표본 오류율이 높으면 그 세션 전체 재검수
- **목표 수량 (칸 사진 기준, 주차장별)**
  - 1차: `occupied`·`empty` 각 500장 이상, `unusable` 100장 이상
  - 최종: 각 1,500장 이상, `unusable` 300장 이상 (칸 위치별로 고르게 — 가장 먼 칸·모서리 칸 포함)

### 3-2. EPIC 02 번호 스티커 + 색 (D-30·D-07·D-39·D-31)

- **단위:** `occupied`로 승인된 **칸 사진** 안에서 스티커 하나
- **라벨 칸**

| 칸 | 값 | 기준 |
| --- | --- | --- |
| `sticker_bbox` | 칸 사진 좌표 `[x1,y1,x2,y2]` | 스티커 바탕 전체를 감쌈 |
| `car_id` | **D-54 목록 30개 중 하나** (아래) 또는 비움 | 사람이 **확실히 읽을 때만** 입력. 문자열, 앞 0 없음 |
| `color` | `white` / `green` / `blue` | **스티커 바탕색** (D-07) |
| `vehicle_type` | `general` / `ev` / `accessible` | 색에서 자동: 흰=`general`, 초록=`ev`, 파랑=`accessible` |
| `readability` | `readable` / `unreadable` | 흐림·각도·가림으로 못 읽으면 `unreadable` → `car_id` 비움 |
| `rotation` | `0` / `90` / `180` / `270` | 위에서 본 스티커 방향 (180° 혼동 확인, D-31) |

- **허용 번호 (D-54, 최종 30대 — D-39 대체)**
  - 🟢 `ev` 5: 11 · 23 · 42 · 57 · 85
  - 🔵 `accessible` 5: 14 · 32 · 49 · 55 · 77 (49는 D-53 예외)
  - ⚪ `general` 20: 10 · 12 · 13 · 20 · 21 · 22 · 24 · 30 · 31 · 33 · 34 · 40 · 41 · 43 · 44 · 58 · 75 · 78 · 87 · 88
  - 예비 없음 (규칙상 최대 30개). 인쇄 실패 시 같은 번호 재인쇄
- **검수 규칙 (자동 확인 가능)**
  - `car_id`가 목록에 없으면 거절
  - **번호와 색이 배정표와 다르면 거절** (예: 23인데 `white` → 오류)
  - 6·9가 들어간 번호가 나오면 거절 (D-31) — **49만 예외(D-53)**
- **목표 수량:** 번호당 1차 10~20장, 최종 25~40장 (30개 균형), `unreadable` 100장 이상 따로
- **모델 출력 연결:** 학습은 "번호 24클래스(+예비) 분류 + 색 3클래스" 또는 "OCR + 배정 목록 화이트리스트" (vision-pipeline 스킬 4장). 어느 쪽이든 **확신 낮으면 `car_id=null`**

### 3-3. EPIC 03 LED 모의 화재

- **단위:** 원본 **전체 프레임**
- **라벨 칸:** `led_state` (`on` / `off` / `none` = LED 없음), `led_bbox` (켜진 LED마다), `distractor` (빨간 미니카·빨간 스티커·반사광이 있으면 `true` + 위치)
- **기준:** 사람이 봐도 켜졌는지 애매하면 `unusable`로 따로 (학습 제외)
- **목표:** 켜짐 250~400 / 꺼짐·일반 200~300 / **오탐 유발(빨간 물체) 150~300** (`AI데이터셋_수집계획.md` 2장 그대로)
- 표기: 항상 **"모의 화재"** (규칙 6)

### 3-4. (부가, D-46) 주차 위치 — 칸만 만들어 두기

- 칸 사진 라벨에 `placement` 칸을 두고 **지금은 비워도 됨**: `normal` / `line_cross`(선 침범) / `two_spaces`(두 칸 걸침) / `outside`(칸 밖)
- 대량 수집 때 **일부러 이런 장면을 섞어 두면** 나중에 재촬영 불필요
- 전용 칸 비교(일반차가 전용 칸에)는 라벨이 아니라 **서버 판정** (모델은 차종만, 위반 확정은 서버)

## 4. 학습/검증/시험 나누기 (누수 방지)

1. **세션 단위로만** 나눈다 (`session_id`). 같은 세션의 사진은 모두 같은 분할
2. 칸 사진·스티커 사진은 **원본 프레임(`source_frame_id`)을 따라감** — 한 프레임의 칸들이 train/test로 갈리면 안 됨
3. **시험(test) = 정밀 카메라 `cam_hq`의 별도 세션** (사람 검수 100%). 대량 `cam_bulk`는 train/val에만
4. 비율 목표 70 / 15 / 15, test는 **고정·버전 이름** (`occupancy_test_v1`) — 개선 전후는 같은 test로 비교
5. 가·나 주차장 **둘 다** test에 포함
