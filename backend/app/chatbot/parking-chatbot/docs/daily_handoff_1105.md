기준: 관리봇 업무정리와 main `4e048c8`, 결정 브랜치 `0ff5ae4`, 통합 브랜치 `5163d0d`. 담당자에게 자동 전송하거나 Jira를 변경하지 않았다.

## 모델 결정 자료 — 김한별님 확인

아래 수치는 **관리봇이 전달한 11/04 실측 요약**이다. 원자료·평가 세트·반복 조건이 제공되지 않아 직접 재계산/동일 조건 비교하지 않았다. 이번 코드 수정의 전후 이해율로 사용하지 않는다.

| 구성 | 전달 정답률 | 전달 평균 / 최대 | 도구 호출 성공률 | 비용 |
| --- | --- | --- | --- | --- |
| 규칙만 | 14% | 미제공 | 해당 없음 | LLM 호출 없음 |
| OpenRouter Gemma 4 26B | 66~74% | 약 1.1초 / 3.0초 | 미제공. 정답률과 구분 필요 | 사용량·실측 비용 미제공 |
| OpenRouter Claude Haiku 5.5(전달 이름) | 83% | 약 1.3초 / 1.8초 | 미제공 | 정확한 OpenRouter 모델 ID·사용량·실측 비용 미제공 |

요청 문장: “김한별님, 원자료의 동일 평가 세트·wrong_tool·도구 호출 성공률·지연·비용을 확인해 D-44 모델과 정확한 OpenRouter ID를 결정 부탁드립니다. 그 전에는 D-18의 기존 모델과 옵션 기본값을 유지하겠습니다.”

시연 PC에서 김한별님이 넣을 변수는 `LLM_PROVIDER`, `LLM_MODEL`, `OPENROUTER_API_KEY`다. 기존 실행 설정 `LLM_ENGINE=langchain`을 확인하고, 키 값은 `.env`에만 둔다. 키가 없어도 `LLM_PROVIDER=none`으로 대본은 실행한다. 실제 LLM 비교는 사람이 기존 `tools/compare_models.py`로 수행하며 holdout을 보고 설명·예시를 맞추지 않는다.

## 스티커·목업 — 기대값 변경 승인 필요

D-39의 전기차는 23·42·57·85, 장애인은 14·32·55·75다. 현재 단독 목업은 13·21·28을 전기차로 둔다. `tests/test_supplement.py`의 28번 전기차, `tests/test_v29_rules.py`의 17번 B-01, 다수 결제·스냅샷 검사가 기존 번호/배치를 명세로 사용한다.

관리봇의 목업 전면 교체 요청과 공통 원칙의 기존 기대값/설정 보존이 충돌한다. 사용자 승인 없이 기대값·CSV를 바꾸지 않았고, 시험용/시연용 새 모드도 만들지 않았다. API 모드에서는 서버의 번호·vehicle_type을 그대로 사용하므로 현재 실제 시연은 서버 데이터로 확인한다.

요청 문장: “김한별님·서정범님, D-39로 단독 목업을 바꾸려면 기존 차량 배치/전기차/스냅샷 기대값 갱신 범위를 승인 부탁드립니다. 서버 번호 인식 범위 10~99를 D-39 목록만으로 제한하는 변경은 하지 않겠습니다.”
