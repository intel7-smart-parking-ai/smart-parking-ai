# 음성 전사문을 기존 챗봇에 연결하는 기준

기준: v2.15.6 / 2026-11-05 KST. 이 문서는 기존 공개 계약을 설명하며 새 API나 필드를 추가하지 않는다.

## 연결 방법

녹음 → STT → 수정 가능한 초안 → 사용자가 전송 → 기존 `POST /api/v1/chat` 순서로 연결한다. 음성 서버의 가상 챗봇 응답이 아니라 팀의 기존 챗봇 엔드포인트를 사용한다.

```json
{
  "session_id": "same-session-as-existing-ui",
  "request_id": "new-id-for-this-chat-request",
  "text": "이십 삼 번 차량 위치"
}
```

기존 세션·요청 재전송·`runtime_id`·확인 칩의 `confirmation_token` 처리는 기존 화면과 같다. `text`는 최대 200자이며 초과 시 사용자에게 수정 요청한다. 자동 절단하지 않는다.

## 번호 해석

| 입력 | 처리 |
|---|---|
| `23번`, `이십삼번`, `이십 삼 번`, `이 십 삼 번` | 차량 `"23"` |
| `삼 십 번` | 차량 `"30"`. 끝의 십만 읽어 `"10"`으로 사용하지 않음 |
| `이십 삼 번 말고 삼 십 번` | 정정한 대상 `"30"`으로 기존 재확인 |
| `이십 삼 번과 사십 일 번` | 대상 하나를 다시 질문 |
| `백 십일 번`, `일칠번`, `이십 3번`, `2 3번` | 일부 숫자를 잘라 쓰거나 이전 차량으로 대체하지 않고 유효 번호를 다시 요청 |
| `이십 삼 번 칸`, `삼십 분`, `이천삼백 원` | 차량번호로 변환하지 않음 |
| `이번 요금은?` | 일상 표현을 차량 2번으로 바꾸지 않음 |
| `0123`, `17가1724` | 기존 가상 차량 식별 규칙 유지 |

두 자리 한자어 수사(십·이십삼·삼십 등)의 공백 변형을 보완했다. 고유어 수사(열일곱·스물세 등)나 숫자를 한 자리씩 읽는 표현(일칠 등)을 새로 지원한다는 뜻은 아니다. 불명확한 번호는 사용자가 수정·재확인하도록 한다.

원본 전사문은 대화 기록과 분류기에 그대로 전달한다. 번호 추출에만 국소 정규화를 적용하고 문장 전체 공백을 삭제하지 않는다. “조금 확인”처럼 조회 목적이 모호한 문장을 위치·요금으로 임의 확정하지 않는다.

## 확인 단계의 책임

전사 초안 전송은 차량·모의 결제의 승인을 대신하지 않는다. 기존 응답의 `flow`, `chips`, `confirmation_token`, `safety`를 기존 UI 규칙으로 반영한다.

현재 챗봇 API에는 음성 출처를 구분하는 `input_mode`가 없고, 기존 텍스트 “네” 확인 동작도 유지한다. 따라서 이 패치가 서버의 음성 자동 승인 차단을 구현했다고 설명하면 안 된다. 음성 화면은 실행 확인 단계에서 마이크를 막고 이미 진행 중인 늦은 전사를 폐기하는 정책을 적용해야 한다. 서버 출처 정책은 별도 공개 계약 변경으로 공동 설계한다.

마이크 권한·녹음 종료·브라우저 취소·오디오 검증·모델 준비·추론 동시성·HTTPS/QR은 음성 모듈과 화면의 수정 범위다. 이 챗봇 패치에는 해당 서버/프론트 코드가 포함되지 않는다.
