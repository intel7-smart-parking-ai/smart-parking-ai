## 화면 피드백과 원인

| 화면 질문 | 이전 답 | 원인 |
|---|---|---|
| 빈자리 몇 개 있어? (칩 포함) | "김해공항 주차장에 64자리 있어요" | 주차장 미지정 시 `navigation.query`가 빈자리가 가장 많은 한 곳을 골라 첫 문장으로 답함 |
| 비행기가 2시20분 출발인데 3시간 전에 도착해도 혼잡하지 않을까? | 일반 실패 안내 | 주차장 이름·빈자리 단어가 없고, '비행기'→공항 연결 규칙과 혼잡 '예측' 질문 처리 경로가 없음 |
| 신세계백화점 엘리베이터 몇 개야 | 일반 실패 안내 | 시설 질문을 받을 intent·데이터가 없음 |
| 김해 공항 주차장에서 국제선 청사로 가장 가까운 주차구역 | 일반 실패 안내(화면) / 현재 코드는 빈자리 수만 답함 | 청사와의 거리 데이터가 없는데 질문 의도를 구분하지 않음 |
| 공항 주차장 / 기차 주차장 | 일반 실패 안내 | 별칭 부족. '공항'은 `8cc06ae`(12:16)에서 추가됐고 '기차'류는 여전히 없음 |

LLM이 꺼진 규칙 경로에서는 위 질문이 모두 `unknown` → "잘 이해하지 못했어요"로 끝났다.

## 변경

- **주차장 미지정 빈자리**: 한 곳을 임의로 고르지 않는다. "전체 주차장 빈자리는 총 N자리예요" + 주차장별 한 줄(만차·경보 중·이용 제한·확인 불가 표기) + "어느 주차장을 안내해 드릴까요?"와 주차장별 칩(`lot_*`, 최대 4개). 구역 질문(충전·장애인)도 같은 형식.
- **별칭**: 부산역(기차, 기차역, 부산 역, 부산역사, KTX), 김해공항(김해 공항, 김해국제공항, 국제공항, 비행장), 신세계(신세계 백화점, 센텀, 센텀시티, 신세계센텀시티). `lots.json`만 수정.
- **데이터 없는 주차장 질문**(`chatbot/info_gaps.py`): 규칙 결과가 `unknown`이거나 단순 빈자리일 때만 적용하고, 경보·대피·요금·결제·관리자·차량 질문은 기존 경로가 우선이다.
  - 혼잡 예측(시각·출발·도착·내일 등): "혼잡 예측은 아직 제공하지 않아요" + 지금 기준 빈자리 + "도착 직전에 다시 물어보세요". '비행기·출국·국제선'→공항, '기차·KTX'→부산역, '쇼핑·백화점'→신세계로 주차장을 짐작(단서가 한 곳일 때만).
  - 지금 붐비는지(주차장 지정 시): 현재 빈자리로 답함. 주차장 없는 비교 질문('어디가 덜 붐빌까')은 기존 LLM 분류 경로를 유지.
  - 시설(엘리베이터·화장실·계단·출입구·운영 시간·셔틀·높이 제한·편의시설·청사 가는 길): `guide`에 등록된 문장이 있으면 그대로, 없으면 "아직 챗봇에 등록되지 않았어요. 현장 안내판이나 관리자에게 확인해 주세요" + 대안 칩.
  - 특정 시설과 가장 가까운 구역: `guide.terminal` 등이 없으면 추천하지 않는다고 밝히고 현재 빈자리를 함께 보여 줌.
- 새 intent·칩 ID·카드 type·flow·공개 API는 없다. 내부 params(`info_gap`, `info_topic`, `info_label`)만 추가했다. 외부 모델을 호출하지 않는다.

## 시설 안내 설정집(`lots.json`의 `guide`)

팀이 현장에서 확인한 문장만 넣는다. 비워 두면 '미등록'으로 답하며, 챗봇이 내용을 만들지 않는다(루트 CLAUDE.md 5번).

```json
"guide": {
  "terminal": "B 구역 엘리베이터로 올라가면 국제선 청사 3번 출입구와 바로 이어져요.",
  "elevator": "주차장 각 층 중앙에 2대씩 있어요."
}
```

사용 가능한 키: `terminal`(청사·터미널 가는 길/가까운 구역), `elevator`, `stairs`, `restroom`, `entrance`, `hours`, `shuttle`, `height`, `amenity`. 그 밖의 키나 문자열이 아닌 값은 시작 시 `ValueError`로 거부한다.

## LLM 기본 설정(OpenRouter)

- `.env.example` 기본값: `LLM_PROVIDER=openrouter`, `LLM_MODEL=anthropic/claude-haiku-5.5`. 키 줄(`# OPENROUTER_API_KEY=`)은 계약상 주석으로 둔다(공개 계약 테스트가 주석 아닌 키 이름 목록을 고정).
- `config.py`: `LLM_PROVIDER=openrouter`인데 `LLM_MODEL`이 비어 있으면 Haiku 5.5. 코드 기본 `LLM_PROVIDER`는 `none` 그대로(키 없는 환경·테스트 보호).
- 키가 없으면 `missing_key`로 LLM을 건너뛰고 규칙 파서만 쓴다(오류 없음).
- 모델 근거: KAN-51 실측 Haiku 5.5 83%·평균 1.3초 vs Gemma 4 26B 66~74%·평균 1.1초. **D-44 PM 확정 전 제안값**이며, Gemma로 되돌릴 때는 `.env`의 `LLM_MODEL=google/gemma-4-26b-a4b-it` 한 줄만 바꾼다.
