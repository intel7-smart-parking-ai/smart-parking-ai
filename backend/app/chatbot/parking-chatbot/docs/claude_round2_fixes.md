## 검토 결과와 직접 관찰한 결과

| 지적 | 이번 실행에서 관찰 | 처리 |
|---|---|---|
| ‘관리자 불러 주지 마세요’ | 실제 관리자 문의 등록 | 공백을 허용한 공통 부정 판정으로 보정 |
| ‘관리자 말고 요금’ | 실제 관리자 문의 등록 | 거절한 관리자 부분을 제외하고 남은 요금 조회만 처리 |
| 관리자 거절에 환불 안내 | ‘직원은 안 불러도 돼요’에 환불 불가 문구 | 취소 대상을 구분하고 관리자 거절에는 호출하지 않는다는 안내 |
| ‘결제 안 해도 나갈 수 있어요?’ | 요청 취소 응답 | 요금 규칙 질문으로 처리 |
| ‘7번 말고 다른 차’ | 이 실행에서는 차량 확인 카드가 아닌 일반 미인식 안내. 파서에는 거절한 07이 남음 | 거절한 번호를 후보에서 제외하고 다른 번호를 요청. 이전 결제 확인과 선택 차량 정리 |

마지막 항목은 첨부 문서의 ‘07번 확인 질문’과 관찰 결과가 다르다. 검토 결론을 그대로 재현했다고 적지 않고, 실제 확인한 미인식·번호 후보 잔존 문제를 기준으로 보정했다.

## 보정한 동작

- ‘불러 주지 마세요’, ‘호출해 주지 마세요’, ‘연결해 주지 말아줘’와 붙여 쓴 형태를 같은 부정으로 처리한다. 부정하지 않은 ‘관리자 불러 주세요’는 기존처럼 즉시 접수한다.
- ‘관리자 말고 요금’은 차량이 선택돼 있으면 요금만 조회하고, 선택 전이면 차량번호를 묻는다. 미인식 대안이 LLM 경로로 돌아가 거절한 관리자 호출을 다시 실행하지 않도록 한다.
- 관리자 거절·일반 취소·결제 거절에 불필요한 환불 문구를 붙이지 않는다. 미완료 확인이 없는 명시적 결제 취소 맥락에서만 환불 미지원 안내를 남긴다. 접수 완료한 문의를 취소하는 새 기능은 추가하지 않는다.
- 정정할 새 번호가 없으면 다른 차량번호를 요청한다. 이전 번호·확인 토큰으로 결제하지 않는다. 원래 요금 조회를 진행 중이었다면 새 번호 확인 뒤 그 조회를 이어간다.
- 위 안내 문구는 `chatbot/templates.py`에 두었다. 문구는 이 파일, 버튼은 `chatbot/chips.json`에서 수정한다.

## 검사

- 기존 질문 195개에 이번 재현·공백 변형 10개를 추가: **205/205**.
- Python 검사 7개 추가: **157개 통과**, 선택 FastAPI 검사 포함.
- 기존 Chromium **15항목**, 안정화 Chromium **12항목** 재실행 통과.
- 새 검사는 공백 조합별 부정의 부작용 없음, 긍정 호출 유지, 대안 요금 조회, 취소 문구, 요금 규칙 질문, 새 번호 없는 정정·이전 확인 차단·새 번호로 조회 계속, 거절 대상의 LLM 경로 재진입 방지를 확인한다.
- 원시 결과: `validation_results.json`, `validation_python.txt`, `validation_questions.txt`, `validation_browser_existing.txt`, `validation_browser_stability.txt`.

모두 로컬 mock·LLM 비활성 기준이다. LLM 거절 경로 검사는 실제 모델이 아닌 분류기 대체 응답으로 실행했다. 추가 문장은 알려진 실패를 보정한 회귀 사례이며 실사용 정확도·새 비공개 표본 평가가 아니다.

## 유지한 정책과 다음 단계

- Lv2에서는 **전체 모의 결제 중지**를 유지한다. 다른 주차장만 결제를 허용하는 정책으로 바꾸지 않았다. 주차장별 허용은 팀이 시연 시나리오를 확정할 때 결정할 사항이다.
- 관리자 키가 없으면 mock·서버 자신(loopback)만 관리자·시연 API를 쓸 수 있다. 휴대폰·다른 PC로 관리자 기능을 쓰려면 `ADMIN_TOKEN`과 화면의 접근 키를 준비한다.
- 이 버전을 팀원 비공개 질문·실제 기기 리허설의 기준으로 고정한다. 신규 기능·슈퍼바이저 AI는 추가하지 않는다.
- 실제 API v1 연결, 최종 모형의 주차장·차량 설정, 실제 기기 통신·지연 검증은 남아 있다.
