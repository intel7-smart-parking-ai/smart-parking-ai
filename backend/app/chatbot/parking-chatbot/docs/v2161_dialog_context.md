# v2.16.1 대화 맥락 이해 · 데이터 활용 답변

기준: main `d447a52` + v2.15.9 + v2.16.0. 변경은 `backend/app/chatbot/` 안쪽뿐이며 공개 API·intent·칩 ID·카드 type·flow는 그대로다.
LLM 없이 규칙 경로에서 동작하고, 문장 완성은 파서 앞에서 하므로 LLM을 켜도 같은 완성 문장을 받는다.

## 적용한 방법론

| 방법론(참고) | 이 챗봇에 적용한 방식 | 파일 |
|---|---|---|
| 대화 상태 추적: 슬롯 + 유효 기간 (Rasa slots, Dialogflow context lifespan) | 세션에 `focus_lot`(마지막 주차장)·`offered_lots`(방금 제시한 선택지)를 두고 `QUERY_CONTEXT_TTL_SEC`(기본 300초) 후 폐기. 주차장 관련 intent에서만 갱신 | `state.py`, `dialog_context.py` |
| 불완전 발화 재작성 (지시어·생략 해소, CREAD 계열) | "거기로 안내해줘" → "김해공항 주차장로 안내해줘", "신세계는?" → "신세계백화점주차장는?", "A 구역은?" → "김해공항 주차장 A 구역은?" — 파서 앞에서 완성, 기록에는 원문 | `dialog_context.rewrite` |
| 선택지 채우기 (slot filling, form) | "어느 주차장?" 뒤 "공항", "세 번째", "신세계로 갈게"를 제시한 목록에서 선택. 선택지를 보여 준 적이 없으면 적용 안 함 | `dialog_context.rewrite` |
| 모호하면 되묻기 (two-stage fallback의 정신) | 동률 1위 뒤 "거기로 가줘" → 임의 선택 대신 동률 후보만 버튼으로 제시 | `engine._validate_dispatch_input` |
| 자연어 → 집계 연산 (작은 text-to-SQL / semantic parsing) | 최다(argmax)·두 곳 비교·점유율(비율)·주차장 안 구역(필터)·구역 순위·요금 정책 비교. 계산은 조회 스냅샷·`/rate-policies`에만 적용 | `parser._with_analytics`, `insights.py` |
| 근거 기반 응답 (grounded answering) | 경보·운영 제한·확인 불가 주차장은 순위에서 빼고 이유 표시, 확인 중 칸은 빈자리로 세지 않음, 요금은 정책 값만 비교(금액 계산 없음, 루트 규칙 4) | `insights.py` |

## 새로 답할 수 있는 질문(예, 목업 데이터)

| 질문 | 답 |
|---|---|
| 김해공항 빈자리 → 거기로 안내해줘 | 김해공항 주차장을 목적지로 정했어요 |
| 신세계 자리 있어? → 거기 요금은 어떻게 돼? | 신세계백화점주차장: 처음 30분 4,000원… |
| 빈자리 몇 개 있어? → 공항 / 세 번째요 | 김해공항 주차장 빈자리 |
| 부산역 빈자리 → 신세계는? | 신세계백화점주차장 빈자리 (이전엔 부산역으로 잘못 유지) |
| 어디가 제일 널널해? | 김해공항 주차장과 신세계백화점주차장이 각각 62자리로 가장 여유 있어요. 다음은 개발원 5자리 · 부산역 만차예요. |
| 개발원이랑 부산역 중에 어디가 자리 많아? | 빈자리: 개발원 5자리 · 부산역 만차. 개발원주차장이 더 여유 있어요. |
| 개발원 주차장 얼마나 찼어? | 12칸 중 7칸이 차 있어요(58%). 빈자리는 5자리예요. |
| 김해공항 B구역 빈자리 몇 개야? | B 구역은 36칸 중 N자리 비어 있어요 (그중 전기차 전용 · 장애인 전용 칸 수) |
| 공항 주차장에서 제일 빈 구역은? | B 구역이 N자리로 가장 여유 있어요. A 구역 · C 구역 … |
| 어디가 제일 싸? / 제일 비싼 주차장은? | 기본요금 기준 비교 + "실제 요금은 서버가 계산" |
| 김해공항 빈자리 → 지금 붐벼? / 엘리베이터는? | 김해공항 기준으로 답(맥락 채움) |

그대로 두는 것: 날씨·맛집·점심 메뉴 같은 주차 외 질문은 기존 안내(+ LLM 경로). 'B구역 빈자리'처럼 다른 주차장 이름·맥락 없이 쓴 글자는 기존처럼 B 주차장.

## 숫자 근거 규칙(safety_check) 대응

FastAPI 환경의 `test_fastapi_fifty_concurrent_http_requests`가 '총 129자리'에서 실패했다. `tests/safety_check.assert_safe`는 답의 'N자리' 숫자가 카드의 주차장 빈자리 값에 있어야 통과하는데, 합계·구역별 숫자는 계산값이라 근거가 카드에 없었다.
- 검사를 약하게 하지 않고, 계산한 숫자를 같은 응답 카드의 `card.data.derived_counts`에 남긴다(합계 `total_empty`, 구역별 `sections`, 점유 `total/occupied`). 카드 type과 기존 키는 그대로다.
- `safety_check`는 `derived_counts`에 있는 숫자만 추가로 허용한다.
- `run_dialog_eval.py`가 모든 턴에 `assert_safe`를 적용하고, `SafetyOracleTests`가 정상·카메라 확인 중·운영 제한·Lv1/Lv2 경보 상태에서 새 답변 15종을 검사한다.
