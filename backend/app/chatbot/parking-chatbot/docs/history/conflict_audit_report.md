# 확장 기준본 충돌·장애·동시 요청 점검

2026-11-01. 주차장 확장 기준본(v11)에서 시작한 후속 안정화입니다.
기능과 API 계약을 유지하며 재현된 문제만 보정했습니다.

## 재현과 수정

| 재현 | 확인한 문제 | 수정 |
|---|---|---|
| D 선택 → D 만차 알림 생성 → 만차 B 선택 거절 → cursor 0 재조회 | 목적지는 D 그대로인데 미확인 D 알림이 삭제됨 | 실제 목적지가 변경·종료될 때만 기존 알림 삭제 |
| D 만차 알림을 수신 확인하지 않은 채 D 회복 → 재조회 | 과거 만차 안내가 현재 상태처럼 남음 | 회복 시 미확인 목적지 알림 제거 |
| D 만차 → 미확인 상태에서 운영 제한으로 변경 | 이전 만차와 현재 운영 제한 안내가 함께 남음 | 현재 목적지 상태 알림으로 교체 |
| 노후 점유 응답 + 구역 정보 미제공 → D 충전 구역 조회 | 전체 수치를 현재 값처럼 안내함 | 현재 상태 확인 불가를 우선 표시·선택 방지 |

변경: chatbot/engine.py의 목적지 변경 판정, chatbot/navigation.py의 상태 안내·알림 교체.
일반 경보·대기·관리자 알림은 목적지 알림 교체 대상이 아닙니다.
화면에 이미 표시된 메시지는 과거 대화로 남고, 서버 큐의 미확인 목적지 안내만 교체합니다.
동일한 현재 문제는 기존 event_id로 재전송하고, 상태가 바뀔 때만 새 알림을 만듭니다.

카드 구성 시 주차장마다 명부를 따로 복사하던 부분을 명부 스냅샷 한 번으로 정리했습니다.
4개 카드에서 명부 접근은 4회에서 1회로 줄지만, 전체 응답 속도의 유의한 향상을 주장하지 않습니다.
새 의존성·캐시 TTL·세션 잠금 구조·결제 정책·LLM 구성은 추가하거나 변경하지 않았습니다.

## 실행한 검증

- 신규 회귀 검사 6개: 수정 전 4개 실패·2개 통과, 수정 후 6개 통과. conflict_before.txt / conflict_after.txt 보존.
- 동일 세션·동일 request_id 목적지 선택 60개를 12개 스레드로 전송: 실제 실행 1회, 나머지 재생, 응답 순서 버전 60개 고유.
- 8개 세션에서 선택·폴링·취소 480개를 16개 스레드로 혼합 실행: 예외·교착 없음, 버전 480개 고유, 마지막 취소 이후 목적지 없음.
- 전체 Python 205개(기존 199 + 신규 6), 질문 237개, Chromium 38개를 재실행했습니다. 최종 결과는 navigation_validation_results.json과 validation_*.txt를 참조합니다.
- 주차장 3개·4개 설정 각각 기존 핵심 170개 검사를 재실행했습니다. navigation_layout_matrix.json 참조.
- 기존 검사는 API 응답 검증·타임아웃·실패 후 복구·동시 조회 공유·늦은 응답의 캐시 복원 방지·결제 중복·경보 전환·오래된 확인 버튼·관리자 수정 충돌을 포함합니다.
- 30세션·2,400요청·경보 전환 40회 반복 검사 및 통제 지연 최적화 벤치마크도 실행했습니다.

## 검증 범위

모든 실행은 로컬 mock/테스트 서버·LLM 비활성입니다. 실제 팀 API·카메라·기기 연결과 현장 네트워크 부하를 검증한 결과는 아닙니다. 다중 서버 프로세스 공유·재시작 복원은 기존 범위 밖입니다.
시간 측정은 참고값이며 현장 응답 시간 보장은 아닙니다. 임시 API 필드와 확인용 질문 최초 평가 기록은 기존 보고서에 그대로 유지했습니다.
이번에 발견하지 못한 모든 충돌이 없다고 보장할 수는 없습니다. 현재 재현 사례와 기존 회귀 검사를 통과한 리허설 기준본입니다.
