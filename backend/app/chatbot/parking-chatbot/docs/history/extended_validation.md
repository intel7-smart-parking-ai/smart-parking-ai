# 추가 현실적 질문 검증 — 2026-11-01

## 범위

현재 제공하는 빈자리·차량 위치·요금 규칙/조회·모의 결제·출차 진단·관리자 요청/상태·대기·경보 안내 안에서 질문을 늘렸다. 환불, 이메일 영수증, 차량 제어 같은 미구현 요청은 실제 실행하지 않고 fallback으로 처리하는지 포함했다. 기능을 추가한 것이 아니라 파서 우선순위·부정 표현·상태 조회 인식을 보정했다.

## 세트와 결과

| 세트 | 문장 수 | 결과 |
|---|---:|---:|
| 최초 질문 | 36 | 36/36 |
| 1차 현실적 질문 | 69 | 69/69 |
| 이번 보정용 | 50 | 보정 전 27/50 → 최종 50/50 |
| 별도 확인용 | 20 | 첫 평가 20/20, 최종 20/20 |
| 합계 | 175 | 175/175 |

별도 확인용 문장은 보정용 50문장과 함께 파일로 작성한 뒤, 첫 규칙 보정이 끝날 때까지 평가하지 않았다. 첫 평가 당시 보정용에는 2개 실패가 남았지만 확인용은 20개 모두 통과했다. 이후 남아 있던 보정용 2개만 수정하고 모든 세트를 재검사했다. 확인용 결과에 맞춰 실패 문장을 고친 것은 아니다.

다만 모든 문장은 같은 작업자가 직접 작성했으며 실제 사용자 로그도, 독립 평가자의 블라인드 평가도 아니다. 보정용 통과율은 회귀 결과다. 확인용 20개 역시 일반적인 현장 정확도 추정에는 작다.

## 주요 발견과 보정

- `관리자 필요 없어`, `직원은 부르지 마`, `호출하지 말고 기다려`: 신규 관리자 호출 대신 진행 중 요청 취소.
- `결제 말아줘`, `결제 안해도 돼`, `아직 정산하지 말아주세요`: 결제 실행 의도로 보내지 않음.
- `결제 말고 요금만 보여줘`: 요금만 조회. 기존 결제 확인도 종료.
- `결제된 건지 알려줘`: 현재 결제 상태 조회.
- `직원 불렀는데 확인했나요`, `관리자 언제 오나요`, `관리자 호출됐나요`: 신규 호출 대신 기존 문의 상태 조회. 도착 시간을 추정해서 만들지 않음.
- `차단기가 먹통이에요`: 출차 문제 진단.
- `주차요금 계산 기준 좀`: 현재 요금 대신 요금 규칙 안내.
- `대기하지 않을게요`: 등록 취소.
- `네 맞아요`, `네, 맞습니다`, `ㅇㅋ`, `아니에요`, `아뇨 틀렸어요`: 완결된 짧은 확인/부정 표현 처리.

짧은 확인은 문장 전체가 확인 표현인 경우에만 인식한다. 긴 문장에 '네'라는 글자가 들어갔다고 실행 동의로 쓰지 않는다.

## 부작용 검사

문장 의도만 검사하지 않고 다음을 실제 모의 엔진에서 확인했다.

1. 관리자 거절 표현으로 문의가 만들어지지 않음.
2. 관리자 상태 질문으로 새 문의가 만들어지지 않음.
3. 결제 상태 질문으로 결제 확인 상태에 들어가거나 paid가 바뀌지 않음.
4. 결제 준비 중 조회만 요청한 뒤 '네'를 말해도 이전 결제 실행 안 됨.
5. 여러 형태의 결제 거절 후 '네'를 말해도 결제 안 됨.
6. 자연스러운 확인 응답으로 기존 차량 요금 조회가 이어짐.
7. 대기 거절 후 실제 대기 등록이 취소됨.
8. 결제 준비 중 이메일 영수증 같은 미구현 질문이 끼면 이후 '네'로 결제되지 않음.

새 테스트는 두 CSV 검사 메서드와 위 8개 행동 검사로 총 10개다. 기존 98개에 더해 **Python 108/108 통과**했다. Chromium 15항목도 재실행해 모두 통과했다. 문장 175개를 Python 테스트 108개와 중복 합산하지 않는다.

## 재실행

```bash
python tests/run_eval.py tests/questions.csv tests/questions_realistic.csv tests/questions_extended.csv tests/questions_holdout.csv
python -m unittest discover -s tests -v
python tests/run_browser_checks.py
```

문장 평가는 LLM_PROVIDER=none으로 실행했다. 회귀 테스트도 외부 LLM 없이 모의 데이터로 실행한다. 브라우저 검사는 Node.js/Playwright/Chromium이 필요하다. `tests/extended_before.json`에는 보정 전 실패 23건을 남겼다.

## 남은 검증 범위

- 질문 하나에 여러 차량·작업이 섞이거나 대상이 불명확한 지시어가 있는 경우.
- 언어적 부정의 세밀한 차이: 취소 명령과 '안 해도 되나요?' 같은 규정 질문.
- 심한 오타·음성 인식 오류·새로운 표현 전반.
- 아직 구현되지 않은 전용면별 조회·예약·환불 등을 실제 지원하는지의 별도 범위 검토.

이번에는 새 모델, 자동 오타 교정기, 외부 API를 추가하지 않았다. 다음 시연 리허설에서 팀원이 문장 목록을 보지 않고 직접 질문한 로그를 모아, 보정용과 최종 확인용을 다시 구분하는 것을 권장한다.
