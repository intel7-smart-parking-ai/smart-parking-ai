# Claude 정리본 변경 보고서 (동결 기준본)

2026-11-02 · 기준: GPT 주차장 확장·구역·목적지 안내본(v5)
반영 지시서: `EPIC06_최종수정지시서.md`, `EPIC06_기능정리_지시서.md` (단, 문의 상태 추적은 **삭제 대신 끄기**)

이 버전을 **코드 동결 기준본**으로 합니다. 이후 변경은 팀원 리허설 실패 문장, API v1 형식 교체, 미니카 실측값 반영만 합니다.

## 1. 무엇을 바꿨나

### 1-1. 겹치는 기능 줄이기 (칩만 정리, 기능은 유지)

| 항목 | 변경 |
|---|---|
| 빈자리 대기 칩 | 다른 주차장으로 갈 수 있으면 대안 칩만. **이용 가능한 곳이 하나도 없을 때만** "자리 나면 알려줘"(아무 주차장) 칩 |
| 구역별 대기 칩 | 칩으로 제공하지 않음 |
| 문장으로 대기 요청 | "B 자리 나면 알려줘" 등은 기존처럼 등록 |
| "내 이용 현황" 칩 | 모든 칩 묶음에서 제거. 문장으로 물으면 기존처럼 진행 표시 카드로 답함 |
| "목적지 취소" 칩 | 목적지가 있을 때만 표시 |

### 1-2. 관리자 문의 상태 추적 끄기 (`CALL_STATUS_TRACKING=0`, 기본값)

| 항목 | 꺼진 상태(기본) | 켠 상태(`=1`) |
|---|---|---|
| 관리자 호출 | 즉시 접수, 상황 요약, 상황 보고서 연결 | 같음 |
| 상태 변경 버튼(확인 중·처리 완료) | 관리자 화면에서 숨김, API는 400 | 이전 동작 |
| 사용자 상태 알림·해결 확인 버튼 | 없음 | 이전 동작 |
| "내 문의 상태" 칩 | 숨김 | 이전 동작 |
| 같은 사람의 반복 호출 | 같은 세션·차량·사건 + **마지막 호출 후 10분 이내**면 하나로 (`CALL_MERGE_SEC=600`) | 이전 동작(접수·확인 중이면 통합) |
| "관리자 확인했나요?" 등 상태 질문 | 새 호출 없이 고정 답변 | 이전 동작 |

- 상태 질문 답변: "관리자 화면에 문의가 접수돼 있어요. (문의 #2) 처리 상황은 현장 관리자에게 확인해 주세요." / 문의가 없으면 "접수된 관리자 문의가 없어요. 필요하면 관리자 호출을 눌러 주세요."
- 반복 호출 답변: "관리자 화면에 이미 접수된 문의가 있어요. (문의 #1)"
- 경보 중 재호출은 기존처럼 새 문의로 등록되고 상황 보고서에 연결됨

### 1-3. 시연 도구 (이용자 화면 "테스트" 패널, `/demo` 경로, mock 전용)

| 버튼 | API | 동작 |
|---|---|---|
| 입차 1대 | `POST /demo/enter {lot_id}` | 선택 주차장의 빈 칸 하나를 시연용 점유 |
| 만차로 만들기 | `POST /demo/fill {lot_id}` | 남은 칸을 모두 시연용 점유 |
| 시연 점유 비우기 | `POST /demo/clear {lot_id}` | 시연용 점유만 비움 (실제 차량 기록 유지) |
| 운영 제한 켜기/끄기 | `POST /demo/restriction {lot_id, restricted, reason}` | 진입 불가와 사유 설정 |
| 선택 차량 입차 | `POST /demo/enter {lot_id, vehicle_no}` | 지정 차량을 입차 (목적지 감시 종료 시연) |

- 시연용 점유는 차량 번호가 없는 칸 점유입니다. 차량 목록·상황 보고서 영향 차량에는 섞이지 않습니다. 패널 아래에 현재 시연 설정이 표시됩니다.
- `DATA_SOURCE=api`에서는 기존 경보·출차처럼 사용 불가로 응답합니다.
- 관리자 키 규칙은 기존과 같습니다 (`ADMIN_TOKEN` 없으면 서버 PC에서만).

### 1-4. 문구 (쉬운 말, 내부 표현 제거)

| 상황 | 이전 | 지금 |
|---|---|---|
| 만차 조회 | B 주차장은 만차 상태예요. | B 주차장은 만차예요. |
| 목적지 만차 알림 | D 주차장이 만차 상태로 바뀌었어요. | D 주차장이 만차가 됐어요. |
| 목적지 경보 알림 | D 주차장이 경보 상태로 바뀌었어요. | D 주차장에 경보가 발생했어요. |
| 운영 제한 조회 | C 주차장은 운영 제한: 점검 중 상태예요. | C 주차장은 지금 이용할 수 없어요. (점검 중) |
| 운영 제한 알림 | C 주차장이 운영 제한: 점검 중 상태로 바뀌었어요. | C 주차장을 지금 이용할 수 없게 됐어요. (점검 중) |
| 상태 확인 불가 | …현재 상태 확인 불가 상태예요. | … 상태를 지금 확인할 수 없어요. |
| 놓친 경보 + 해제 | "경보 이력: … Lv2 발생을 서버가 관찰했어요…" + "경보가 해제됐어요…" (2개) | "잠시 D 주차장에 경보가 있었고 지금은 해제됐어요. 운영 재개 여부는 관리자 안내를 확인해 주세요." (1개) |
| 지나간 해제 메시지 | "경보 이력: 경보 해제…" | 보내지 않음 (현재 상태만 전달) |

운영 제한 사유는 지시서 예시("점검 중이라 이용할 수 없어요")와 달리 괄호로 붙였습니다. 사유가 "공사"처럼 어떤 말이 오더라도 문장이 어색해지지 않게 하기 위해서입니다.

## 5. 남은 한계

- 세션·목적지·대기·문의·보고서는 서버 메모리 저장
- 이미 입차된 차량을 선택한 상태에서 목적지를 정하면 바로 "입차 확인으로 감시 종료"가 됨 (GPT 설계 유지. 시연에서는 차량 선택 전에 목적지를 정할 것)
- LLM 분류기는 여전히 꺼져 있음 (`LLM_PROVIDER=none`)
