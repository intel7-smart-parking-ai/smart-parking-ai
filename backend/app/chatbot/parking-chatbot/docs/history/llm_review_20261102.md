# LLM 분류기 점검 (2026-11-02)

동결 예외 사유: LLM을 켜는 순간 D 주차장 문장이 틀리게 분류될 수 있는 결함. 규칙 파서·응답·화면 동작은 바뀌지 않음.

## 2. 켜기 전에 꼭 할 것

### 2-1. 실패가 조용히 묻힘 (코드 검토)

`classify()`는 모든 오류를 `except Exception: return None`으로 삼키고 기록을 남기지 않는다.
API 키 누락, 모델 이름 오타, 3초 초과, JSON 형식 오류가 전부 "이해하지 못했어요" 안내로만 보인다.

- 위험: 켰다고 생각했는데 실제로는 한 번도 안 쓰이는 상태를 모를 수 있음
- 위험: 11/11 측정 지표 중 실패율을 셀 수 없음
- 조치: 실패 이유별(시간 초과 / 통신 오류 / 응답 형식 오류 / 허용 밖 intent) 로그와 횟수 기록. 수정량은 `llm.py` 안 10줄 안팎

### 2-2. 지금 질문 세트로는 LLM 효과를 잴 수 없음 (실행 확인)

질문 7세트 237문장은 전부 규칙 파서가 처리한다. LLM으로 넘어가는 건 범위 밖 문장(날씨 등)뿐이다.
그래서 LLM을 켜도 지금 세트의 정답률은 그대로이고, 늘어나는 건 응답 시간뿐이다.

- 조치: **규칙이 놓친 문장만 모은 LLM 평가 세트**를 따로 만든다. 팀원 블라인드 리허설에서 나온 실패 문장이 바로 그 재료
- 비교: 같은 세트로 "규칙만" vs "규칙 + LLM"의 정답률, 평균·최대 응답 시간

### 2-3. intent 뜻 설명이 없음 (코드 검토)

지시문은 intent 25개를 이름만 나열한다. `fee_rule`(요금 규칙)과 `get_fee`(내 차 요금),
`my_status`(이용 현황)와 `find_my_car`(차 위치), `alert_near_my_car`(내 차 근처 경보) 같은 구분은 이름만으로 헷갈릴 수 있다.

- 조치: intent마다 한 줄 설명과 예문 1개. 2-2의 평가 세트로 효과 확인

## 3. 동작·사용성

| 항목 | 내용 | 판단 근거 |
|---|---|---|
| 응답 시간 | 규칙 파서 평균 약 1.5ms. LLM은 규칙이 모를 때만 부르지만, 그때는 외부 서버 왕복으로 최대 3초(`LLM_TIMEOUT_SEC`)까지 기다림. 범위 밖 잡담도 LLM을 거침 | 실행 확인(규칙), 코드 검토(LLM) |
| 경보 Lv2 중 | 대피 상황에서 3초 대기는 길다. Lv2일 때는 LLM을 건너뛰고 바로 경보 칩으로 안내하는 안 검토 | 코드 검토 (지금은 경보 단계와 무관하게 호출) |
| 시연장 통신 | 와이파이가 끊겨도 3초 뒤 칩 안내로 넘어가 기능은 유지. 다만 모르는 문장마다 3초씩 멈춤. 시연 때 제한 시간을 1.5초로 줄이는 안 | 코드 검토 |
| 구역 값 | LLM 경로는 구역(zone)을 받지 않음. 원문에서 규칙이 뽑은 구역은 그대로 유지되므로, 등록되지 않은 새 별칭일 때만 빠짐 | 코드 검토 |

## 4. 안전장치 (이미 있음)

| 장치 | 내용 | 테스트 |
|---|---|---|
| 허용 intent 검사 | 목록 밖 intent는 무시하고 규칙 결과 사용 | `test_regressions` |
| 확인 단계 보호 | LLM이 `confirm_yes`를 내도 결제·확인을 통과시키지 못함 | `test_regressions` |
| 실행 대상 보호 | 결제·관리자 호출에서 사용자가 말하지 않은 차량 번호를 LLM이 넣을 수 없음 | `test_regressions` |
| 값 검사 | 주차장 ID는 현재 명부, 차량 번호는 범위 안만 통과. 사용자 문장에서 뽑은 값이 LLM 값보다 우선 | `test_regressions` |
| 관리자 부정 표현 | "관리자 말고 ~"는 LLM으로 넘기지 않음 | `test_claude_round2` |
| 숫자·문장 생성 금지 | LLM 출력은 intent와 값뿐. 빈자리·요금·경보 문장은 템플릿과 API 값 | 구조 |

사용자가 지시문을 바꾸려는 문장을 넣어도, 결과는 허용된 intent 중 하나로 잘못 분류되는 것이 최대이고 결제는 확인 단계를 거친다.

## 5. 운영·발표

- 외부 전송: 규칙이 모르는 문장만 외부 LLM 서버로 간다. 차량 번호는 장난감 번호라 개인정보는 없음. 발표 때 한 줄 언급 가능
- 비용: 응답 최대 100토큰, 지시문 수백 토큰, 모르는 문장만 호출 → 시연 규모에서는 작음. API 키 발급·비용 부담 주체는 팀 결정
- 모델: 분류만 하므로 가볍고 빠른 모델이 적합. 응답 시간 측정 후 결정
- 키 이름: 레포 루트 `.env.example`은 `LLM_API_KEY`, 챗봇은 `ANTHROPIC_API_KEY`/`OPENAI_API_KEY`. 챗봇 폴더의 `.env`를 읽으므로 동작에는 문제없음, PR에 명시
