## 코드 검토 수준 및 남은 한계

- 실제 팀 백엔드·DB·카메라·차단기·사용자 웹(EPIC07) 연결은 실행하지 않았습니다. API 우선순위 검사는 모의 HTTP 응답으로 확인했습니다.
- 별도 `EPIC06_챗봇_작업지침서.md`는 검색으로 확보하지 못했습니다. 첨부 작업 지시서와 기존 프로젝트 범위에 따라 구현했습니다. 제공되면 충돌 여부를 대조해야 합니다.
- A/B 실물, C/D 가상, 각 8칸, 일반 6·충전 1·장애인 1은 임시 설정입니다. 미니카 실측과 API 합의 후 설정을 바꿉니다.
- lots·zones·운영 제한·destination·catalog는 PROVISIONAL입니다. 11/02 대조 항목은 api_contract.md에 있습니다. API 명부는 전체 목록 응답을 전제로 합니다.
- 목적지는 안내용 상태이며 예약·지도·경로를 만들지 않습니다. 실제 입차 주체는 선택 차량 컨텍스트로만 확인합니다. 차량을 선택하지 않으면 취소/TTL로 종료합니다.
- 세션·목적지·대기·알림은 메모리입니다. 서버 재시작과 다중 프로세스 공유는 기존 범위 밖입니다.
- 구역 수를 모르면 0으로 만들지 않습니다. 장애인 자격·충전 시작·과금은 판단하지 않습니다.
- 응답 시간 수치는 로컬 측정이며 현장 네트워크 성능 보장은 아닙니다. 외부 의존성을 새로 추가하지 않았습니다.

## Claude 재검토 요청 사례

| 재현 상태·문장 | 기대 동작 |
|---|---|
| B에 빈자리 생성 → “B로 갈게” → B 만차 → updates 두 번 | 목적지 B 유지, 대안 알림 한 번, 같은 상태 반복 없음 |
| 목적지 B → B Lv2 | B 후보 제외, 경보 배너·대피 흐름 유지, 다른 목적지는 사용자 선택 |
| 기본 만차 B → “B로 안내” | 선택 거절, 최대 두 대안 |
| 모든 주차장 만차/제한 | 빈자리를 지어내지 않고 대기 제안 |
| 목적지 D → “7번 차 위치” → “네”로 parked 확인 | 목적지 null, 대기 등록은 별도 유지 |
| D 안내 버튼을 받은 후 D 만차로 변경 → 예전 버튼 클릭 | 최신 상태 재검사 후 선택 거절 |
| “B 충전 구역 자리 있어?” → “그럼 C는?” → “일반 구역은?” | B/ev → C/ev → C/normal |
| 위 조회 후 요금 질문 또는 5분 경과 | 구역·주차장 문맥 초기화 |
| zones 미제공 → 충전 구역 조회 | 미제공 안내·전체 수치, 충전 빈자리 0으로 추정 금지 |
| 목적지 D → entry_allowed=false, 점검 중 | 운영 제한 사유·대안 알림 한 번, 경보와 구분 |
| D 관련 조회 후 “이디야 근처 맛집” | D로 임의 해석하지 않음 |
| “호출 하지 말아 주세요” / “관리자 불러 주지 마세요” | 동일 거절 안내, 새 호출 없음 |

기존 최적화·안정화 보고서는 과거 작업 기록입니다. 현재 검사 결과는 이 문서와 navigation_validation_results.json을 기준으로 확인합니다.
