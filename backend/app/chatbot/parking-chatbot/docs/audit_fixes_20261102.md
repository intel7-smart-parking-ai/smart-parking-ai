## 수정 결과

검수에서 재현한 6개 오류와 기존 FastAPI 검사 설정 1건을 수정했다. API와 LLM의 본문 수신 처리를 공통화했고, 기존 기능과 비활성화 정책을 유지했다. 관리자 문의 상태 추적은 기본 꺼짐이며 관리자 호출·접수·상황 보고서 연결은 그대로 사용할 수 있다. 대기와 이용 현황은 문장으로 요청할 수 있다.

| 검수 항목 | 수정 내용 | 확인한 동작 |
|---|---|---|
| F-01 출차 차량 변경 | 목록을 적용할 때 현재 선택을 보존하고 이전 새로고침 응답을 무시 | 느린 응답 중 07 선택 유지, 중간에 08로 바꾸면 08 유지, 출차 시 선택 차량만 제거 |

## 경계 처리

- API와 LLM 응답은 **1MiB 이하**로 제한한다. `Content-Length`가 없더라도 상한을 넘는 본문을 거절한다. 본문 길이가 명시된 경우 실제 길이도 확인한다. 한도 초과는 기존 정보 확인 불가·LLM 대체 안내 경로로 처리된다.
- 시간 제한은 각 외부 호출의 설정값과 현재 화면 요청의 남은 예산 중 작은 값을 적용한다. 이 제한은 느린 본문과 연결 후 헤더 수신에도 적용된다. 원래 문서의 “LLM 3초”는 외부 응답을 기다리는 설정값이며 화면 전체가 항상 3초 이내 완료된다는 의미가 아니다.
- 타이머가 끝나면 진행 중인 읽기를 깨우기 위해 소켓을 shutdown한다. 요청 종료 때 타이머를 취소하고 회수한다. TLS 인증서 검증을 유지하며, 로컬 HTTPS 검사에서 신뢰하지 않은 인증서는 거절하고 신뢰한 인증서로는 정상 수신·시간 제한 종료를 확인했다.
- OS 이름 해석(DNS) 자체를 별도 프로세스로 격리하지는 않았다. 이번 시간 제한 재현은 로컬 IP의 HTTP/HTTPS 통신 대상이다.
- 선택 차량이 목록에서 사라지면 임의로 다른 차량을 고르지 않고 출차 버튼을 비활성화한다. 다음 출차를 하려면 차량을 다시 선택해야 한다.
- 실제 boolean만 허용하지만 두 서버의 잘못된 입력 HTTP 코드는 프레임워크에 따라 개발 서버 400, FastAPI 422가 될 수 있다. 둘 다 상태를 바꾸지 않는 4xx 거절로 검사했다.
- 세션 사용 예약 중 초기화 요청은 409로 거절한다. 정상 요청 또는 실패 요청이 끝나면 예약을 해제해 이후 유휴 정리와 초기화를 허용한다.

## 실행한 검증

| 검사 | 결과 |
|---|---|
| Python 전체 | **242/242 통과, 건너뜀 0** — 기존 227개 + 새 회귀 검사 15개 |
| Chromium 전체 | **51/51 통과** — 기존 45개 + 새 경계 검사 6개 |
| 질문 CSV 7개 | **237/237** — 분류 평가이며 전체 대화 시나리오 수와 구분 |
| 동시 실행 시나리오 | **30사용자·2,400요청·경보 변경 40회**, 내부 단언 모두 통과, 종료 시 미완료 공유 조회 0 |
| 기존 최적화 벤치마크 | 동시 차량/빈자리 조회 각각 12건을 백엔드 읽기 1회로 공유 |

Python 전체는 12.801초에 완료됐다. 로컬 모의 데이터, LLM 비활성 환경으로 실행했고 FastAPI/httpx를 설치해 선택 검사도 모두 실행했다. 별도 LLM 검사는 외부 공급자가 아닌 공통 전송 경로를 로컬 HTTP 서버로 시험한 것이다. TLS 검사에는 신뢰·비신뢰 로컬 인증서를 사용했다.

동시 조회 벤치마크는 40ms 모의 지연 조건에서 차량 조회 최대 42.27ms, 빈자리 조회 최대 46.04ms였다. 이는 통제된 검사 결과이며 실제 팀 API 응답 시간이나 일반적인 처리량 보장은 아니다.

원시 결과는 `docs/validation_20261102/`에 포함했다. 새 테스트는 다음 두 파일이다.

- `tests/test_audit_fixes.py`: 실제 HTTP/HTTPS 수신, 세션 경합, 입력 검증, 두 서버의 거절 정책
- `tests/browser_audit_fixes.cjs`: 느린 새로고침, 중간 선택 변경, 응답 역전, 출차 대상, 빈 입차 입력

전체 선택 검사를 실행하려면 FastAPI/httpx, Node.js/Playwright/Chromium이 필요하다. HTTPS 회귀 검사는 로컬 검사 인증서 생성을 위해 openssl을 사용하며 없으면 그 검사만 건너뛴다. 개발 서버 자체는 기존처럼 Python 표준 라이브러리만으로 실행할 수 있다.

## 남은 범위

실제 팀 API의 경로·필드·결제 및 카메라/출구 장치 연결, 실제 LLM 공급자 연결, 시연 기기의 장시간 운용은 별도 검증 대상이다. 메모리 저장·단일 프로세스 운영 조건과 기존 보존 정책은 그대로다. 화면 메시지와 운영 이력의 장기 보존 상한은 이번 6개 오류 수정에 포함하지 않았다.
