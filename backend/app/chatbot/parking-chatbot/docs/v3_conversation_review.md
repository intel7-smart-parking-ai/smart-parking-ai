# 대화 개편 검토본

2026-11-07, 팀 main `86c3069` 기준. 작업 브랜치는 `feature/KAN-9-agentic-rebuild`이다.

## 동작

| 입력 | 처리 |
|---|---|
| “23번 차 위치랑 요금 알려줘” | 명확한 번호로 위치·요금을 한 응답에 표시한다. 두 응답의 방문 기록이 맞지 않으면 요금은 미확인으로 안내한다. |
| “결제는 하지 말고 위치랑 요금만” | 조회한다. 결제 견적 승인 상태를 만들지 않는다. |
| “23번 위치·요금 알려주고 결제도 해줘” | 조회와 서버 견적을 보여 주고 모의 결제 승인 버튼을 표시한다. 승인에만 결제 요청을 전송한다. |
| “공항이랑 신세계 중 어디가 좋아?” | 두 곳의 빈자리와 기본요금을 표시하고 사용자가 선택하게 한다. |
| “전기차인데 공항 쪽에 30분 뒤 도착해” | 현재 충전 구역 상태와 예측 한계를 설명한다. 조건이나 대상이 모호한 경우 필요한 정보를 묻는다. |
| “그럼 일반 자리는?” | 같은 세션의 장소·비교 후보에서 일반 구역을 다시 확인한다. |
| 칩 또는 대피 안내 | 기존 업무 흐름과 응답 형식을 사용한다. |

LangChain 에이전트 하나가 원문과 최근 대화를 받고, 내부 조회 결과를 읽어 답한다. 호출 수와 요청 시간을 제한한다. 내부 정책·시설 안내는 승인된 팀 자료와 시연 설정에서 검색한다. 차량·결제·관리자·주차 업무는 `workflows/`에 나눴다. 모델에는 조회와 작업 제안 권한을 주고, 확인 상태와 실행은 업무 흐름에서 관리한다. 기존 응답 카드와 칩을 사용한다. 가상 차량번호 검색은 팀 API 지원 범위에 따른다.

## 검증

| 범위 | 결과 |
|---|---|
| 챗봇 전체, LangChain 설치 | 654개 실행, 652 통과, 2 건너뜀 |
| 챗봇 전체, LangChain 미설치 | 654개 실행, 633 통과, 21 건너뜀 |
| 팀 백엔드 pytest | 357 통과 |

| 기존 규칙 질문 세트 | 248/248 |
| 기존 대화 세트 | 개발 51/51턴, 별도 평가 22/22턴 |
| 새 복합 대화 수락 검사 | 11개 통과 |
| 시연 서버 HTTP 리허설 | 6/6 |

팀 등록 경로 `POST /api/v1/chat`에서 LangChain과 실제 API 어댑터를 사용했다. OpenRouter 호환 로컬 시험 서버가 조회 도구 호출과 최종 응답을 반환했다. 최초 원문과 후속 질문의 대화 이력, 도구 결과로 전달된 빈자리·요금, 모델 응답 후 카드, 제공자 503 이후 칩 동작을 확인했다. 이 검사에서 주차 백엔드의 쓰기 요청은 0건이었다. 모의 결제 POST의 승인 전 차단, 승인 재사용, 뒤늦은 Lv2 경보는 별도 테스트로 검증했다.

팀 런타임 패키지와 새 모델 의존성을 격리 환경에 함께 설치해 충돌 없이 import되는 것을 확인했다. Docker 기동 명령과 팀 기본 이미지로 돌아가는 절차는 [에이전트 실행 안내](agent_runbook.md)에 있다.

실제 OpenRouter 키가 필요한 Gemma 응답 품질과 3초 목표는 시연 PC에서 측정한다. 이 환경에는 Docker CLI가 없어 컨테이너 빌드·기동은 확인 대상이다. Chromium 실행 검사는 소켓 권한 오류로 시작 단계에서 멈췄다. 위 화면 로직 검사와 팀 HTTP 검사는 별도로 실행했다.
