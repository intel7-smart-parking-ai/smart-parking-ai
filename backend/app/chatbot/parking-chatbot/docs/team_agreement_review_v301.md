# 챗봇 v3.0.1 팀 합의 대조표

팀 저장소 기준은 `main`의 `86c30692379f474bf54947efa0df22e9b96d7aa2`이다. 팀 `docs/DECISIONS.md`, `docs/API_CONTRACT.md`, `docs/DAILY.md`, `CLAUDE.md`와 11월 6일 윤명수님 Q&A를 확인했다. 이 ZIP은 팀 저장소의 `backend/app/chatbot/` 전체 교체본이다. 팀 공통 API와 화면은 기준 커밋의 것을 사용한다.

| 근거 | 반영 및 확인 |
| --- | --- |
| D-05 · 전용 주차칸 | 일반차는 전기차·장애인 전용칸을 이용할 수 없다. 모델이 반대로 답하는 상황을 실제 대화 경로에서 재현했고, 승인된 안내 문구가 표시되는 것을 테스트했다. |
| D-06 · 차량번호 계약 | 팀 API의 두 자리 차량번호 `10`~`99` 계약을 유지한다. 시연 스티커 30개는 목업 배정에 적용한다. |
| D-09 · D-49 · 서버 견적과 결제 | 서버 금액과 `quote_id`로 견적을 표시한다. 승인 이후에만 멱등 키를 붙여 모의 결제를 요청한다. 결제 완료 금액은 서버 값을 사용한다. 승인 전·중복 승인·뒤늦은 대피 경보와 서버의 409 `EVACUATION_ACTIVE` 응답을 검사했다. |
| D-18 · D-33 · OpenRouter | 팀 기본 모델 `google/gemma-4-26b-a4b-it`과 환경변수 `OPENROUTER_API_KEY`를 사용한다. 키가 없거나 호출이 실패하면 내부 조회와 칩으로 안내한다. 시연용 키는 PM 관리 항목이다. |
| D-41 · D-50 · 연동 범위 | 변경 파일은 챗봇 폴더에 있다. 기존 팀 채팅 경로, 카드·칩, 음성 UI 접점과 응답 언어 처리를 유지했다. |
| D-54 · D-57 · D-59 · 배치 | 최종 30대(전기차 5·장애인 5·일반 20)와 156칸(A 12·B 16·C 64·D 64)을 대조했다. C의 21번·57번과 D의 30번 목업 차량은 일반칸에 둔다. C·D 전용칸은 최종 D-59 배치를 쓴다. |
| D-55 · 시설 안내 | 등록한 시연 설정은 시연용으로 표시한다. 미등록 시설이나 운영 정보는 확인이 어렵다고 안내한다. Lv2 대피가 우선한다. |
| D-58 · 통합 런타임 | 팀 Docker 런타임에 선택적으로 LangChain 대화 기능을 추가하는 Compose 파일과 [실행 안내](agent_runbook.md)를 제공한다. 8002 데모 서버는 팀 합의상 예비 경로다. |
| D-61 · 팀 리뷰와 병합 | 챗봇 교체본은 로컬 브랜치에서 작성했다. 팀 병합 단계는 PM 확인 후 진행한다. |
| 윤명수님 Q&A · 관리자 호출 | “관리자 부르면 돈 들어?”는 안내로 처리한다. 테스트에서 관리자 호출과 모델 실행 모두 0건이었다. 기존 칩과 명확한 규칙 요청은 바로 접수하고, 모델의 호출 제안은 확인을 거친다. |
| 윤명수님 Q&A · 음성 입력 | 기존 웹 음성입력은 화면의 입력란을 채우며 사용자 전송이 필요하다. 승인·대피 중 마이크가 차단된다. 서버에는 음성과 타이핑을 구분하는 입력 필드가 없다. |

## 대화 개편에서 확인한 동작

- 명확한 번호는 추가 확인 없이 위치와 요금을 함께 조회한다. 번호가 모호하면 확인 질문을 하고, 결제는 별도로 승인받는다.
- 공항·신세계 비교, 충전·일반칸으로 조건 바꾸기, 현재 상태를 기준으로 한 도착 문의를 같은 세션에서 이어갈 수 있다. 새 세션은 새로 시작한다. 현재 조회가 빈자리를 반환했는데 모델이 “만차”라고 답한 경우 조회값을 보여 주는 회귀 테스트를 추가했다.
- 원문·이전 대화를 읽고 내부 도구를 사용하는 LangChain 모델은 조회와 작업 제안에 관여한다. 결제와 관리자 접수 같은 실행은 챗봇 업무 코드가 통제한다. 기존 칩도 독립적으로 사용한다.

## 팀 결정 또는 시연 PC 확인 항목

- D-44의 Haiku 전환은 PM 확인 대기 상태다. D-55 설정집은 실제 PM 승인 데이터가 들어오면 연동한다. D-56의 음성 공급자 변경, Q&A의 추가 구조 재편과 Langfuse는 제안 단계로 분류했다.
- 이 환경에서는 OpenRouter 호환 로컬 서버로 팀 HTTP 경로, 실제 도구 실행과 모델 응답 처리, 제공자 장애 후 복구를 확인했다. 시연 PC의 실제 Gemma 답변 품질과 3초 목표, Docker 컨테이너 기동, 실제 마이크와 브라우저 화면은 현장 확인 대상이다.
