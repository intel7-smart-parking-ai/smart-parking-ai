# v2.15.6 — 음성 전사문 번호 해석 오류 수정

작성: 2026-11-05 KST. 기준 납품본: v2.15.5. 팀 main 확인: `2eae627463d72236fc5c11686fa9bd01b5c31aa5`.

## 변경 이유

`이십 삼 번`에서 ‘삼’만 읽거나 `삼 십 번`을 30이 아닌 10으로 읽는 문제를 고쳤다. 음성 전사문이 아라비아 숫자로만 들어온다고 가정하지 않고, 번호 표현 전체를 기존 차량 ID로 해석한다.

## 구현 범위

- `chatbot/parser.py`: `번`으로 표시한 숫자 표현의 범위를 먼저 읽고, 두 자리 한자어 수사의 공백 변형을 정규화한다. 잘못된·혼합·부호·소수·범위 밖 표현은 부분 숫자를 사용하지 않는다.
- 정정 표현은 대체 대상 구간을 다시 해석한다. 대체 대상이 둘 이상이면 첫 번호를 고르지 않고 되묻는다. 여러 번 정정한 경우 마지막 구간을 사용한다.
- 아라비아/한글 숫자가 섞인 여러 차량 요청도 모호성 검사에 포함한다.
- `이번 요금` 같은 일상 표현, 칸·금액·시간·가상 차량 규칙과 기존 원본 전사 기록을 유지한다.
- `tests/test_v2156_spoken_numbers.py`: 관련 회귀 16개 추가. 1~99 읽기 경계, 정정·모호성·유효하지 않은 번호, 이전 확인 토큰, 부정 발화, LLM 번호 덮어쓰기, 실제 HTTP 계약을 검사한다.
- `docs/voice_input_contract.md`: 기존 음성 전송 접점과 이번 패치의 범위를 정리한다.

기존 공개 API·요청/응답 필드·칩 ID·확인 방식·200자 제한·차량/요금 데이터·모델·설정은 변경하지 않았다. 기존 검사의 기대값은 변경하지 않았다. 제품 코드 변경은 파서 1개 파일이다.

## 검증 기록

질문 검사 9세트 248문항은 기존 입력과 기대값을 그대로 사용했다. 전체 검사는 확인한 팀 main을 격리 복사하고 `backend/app/chatbot`에 수정본을 배치해 실제 폴더 구조에서 수행했다.

| 검사 | 최종 결과 |
|---|---|
| 음성 번호 회귀 | 16개 통과, 실패·오류·skip 0. 전체 검사에도 포함되므로 합산하지 않음 |
| 선택 LangChain 의존성 미설치 전체 | 553개 중 544 통과 / 9 skip, 실패·오류 0 |
| 선택 LangChain 의존성 설치 전체 | 553개 중 551 통과 / 2 skip, 실패·오류 0 |
| 기존 질문 | 9세트 248/248 통과, CSV·기대값 변경 없음 |
| 팀 시연 서버 HTTP | 확인한 main의 demo_main 기반 격리 서버에서 기존 리허설 6/6 통과 |
| 공개 계약·핵심 파일 | HTTP 라우터·엔진·상태·어댑터·static·JSON 설정 등은 v2.15.5와 바이트 동일 |
| 실제 브라우저 | 실행 시도했으나 Chromium 시작 단계에서 환경의 socket 권한 제한으로 중단. 브라우저 통과로 집계하지 않음 |

선택 의존성 설치본은 제공된 requirements-llm.txt의 고정 버전을 별도 검증 경로에 설치했으며 제품 의존성 파일은 변경하지 않았다. 설치 환경의 skip 2개는 RUN_SLOW=1 장기 검사다. 미설치 환경은 여기에 선택 LLM 의존성 관련 검사 7개가 추가로 skip됐다. 실제 유료 LLM 호출은 하지 않았다.

처음 단독 ZIP 배치에서 전체 검사를 실행했을 때 팀 `backend` 경로를 찾지 못하는 검사 2개가 실패했다. 검사나 기대값을 바꾸지 않고 팀 레포 구조로 옮긴 뒤 위 최종 결과를 얻었다. 수정 과정에서 정정 대상 뒤의 ‘차량/차’ 표현도 기존 번호 단독 확인 의미를 유지하도록 점검했다.

확인한 main과 납품 기준 v2.15.5의 차이는 questions_demo_1106.csv의 줄바꿈(CRLF/LF)뿐이었고 내용·기대값은 같았다. 패치는 해당 CSV를 수정하지 않는다.

## 적용 방법

ZIP에 전체 챗봇 폴더와 `APPLY_v2156.patch`를 함께 넣었다. 기존 팀 레포에는 전체 폴더를 무조건 덮기보다 저장소 루트에서 패치를 먼저 확인하는 방식을 권장한다.

```sh
git apply --check /path/to/APPLY_v2156.patch
git apply /path/to/APPLY_v2156.patch
```

확인한 main에서 `git apply --check`를 수행했다. 로컬 변경과 겹치면 기존 변경을 보존한 채 파일별로 병합한다. 코드 본문 변경은 `chatbot/parser.py`이며 테스트·README·문서가 함께 추가/갱신된다. 자세한 경로는 ZIP의 APPLY_GUIDE.md에 있다. 이 작업은 원격 저장소에 push하거나 PR을 만들지 않았다.

## 남은 범위

- 이번 수정은 챗봇이 받은 텍스트의 번호 해석이다. 실제 Whisper 정확도, 모바일 마이크·발화 종료·취소·서버 추론 슬롯·QR 수정 완료를 뜻하지 않는다.
- 기존 텍스트 “네” 확인은 유지된다. 서버 수준 음성 출처 검증은 추가되지 않았다. 음성 화면의 실행 확인 단계 차단과 늦은 전사 폐기는 별도 연동 작업이다.
- 모호한 질문 목적·고유어/숫자열 읽기를 임의 추정하지 않는다.
- KAN-67 safety 응답·payment 영수증 복원·vehicle-search·D-54 목업 데이터·DATA-01/DNS-01은 이번 음성 번호 패치에 섞지 않았다.
- 실제 LLM·Windows·현장 휴대폰·실물 장비 시험, 저장소 push/PR/병합은 별도다.
