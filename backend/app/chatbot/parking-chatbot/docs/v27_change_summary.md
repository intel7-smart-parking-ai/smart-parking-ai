GET 재사용은 하나의 engine.handle/updates 실행에만 한정한다. 기존 CachedAdapter의 TTL·세대·결제 캐시는 그대로다. 실패는 해당 요청 안에서만 재사용한다. 전송 실패를 성공으로 캐시하지 않는다.

API 응답 전체의 외부 호출 예산을 min(남은 REQUEST_BUDGET_SEC, BACKEND_TIMEOUT_SEC)로 제한했다. 경보용 초기 명부 조회가 지연된 뒤 위치 조회를 새로 기다리는 누적을 막기 위해 필요하다. 기본 2초의 총 외부 예산이며 세션 잠금 대기 정책은 유지한다. 이 예산 안에 작업을 끝내지 못하면 추가 HTTP를 보내지 않고 확인 불가로 답한다.

경보 미확인 안내를 일반 답변에서 반복하지 않아도 배너는 현재 연결 상태를 계속 표시한다. 마지막 성공 Lv2의 안전 카드는 계속 유지한다.

동일 표준 HTTP 가짜 서버를 v2.6 ZIP과 수정본에 연결했다. 질문 확인 대화가 포함되는 경우 그 호출도 기록했다.

지시서의 A 빈자리 10회와 이 재현의 9회는 호출 문맥이 다르다. 여기서는 엔진 대화를 직접 넣었고 브라우저 초기 설정 조회는 포함하지 않았다. 제시된 10회를 그대로 실측값으로 옮기지 않았다.

## 문구

| 원인 | 답변 |
| --- | --- |
| 위치 성공 + session_id null | 아직 요금 정보를 확인할 수 없어요. |
| 위치/요금 연결 실패·타임아웃·5xx | 현재 요금 정보를 확인하지 못했어요. 잠시 후 다시 조회해 주세요. |

경로 자체 404 문장의 후반은 기존 API 검사에서 확인 불가 표현을 요구하기 때문에 유지했다. 기존 테스트 기대값은 수정하지 않았다.
