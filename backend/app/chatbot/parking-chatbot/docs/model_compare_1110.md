# 챗봇 모델 실측 비교 — gemma vs Claude Haiku 5.5 (11/10, D-18 후속 · D-44 결정 자료)

D-18: 챗봇 LLM은 OpenRouter `google/gemma-4-26b-a4b-it`, "도구 호출 지원·응답 속도는 서정범이 실측 후 보고, 부적합하면 OpenRouter 안에서 모델만 교체". D-44는 Gemma → Claude Haiku 5.5 결정용으로 비워 둠.

## 조건

- 코드: `feature/KAN-9-v33-on-main`(v3.3 통합 + 리뷰 반영), mock 데이터, 모니터링 로컬 기록
- 질문: 사용자가 '이러면 안 된다'고 보낸 화면 사례 15대화(`tests/dialogs/screenshot_cases.json`) + main 새 기능·출차 5대화 = 24턴
- 실행: `python tools/run_dialogs.py <질문 파일> --env-file <키 파일>`, 모델만 `LLM_MODEL`로 바꿔 같은 순서로 실행
- 시간 제한: 질문당 8초(답 작성 호출 5초)

## 결과

| | gemma-4-26b-a4b-it | claude-haiku-5.5 |
|---|---|---|
| AI가 직접 쓴 답 | 16/24 | **19/24** |
| 조회 없이 되묻기만 한 답 | 5 ("어느 주차장을 이용하실지 말씀해 주세요") | **0** |
| AI 답이 버려져 규칙 답 | 6 | 3 |
| 평균 / 최대 응답 | **3.2초** / 5.7초 | 4.4초 / 6.8초 |
| 비용(턴당, 실측) | **약 $0.0005** | 약 $0.0013 (약 2원) |

나머지 턴은 일부러 코드가 맡는 것(충전 현황 카드, 혼잡도 예측)이다.

## 판단

- gemma는 도구 호출은 되지만, 맥락이 필요한 질문에서 **조회 없이 되묻는 경향**이 있고 근거 검사에서 버려지는 답이 많다. 그럴 때는 규칙 답이 나가 사실은 맞지만 대화가 딱딱하다.
- Haiku는 앞 대화(차 종류·차 번호·보던 주차장)와 조회를 엮어 답한다. 1초 정도 느리고 비용은 약 2.6배지만, 시연 200턴 기준 약 $0.25 수준이다.
- **권장: 시연은 Haiku 5.5** (D-44). 키 한도는 시연 PC 키 담당(D-33, PM)이 설정. gemma로 유지하면 규칙 답 비중이 늘어난다는 점을 감안.

## 설정 방법

- 시연 PC 루트 `.env`: `LLM_MODEL=anthropic/claude-haiku-5.5` (키는 기존 `OPENROUTER_API_KEY`)
- 주의: 챗봇 폴더 `.env`와 루트 `.env`의 `LLM_MODEL`이 다르면 실행 방식에 따라 다른 모델이 쓰인다(개발 서버·Docker는 루트 `.env`가 우선). 11/09 밤 실측이 Haiku였던 것도 이 때문.
