# v2.15.5 — 최신 프로젝트 명세에 맞춘 검증 기준

작성: 2026-11-05. 기준: v2.15.4 `b0e67e1`.

## 변경 이유와 범위

사용자의 “검증할 때도 최신 프로젝트 내용을 반영한다”는 지시에 따라 과거 지침과 테스트의 낡은 가정을 정리했다. **제품 기능과 런타임 코드는 변경하지 않았다.** 변경 범위는 `backend/app/chatbot/` 안의 지침·README·대본·레포 대조표와 선택 부하 검사의 기대 표현이다. 후속 첨부 `챗봇_반영사항_1105.md`도 현재 구현과 대조했다.

팀 원격 HEAD와 추적 참조를 대조해 다시 확인했다. main은 `4e048c8d7cfb7fccb3f13d7b3ccb326884ca1fd1`로 동일하지만, progress-status는 `3cab1b0738a582f2fc7f1273a6fa31ce73a021bd`, 미병합 통합 브랜치는 `f30cd77b3d03d42df3752976dfc6afaa7f382c60`으로 갱신돼 있었다. 단일 브랜치 clone의 fetch 설정 때문에 예전 참조를 최신으로 읽지 않도록 원격과 명시적으로 대조했다.

팀 DECISIONS의 D-49~D-51, 통합 개발운영지침서·GIT_RULES·API_CONTRACT·RUNBOOK_DEMO_HOST를 읽었다. 통합 지침/API 문서의 착수 초안·미갱신 상태와 더 최근의 확정 결정을 구분했다.

## 적용한 원칙

최신 사용자 승인 범위와 레포의 확정 팀 결정·API 계약을 먼저 확인하고, 이를 검증하도록 테스트를 유지한다. 이전 AI 검토의 제한을 그 위에 두지 않는다. 현재 코드가 그렇게 동작한다는 이유만으로 기대값을 바꾸지 않는다. D-49처럼 이미 승인된 공식 API 소비 경로 변경을 과거의 경로 동결 규칙만으로 막지 않는다.

| 대상 | 처리 |
| --- | --- |
| 승인 배정표·설정 가능한 표시 이름·질문 개수 등 | 근거를 남기고 관련 fixture·기대값·문서를 함께 갱신 |
| 결제 중복·확인 없는 실행·세션 혼입·거절 응답의 상태 변경·Lv2 안전 정책 | 보호 검사 유지. 실패 동작에 맞춰 기대값을 완화하지 않음 |
| 미확정 제안·모델 변경·새 기능·계약/정책 변경 | 먼저 보고하고 필요한 결정을 받음 |
| 작은 수정과 최종 검증 | 관련 검사부터 수행하고 마지막에 영향에 맞는 전체 검증. 파일마다 전체 검사 반복 금지 |
| 보고 | 새 실행과 이전 결과 참고, 검사 오류와 구현 오류, 미실행과 실패를 구분 |

상세 기준은 `docs/validation_policy.md`다. 같은 확정 명세를 반영하기 위해 이미 받은 승인을 다시 요청하지 않으며, 새 기능은 임의 추가하지 않는다.
