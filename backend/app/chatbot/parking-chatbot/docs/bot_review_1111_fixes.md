## 4. "구조적으로 남는 한계" 세 가지 — 고친 것 (11/11 오후)

| 한계 | 원인 | 고친 방법 | 결과 |
|---|---|---|---|
| 모델이 두 번 연속 느리면 답이 한국어로 나감 | 숫자만 다른 문장도 매번 모델에 번역을 맡겼다 | **문장 틀 단위로 기억**: 숫자·주차장 이름·칸·번호판을 가린 틀이 같으면 번역을 다시 쓰지 않는다. 대표 답 199개 틀은 미리 번역해 `chatbot/translation_seed.json`에 넣었다(`tools/build_translation_seed.py`, 사람이 읽고 교정) | 규칙 답·버튼은 모델 없이 번역된다. 모델을 완전히 끊어도 HTTP 10건 중 10건이 번역됨 |
| 질문 번역이 실패하면 외국어 원문이 엔진에 들어감 | 모델이 숫자를 바꾸면(`0475`→`475`) 번역을 통째로 버렸다 | **질문의 숫자를 자리표시로 가려서** 보낸다(모델이 숫자를 볼 수 없다). 검사에 걸리면 제한 시간 안에서 한 번 더. 'two hours'→'2시간' 같은 수사는 허용 | 외국어 30문항 × 동시 4명에서 질문 번역 실패 0건 |
| 가상 차량(네 자리·번호판)은 규칙만 답함 | 대화 AI에 가상 차량 조회 도구가 없었다 | **조회 도구 `virtual_vehicle_info` 추가**. 사용자가 말한 번호만 조회 가능. 위치·요금·출차만 묻는 단순 질문은 규칙이 그대로 답하고(0초), 다른 것을 함께 물으면 대화 AI가 도구로 답한다. 근거 검사는 가상 차량 결과도 위치·요금 기록으로 대조한다 | 복합 질문 4개 모두 AI 답(1.6~3.4초), '그 차 지금 나가면 얼마고…' 이어 묻기도 됨 |

만들면서 찾은 것:

- **"번호판 뒤 4자리"가 주차 "4자리"로 번역되고 있었다.** 가리기 규칙이 `N자리`를 전부 빈자리 수로 봐서 `4 spaces`·`4个车位`로 나갔다("차량번호 뒤 4 spaces 8928로…"). '뒤·끝 N자리', 'N자리 숫자'는 숫자만 가리도록 고쳤다.
- **번역문에 한국어 낱말이 남는 경우**(`…拨打 119 进行 신고`, `基本料金 기준으로…`)는 다시 받는다.
- **안전 문구 오역**: 일본어에서 "안에 계시면"이 "車内にいる場合(차 안에 있으면)"로 나왔다. 번역 지시문에 뜻을 적고, 미리 번역 파일은 "施設内にいる場合"로 교정했다.
- 대화 AI가 실패해 규칙으로 넘어와도 차량 답을 빠뜨리지 않는다(차량 답 + 나머지 질문의 규칙 답을 합쳐서 낸다).
- 오전·오후를 빠뜨린 번역은 그 답에는 쓰되 기억하지 않는다.

여전히 남는 것:

- 대화 AI가 새로 쓴 답은 틀이 없어 모델 번역이 필요하다. 모델이 두 번 연속 6초를 넘기면 그 답만 한국어로 나간다(규칙 답은 해당 없음).
- 미리 번역 파일은 한국어 문구가 바뀌면 그 틀만 다시 모델에 맡겨진다(틀린 번역이 나가지는 않는다). 문구를 바꾼 뒤에는 `tools/build_translation_seed.py`로 다시 만든다.
- 번역 품질은 제가 읽고 교정한 수준이다. 일본어·중국어 화자의 검수는 받지 않았다.
- 113문 시험(KAN-91)은 질문지 파일이 없어 여전히 돌리지 못했다.

오류 점검(`tools/robust_check.py`, 모델 없음): 이상한 입력 30개·조회 도구 이상한 번호 11개·깨진 모델 응답 6종·16스레드 × 60회 동시 번역·HTTP 10건에서 예외 0건, 500 응답 0건.

- 증상(봇, 테스트 서버): 카메라가 끊긴 개발원주차장(12칸 모두 '확인 필요')에 "개발원 주차장 자리 있어?" → 대화 AI가 "만차라서 이용 가능한 자리가 없어요". 규칙 답은 "(카메라 확인 중 N칸)"을 붙이는데 AI 답에서는 빠졌다.
- 원인: 서버는 빈자리 0·확인 필요 N으로 준다. 조회 도구가 이를 그냥 `만차`로 넘겼고, 근거 검사는 빈자리가 0이면 "만차" 표현을 통과시켰다. '모르는 상태'와 '찬 상태'를 구분하지 않았다.
- 고친 것
  - 조회 결과(`parking_status`·`compare_lots`)의 행에 `camera_check`("카메라 확인 중 N칸. 비었는지 알 수 없다…")를 싣는다. 확인 중인 칸이 없으면 넣지 않는다.
  - 근거 검사 `full_without_camera_note`: 빈자리 0 + 확인 중인 칸이 있는 주차장을 카메라 확인 언급 없이 "만차·자리 없음"이라고 하면 막고 고쳐 쓰게 한다. 진짜 만차(확인 중 0칸)는 그대로 통과.
  - 규칙 답: 목적지로 고른 주차장이 만차일 때도 "(카메라 확인 중 N칸)"을 붙인다(빈자리 답과 같은 문구). 대화 AI가 시간 초과일 때 코드가 만드는 비교 답에도 넣었다.
- 확인(gemma 실모델, 개발원 빈칸을 확인 필요로 만든 모의 데이터, 질문 7개): 개발원을 카메라 언급 없이 만차라고 한 답 0/7. 부산역(진짜 만차)은 "만차"로 정상. 챗봇 테스트 1011개 통과(2개 건너뜀), 이번 테스트 10개.
- 남긴 것: 규칙 답의 문구 자체("만차예요. (카메라 확인 중 N칸)")는 그대로 뒀다. 12칸이 전부 확인 중일 때는 "확인된 빈자리가 없어요"가 더 정확하지만, 문구를 바꾸면 미리 번역해 둔 줄과 어긋나 동결 뒤로 미뤘다.

## 9. #120 후속: 확인 중인 칸이 있으면 "만차"라는 말 자체를 쓰지 않는다 (11/11 오후 · 브랜치 `fix/KAN-9-chatbot-uncertain-wording`)

봇의 #120 검증(`서정범_120_후속.md`)에서 남은 항목 A·B·D(문법)를 고쳤다. 8번의 "남긴 것"이 이 항목이다.

- 현상: 정보는 맞지만 문장이 "만차예요. (카메라 확인 중 12칸)", "빈자리 0칸, 만차, 카메라 확인 중 12칸", "currently full … being verified"처럼 만차라고 단정한 뒤 뒤집는다. 번역하면 "full/満車/已满"이 된다.
- 원인: ① 규칙 답이 `status_sentence(…, "만차")`에 괄호만 덧붙였다. ② 조회 도구가 대화 AI에 `reason: "만차"`, `availability: "full"`을 그대로 넘겼다. ③ 근거 검사가 "만차 근처에 카메라 문구가 있는지"만 봤다.
- 고친 것 (빈자리 0 + 확인 중인 칸이 있을 때만. 확인 중 0칸인 진짜 만차는 전과 같이 "만차")
  - A 규칙 답: `navigation.status_sentence(pending=…)` → "개발원주차장은 확인된 빈자리가 없어요. (카메라 확인 중 12칸)". 전체 요약은 "개발원주차장 확인된 빈자리 없음 · 부산역주차장 만차", 비교 답은 "확인된 빈자리 없음, 카메라 확인 중 12칸", 목적지 알림은 "…에 확인된 빈자리가 없어졌어요.". 판정(`reason()`)은 그대로 두고 문장만 바꿨다.
  - B 대화 AI: 조회 결과의 사유·상태를 `확인된 빈자리 없음`·`unknown`으로 바꿔 넘기고, `camera_check`에 "이 주차장은 '만차'라고 하지 않는다"를 적었다. 근거 검사는 카메라 언급이 곁에 있어도 "만차"라는 낱말이면 막고 고쳐 쓰게 한다("확인된 빈자리는 없고 …확인 중"은 통과).
  - D 영어 문법: 개수 뒤 동사("12 spaces is" → "are", was → were, has → have).
  - 새 규칙 문장 5종의 영·중·일 번역을 `translation_seed.json`에 넣었다(모델 호출 없이 바로 번역).
- 확인(gemma 실모델, 봇과 같은 10문장, 개발원 빈칸을 확인 필요로 만든 모의 데이터): 개발원을 "만차/full/満車/已满"라고 한 답 0/10, 부산역(진짜 만차)은 "만차"로 정상. 고쳐 쓰기(repair) 0회, 시간 초과 1회(충전 자리 질문 → 규칙 답도 "확인된 빈자리 없음"), 평균 2.9초(봇 측정 평균 4.2초 — 서버·데이터가 달라 참고값). 규칙 답 4종을 영·일·중으로 번역한 12개에서도 개발원을 "full/満車/已满"라고 한 것 0/12. 챗봇 테스트 1014개 통과(2개 건너뜀), 이번 테스트 13개.
- 남긴 것: 일본어 "台"→"区画"는 동결 뒤(아래 10번 참고).

## 10. 번역 마무리: 목록 줄의 어색한 번역, 중국어·일본어 띄어쓰기 (11/11 오후 · 같은 브랜치)

- 영어 주차장 이름: 고칠 것이 없었다. 봇의 500문항 원본에서 "Gaebalwon"은 봇이 쓴 질문에만 나오고(23회), 우리 답은 전부 "Development Center Parking"(29/29)이다. 화면의 영어 이름(`frontend/src/serviceTranslations.js`)과 같다.
- 어색한 번역("checking 5 spaces cameras", "124 spaces total available parking spaces in the entire parking lot")
  - 원인: 전체 요약 줄("A 확인된 빈자리 없음 · B 만차 · C 62자리 (카메라 확인 중: A 5칸)")과 비교 줄("이름 · 빈자리 5칸, 기본요금 …")은 주차장 상태의 조합마다 모양이 달라 줄 통째로는 미리 번역해 둘 수 없었다. 그래서 모델이 그때그때 옮겼다.
  - 고친 것: 구분 기호(` · `, ` / `, `, `)로 나눈 조각이 모두 아는 틀이면 조각별로 옮겨 이어 붙인다(`response_locale._known_line`). 하나라도 모르는 조각이 있으면 전처럼 줄 통째로 모델에 묻는다. 조각과 어색했던 줄의 번역은 사람이 써서 `tools/build_translation_seed.py`의 `HAND`에 두었다(새로 만들어도 유지, `--fix-only`로 반영).
  - 결과: 규칙 답의 줄 68종(평소·개발원 확인 중·개발원+공항 확인 중 × 질문 60개) 가운데 모델이 필요한 줄 14종 → 0종. 규칙 답은 외국어에서도 모델 없이 같은 문장으로 나온다.
  - 대화 AI가 자유롭게 쓴 문장은 여전히 모델이 옮긴다. 번역 지침에 "카메라 확인 중 N칸"·"확인된 빈자리 없음"의 뜻을 적어 줄였지만 문장마다 보장되지는 않는다.
- 중국어·일본어 띄어쓰기: 문장 안의 주차장 이름·개수 앞뒤 빈칸을 지운다("目前 开发院停车场 已满。" → "目前开发院停车场已满。", "合計 124台 です" → "合計124台です"). 목록 줄의 구분용 빈칸은 남긴다.
- 영어 문법: "There are 1 space" → "There is 1 space".
- 확인: 챗봇 테스트 1030개 통과(2개 건너뜀), 이번 테스트 16개(`test_translation_pieces_1111.py`). 실모델 10문장에서 개발원을 "만차/full/満車/已满"라고 한 답 0/10.

## 11. 전체 빈자리 합계와 요금표 (11/11 시연에서 나온 두 가지 · 브랜치 `fix/KAN-9-chatbot-total-and-fee-guide`)

### 합계
- 증상(시연): 전체 주차 가능 수가 틀리게 보였다는 제보. 로컬 시연 모드 서버 + gemma로 26번 돌려 틀린 합계가 화면에 나간 경우는 재현하지 못했다. 다만 아래 세 가지를 확인했다.
  1. 대화 AI가 주차장별 숫자를 직접 더한다("총 91자리입니다"). 지침은 더하지 말라고 하지만 합계 값을 주지 않았기 때문이다.
  2. 근거 검사는 "조회 결과에 있는 숫자인가"만 봤다. 맞게 더한 답도 버려져 규칙 답으로 바뀌었고(3~5초), 틀리게 더한 값이 조회 결과의 다른 숫자(전체 칸 수 64 등)와 우연히 같으면 통과할 수 있었다.
  3. 빈자리가 있는 주차장에 확인 중인 칸이 있으면 "21개 (카메라 확인 중인 칸 1개 포함)", "정확한 빈자리는 20개"처럼 틀린 말이 실제로 나갔다. #120에서 넣은 안내 문장("확인된 빈자리는 없고 …")이 빈자리가 있는 주차장에도 붙어 있었기 때문이다.
- 고친 것
  - 조회 결과(`parking_status`·`compare_lots`)에 코드가 계산한 `summary.total_empty`를 싣는다. 규칙 답의 "총 N자리"와 같은 기준(경보·이용 제한·확인 불가인 주차장은 뺀다).
  - 근거 검사 `wrong_total`: "총/합쳐서/합계 N자리"의 N은 `total_empty`와 같아야 한다. 한 주차장의 "총 64칸 중 21칸"은 대상이 아니다.
  - 근거 검사 `uncertain_included`: 확인 중인 칸을 빈자리에 "포함"이라고 하면 막는다. 조회 결과의 안내 문장도 빈자리가 있는 주차장용을 따로 썼다("빈자리 N칸에 들어 있지 않다").
- 확인(로컬 시연 모드 서버 + gemma, 합계 질문 4종 × 2번): AI가 합계를 말한 답 9번 모두 서버 합계와 일치, 나머지 1번은 규칙 답(역시 일치). 고치기 전에는 합계를 묻는 문장의 AI 답이 6번 중 6번 버려졌다.

### 요금표
- 증상(시연): 화면의 '주차요금' 버튼("주차요금 안내해줘")을 누르면 "차량 번호를 알려주세요"가 나왔다.
- 원인: "요금"이 든 문장을 내 차 요금(`get_fee`)으로 분류했다. 대화 AI는 조회 없이 "어느 주차장?"이라고 되물어 근거 검사에서 버려졌고, 규칙 답이 차량 번호를 물었다.
- 고친 것: "주차요금 안내해줘", "요금 안내", "요금표 보여줘"는 요금표 질문(`fee_rule` + `fee_table`)으로 분류하고, 서버 요금 정책을 주차장마다 한 줄씩 옮긴 요금표를 규칙이 바로 낸다(대화 AI를 거치지 않음, 0.1초). 차량 번호·"내 차"·기간이 섞이거나 주차장을 말하면 전과 같다. "요금 얼마야"는 그대로 내 차 요금.
- 요금표 세 줄 틀의 영·중·일 번역을 `HAND`에 넣었다(모델 없이 번역).
- 확인: 챗봇 테스트 1048개 통과(2개 건너뜀), 이번 테스트 17개(`test_total_and_fee_table_1111.py`).

## 13. 전수검사: 로컬에 프로젝트를 띄워 챗봇 답을 서버 값과 대조 (11/12 · 브랜치 `fix/KAN-9-chatbot-fullcheck-1112`)

시연 사이트에서 "빈자리 수가 서버와 안 맞아 보인다"는 제보(챗봇 "총 56자리" ↔ 관리자 화면 "71 / 156면 주차 중")의 원인을 확인한 뒤, 같은 종류의 문제가 더 없는지 전부 대조했다.

### 제보의 원인
- 숫자는 서로 맞았다: 156면 = 주차 중 71 + 빈자리 56 + 확인 필요 29. 관리자 상자가 주차 중만 보여 줘서 156 − 71 = 85로 읽힌 것이다. 차이 29는 카메라가 끊긴 개발원 12·부산역 16과 김해공항 1의 "확인 필요" 칸이다. 서버가 확인 필요 칸을 빈자리에도 주차 중에도 넣지 않는 것은 의도된 동작이다(리뷰 봇 확인).
- 실제로 어긋난 것은 챗봇 카드였다. 글은 "확인된 빈자리 없음"인데 카드는 "만차"로 표시했다(#137에서 수정).

### 검사 방법
- 로컬에 프로젝트 서버를 시연 모드로 띄우고 통합 경로(`POST /api/v1/chat`, 화면이 쓰는 경로)로 물었다.
- 실물 주차장 A·B는 영상 이벤트(`/internal/vision-events`)를 계속 보내 "관측 중"으로 만들고(스티커 차 7대), 끊으면 10초 뒤 "확인 필요"가 된다. 가상 주차장 C·D는 시뮬레이션을 멈춰 값을 고정했다.
- 답의 글과 카드에서 주차장별 빈자리 수·확인 중 칸 수·합계·상태 말(만차·확인된 빈자리 없음·경보 중)·차 위치(주차장·칸·번호판)·요금·결제 상태·요금표·예상 요금을 뽑아, 질문 전후의 서버 값(`/parking-lots`, `/spaces`, `/alerts`, `/rate-policies`, `/sessions/{id}/fee`)과 대조했다. 그 사이 서버 값이 바뀌면 다시 물었다.
- 상태 다섯 가지: 평소 / 번호를 못 읽은 차 1대 / 결제 후 / Lv2 경보 / 카메라 끊김. 질문은 주차장·구역·차량·요금·경보·이어 묻기를 조합했다.

## 14. 무료 회차 정책 안내 (11/12 · PM 결정 · 브랜치 `fix/KAN-9-chatbot-free-policy`)

리뷰 봇이 테스트 서버(AI 켬) 99문항을 돌려 실패한 2건.

- 증상: "무료 시간 있어?" → 기본요금만 답하고 5분 무료를 말하지 않음. "5분 안에 나가면 공짜야?" → "잘 이해하지 못했어요".
- 원인: 서버는 #140부터 요금 정책(`/rate-policies`)에 `free_minutes`를 주는데, 챗봇이 정해진 다섯 키만 남기고 버렸다. 무료 회차를 묻는 말을 알아보는 규칙도 없었다.
- 고친 것 (챗봇은 요금을 계산하지 않는다. 서버가 준 무료 분을 옮겨 적기만 한다)
  - `adapters.get_rate_policies`: `free_minutes`를 선택 값으로 보존(0 = 무료 회차 끔). 필수 키(`RATE_KEYS`)는 다섯 개 그대로라 목업 설정 검증·견적 비교는 바뀌지 않는다.
  - 무료 회차 질문("무료 시간 있어?", "5분 안에 나가면 공짜야?", "무료 회차 몇 분이야?", "몇 분까지 무료야?")은 규칙이 바로 답한다: "네, 입차 후 5분 이내에 출차하면 무료(0원)예요. 5분이 지나면 기본요금부터 계산돼요." 무료 분이 0이거나 없으면 "지금은 무료 회차 시간이 없어요. …", 주차장마다 다르면 주차장별로 적는다.
  - 요금표·주차장 요금 답 끝에 "입차 후 5분 이내에 출차하면 무료예요." 한 줄. (봇 제안은 요금표 줄마다 괄호로 붙이는 것이었는데, 네 줄에 같은 말이 반복돼 모든 주차장이 같을 때는 한 줄로 모았다.)
  - 대화 AI: 요금 정책 조회 결과에 `free_minutes`와 문구를 싣고, 지침에 뜻을 적었다. 주차 무료 시간을 충전 무료처럼 말하지 않게 했다.
  - "무료로 해줘", "요금 깎아줘"는 전과 같이 거절한다. "전기차 충전 무료야?"·"Are there free spaces?"는 무료 회차 질문으로 보지 않는다.
  - 새 문장의 영·중·일 번역을 미리 넣었다.
- 확인: 챗봇 테스트 1100개 통과(2개 건너뜀), 이번 테스트 14개(`test_free_policy_1112.py`). 로컬 시연 모드 서버 + gemma에서 한국어 3문장·영어·일본어·중국어 각 1문장이 모두 서버 값(5분)으로 답했고(0.0~2.1초, 대화 AI를 거치지 않음), "무료로 해줘"·"요금 깎아줘"는 거절, "전기차 충전 무료야?"는 "충전 요금은 안내 자료에 없어요"로 답했다.
