# 코드 검토 및 필요한 수정 — 2026-10-31

## 판단

현재 테스트 모델의 분리 구조(규칙/선택 LLM → 대화 엔진 → 데이터 연결층 → 템플릿)는 유지할 만합니다.
기능 추가나 프레임워크 교체는 하지 않았습니다. 기존 36개 질문은 수정 전에도 모두 통과했지만,
그 검사는 문장 분류만 확인하므로 대화 상태, 여러 사용자, 통신 장애까지 정상이라는 뜻은 아닙니다.
아래의 재현 가능한 오류와 관련된 처리만 보완했습니다.

## 주요 재현 사례와 수정

| 항목 | 원본에서 관찰한 동작 | 수정 후 |
|---|---|---|
| 이전 결제 요청 잔존 | `7번 결제 → 빈자리 → 네` 입력 시 이전의 7번 차량 결제가 실행됨 | 다른 기능을 요청하면 이전 확인 후보·보류 작업 취소 |
| 빈자리 중복 안내 | B 대기자 2명, 12번 차 1대 출차 후 두 사용자가 순차 조회하면 둘 다 1자리 안내를 받음 | 이미 안내한 빈자리를 다음 조회에서 다시 배정하지 않음 |
| 경보 위치와 보고서 불일치 | A-6 Lv1에서 B-3 Lv2로 변경해도 보고서는 A 위치를 유지 | 이전 기록을 위치 변경으로 종료하고 B-3 보고서·영향 차량 생성 |
| 출차 차량의 오래된 정보 복원 | 차량 조회 성공 → 출차로 None → 통신 실패 순서에서 이전 위치가 다시 반환됨 | None 결과 수신 시 해당 캐시 폐기 |
| 차량 번호 부분 오인식 | `이십오번 차 위치`를 15번으로 해석 | 범위 밖 번호로 처리 |
| 자연스러운 위치 질문 | `7번 차 어디 있어?`를 의도 미확인·번호 입력으로 처리 | 내 차 위치 조회로 분류 |
| 잘못된 요청 본문 | 배열 text, 잘못된 JSON 등에서 요청 처리 예외 | 개발 서버는 JSON 오류 응답, FastAPI는 입력 검증 응답 |
| 무료 시간 중 모의 결제 | 무료 결제도 paid_at을 저장하여 무료 시간 이후에도 결제 완료 상태 지속 | 0원 안내는 하되 유료 요금 면제로 영구 저장하지 않음 |

추가 보완:

- 같은 세션의 동시 요청을 순서대로 처리하고, 관리자 호출 ID와 보고서 변경에 잠금을 적용했습니다.
- 확정 보고서의 재확정은 기존 결과를 반환합니다. 응답에 포함된 체크리스트를 수정해도 원본 보고서가 바뀌지 않도록 복사합니다.
- 외부 조회 실패 시 캐시가 없으면 조회 불가를 안내합니다. 경보 조회 실패를 '경보 없음'으로 표시하지 않습니다.
- 오래된 빈자리 정보로 새 대기 알림을 보내지 않습니다. 이용 현황·출차 진단에도 오래된 정보임을 표시합니다.
- 결제 후 이전 요금 캐시를 폐기하고, 결제 성공 후 후속 요금 조회가 실패해도 성공 결과는 유지합니다. 결제 자체를 자동 재시도하지 않습니다.
- LLM 결과의 의도·params 형식·차량/주차장 값을 검사합니다. 문장에서 직접 추출한 번호를 우선하고, LLM이 확인 응답을 대신 만들 수 없도록 했습니다.
- API 모드에서 모의 경보·출차를 실행하면 가짜 성공 대신 사용 불가를 반환합니다.
- FastAPI 정적 파일 경로를 실행 위치가 아니라 파일 위치 기준으로 지정했습니다.

## 조회 최적화

같은 HTTP 요청 안에서는 경보 스냅숏을 재사용합니다. 대기자가 없으면 빈자리 대기 처리를 위한 점유 조회를 생략합니다.

원본과 수정본에서 각각 개발 서버를 실행하고, 경보·대기자가 없는 상태로
`GET /api/v1/chat/updates?session_id=check&since=0`을 1회 호출하여 어댑터 함수 호출 수를 측정했습니다.

| 호출 | 원본 | 수정본 |
|---|---:|---:|
| 경보 조회 | 2 | 1 |
| 빈자리 조회 | 1 | 0 |
| 합계 | 3 | 1 |

이는 해당 조건에서의 **조회 횟수 감소**입니다. 실제 팀 API의 응답속도나 전체 처리량 향상을 측정한 결과는 아닙니다.
클라이언트마다 2초 폴링하는 기존 방식은 유지했습니다. 현재 규모에서 캐시 서버나 WebSocket 도입까지 할 근거는 부족합니다.

## 화면 코드 보완과 검증 한계

- 응답 대기 중 전송 버튼을 누를 때 입력문을 지우지 않도록 변경했습니다.
- 한글 조합 중 Enter를 전송으로 처리하지 않도록 변경했습니다.
- 일반 대화 응답이 경보 알림 수신 커서를 먼저 올려서 경보 메시지가 누락되는 경로를 수정했습니다.
- 중첩 폴링을 방지하고, 자동완성의 이전 응답이 최신 입력 결과를 덮어쓰지 않도록 했습니다.
- 관리자 메모 저장 실패 시 입력을 유지하고 오류를 표시합니다. 확정 시 미저장 메모가 있으면 저장 성공 후 확정합니다.
- 초기화 후 관리자 목록에 이전 보고서가 남지 않도록 했습니다. 카드의 동적 문자열도 HTML 이스케이프했습니다.

두 HTML의 JavaScript 구문 검사는 통과했습니다. 브라우저 실행 파일 다운로드가 손상된 파일로 실패하여
**실제 브라우저 렌더링·클릭 동작은 이번 환경에서 검증하지 못했습니다.** 위 화면 변경은 코드 검토·구문 검사 수준입니다.

회귀 테스트는 외부 API나 유료 LLM을 호출하지 않습니다. FastAPI/httpx가 없으면 관련 6개 검사만 건너뜁니다.
실제 팀 백엔드·YOLO/OpenVINO·LLM API는 이 압축파일에 연결되어 있지 않으므로 연동 성능을 검증했다고 볼 수 없습니다.

## 이번에 유지한 범위와 후속 연동 사항

- A/B/C 3개 주차장·각 8칸, 화면 디자인, 기존 기능은 유지했습니다. 다른 프로젝트 논의 내용을 추정해 구조를 바꾸지 않았습니다.
- API 경로·응답 필드의 TODO는 팀 계약 확정 후 연결할 항목으로 남겼습니다. 백엔드 응답 형태가 현재 가정과 다른 경우까지 보장하지 않습니다.
- 세션·보고서·대기열은 메모리 저장이고, 개발 서버와 시연 API에는 인증이 없습니다. 단일 프로세스 테스트 모델이라는 현재 전제를 유지했습니다.
- 대기 알림은 예약이 아닙니다. 폴링 사이의 입출차가 상쇄되면 빈자리 수만으로는 교체를 알 수 없습니다. 입출차 이벤트 연동이 필요합니다.
- 경보는 활성 위치 하나만 표현합니다. 여러 위치의 동시 경보 지원은 별도 계약과 상태 모델이 필요하여 이번에 추가하지 않았습니다.
- 근접 차량은 기존처럼 칸 번호 차이 1 이하로 계산합니다. 실제 배치의 기하학적 거리를 계산하는 기능은 아닙니다.
