작성일: 2026-11-04. 범위: `backend/app/chatbot/`만. 실제 LLM API 호출 0회이며, 이번 검사로 LLM 정답률 향상을 주장하지 않는다.

- 공개 팀 레포 확인 시 main은 `5ff9242bdc6a78b8aa5452655ca4d538a3609f9f`, v2.14.2 작업 브랜치 `feature/KAN-9-chatbot-stability-review`는 `e507073c91ab456a06e609768a9762b8734bad3f`였다. 아직 병합되지 않아 지시서에 따라 후자를 기준으로 삼았다.

## 3. B — 도구 설명 22개 전후

도구별로 기능·다른 표현·실행하지 않는 일/구분 기준을 한국어 두 문장 이내로 정리했다. 기존 검사에서 요구하는 `예:` 표기는 유지했다. 도구 선택 강제, 도구 이름·인자 스키마 변경은 없다.

직접 호출 경로 `llm.py`는 이 설명 사전을 공유하지 않고 기존 일반 system prompt를 사용하므로 수정하지 않았다. C도 지시서대로 LangChain 경로에만 적용했다.

## 4. C — 예시 메시지 3쌍

`LLM_FEWSHOT` 기본값은 `0`이다. `.env.example`에는 주석으로만 안내했다. 켜면 아래 세 예시가 각각 HumanMessage → AIMessage(tool_calls 1개) → ToolMessage 형식으로 현재 사용자 문장 앞에 들어간다. 인자는 모두 `{}`이며 실제 업무 함수를 연결하지 않는다.


| 사용자 문장 전문 | AI 도구 호출 | ToolMessage 전문 |
| --- | --- | --- |
| 청구된 내역의 액수만 열람할게요 | get_fee({}) | 업무를 실행하지 않은 분류 예시입니다. |
| 상주 인력의 상담 가능 시간을 알고 싶습니다 | admin_help({}) | 업무를 실행하지 않은 분류 예시입니다. |
| 수채화 물감은 어느 종이가 잘 받나요 | unknown({}) | 업무를 실행하지 않은 분류 예시입니다. |



- 메시지 순서: system → 위 예시 9개 메시지 → 현재 human. 끄면 기존처럼 system/human 2개만 보낸다.
- 예시 켬/끔을 캐시 키에서 구분하며, 호출 도중 모드가 바뀌면 이전 모드의 결과를 사용하지 않는다. 기존 동시 2개·최대 3초 및 업무 실행 경계는 유지한다.
- 추가 입력량의 대략값: 예시 9개를 OpenAI 메시지 형태의 JSON으로 직렬화하면 UTF-8 1,062바이트/872문자, `o200k_base`로 약 **248토큰**이다. 이는 비교용 토크나이저 추정치이며 Gemma/Haiku의 실제 청구 토큰 수는 측정하지 않았다. 모델별 역할/도구 포맷 오버헤드에 따라 달라진다.
- 가짜 모델 검사로 메시지 순서, 켬/끔 분리, 예시 자체의 관리자 접수 0건, 결제 확인 유지, Lv2 분류 호출 0건을 확인했다.

## 5. D — 1회차 미인식 칩

`FALLBACK_HINTS` 기본값은 `0`이다. `unknown` 1회차에만 고정 단어로 관련 기존 칩을 최대 3개 골라 앞에 배치하고 기본 칩으로 나머지를 채운다. 총 개수는 기존 이하이며, 기존 칩 필터도 거친다. `UNKNOWN_FIRST` 텍스트와 업무 흐름은 그대로다.


| 단어 | 대상 의도 | 실제 기존 칩 ID / 처리 |
| --- | --- | --- |
| 요금·주차비·사용료·계산·정산 | get_fee / pay_fee / fee_rule | fee / pay / fee_rule |
| 어디·잊·찾 | find_my_car / change_vehicle | find_car / change_vehicle |
| 막대·차단기·출구·못 나가 | exit_help | 해당 칩 없음 → 기본 칩 유지 |
| 카드·승인·거절·결제 오류 | payment_issue | 해당 칩 없음 → 기본 칩 유지 |
| 직원·관리자·사람·근무 | admin_help | 해당 문의 칩 없음 → 기본 칩 유지 |
| 그만·취소 | cancel_destination / cancel_action | destination_cancel / cancel_action; 목적지 없는 경우 목적지 취소는 기존 필터로 숨김 |



새 칩을 금지한 조건에 따라 `exit_help`·`payment_issue`·`admin_help`용 칩을 만들지 않았다. 따라서 이 세 종류의 표현만 있는 경우 기본 칩을 유지한다. 여러 종류 단어가 함께 있으면 사용할 수 있는 다른 종류 칩이 선택될 수 있다. `call_admin`은 맞춤 후보에서 제외했다. 2회차 미인식과 Lv2 경보 우선 처리는 기존 그대로다. 업무를 실행하는 추가 LLM 호출도 없다.

### 측정 실행 방법

`tools/compare_models.py`는 사람이 실행할 때만 API를 호출한다. import만으로 호출하지 않는다. 레포 밖 별도 `CHATBOT` 폴더로 **parking-chatbot 전체**를 복사한 뒤 그 폴더에서 실행한다(스크립트 하나만 복사하면 상대 프로젝트 import가 없다). 기준 v2.14.2 측정은 별도 원본 복사본에 이 평가 스크립트와 고정 평가 세트만 놓고 같은 모델 조건으로 한다. 실행에 필요한 제공자·모델·키는 그 복사본의 `.env` 또는 환경변수에만 둔다. 출력 CSV는 레포 밖에 생성한다.

PowerShell 예시(후보 ID는 실제 값으로 바꾼다):

```powershell
$env:PYTHONIOENCODING = "utf-8"
python tools/compare_models.py --models "MODEL_1" "MODEL_2" "MODEL_3" "MODEL_4" "MODEL_5" --repeats 3 --files tests/llm_eval_questions.csv tests/llm_eval_holdout.csv --fewshot 0 1 --output comparison-v215.csv
```

`LLM_ENGINE=langchain`, 제공자 및 키가 있어야 실행된다. 출력은 모델/예시/파일별 평균 정답률·다른 도구·미인식·timeout·평균/최대 지연의 표와 CSV다. `unknown_correct`, `invalid_intent`, `invalid_params`도 CSV에 기록한다. 카운트는 3회 합계, 정확도/평균 지연은 3회 평균, 최대 지연은 3회 중 최댓값이다. 키는 CSV/표에 넣지 않는다. 3회 반복 시 무관 문장은 18건이므로 `unknown_correct` 총합뿐 아니라 각 회차가 5/6 이상인지도 확인한다(필요하면 `--repeats 1`로 회차별 파일 저장).

채택은 holdout 기준으로 모두 충족할 때만 한다.

1. `wrong_tool + invalid_intent + invalid_params == 0`.
2. 기준 모델/설정보다 정답률 상승.
3. 최대 응답 3,000ms 이내, 평균 응답은 기준의 1.3배 이하.
4. 무관 문장 6개 중 unknown 처리 5개 이상. 엉뚱한 도구 선택은 1번 기준으로도 탈락한다.
5. 정답률 차이가 ±5%p 이내이면 사람이 공급자 가격과 실제 지연을 확인해 더 저렴하고 빠른 설정을 고른다. 비용은 이 스크립트가 계량하지 않는다.

실측 전에는 `.env`에서 `LLM_FEWSHOT=0`, `FALLBACK_HINTS=0`을 유지한다. 채택 후 필요한 항목만 1로 설정하고 프로세스를 재시작한다. 되돌릴 때는 해당 값을 0으로 하고 재시작한다. B는 별도 스위치가 없으므로 실측에서 나빠지면 설명 변경 커밋만 되돌리는 방식으로 검토한다.
