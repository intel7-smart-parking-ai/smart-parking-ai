## 추가 대화 시나리오

1. 차량번호 없는 요금 질문 → 7번 입력 → 맞아요 → 07번 요금 표시.
2. 7번 요금 → 아니 8번이에요 → 네 → 08번 요금 표시.
3. 07번 차량 선택 → 결제했는데 못 나가요 → 출차 진단. 실제 paid 상태를 임의로 변경하지 않음.
4. 관리자 부르지 말아줘 → 신규 문의 생성 없음.
5. 관리자가 확인했나요? → 기존 문의 조회. 신규 문의 생성 없음.
6. 결제 준비 → 결제하지 마세요 → 네 → 결제되지 않음.
7. 결제 준비 → 그럼 B는? → 네 → 이전 결제 실행 안 됨.
8. B 대기 등록 → C 빈자리 조회 → 내 대기 순번 → 기존 B 등록 유지.
9. 입차 기록 없는 24번 차량 → 직원 연결 → 즉시 문의 등록.
10. 07번 차량 선택 → 8번 차 와이퍼 고장 → 선택 차량은 07번 유지.
11. Lv2 모의 경보 → 차량번호 없이 관리자 요청 → 확인 단계 없이 접수.

## 수정 파일

- `chatbot/parser.py`: 의미 범주를 보완. 요금 규칙/현재 요금, 출차 장애/결제 상태, 신규 호출/상태 질문, 부정 표현을 구분.
- `tests/questions_realistic.csv`: 69개 질문과 기대 의도·주차장·차량.
- `tests/test_realistic.py`: 문장 및 대화 행동 검사.
- `tests/run_eval.py`: 여러 CSV 경로를 지정할 수 있도록 확장. 경로 미지정 시 기존 36개 실행 방식 유지.
- `tests/realistic_before.txt`: 보정 전 실패한 12문장 기록.

임의의 오타 전체를 자동 교정하는 기능을 추가한 것은 아니다. 실제 표현·붙여쓰기·축약형 중 이번에 작성하고 확인한 범위를 보완했다. 심한 오타, `그거`, `아까 거` 같은 대상이 불분명한 지시어, 여러 작업이 섞인 요청, 미구현 기능의 세부 문의는 추가 사용자 테스트가 필요하다.

## 재실행

```bash
# 규칙 파서 기본 설정(LLM_PROVIDER=none)에서 문장 평가
python tests/run_eval.py tests/questions.csv tests/questions_realistic.csv

# 전체 회귀 검사: FastAPI/httpx 설치 시 관련 검사 포함
python -m unittest discover -s tests -v

# Node.js + Playwright/Chromium이 있는 환경에서 화면 검사
python tests/run_browser_checks.py
```

이번 실행은 LLM 없이 모의 데이터와 로컬 서버로 검사했다. 시연 PC에서도 같은 명령을 실행하고, 팀원 3~5명이 문장 목록을 보지 않은 상태에서 직접 질문하게 한 뒤 실패 문장을 추가하는 것을 다음 검증으로 권장한다. 추가로 수집한 문장은 보정용과 최종 확인용을 구분해야 과대평가를 줄일 수 있다.
