> 모델 gemma-4-26b · §1~6은 mock 데이터, **§8은 최신 main의 실제 서버**에 붙여 잰 값 · 실모델 측정은 한 번씩 돌린 값이라 ±1턴은 우연일 수 있다.

## 추천 구성

```
LLM_ROUTE_CHECK=1            # 규칙이 직접 맡으려는 문장을 AI가 확인
LLM_ROUTE_CHECK_FAST=1       # 그 처리의 말로만 된 문장은 확인 생략 (기본값)
LLM_ROUTE_CHECK_PARALLEL=1   # 확인과 대화 AI를 함께 시작
LLM_ROUTE_CHECK_MODEL=google/gemma-4-26b-a4b-it   # 대화 모델이 Haiku여도 확인은 gemma
```

기본값은 전부 꺼짐이라 켜지 않으면 확인 호출은 없다. 단, 이 브랜치의 아래 '찾아서 고친 것' 3가지는 스위치와 무관하게 적용된다.

## 2. 찾아서 고친 것 — 확인 단계보다 큰 병목이 뒤에 있었다

추천 구성에서도 틀린 4턴을 따라가 보니 가로채기가 아니라 **대화 AI 답을 버리는 단계**가 원인이었다.

| 증상 | 원인 | 고친 것 |
|---|---|---|
| '내 차 어디에 세워야 해?' → AI가 "어디로 가시는지 알려주시면…"이라고 잘 되물었는데 버려지고, 같은 답을 한 번 더 쓰게 한 뒤(모델 2번) "차량 번호를 알려주세요" | 근거 검사가 '조회 없이 답함(no_evidence)'으로 판정. 되묻기는 사실을 말하지 않는데도 운영 질문이면 무조건 막았다 | `agents/evidence.py no_tool_reply_ok`: 사용자에게 묻기만 하는 답은 통과. 숫자·칸·상태·비교·실행 주장은 그대로 막고, 차량 번호를 묻는 답은 제외(번호 입력 흐름은 규칙이 연다). "예측할 수 없어요"도 거절 표현으로 인정 |
| '신세계로 가자', '공항으로 갈게' → "잘 이해하지 못했어요" | 별칭(신세계·공항)은 주차 맥락 낱말이 있어야 읽히는데 '가자'는 맥락 낱말이 아니었다. AI는 목적지를 정할 수 없어 "안내해 드릴게요"라고 썼다가 막힘 | `parser.py`: 가는 말로만 된 문장이면 별칭을 읽어 목적지 설정('부산역으로 가는 버스 있어?'는 그대로 대화 AI) |
| '차 어디에 대는 게 좋아?' → AI 답이 버려진 뒤 "차량 번호를 알려주세요" | 대체 규칙 답이 '내 차 찾기'로 읽음 | `engine._plausible_reading`: 세울 곳을 묻는 말이면 빈자리 안내 |

이 3가지는 가로채기 확인과 무관하게 지금 main에도 있는 문제다(확인 끔에서도 7 → 3으로 줄었다).

## 6. 지금 구조가 최적인가

**이 프로젝트 조건(11/12 동결, 모델 호출 1~3초, 결제·신고는 즉답이어야 함)에서는 이 구조가 맞다.** 근거와 한계는 이렇다.

| 대안 | 맞는 답 | 속도 | 판단 |
|---|---|---|---|
| 규칙만(지금 main) | 가로채기 오류가 남음(새 문장 31턴 중 3) | 가장 빠름 | 틀린 답을 0초에 낸다 |
| 규칙 + 차례로 확인 | 잡음 | 맞는 명령까지 0.7~1.5초 늦어짐 | 추천 구성보다 나은 점이 없다 |
| **규칙 + 빠른 길 + 동시 확인(추천)** | 새 문장 31턴 틀린 답 0 | 맞는 명령 0초, 구해 낸 턴은 대화 AI 시간만 | 채택 |
| AI가 매 턴 먼저 읽기(CALM식) | 비슷할 것(재지 않음) | 지금 0초인 턴까지 전부 1초 이상 | 모델이 죽으면 규칙 길을 어차피 또 유지해야 함. 얻는 것 없이 느려진다 |

한계 — '최적'이라고 단정할 수 없는 부분:

1. 표본이 작다. 새 문장 31턴 + 가로채기 문장 12턴 + 기존 86턴, 모델 1종, 각 1~3회 실행.
2. 실제 서버는 §8에서 확인했다(가상 C·D 시뮬레이션). 카메라가 붙은 실물 A·B 데이터와 실모델 동시 사용은 재지 않았다. 동시성은 가짜 모델로만 봤다.
3. 남은 낭비: 대화 AI 답이 버려지고 규칙 답이 나가는 턴이 31턴 중 4개 있다('우리 차 어디 있는지 알려줘', '거기로 안내해줘' 등). 답은 맞지만 모델을 2번 부르고 1.8~4.1초가 걸린다. 다음 손볼 곳은 확인 단계가 아니라 여기다(차량 번호를 묻는 초안이면 고쳐 쓰기 없이 바로 규칙 답, '거기로 안내해줘'는 규칙이 앞 대화로 처리).
4. 빠른 길의 낱말 목록은 사람이 쓴 것이다. 모자라면 확인이 한 번 늘 뿐이지만, 목록에 있는 말로만 된 엉뚱한 문장은 걸러 내지 못한다(새 문장 55개에서는 0건).

### 판단

- 스위치를 끈 기본 상태에서도 최신 main보다 틀린 답이 적고(8 → 3), 조회 실패 답이 없어졌다. 기존 질문지에서 나빠진 것은 없다.
- 추천 구성은 그 위에 가로채기 오류를 잡는다(8 → 0, 1/12 → 11/12). 켤지는 PM 결정 사항이고, 꺼 두면 확인 호출은 없다.
- 그래서 브랜치를 올린다. 시연 PC(오버레이·카메라 연결)에서의 확인과 실모델 동시 사용 확인은 남아 있다.
