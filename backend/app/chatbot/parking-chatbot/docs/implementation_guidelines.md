## 범위와 변경 순서

1. 삭제: 빈자리 대기, 문의 상태 변경, 독립 이용 현황. engine/parser/chips/catalog/navigation/templates와 두 서버·화면의 참조를 함께 제거한다. 대기 질문은 현재 빈자리 조회, 이용 현황 질문은 내 차 위치, 문의 상태 질문은 접수 여부의 고정 답변으로 연결한다.
2. 사람 우선: templates/engine/chips에서 Lv2 안내·배너·알림의 재진입 금지·차량 이동 금지를 일관되게 적용한다. 설명은 두 줄과 카드로 나누며, 모의 화재 표기를 유지한다.
3. 현장 정보: lots/catalog에서 위치·전기차·구역·출구·설비를 검증하고 incidents가 브리핑을 만든다. 관리자 화면은 이를 표시·복사한다. 시설 미확인과 차량 목록 실패를 0/없음으로 추정하지 않는다.
4. 확인 중 칸: contracts/adapters/navigation/화면에서 uncertain을 선택 필드로 지원한다. 확정 empty만 추천·목적지에 사용한다. 시연 변경은 기존 관리자 권한 경계를 적용한다.
5. 미인식 후보: adapters/contracts에서 번호 null과 입차 시각을 지원한다. 후보 선택은 위치 조회만 허용하며 세션 번호로 연결하지 않는다. 요금·결제는 차단하고 관리자 문의에 후보 위치를 포함한다.
공통 검수 보완: 입력 크기·로그 보관 제한, 실제 주차장 ID 보존, 번호가 있는 차량 변경의 확인 단계, 유한한 설정값 검증을 각 기존 책임 파일에서 적용한다. 첨부 기준본에 없는 LangChain 초기화 잠금 문제는 후속 라우터 작업의 필수 검사로 남긴다.

## 보존할 동작

동일 세션 직렬화, 요청 ID 재생, 일회성 차량·결제 확인, 실행 직전 요금 재확인, 세대가 바뀐 캐시 폐기, 알림 재수신·커서, 경보 스냅샷, 관리자 호출 중복 통합, 보고서 revision 검사를 보존한다. 공용 알림 큐와 카드 내부 이용 단계는 계속 사용한다.

## 문구와 사실성

관리자 자동 연락·실제 화재 대응·실제 차단기 개방을 구현된 기능처럼 약속하지 않는다. 차량 피해 확인은 현장 관리자에게 요청하도록 안내하고, 차량 정보가 등록됐다는 문구는 실제 문의 접수 후에만 쓴다. 소방 장비는 가능성과 참고 정보로 제시하며 판단 주체는 소방이다. 실측 전 설정은 PROVISIONAL이다.

## 검사·완료 기준

현재 검증 절차는 관련 검사 → 변경을 모은 뒤 필요한 전체 검사 순서다. 질문 세트는 현재 파일 목록을 확인하며 2026-11-05 기준 9세트 248문항이다. 확정 명세에 따른 fixture·표시 이름·기대 개수 갱신은 근거와 변경 전후를 기록한다. 검사 의미와 안전 조건은 유지한다. 실패·누락·경계·동시 요청 및 영향 있는 서버 계약·Chromium 화면을 검사하고, 실제 실행한 것과 API·LLM·Windows 미검증 범위를 구분한다.

현재 수정 범위는 backend/app/chatbot/ 안이며 작은 단위의 로컬 커밋을 만든다. 원격 저장소 병합은 PM 검토 후 진행한다. 위 11/02 계획의 LangChain 제외는 당시 범위다. 현재 구현된 선택 LangChain 경로의 설치·미설치 검증은 최신 원칙에 따라 유지한다.
