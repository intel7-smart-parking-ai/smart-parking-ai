# D-24 추가 아이디어 검토

2026-11-04. PM이 진행률을 보고 배정하기 위한 문서다. 아래 시간은 챗봇 담당자의 구현·검증 작업량 추정이며, 타 담당자의 데이터 준비·연결 시간은 별도다. 현재 답 예시는 LLM을 끈 Mock 모드에서 직접 실행해 기록했다. 아래 아이디어의 코드 구현은 이번 작업에 포함하지 않았다.

## 1. 만차 시 다른 주차장 추천

| 항목 | 내용 |
|---|---|
| 사용자 질문 예시 | “부산역주차장 만차면 어디로 가?” / “충전 자리가 있는 다른 곳은?” / “가상 주차장 말고 실제 주차장은?” / “가까운 곳부터 알려줘” |
| 지금 이미 있는 것 | `navigation.reason`이 만차·경보·운영 제한을 구분하고 `alternatives`가 빈자리 수와 명부 순서로 최대 두 곳을 제안한다. 실제 출력은 “부산역주차장은 만차예요. 신세계백화점주차장 62자리 / 북항주차장 10자리”. 전용 구역 질문의 출력은 “부산역주차장 충전 구역은 만차예요. 신세계백화점주차장 충전 구역 8자리 / 북항주차장 충전 구역 2자리”. `choose`와 `monitor`는 목적지를 정하고 만차·제한으로 바뀌면 다시 제안한다. |
| 추가로 필요한 것 | 챗봇 쪽은 실제·가상 구분의 명시와 선택 조건, 거리 기준 정렬을 검토한다. 서버 API 쪽은 출발 기준점과 검증된 이동 거리·시간이 필요하다. 화면 쪽은 실물·가상 배지와 대안 선택 버튼을 합의한다. C·D가 가상이므로 실물 이용자가 실제로 이동할 곳처럼 표현하지 않도록 기준을 정해야 한다. |
| 필요한 데이터·API | 기존 `lot_id`, `kind/type`, 구역별 빈자리·운영 상태를 재사용한다. 추가 제안은 `from_lot_id`, `to_lot_id`, `distance_m`, `travel_seconds`, `updated_at`이다. PM 김한별님과 서버 박해준님이 출발 기준·데이터 출처를 결정하고, 화면 김채린님이 구분 표기를 정한다. 현재 서버 계약에는 거리·이동 시간이 없다. |
| 답변 예시 | “{현재 주차장}은 만차예요. {대안 주차장}에 {빈자리}자리 있어요.” / “실물 주차장 중 이용 가능한 충전 구역은 {주차장} {충전 빈자리}자리예요.” / “이동 거리가 연결되지 않아 가까운 순서는 확인할 수 없어요.” |
| 작업량 | 기존 추천 문구·실물/가상 구분 보완은 약 2~4시간. 거리 기준 추천은 데이터 계약 후 약 0.5~1일 추정. 서버와 도면 정보 준비에 의존한다. |
| 위험·주의 | 거리·분 수·예약 가능성을 생성하지 않는다. 경보와 운영 제한을 먼저 확인한다. 만차와 전용 구역 만차를 구분하고, 미확인 칸을 빈자리로 세지 않는다. 추천은 예약이 아니다. |

## 2. 엘리베이터·출입구 가까운 빈자리

| 항목 | 내용 |
|---|---|
| 사용자 질문 예시 | “엘리베이터 가까운 자리는?” / “출입구에서 덜 걷는 자리는?” / “장애인 전용 칸 중 입구에 가까운 곳은?” / “B-06에서 어느 출입구가 가까워?” |
| 지금 이미 있는 것 | `lots.json`에 주차장별 `exit`, `exits` 이름이 있고 `navigation.choose`·`monitor`가 주차장 단위 목적지를 관리한다. 실제 출력은 “개발원주차장을 목적지로 정했어요. 개발원주차장에 5자리 있어요.” 운영 제한을 넣은 후에는 “개발원주차장을 지금 이용할 수 없게 됐어요. (시연 운영 제한) 신세계백화점주차장 62자리 / 북항주차장 10자리”가 알림으로 나왔다. 출구 이름만으로 특정 칸과의 거리나 보행 동선을 판단할 수 없다. |
| 추가로 필요한 것 | 챗봇 쪽은 목적 시설과 차량 조건을 추출하고, 서버가 준 순위에서 이용 가능한 칸을 제시하는 흐름이 필요하다. 서버 API 쪽은 칸별 빈자리·전용 조건과 시설별 순위 표를 연결한다. 화면 쪽은 목적 시설·칸 강조와 도면 안내가 필요하다. 기존 주차장 단위 목적지 감시를 칸 단위로 확장할지는 별도 결정한다. |
| 필요한 데이터·API | 칸별 거리 표가 필요하다. 최소 제안은 `{lot_id, space_id, to: "elevator_1", distance_rank}`와 시설 이름 `{lot_id, to, label}`이다. `distance_rank`는 실측 미터값과 구분한다. 미터·소요 시간·접근 가능한 보행 경로가 필요하면 별도 검증 필드를 정한다. 도면·시설 위치는 PM 김한별님과 카메라·ROI 우지원님이 확인하고, 박해준님이 조회 계약, 김채린님이 도면 표기를 정한다. 실제 데이터 제공 담당은 PM 확인이 필요하다. |
| 답변 예시 | “{주차장} {시설 이름} 기준으로 가까운 빈자리는 {칸 번호}예요.” / “조건에 맞는 빈자리가 없어 {대안 시설 또는 주차장}을 확인해 주세요.” / “이 주차장의 엘리베이터 위치·거리 정보가 아직 연결되지 않았어요.” |
| 작업량 | 시설별 정적 순위와 기존 빈자리 조회를 잇는 작업은 계약·데이터 확보 후 약 1~2일 추정. 도면 경로 안내와 칸 단위 목적지 감시는 별도 산정한다. |
| 위험·주의 | 칸 번호 차이와 실제 보행 거리는 다르다. 출차 출구·보행 출입구·대피 출구를 혼용하지 않는다. 전기차·장애인 전용 조건과 운영 제한을 확인한다. 대피 중에는 가까운 주차칸·차량 이동을 안내하지 않는다. 시설 정보가 없으면 추측하지 않는다. |
