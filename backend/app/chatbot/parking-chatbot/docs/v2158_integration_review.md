# v2.15.8 연결 경계 안정화·담당별 통합 검토

기준일: 2026-11-06 KST. 기준 main `9265c12fd1392487c3065e5735f73d13065cdab5`.
이 문서는 로컬 수정 준비본의 검토다. 원격 push·PR·main 병합·현장 적용은 수행하지 않았다.

## 1. 역할과 구현 범위

우리 역할은 기존 주차 서버를 근거로 질문을 해석하고, 같은 차량·주차 세션·확인 상태 안에서 안전하게 조회·안내하는 것이다. 카메라 관측·입출차 확정·요금 계산·영수증 생성·화면 구현을 별도로 복제하지 않는다.

최신 main은 PR #63의 공용 결제 클라이언트 견적 전달 수정이 추가된 상태다. 이전 `73ef711` 대비 `clients/` 두 파일 변경이며 챗봇 변경은 없다. 이 변경을 유지한 새 작업 사본에 v2.15.7 준비본과 이번 수정을 합쳤다. main 직접 수정과 다른 담당 폴더 변경은 없다.

구조적 안정화의 목표는 모델을 크게 바꾸는 것이 아니라 **의도 해석→공식 API→검증→카드→확인 상태**의 경계를 일관되게 만드는 것이다. 이번에는 짧은 발화와 영수증 재조회 복원을 수정했고, v2.15.7의 KAN-67·DATA-01도 유지했다.

## 2. 수정 내용

### 짧은 차량 위치 요청

기존 파서는 `23번 위치`, `11번 말고 23번 위치`에서 번호는 추출하지만 의도를 unknown으로 남겼다. 기존 규칙과 취소·부정 처리를 먼저 거친 다음, 유효한 한 차량의 `번 위치` 끝맺음에 한해 위치 조회로 해석한다.

`이십 삼 번 위치`, `23번 위치 알려줘`, 정정 후의 차량번호도 지원한다. 차량 확인 단계는 그대로 유지한다. 여러 차량·잘못된 번호·칸 번호·‘위치 알려주지 마’는 새 규칙으로 자동 조회하지 않는다.

검토 중 발견한 `23번은 빼고 출구 위치`, ‘화장실 위치’ 과도 매칭도 규칙 범위를 좁혀 막고 회귀 사례에 넣었다. 요금·취소 등 기존 의도의 우선순위와 질문 정답 기대값은 바꾸지 않았다.

### 서버 완료 영수증 재조회 복원

D-49의 서버 fee 응답에 이미 완료 영수증이 있는데 어댑터가 버려, 챗봇은 ‘이미 결제했어요’만 답했다. 이제 선택적인 영수증을 검증해 기존 payment 카드로 복원한다. 새 결제 POST나 요금 재계산은 하지 않는다.

검증 기준:

- 현재 세션과 정확히 같은 session_id, 제공된 car_id·lot_id도 일치.
- 상태 completed, 비어 있지 않은 payment_id.
- 금액은 boolean이 아닌 0 이상 정수이며 최상위 amount_krw와 일치.
- 승인/생성 시각은 시간대가 있고 허용 오차를 넘는 미래가 아님.
- 영수증 없음/null인 기존 API는 그대로 지원.
- 불일치는 과거 캐시 영수증으로 바꿔 정상 표시하지 않음.
- stale 데이터는 새로 확인된 payment 카드로 승격하지 않음.

안전 우선순위도 검수했다. `payment_blocked=true`이면 선택 영수증의 오류가 대피 안내를 가리지 않도록 영수증을 제외하고 차단·fee 안내를 유지한다. 검토 중 이 교차 조건을 발견해 수정·회귀 검사에 추가했다.

영수증 카드 생성은 공통 `_fee_card()`로 모아 요금 재조회·이미 결제된 결제 요청·확인 중 서버가 완료를 알려 주는 경로에서 같은 기준을 사용한다. 영수증이 없는 과거 결제 요청의 카드 동작은 보존한다.

### 기존 준비본 유지

- KAN-67: 늦은 fee 차단/POST409에서 safety·banner 전달, 같은 요청 재생, 요청 간 근거 격리.
- DATA-01: 빈자리 응답의 계약·시각·캐시 세대 검증 후 칸 목록과 집계 공개.
- 공식 API 경로·칩 ID·서버 결제 body·확인 토큰·모델 설정은 유지.

## 4. 팀원과 맞출 변경 요청 — 아직 전송하지 않음

### 김채린님: 공통 화면·상태

1. 기존 ChatPanel을 텍스트·음성의 공통 입력 지점으로 사용하고 session_id를 하나로 유지한다.
2. flow만이 아니라 chips/card/banner/safety에도 최신 응답 적용 규칙을 적용한다.
3. 전송 이후 작성·삭제한 초안을 보존한다. 200자 초과는 원문 유지 후 수정 안내한다.
4. 결과 불명확한 동일 요청은 본문·토큰·request_id를 보관해 재전송하고, 새 업무에만 새 ID를 만든다.
5. runtime_id/state_version과 경보 갱신을 연결하고 과거 확인 버튼이 남지 않게 한다.
6. 이번 영수증은 기존 payment 카드의 amount/payment_id/paid_at 필드를 사용한다. KAN-67의 safety·차단 배너도 실제 화면에서 확인한다.

완료 증거: 하나의 실제 화면에서 조회→차량 확인→요금→모의 결제→영수증 재조회→경보→재시도를 실행한 기록.

### 윤명수님: 전사 전용 모듈

4차 개선본의 자체 차량·요금·결제 엔진을 통합 경로에서 제외하고 기존 챗봇으로 보낸다. 짧은 발화 처리는 이번 파서와 공유하고 별도 숫자 사전을 계속 확장하지 않는다.

오래된 resume 성공 격리, 빈 문자열 편집 보존, 전체 응답 적용 순서, 자동 절단 제거, 작업 제출 실패의 busy 복구, lifespan까지 동일한 로더 사용이 남아 있다. 상세 재현과 요청은 별도 4차 음성 제안서를 따른다.

음성 요청 ID는 전사 추적용이며 챗봇 업무 요청 ID·결제 확인 토큰과 용도를 섞지 않는다. 음성 ‘네’를 확인 없이 결제 실행으로 보내지 않는다.

### 통합 담당·PM: 실행 모드·배포

demo_main8002와 runtime demo/real의 제공 기능을 구분한다. 실제 UI 커밋·서버 모듈·프록시·데이터 모드를 고정해 기록한다. voice 공개 경로·upstream·본문 제한·HTTPS/QR은 승인된 범위에서 담당자가 변경한다. 관리 경로 전체를 공개하지 않는다.

카메라·ROI 미완료 시 실물/모의 전환은 우지원님·PM이 결정하고, 우리 챗봇은 서버 근거와 모의 표시를 따른다. 시연 PC와 현장 장비를 이번 작업에서 조작하지 않았다.

위 재현은 `validation_v2158/runtime_link_probe.json`과 `probe_runtime_link.py`로 확인할 수 있다. 실제 runtime 앱·SQLite·HTTP를 사용하지만 관측·차단 조건은 합성 주입이다.

코드 추적 경로는 `chatbot/parser.py:parse_rules` → `chatbot/engine.py:h_get_fee/h_pay_fee/_execute_payment_locked` → `chatbot/adapters.py:ApiAdapter.get_fee` → 서버 `/api/v1/sessions/{session_id}/fee` → `_fee_receipt/_fee_card/_respond`다. 빈자리는 `_space_snapshot` → `CachedAdapter` 계약·시각·세대 검증 → `Catalog.adopt` 순서로 공개한다.

우선 인계는 **현재 A/B 실물 조회·모의 결제·경보의 한 화면 통합**이다. 음성은 같은 챗봇 입력 경로에 전사문을 넣는다. STT나 가상 D 확장 때문에 텍스트 P0의 차량·결제 확인 규칙을 복제하지 않는다. 이는 저장소 CLAUDE.md의 서버 상태·요금 단일 권위 및 P0/P2 구분을 따른다.

전체 회귀는 앞선 수정 단계에서 574건 통과(skip 포함)한 기록도 있지만, 최종 코드의 통과로 대체하지 않는다. 병렬 회차 실패와 최종 단독 회차 실패를 모두 보존했다. 로그에서 HTTP 전송 시간 초과는 확인됐으며, 자원 경합이 원인이라는 설명은 아직 추정이다. 실패 조건을 비운영 PC의 동일 커밋·의존성에서 다시 확인해야 한다. 현재 응답만으로 모든 실패를 제품 버그 또는 환경 문제로 단정하지 않는다.

DNS-01은 합성 200ms 이름 해석에서 20ms 요청 예산의 허용 오차 150ms를 초과해 약207ms를 소비했다. 현재 transport는 연결 후 본문 시간 예산을 적용하지만 동기 DNS 자체를 중단하지 못한다. 이후 수정 시에는 단순 timeout 증가 대신 제한된 DNS 작업·큐·재사용·종료 동작을 함께 설계하고 리소스 누수 및 기존 proxy/TLS 회귀를 확인한다.

리허설·질문·soak·서버/프런트 검사는 세부 최종 경계 수정 이전 실행도 포함하므로 전체 최종 회귀 통과를 대신하지 않는다. 최종 코드의 직접 근거는 신규 통합 9건, 76건 묶음, 최종 전체 실패 로그와 패치 무결성 검사다.

정확한 실행 결과는 동봉 `validation_v2158/`의 최종 로그와 결과 JSON에 기록한다. 전체 테스트와 특정 회귀·리허설은 중복 범위이므로 합산 점수로 표시하지 않는다. 동결 수락 기준은 변경하지 않고 남은 실패·미실행을 유지한다.

적용은 최신 main 위에서 `git apply --check` 후 패치로 진행한다. 패키지는 v2.15.7 수정까지 포함한 누적 패치와 전체 챗봇 사본을 제공한다. v2.15.7을 이미 적용했다면 파일을 덮기보다 충돌을 대조한다. 상세 실행 명령은 패키지의 APPLY_GUIDE.md를 따른다. DB 마이그레이션은 없다.
