## PowerShell — 자동 사전 점검

팀 레포 루트에서 실행한다. `.venv`와 backend 테스트 의존성은 팀 구축 문서대로 준비한다.

```powershell
$env:PYTHONIOENCODING = "utf-8"
.\.venv\Scripts\python.exe backend/app/chatbot/parking-chatbot/tools/preflight_1106.py --rehearsal
```

기본은 규칙 질문 전체와 격리 HTTP 대본 6개다. 전체 unittest도 필요하면 `--unit`을 추가한다. 결과는 챗봇 `.validation/preflight_1106/`의 JSON·로그에 남는다. 누락/실패/시간 초과는 성공으로 표시하지 않는다. 같은 출력 위치를 다시 사용하면 해당 검사 로그는 갱신되므로 보존하려면 `--output <새 폴더>`를 사용한다.

별도 필수 검사:

```powershell
$env:LLM_PROVIDER = "none"
.\.venv\Scripts\python.exe -m pytest tests/ -q
# 챗봇 루트로 이동한 뒤: 동결 수락 검사. 남은 DNS 권고 실패와 브라우저 미실행을 그대로 기록.
Set-Location backend/app/chatbot/parking-chatbot
& ../../../../.venv/Scripts/python.exe qa/run_acceptance.py --python-only --output .validation/acceptance_1106
```

위 마지막 Python 경로는 챗봇 루트에서 레포 루트까지 네 단계 기준이다. 불확실하면 처음에 `$python = (Resolve-Path .\.venv\Scripts\python.exe).Path`로 절대 경로를 보관하고 이동 후 `& $python ...`로 실행한다.

## 김채린님에게 전달할 변경 요청 — 아직 전송하지 않음

대상은 PR #61 `62e760c`의 ChatPanel이며 다른 담당 폴더를 이 준비본에서 변경하지 않았다.

1. 요청 성공 시 무조건 `setText('')`하므로 대기 중 작성한 새 초안이 지워진다. 전송 시점 초안과 현재 편집 버전을 비교해 비운다.
2. 재시도마다 `request_id`가 바뀐다. 본문·확인 토큰·요청 ID를 결과 확인까지 보관하고 같은 요청은 같은 ID로 재전송한다. 새 업무에는 새 ID를 쓴다.
3. 새 Lv2 경보가 와도 기존 확인 버튼이 활성 상태다. 경보·확인 상태를 동기화하고 서버를 최종 차단 주체로 유지한다.
4. 서버 재시작·늦은 응답을 `runtime_id`·`state_version`으로 구분하고 필요한 `/chat/updates` 공개 경로를 통합 담당과 검토한다. 관리 경로 전체를 공개하지 않는다.
5. 이번 KAN-67은 서버 차단을 구조화된 안전 카드로 전달한다. `banner.level`은 기존 경보 표시 정책을 유지하며 경보 없음이 조회된 경우 0일 수 있다. 배너의 차단 문구와 `safety`를 표시하되 경보 미조회 상태를 Lv2로 만들어 표시하지 않는다.

완료 증거: 같은 실제 화면에서 정상 조회·확인·결제·재시도·경보 전환을 실행한 기록. 소스 대역 시험이나 빌드 성공과 구분한다.

## 윤명수님·PM에게 확인할 사항 — 아직 전송하지 않음

- 윤명수님: 인증서 재발급·키 제외 재정리, 권한 요청 중 중복 녹음 방지, 모든 종료 경로의 트랙 정리, 취소 후 늦은 결과 폐기, 실제 추론 종료까지 슬롯 유지.
- PM: D-44 모델·D-56 음성 방식·MapLibre 승인·실물 실패 시 모의 전환. 음성은 PC 기본 P0와 분리한다.
- 카메라·ROI 코드는 우지원님 영역이다. 저장소 밖의 진행 여부를 이 준비본으로 판정하지 않는다.
