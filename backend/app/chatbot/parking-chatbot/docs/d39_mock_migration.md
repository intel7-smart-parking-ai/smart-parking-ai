# D-39 목업 데이터 변경 계획·대응표

기준 v2.15.3 `3e5e55e`. 사용자가 D-39 데이터 및 관련 테스트 기대값 갱신을 승인했다. 승인 범위는 번호·차종 의존 값이며, 검사 목적·안전 보호·시간·요금·칸 수를 바꾸지 않는다.

## 작업 순서

1. 기존 배치를 유지하는 일대일 대응표를 먼저 고정한다.
2. lots.json의 번호·전기차 목록 및 목업 전용 차종 메타데이터를 D-39에 맞춘다. 기존 vehicle_type 전달 형식을 재사용하며 새 기능·환경변수·전환 모드는 추가하지 않는다.
3. 기존 목업 번호에 의존하는 테스트/브라우저 입력·기대값만 대응표로 갱신한다. 순수 파서·API fixture·LLM 평가·holdout·질문 CSV는 유지한다.
4. D-39 일치·배치/이용시간 보존·API 차종 우선·10~99 입력 범위를 회귀 검사한다. 최종 전체 검증은 변경을 모아 한 번 실행한다.

D-39의 24대 중 초기 주차 차량은 기존과 같은 19대다. 나머지 10·14·55·75·85는 설정 차종표에만 있고 초기에는 주차하지 않는다. 주차장·칸·점유 수·이용시간·요금 정책·견적·결제·경보 처리를 보존한다. 예비 번호는 초기 주차/차종표에 섞지 않는다. assigned_car_ids=null을 유지해 서버/파서의 10~99 허용 범위를 24대로 제한하지 않는다.

관련 검사 중 추가 확인: 기존 reset은 위 19대에 B 만차용 번호 90~83 차량 8대를 자동 생성했다. 이 임의 번호는 D-39에 없으므로 번호 없는 초기 만차 점유로 바꾼다. B 16칸 점유·전체 점유 27칸은 유지하며 실제 번호를 가진 차량은 19대다. 초기 만차 점유는 수동 시연 점유와 구분해 기존 clear_demo 및 demo_state 동작을 보존한다. 미입차 후보 검사에 쓰던 34번은 새로 주차하는 번호가 되므로 미입차 99번으로 옮긴다.

공개 계약 고정 JSON은 변경하지 않는다. test_public_contract의 demo_cars 데이터 개수만 기존 27대에서 D-39의 명시 차량 19대로 맞추며, 기존 각 항목의 키·타입 검사는 유지한다. 명시 차량 19대·전체 점유 27칸·24대 차종표는 별도 회귀에서 정확히 검사한다.
