## 다음 코드 수정 순서와 완료 기준

1. **완료 영수증 소비 보완:** 이미 결제한 응답에서 서버가 준 영수증만 사용한다. 영수증이 없거나 식별자가 다르면 임의 생성하지 않는다. 새 결제 POST 0, 기결제 안내, 같은 세션/차량/금액, 차단 상태 우선 처리를 검사한다.
2. **가상 위치 조회 연결:** 승인된 `GET /api/v1/vehicle-search?vehicle_number=1724`를 사용한다. 단일 일치만 위치로 안내하고 404(없음/복수)·422·시간 초과·미확인/오래된 응답을 검사한다. 앞자리 0 보존, 전체 번호판과 마지막 4자리 검증, 실물 car_id와 분리를 확인한다. 자동으로 실물 결제 대상에 연결하지 않는다.
3. **최신 서버 연결 검증:** main과 미병합 통합 브랜치를 구분해 기존 6문항 리허설·api_smoke·경보 중 결제 차단을 확인한다. 현재 ChatPanel의 칩·safety 표시와 음성 입력 제어는 김채린 PC에서 확인한다.
4. **안정성 문제 별도 처리:** DATA-01은 거절된 응답의 명부 변경 문제다. 기준 완화로 없애지 않고 관련 함수의 게시 시점·조회 횟수·캐시 세대를 검증하는 수정 대상으로 유지한다. DNS-01은 advisory와 실제 운영 영향을 구분한다.

위 내용은 구체적인 후속 구현 범위와 검증 방향이다. 이번 변경에서 영수증 소비·가상 검색·음성 기능을 구현 완료한 것으로 보고하지 않는다. 이번 실제 수정·실행 결과는 `v2155_change_summary.md`를 따른다.

## 변경 가능한 과거 제약과 유지할 경계

- 확정 팀 명세를 반영하는 fixture·표시 이름·질문 개수·공식 API 소비 경로 변경은 진행 가능하다. 과거 “기대값/경로는 전부 변경 금지” 지침으로 막지 않는다.
- 사용자와 팀이 이미 승인한 같은 내용을 재승인받지 않는다.
- 담당 폴더 밖 소스, 공통 API/DB 정의, 프런트 마이크 버튼, 서버 금액 계산은 임의 변경하지 않는다.
- 결제 확인·멱등성·경보 안전·미인식/불확실 데이터 처리와 실제 실패 보고는 유지한다.
- 기능 추가·삭제나 미확정 계약 결정은 먼저 설명하고 허락/팀 결정을 받는다.
