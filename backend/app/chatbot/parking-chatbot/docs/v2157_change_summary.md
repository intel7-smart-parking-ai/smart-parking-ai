## 수정한 동작

### KAN-67: 서버 결제 차단을 안전 UI로 전달

- 초기 `/alerts`에 Lv2가 없어도 fee의 `payment_blocked=true` 또는 결제 `409 EVACUATION_ACTIVE`가 확인되면 기존 대피 문구와 함께 `safety`·차단 `banner`를 제공한다.
- 조회하지 않은 경보 단계·위치·발생 시각은 만들지 않는다. 배너는 기존 경보 표시 정책을 유지하고 새로 Lv2를 만들지 않는다. 경보 없음이 조회된 경우 단계는 0일 수 있다. 서버 차단 사실은 문구로 전달한다.
- 같은 요청 ID로 차단 응답을 재생해도 안전 안내를 유지한다. 새로운 정상 확인이 진행 중이면 오래된 차단 응답으로 그 확인을 취소하지 않는다.
- 근거는 기존 요청별 ContextVar 범위에서 관리한다. 다음 요청이나 다른 세션으로 차단 상태가 새지 않는다.
- 결제 재시도·확인 절차·모의 결제 body·공개 응답 키는 유지한다. 내부 재생 근거는 HTTP JSON에 노출하지 않는다.

### DATA-01: 빈자리 스냅샷 검증 후 명부 공개

- `/spaces` 정규화 과정에서 빈자리 경로가 공유 명부를 먼저 갱신하지 않는다. 후보 칸 목록은 dict 속성으로만 전달하며 JSON 필드를 추가하지 않는다.
- 전체 집계·시각·계약 검증 및 캐시 세대 확인이 끝난 뒤 명부의 칸 목록·용량을 catalog lock 안에서 한 번에 공개한다.
- 미래 응답·후속 주차장 형식 오류·조회 중 reset은 명부를 바꾸지 않는다.
- 집계 불일치·불완전 목록에서는 새 칸 순서를 채택하지 않는다. 미인식 차량의 순번도 기존 공개 명부 기준으로 유지한다.
- 실패 후 전역 상태를 되돌리는 롤백은 하지 않는다. 다른 요청의 정상 갱신을 덮지 않도록 했다.
- 위치·경보·차량 목록의 나머지 `_spot()` 등록 경로는 별도 점검 대상으로 남긴다. 모든 명부 변경 경로를 해결했다고 확대하지 않는다.
