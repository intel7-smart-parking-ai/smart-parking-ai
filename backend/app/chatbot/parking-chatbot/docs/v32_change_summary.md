| 문제 | 원인 | 수정 |

## 서비스 범위 밖 요청 — 모델 없이 정해진 답 (`boundaries.py`)

예약·자리 보장(현재 빈자리 함께 안내), 할인·감면, 매출, 다른 이용자 차량 정보, 지시 무시 요청, 등록되지 않은 주차장(예: 롯데백화점), 관리자 위치. 모델 상태와 관계없이 같은 답이 나가며 대화 에이전트·키워드 규칙보다 먼저 처리한다.

그 밖: 결제 수단 질문("카드 말고 현금?")은 기존 모의 결제 안내로, 0으로 시작하는 차량 번호는 "쓰지 않는 번호"로 안내. 결제만 요청하면 모델을 거치지 않고 바로 확인 절차.

## 프로젝트 데이터 활용

- **가상 C·D 차량 조회**: `API_CONTRACT`의 `GET /api/v1/vehicle-search?vehicle_number=1724`와 세션 요금(`/sessions/{id}/fee`)을 사용한다. "1724 차량 어디?", "17가1724 요금"에 위치·입차 시각·현재 요금을 답한다(그동안 "준비 중"). 목업은 `lots.json`의 `mock_virtual_plates`.
- **외국어 질문**: 프런트가 보내는 `language`로 비한국어를 감지하면 질문을 한국어로 바꿔 엔진에 넣고(숫자 변경 시 원문 사용), 답은 기존 `response_locale`가 번역한다. 번역 시간을 남기도록 대화 처리 마감을 4초로 제한(`engine.budget_cap`).

## 남은 점

- 모델 응답 시간: 단순 조회도 모델이 2회 호출되면 3~5초. 모델 실패 시 규칙 답으로 대체되어 사실은 같다.
- 결제 요청은 차량 확인 → 견적 확인 2단계(안전 규칙 유지). 가상 차량의 모의 결제는 화면의 차량번호 조회에서 진행.
- 대화 세션당 분당 모델 질문 5개 제한(`LLM_MAX_PER_SESSION_MIN`) 유지.
