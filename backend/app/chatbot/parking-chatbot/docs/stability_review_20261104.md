## 3. 최적화와 유지한 구조

관리자 `/incidents` 폴링은 경보 출처 하나를 얻기 위해 `engine.stats()`를 호출했다. 이 함수는 최대 2,000개 기록을 복사·집계하고 LLM 통계 잠금도 읽는다. 이미 가져온 경보 스냅샷에서 출처를 직접 계산하도록 두 HTTP 서버를 동일하게 정리했다.

| 항목 | 결과 |
|---|---|
| 전체 통계 계산 | 폴링마다 1회 → 0회. 실제 경보·보고서 조회 횟수는 증가하지 않음 |
| 검증 | stats 호출 시 실패하도록 주입해도 FastAPI HTTP와 표준 서버 응답 생성이 정상. 출처 3종(ok/not_provided/unavailable) 동일 |
| 성능 주장 범위 | 불필요한 전체 기록 순회 제거를 확인. 응답 속도가 몇 % 빨라졌다는 주장은 하지 않음 |
| 구조 | 세션 잠금, 공유 조회, 캐시 세대, 알림 cursor, 결제 직렬화, Lv2 결제 중단 정책 유지. 엔진 분리·대규모 정리·의존성 추가 없음 |
