## 팀 통합에서 남은 증거

현재 `backend/app/main.py:create_app()`의 OpenAPI에는 POST `/api/v1/chat`이 없고, 실제 TestClient 호출도 404다. 미리보기에서 라우터를 조합해 수행한 6/6과 구분했다. 이 작업의 수정 허용 범위 밖인 main을 고치지 않았다.

`frontend/src/ChatPanel.jsx`는 `messages`에서 문자열만 추출해 텍스트로 렌더링한다. card/chips/banner/safety를 표시하는 경로는 이 컴포넌트에서 확인되지 않았다. 이는 소스 확인 결과이며, 실제 팀 화면의 해당 기능 E2E를 실행했다고 보고하지 않는다. 정적 챗봇 화면 브라우저 통과가 이 팀 컴포넌트 통과를 대신하지 않는다.

리허설 로그에는 경보 API 404도 있었으며, 경보 상태 미확인 안내로 처리되면서 6개 시나리오가 통과했다. 따라서 이 결과는 위치·요금·확인 결제 미리보기 흐름의 근거이며 실제 경보 API 연결 완료의 근거가 아니다.

## 검사 도구 문제와 재실행 기록

전체 테스트는 설치·미설치 각각 1회만 실행했다. 최초 추가 브라우저 선택자가 마지막 안전 카드까지 선택해 `.kv`를 못 찾고 시간 초과됐다. 요구사항을 바꾸지 않고 마지막 봇 메시지 내부에서 항목을 찾도록 바로잡아 추가 화면 8개만 다시 실행했다. 최종 4 PASS/4 FAIL/0 ERROR이며 두 정상 값 대조군도 통과했다.

main 확인용 probe도 FastAPI의 `_IncludedRouter`에 `.path`가 있다고 가정해 도구 오류가 났다. probe를 OpenAPI 기반으로 고쳐 해당 확인만 재실행한 결과가 등록 없음/404다. 프런트 최초 빌드는 Vite 미설치로 실행 불가였고, 격리 사본에서 기존 package-lock 의존성 65개를 `npm ci --ignore-scripts`로 설치한 뒤 빌드만 재실행해 성공했다. 이 세 최초 오류를 제품 결함 건수에 합산하지 않았다.

## 변경·보존 및 후속 순서

추가/수정한 것은 `qa/`의 기준·합성 인수 검사·브라우저 검사·실행 안내와 이 검증 문서뿐이다. 기준 커밋에 이미 있던 추적 파일은 모두 변경되지 않았다. 운영 코드, 기존 tests/CSV/holdout, API/칩/설정 키, 응답 형식, 잠금·재전송·캐시 세대·cursor·결제 직렬화·Lv2 정책은 보존했다. holdout 질문을 수동으로 열거나 답을 보고 테스트를 튜닝하지 않았다.

권장 후속 순서는 (1) 거절/존재/방법 문의의 의도 구분, (2) null 화면·보고서 갱신·명부 부작용, (3) 평가/연결 검사 도구의 정직한 실패 표시, (4) 필요한 선택 제공자와 조건부 화면, (5) 팀 main·화면·실기기 연결이다. DNS/결제 대기 예산은 구조 변경 없이 가능한지 먼저 설계·검증 방법을 정해야 한다. 이번에는 운영 수정이나 새 기능을 넣지 않았다.
