# v2.15.9 화면 질문 처리 수정

기준일: 2026-11-06 KST / main90f6afc / 로컬 수정 준비본. 원격 push·PR·시연 서버 적용은 수행하지 않았다.

## 문제와 변경

사용자 화면에서 위치 질문은 확인 단계까지 진행됐지만 ‘30번 차량은 있나?’, 질문 가능한 내용 문의, 20번대/20~30번 차량 문의는 일반 실패 안내로 돌아갔다. v2.15.8의 LLM 비활성 규칙 경로에서 이를 재현했다.

- 단일 차량 존재/현재 주차 질문은 기존 find_my_car로 처리한다. 차량 확인을 거친 뒤 공식 위치 API를 읽으며 새 존재 여부 API·응답 형식은 만들지 않는다.
- 지원 질문 문의는 기존 help에 연결하고 구체적인 입력 예시와 모의 결제 안내를 제공한다. 예시에 적힌 차량 번호를 실제 조회 대상으로 선택하지 않는다.
- 번호 범위·번호대·전체 차량 목록은 지원 한계를 설명하고 번호 하나의 위치/빈자리 조회를 안내한다. 범위 끝 번호 하나를 뽑아 조회하거나 일괄 결제/호출하지 않는다. 취소·경보·대피 안내는 우선순위를 유지한다.
- 내부 help 매개변수만 추가했다. 공개 API·기존 intent·칩 ID·카드 type·flow·요금/결제 서버 계약은 그대로다. 모델·키·의존성·다른 담당 폴더는 바꾸지 않았다.

## 23번 입차 기록 없음의 별도 판단

이 문구를 성공 위치로 바꾸지 않았다. API 시험에서는 upstream이 해당 차량404를 반환하면 입차 기록 없음 안내를 유지하고 가짜 위치·영수증·결제를 만들지 않는 것을 확인한다. 실제 사용자의23번은 입차 준비가 안 됐는지, 다른 서버를 조회하는지 아직 모른다. 실제 UI URL·서버 모듈·BACKEND_BASE_URL·동일 환경의 /api/v1/vehicles/23/location 결과를 대조해야 한다. 운영 API 응답·데이터는 이번 작업에서 변경하지 않았다.

## 회귀와 검증

신규 test_v2159_question_routing.py는 화면 질문·동의 표현·정정·칸/시간 오인 방지·범위 일괄 업무 차단·경보/취소 우선·외부 모델 비호출·차량 확인 후 HTTP 조회·없는 차량/미지원 조회에서 업무POST0·오래된 결제 승인 무효화를 확인한다. 기존 질문 기대값은 수정하지 않았다.

실행한 결과:

| 검사 | 결과 |
|---|---|
| 신규 질문 회귀 | 9/9 통과 |
| 기존 질문 세트 | 248/248 통과 |
| 격리 HTTP 리허설 | 6/6 통과 |
| 서버 pytest | 350통과·경고3, 32.76초 |
| 최소 설치 전체 유닛 | 583건: 571통과·2오류·10skip, 163.418초 |
| 선택 SDK 전체 유닛 | 583건: 579통과·1실패·3skip, 110.696초 |
| 전체 회차 실패3건의 단독 재현 | 3/3 통과, 2.006초 |

전체 회차의 오류는 opaque session 요금 조회와 pagination 시험의 HTTP 응답 누락이며 전송 시간 초과가 동반됐다. SDK 회차는 FastAPI 기동 마감 검사에서 실패했다. 같은3건을 단독 실행하면 통과했다. 실패 로그를 보존했으며 자원/환경 원인은 아직 추정이다. **전체 검사 통과를 확정하지 않으며, 적용 대상 환경에서 최종 회귀 재확인이 필요하다.** 기존 기대값이나 시간 제한은 바꾸지 않았다. 프런트 제품 코드를 바꾸지 않아 프런트 빌드는 이번에 반복하지 않았고 실제 사용자 화면도 재검수하지 못했다.

상세 결과는 동봉 validation_v2159 로그를 따른다. 검사 묶음은 중복을 합산하지 않는다. 실제 화면·운영 LLM·시연 서버 검수는 이번 로컬 검사와 구분한다.
