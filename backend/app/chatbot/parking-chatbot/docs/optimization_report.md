# 기능 유지 최적화·안정화 결과

2026-11-01 · 기준: Claude 2차 반영본. 기존 기능·사용자 화면·API 경로·확인 절차를 유지하면서 중복 조회와 불필요한 상태 계산을 줄였다.

## 확인하고 수정한 부분

### 1. 한 요청의 차량 위치 조회 통합

기존에는 ‘내 차 근처 경보’ 문장과 상단 고정 차량 카드가 같은 차량 위치를 각각 조회했다. 요청 단위의 공통 위치 조회 함수를 사용하도록 정리했다. 위치 카드·경보 안내·관리자 요약·고정 카드가 같은 요청의 조회 결과를 재사용한다. 실패 결과도 같은 요청에서는 공유하여 연속 실패 조회를 하지 않는다. 다음 요청은 새로 조회한다.

세션 참조도 요청 동안 재사용한다. 내부 처리에서 같은 세션을 찾을 때 전체 세션 정리와 전역 잠금 획득을 반복하지 않는다. 요청 종료 시 두 참조를 정리하여 다음 사용자의 상태와 섞이지 않도록 한다.

### 2. 동시에 진행 중인 동일 조회 공유

서로 다른 사용자가 같은 차량 위치나 빈자리 현황을 동시에 요청하면 진행 중인 백엔드 조회 결과를 공유한다. 결과는 사용자별 복사본으로 제공한다. 새로 시작한 순차 조회는 매번 백엔드에 요청한다.

결제 전후의 요금 조회는 각각 백엔드에 요청하고 기존 금액·입차 확인과 중복 결제 방지를 유지한다.

공유 조회가 실패하면 대기 요청들도 오류를 전달받고 종료된다. 다음 조회에서 복구할 수 있다. 출차·초기화 중 이전 조회가 늦게 끝나면 그 결과로 차량 캐시를 다시 채우지 못하게 했다. 다른 차량의 출차는 관련 없는 위치 조회를 취소하지 않는다.

### 3. 대기열 계산 축소

기존에는 빈자리 폴링 때 전체 세션마다 대기 상태와 순번을 다시 계산했다. 실제로 알림을 철회해야 하는 경보 위치의 대기 항목만 한 번 확인하도록 바꿨다. 대기 순서·한 자리의 순차 배정·경보 위치의 알림 보류·해제 후 안내는 유지한다.

### 4. 반복 검사에서 발견한 문의 상태 조회 오류

이미 문의가 등록된 뒤 ‘내 문의 상태’를 누르면 버튼 ID 목록이 필요한 곳에 버튼 객체 목록이 전달되어 `TypeError: unhashable type: 'dict'`가 발생했다. 수정 전 기준본에서도 직접 재현했다.

조회 처리 함수가 버튼 ID 목록을 반환하도록 고쳤다. 접수 상태 카드와 처리 완료 후 ‘해결됐어요 / 아직 안 돼요’ 버튼, 같은 문의 재개를 자동 검사와 브라우저에서 확인했다.

## 비교 측정

동일한 로컬 mock·단일 프로세스·LLM 비활성 조건에서 수정 전후를 비교했다. 아래는 통제된 실험 1회 측정이며 실제 팀 서버의 처리량·지연 보장은 아니다.

| 조건 | 수정 전 | 수정 후 | 의미 |
|---|---:|---:|---|
| 근접 경보 조회 8번, 위치 API당 15ms 주입 | 위치 조회 16번 | 8번 | 같은 응답의 문장·카드 중복 제거 |
| 200세션·100대기자, 폴링 12번 | 대기 상태 조회 2,412번 | 12번 | 관련 없는 세션의 순번 재계산 제거 |
| 같은 차량 위치 12명 동시, API 40ms 주입 | 백엔드 조회 12번 | 1번 | 동시 요청의 중복 부하 감소 |
| 빈자리 12명 동시, API 40ms 주입 | 백엔드 조회 12번 | 1번 | 공용 현황 조회의 중복 부하 감소 |

위치/빈자리 동시 요청의 최대 응답 시간은 양쪽 모두 약 40ms대다. 여기서 확인한 이득은 백엔드 조회 횟수 감소다. 근접 경보와 대기 폴링의 개별 실행 시간은 `optimization_before.json`, `optimization_after.json`에 있다. 대기 상태 호출 계측이 포함된 실험이므로 실제 서버 CPU 시간과 동일시하지 않는다.

## 검증 결과

- 질문 분류 **205/205**: 기존 세트 유지. 이번에는 분류 규칙을 수정하지 않았다.
- Python **170개 통과**: 기존 157개와 새 13개. 동시 조회·실패 후 회복·출차/초기화 경합·사용자별 결과 분리·문의 상태 조회 검사를 추가했다.
- Chromium **31항목 통과**: 기존 15, 안정화 12, 이번 4. 관리자 메모 30초 유지, 재시도·새로고침·결제 보호 등 기존 검사도 재실행했다.
- 혼합 반복 **30사용자·2,400요청·40회 경보 변경** 완료: 커서 순서, 차량 대상, 문의-사건 연결, 의도하지 않은 결제 없음, 진행 중 조회 정리 등 명시한 불변 조건을 검사했다.

반복 검사는 합성 시나리오이며 실제 사용자 30명의 실사용 평가가 아니다. 위 기능 검증은 mock 기준이다. 현재 변경의 실제 모델 API·팀 백엔드·장비 연결 성능은 검증하지 않았다.

## 기능 유지 범위

다음 기능을 기존 회귀 검사에 포함했다.

- 빈자리 조회·대기 등록/순서/취소·알림 재전송
- 차량 선택·정정·변경·위치 카드·고정 카드·요금/이용 현황
- 모의 결제 금액 확인·만료·토큰 검사·요금 변경·중복 요청·불확실 결제 처리
- 관리자 즉시 호출·사건별 분리·단계 악화 요약·문의 상태·미해결 재개
- 경보 이력·대피 안내·Lv2 결제 중지·경보 위치의 빈자리 안내 보류
- 관리자 메모 보존·자동 갱신·revision 충돌·보고서 확정
- 사용자 세션 필수·관리자 접근 키·시연 API 비활성화

실행 방법·환경 설정은 기존과 같다. 현재 제한인 단일 프로세스 메모리 저장과 실제 API/DB 미연결도 그대로다. 다음 검증 대상은 실제 팀 서버의 중복 조회 감소·지연·기기 동시 리허설이다.
