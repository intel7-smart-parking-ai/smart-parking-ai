# 챗봇 음성 입력 연결 가이드 (화면 담당 인수인계용)

- 대상: 김채린님(사용자 화면 `frontend/src/ChatPanel.jsx`), 그리고 이 작업을 이어받는 사람·AI
- 작성: 서정범(EPIC 06 챗봇, KAN-9), 2026-11-04, 챗봇 v2.13 기준
- 팀 레포: https://github.com/intel7-smart-parking-ai/smart-parking-ai
- 함께 볼 문서: `docs/chat_response_fields.md`(요청·응답 필드), `docs/v213_change_summary.md`

이 문서는 사람과 AI가 그대로 읽고 작업할 수 있게 "사실 → 규칙 → 할 일 → 완료 기준" 순서로 썼다. AI에게 넘길 때는 8장의 전달문을 복사해 함께 준다.

---

## 1. 한 줄 요약

**음성은 화면에서 글자로 바꾼 뒤, 지금 쓰는 `POST /api/v1/chat`의 `text`로 보낸다.** 챗봇 서버와 nginx는 바꿀 필요가 없다. 다만 **결제 확인 단계에서는 음성을 자동 전송하지 않는다**(4-1).

## 2. 구조와 수정 범위

```
[마이크] → 브라우저 음성 인식(STT, 말→글자) → 인식된 글자 → POST /api/v1/chat {text} → 챗봇 답변(text) → 화면 표시
```

| 구분 | 바꾸는가 | 비고 |
|---|---|---|
| 화면(`ChatPanel.jsx` 등) | 바꿈 | 마이크 버튼, 인식, 전송 규칙. 김채린님 영역 |
| 챗봇(`backend/app/chatbot/`) | 안 바꿈 | 글자 입력과 똑같이 처리됨 |
| nginx(`frontend/nginx.conf`) | 안 바꿈 | 기존 `POST /api/v1/chat`만 사용 |
| 팀 서버(`main.py`, `demo_main.py`) | 안 바꿈 | |

**권장 방식: 브라우저 내장 음성 인식(Web Speech API의 `SpeechRecognition`).** 추가 설치·서버·비용이 없다.
서버에서 음성을 받아 인식하는 방식(Whisper 등)은 음성 파일 업로드 경로, nginx 경로, 비용, 개인정보 처리가 새로 필요해서 남은 일정에서는 권하지 않는다.

## 3. 반드시 알아야 할 사실

### 3-1. 챗봇 요청 규격 (기존과 동일)

| 필드 | 값 |
|---|---|
| `session_id` | 화면 하나당 고정값(지금처럼 `crypto.randomUUID()`를 한 번 만들어 계속 사용) |
| `text` | 인식된 최종 문장. **최대 200자**, 빈 문자열이면 보내지 않음 |
| `request_id` | **발화 한 번마다 새 값**(`crypto.randomUUID()`). 같은 값을 다시 보내면 같은 요청으로 취급됨 |
| `chip_id`, `confirmation_token` | 버튼(칩)을 눌렀을 때만. 음성으로는 보내지 않음 |

응답은 `text`(답변 본문)가 기준이고, 팀 서버에 붙은 상태에서는 `messages: [{text}]`도 같이 온다. `flow`(현재 단계)와 `safety`(Lv2 경보 안내)는 4장 규칙에 쓴다.

### 3-2. 챗봇이 알아듣는 말 (v2.13 규칙 파서로 실제 확인)

음성 인식 결과는 글자 입력과 모양이 다르다. 아래는 말투 그대로 넣어 본 결과다.

| 말한 내용(인식 결과) | 챗봇 처리 | 화면 쪽 대응 |
|---|---|---|
| `17번 차 어디 있어`, `11 번 차 어디야`, `11번차 어디` | 차량 17·11번으로 인식 | 그대로 전송 |
| `십칠 번 차 어디 있어`, `이십칠 번` (한자어 숫자) | 17·27번으로 인식 | 그대로 전송 |
| `열일곱 번 차`, `스물일곱번 차` (고유어 숫자) | **번호 인식 못 함**(번호를 다시 물음) | 안내 문구 예시를 "십칠 번" 또는 "17번"으로 |
| `칠번 차` (한 자리) | "두 자리로 말씀해 주세요" | 정상 동작(번호는 10~99) |
| `일칠번 차` (숫자를 하나씩 읽음) | 번호 오류로 처리 | 안내 예시로 유도 |
| `에이 주차장 빈자리 있어?`, `디 주차장 자리 있어?` | A·D 주차장으로 인식 | 그대로 전송 |
| `개발원 주차장 빈자리`, `부산역 빈 자리 있어요` | 주차장 이름으로 인식 | 그대로 전송 |
| `네`, `예` | **확인으로 처리**(차량 확인, **결제 확인**) | 4-1 참고 |

규칙이 못 알아듣는 문장은 LLM(OpenRouter)이 도구를 고른다. LLM이 꺼져 있거나 상한을 넘으면 "잘 이해하지 못했어요"와 버튼 안내가 나온다.

### 3-3. 브라우저 음성 인식 조건

| 항목 | 내용 |
|---|---|
| 지원 브라우저 | Chrome, Edge, Safari(macOS·iOS), 삼성 인터넷. 대부분 `webkitSpeechRecognition` 이름으로 제공 |
| 미지원 | Firefox(기본 꺼짐) → 마이크 버튼을 숨김 |
| **접속 주소 조건** | **HTTPS 페이지 또는 `http://localhost`에서만 동작.** 같은 와이파이에서 휴대폰으로 `http://192.168.x.x`에 접속하면 마이크가 막힘 |
| 시작 조건 | 사용자가 버튼을 눌러야 시작(자동 시작 불가) |
| 인터넷 | Chrome·Edge는 음성을 Google 서버로 보내 인식 → 인터넷 필요. Safari는 기기 안 인식 가능 |
| 언어 | `lang = "ko-KR"` |

## 4. 지켜야 할 규칙

### 4-1. 결제 확인 단계에서는 자동 전송 금지 (가장 중요)
- 챗봇은 결제 확인 단계(`flow === "confirm_action"`)에서 글자 `네`·`예`를 받으면 **결제를 진행한다**(모의 결제여도 기록이 남음).
- 시연장 소음이나 옆사람 말이 `네`로 인식될 수 있다.
- 규칙: `flow`가 `confirm_action`일 때는 음성 결과를 **입력창에만 채우고 사람이 전송 버튼을 누르게** 하거나, 이 단계에서는 마이크를 끄고 화면 버튼(`confirm_yes`/`confirm_no` 칩)만 쓰게 한다.
- 차량 확인 단계(`confirm_vehicle`)는 결제가 아니라서 자동 전송해도 되지만, 인식된 글자는 화면에 보여 준다.

### 4-2. 최종 결과만 한 번 보내기
- 말하는 중간에 나오는 임시 결과(`interimResults`)는 화면 표시만 하고 **보내지 않는다**. 최종 결과(`isFinal`) 하나만 보낸다.
- 발화 한 번 = 요청 한 번 = 새 `request_id`.
- 이전 요청 답을 받기 전에는 마이크 버튼을 잠근다(지금 `busy` 상태 재사용). 같은 세션 요청이 겹치면 챗봇이 409를 준다.

### 4-3. 인식된 글자를 항상 보여 주기
- 보낸 문장을 "나"의 말풍선으로 그대로 표시한다(지금 글자 입력과 동일). 사용자가 잘못 인식된 걸 바로 알 수 있다.
- 노년층·디지털 약자 사용성(EPIC 06 방향): 큰 마이크 버튼, "듣는 중…" 표시, 예시 문장("예: 십칠 번 차 어디 있어?")을 버튼 근처에 둔다.

### 4-4. 경보(Lv2) 중
- 응답에 `safety`가 있으면 그 안내를 가장 크게, 가장 먼저 보여 준다(음성 입력이어도 같음).
- 답을 소리로 읽어 주는 기능(TTS)을 넣는다면 `safety` 안내를 먼저 읽는다.

### 4-5. 오류 처리
| 상황 | 화면 |
|---|---|
| 마이크 권한 거부(`not-allowed`) | "마이크 권한이 필요해요. 글자로 입력해 주세요." 입력창 유지 |
| 말이 없음(`no-speech`) | "잘 들리지 않았어요. 다시 눌러 말씀해 주세요." |
| 인터넷 문제(`network`) | "음성 인식을 쓸 수 없어요. 글자로 입력해 주세요." |
| 미지원 브라우저 | 마이크 버튼 숨김 |
| 결과가 비었거나 200자 초과 | 보내지 않음(200자에서 자름) |

### 4-6. 비용
- 규칙이 못 알아듣는 말투가 많아지면 LLM 호출이 늘어난다. 챗봇에 상한(세션당 분당 5회, 전체 분당 30회, 하루 1,000회)이 있어 넘치면 버튼 안내로 대체된다. 화면에서 같은 문장을 자동 재전송하지 않는다.

### 4-7. 개인정보 안내
- Chrome·Edge는 음성을 Google 서버로 보낸다. 마이크 버튼 근처나 처음 사용 시 "음성은 브라우저의 음성 인식 서비스로 처리돼요" 한 줄 안내를 권장한다. 녹음 파일은 우리 서버에 저장하지 않는다.

## 5. 할 일 (화면)

1. `SpeechRecognition` 또는 `webkitSpeechRecognition`이 있을 때만 마이크 버튼 표시
2. 버튼 → `start()`, `lang="ko-KR"`, `interimResults=true`(표시용), `continuous=false`(한 문장)
3. 최종 결과 → 앞뒤 공백 제거 → 비면 무시 → 200자 제한
4. `flow === "confirm_action"`이면 입력창에만 채움, 아니면 기존 `send`와 같은 경로로 전송(새 `request_id`)
5. 4-5 오류 문구, 듣는 중 표시, 요청 중 버튼 잠금
6. (선택) 답변 읽어 주기(`speechSynthesis`, `lang="ko-KR"`): 새로 말하기 시작하면 읽기 취소(`cancel()`), `safety` 먼저

## 6. 완료 기준 (시연 PC, `http://localhost` 또는 HTTPS)

| # | 말하기 | 기대 |
|---|---|---|
| 1 | "에이 주차장 빈자리 있어?" | 개발원주차장 빈자리 수 답변 |
| 2 | "십칠 번 차 어디 있어" | "17번 차 맞으세요?" → "네"(음성) → 위치 답변 |
| 3 | "열일곱 번 차" | 번호를 다시 묻는 답변(정상) |
| 4 | 요금 → "결제해 줘" → 결제 확인 단계에서 "네"(음성) | **자동 결제되지 않음.** 입력창에 "네"만 채워지거나 버튼 사용 안내 |
| 5 | 아무 말 없이 기다림 | no-speech 안내, 요청 0건 |
| 6 | 마이크 권한 거부 | 안내 후 글자 입력 가능 |
| 7 | Firefox | 마이크 버튼 없음 |
| 8 | 말하는 중 | 임시 글자만 보이고 요청 0건, 끝나면 요청 1건 |

## 7. 아직 정해지지 않은 것 (PM·팀 확인)

- 시연 접속 방식: 시연 PC 브라우저(`localhost`, 마이크 가능)인지, 휴대폰 접속인지. 휴대폰이면 HTTPS가 필요하다(PM 미결 "외부 터널"과 연결).
- 시연장 소음: 시연 때 마이크 사용 여부와 위치.
- 고유어 숫자("열일곱 번") 지원을 챗봇 쪽에 추가할지: 필요하면 서정범 쪽 다음 버전(v2.14) 후보로 올린다. 화면 쪽은 안내 예시로 먼저 해결한다.

## 8. AI에게 넘길 때 전달문 (복사해서 사용)

```
너는 팀 레포 https://github.com/intel7-smart-parking-ai/smart-parking-ai 의 사용자 화면(frontend)에 챗봇 음성 입력을 붙인다.
기준 문서: backend/app/chatbot/parking-chatbot/docs/voice_input_guide_for_frontend.md (이 문서), docs/chat_response_fields.md.

범위
- frontend/src 안만 수정한다(ChatPanel.jsx 중심). backend/app/chatbot/, nginx.conf, 서버 파일은 수정하지 않는다.
- 브라우저 SpeechRecognition(webkitSpeechRecognition)만 쓴다. 새 서버·외부 STT API·새 의존성 추가 금지.

규칙(문서 4장)
- 인식한 최종 문장만 기존 POST /api/v1/chat의 text로 보낸다. 발화마다 새 request_id. 200자 제한. 빈 결과는 보내지 않는다.
- 응답 flow가 "confirm_action"(결제 확인)이면 음성 결과를 자동 전송하지 말고 입력창에만 채운다.
- 임시 결과는 표시만, 요청은 최종 결과 1회. 요청 중에는 마이크 버튼 잠금.
- 미지원 브라우저는 마이크 버튼 숨김. not-allowed / no-speech / network 오류 문구를 표시하고 글자 입력은 항상 가능하게 둔다.
- safety가 있으면 가장 먼저, 크게 표시한다.

완료 기준: 문서 6장 표 8개 항목. 결과 보고에 각 항목 결과, 바꾼 파일, 테스트 결과(npm test, 빌드)를 적는다.
브랜치: feature/<Jira 키>-voice-input, PR 리뷰 필수, 병합은 김한별님. .env·키는 커밋하지 않는다.
```
