# V35 최종 수집 프로그램 검수



**운영 기본값은 카메라 1에서 A주차장 직사각형 12칸, 카메라 2에서 B주차장 사선 16칸을 천장 시점으로 수집하는 것이다.** 한 측정에 두 원본을 연결하고, 각 칸의 주차선·점유·번호·스티커 배경색과 확인 사유를 표시사진 및 한글 JSON에 남긴다. 완전한 두 장면을 저장한 수, 품질을 통과해 전달한 수, 사람이 승인해 학습에 쓸 수 있는 수를 구분한다.



## 이번에 막은 오류



기존 듀얼 화면에서는 점유 모델이 없을 때 스티커로 차량 후보를 찾았다. 빈칸에 스티커가 없다는 사실만으로는 차량이 가려진 경우와 구별할 수 없어, 실제로 비어 있는 칸도 미확인으로 남았다. 빈칸 한 개가 미확인이어도 해당 장면 전체가 품질 보류였다. 최종본은 촬영자가 실제로 비었다고 확인한 두 장면을 비교 기준으로 사용할 수 있다.



| 과정 | 처리 조건과 결과 |

|---|---|

| 최초 등록 | 두 장치의 새 프레임을 고정하고 기존 ㄷ자 주차선 또는 ArUco 절차로 전체 칸을 등록한다. 작업자는 화면에 표시된 **바로 그 두 장면**에서 차량·손·가림이 없는지 한 번 확인한다. 한쪽의 칸 누락이나 노출·해상도 문제가 있으면 두 기준 모두 등록을 보류한다. |

| 기준 보관 | 두 기준 PNG를 기록하고 각 파일의 SHA-256을 다시 읽어 대조한다. 두 사진과 장치·칸 좌표·시각을 담은 JSON이 준비된 폴더를 한 번에 공개한다. 새 기준이 커밋되기 전에는 이전 기준이 활성 상태다. |

| 측정 | 같은 장치·연결 구간·주차장·시점의 이후 프레임만 비교한다. ArUco 기준이 같고 전체 영상 모서리 변위가 최대 3픽셀인 작은 흔들림은 평면 변환으로 맞춘다. 그보다 큰 이동이나 기준 교체는 재등록을 요구한다. |

| 칸별 판독 | 빈 기준과의 변화량이 낮더라도 25픽셀 이상의 연결된 변화가 있으면 작은 물체·가림 후보로 보류한다. 점유 후보의 번호는 현재 스티커 영역의 복수 전처리 판독을, 배경색은 스티커 내부 픽셀을 사용한다. 전용칸과 차량 종류가 다르면 해당 칸에 경고를 붙인다. |

| 품질과 학습 | 기존 수치 기준을 적용하고 UI의 해당 행에 선명도·해상도·미판독 등 보류 사유를 표시한다. 사진 전달은 두 장면 품질 통과가 기본이다. 학습에는 장면 품질과 칸별 사람 승인을 모두 확인하고 무표시 크롭을 쓴다. 검수 전 자동 후보는 원본과 함께 보관할 수 있다. |

| 저장·내보내기 | 한글 칸별 JSON에 빈 기준 ID·시리얼·시각·원본 해시를 연결한다. 사진 전달 시 실제로 쓰인 기준 사진과 등록 기록도 검증해 함께 복사한다. 같은 기준은 한 번만 전달하며 주차장별로 걸러 전달하면 해당 장면의 카메라 기준만 포함한다. 학습 manifest에는 동시측정 ID와 장치 시리얼도 기록한다. |



새 기준은 `references/dual/<빈기준ID>/`에 보관한다. 카메라를 옮기거나 재연결한 뒤와 새 프로그램 실행 시에는 빈 기준을 다시 확인한다. 이전 V35와 단일 촬영 자료는 최종본의 **저장 폴더 선택**에서 기존 데이터 루트를 지정하면 읽을 수 있다. 빈 기준을 새로 쓴 자료를 보관하거나 다른 PC에서 수집을 이어갈 때는 이 폴더가 포함된 전체 데이터 루트를 옮긴다.



## 파일과 수량으로 확인한 결과



- **제공받은 실제 빈 보드 사진.** 각 사진의 원본 픽셀을 그 사진 자체의 빈 기준으로 재생한 읽기 전용 시험에서 A 12칸·B 16칸 모두 빈칸으로 판정했다. 칸 선명도 기준 때문에 A-01·A-02·A-03과 B주차장의 B-08을 보류했다. 칸별 품질 통과는 A 9/12, B 15/16이고 두 장면 모두 최종 선별은 보류였다. 반복 재생에 따른 변화량·선별 시험으로, 실제 장비가 시간차를 두고 찍은 사진의 정확도는 현장에서 측정할 항목이다. [사진별 결과](EMPTY_BOARD_REPLAY_V35_FINAL.json)

- **차량이 있는 합성 측정.** 한 칸에 초록색 23번 스티커를 배치하고 번호 OCR 응답만 통제했다. 나머지 27칸은 빈칸, 23번은 지정한 장애인 칸에 있는 전기차 종류 불일치 후보로 한글 JSON에 저장됐다. 실제 색·좌표 처리, 상태 판정, 기록, 양쪽 품질 선별과 복사를 통과했다.

- **전달 묶음 검증.** 실제 Tk 화면에 모의 카메라 두 대를 연결해 등록 취소·확인·수집·내보내기·종료를 시험했다. 별도 파일 시험에서 기준 1개로 A/B 측정 1쌍을 전달하면 **칸별 PNG·JSON 28짝, 총 이미지 34개·데이터 JSON 31개**였다. 기준 사진 2장과 등록 JSON 1개를 포함한 수치다. 목적지 폴더를 옮긴 뒤 기준 해시를 대조했고, 기준 원본 한쪽을 손상시키자 해당 측정의 사진과 승인 학습 자료 모두 전달에서 제외됐다.

- **회귀와 중단 시험.** 전체 회귀 488/488 통과, 저장·전달 중단 116건과 마커 등록 중단 4건 통과. 기존 검증 자료 14개 루트의 2,413개 파일을 해시로 대조했다. [전체 회귀시험](TEST_RESULTS_V35.json) · [검증 범위](VALIDATION.json)

- **직전 V35와의 호환.** 직전 배포 코드로 만든 A/B 측정 1쌍을 최종본에서 다시 열었다. 후보 전체 전달은 28칸이었고 품질 통과 필터는 보류 자료를 제외했다. 원본 데이터 루트 102개 파일의 전후 해시가 일치했다.



## 실제 설치 후의 첫 측정



1. 두 카메라를 고정하고 차량을 놓기 전 각 화면에서 A 12칸·B 16칸이 모두 보이는지 확인한다. 두 빈 기준을 등록한다.

2. 번호·스티커색·위치를 아는 차량 한 대를 놓고 측정을 시작한다. 통합 화면과 저장 JSON에서 해당 칸·번호·색이 실제 배치와 일치하는지 대조한다.

3. 품질 통과 자료를 한 번 전달하고 UI 수량과 목적지 기록을 대조한다. 보류됐다면 해당 칸의 사유를 보고 초점·거리·가림을 바로잡는다. 차량을 새로 배치할 때 배치 ID를 갱신한다.



직전 V35에서 실물 D435 두 대의 PC 수신 프레임 30쌍, 시차 3.9~29.0ms를 확인했다. 당시에는 사용자 확인상 보드 설치 전이었으며 실물 완전 측정 저장 수는 0쌍이었다. 이번 증분 시험은 새로 구현한 빈 기준 절차와 저장·전달 동작을 대상으로 했다. 설치 후 D39 실차 번호·스티커색의 현장 정확도와 위반 검출률은 미측정이다. 전용칸 종류 불일치와 배경 변화에 따른 경계 경고는 표시할 수 있으며, 차체 외곽의 선 침범을 확정하려면 별도의 차량 외곽 근거가 필요하다.
