# ArUco 적용 적합성 분석 — V30 코드 기준



2026-11-05. 결론은 **주차칸 위치 등록·구도 변경 대응을 위한 보조 수단으로 적용을 권장**합니다. 현재 실행 환경에서 마커 검출과 평면 좌표 변환의 합성 실험까지 확인했습니다. 실제 인쇄 마커/카메라 비교 시험과 수집 UI 연결은 수행하지 않았습니다. V30에 자동 마커 등록이 이미 구현됐다는 뜻은 아닙니다.



## 1. 현재 프로그램에서 개선할 수 있는 작업



현재 `automatic_setup.read_bay_names/detect_spaces`는 칸 이름 OCR과 실제 주차선 근거를 연결합니다. `anchor_alignment`는 ORB 특징과 평면 변환을 이용해 이전 구도와 같은지 검사합니다. 이동량이 크면 기존 좌표 재사용을 거부하고 이름/선을 다시 읽습니다. 차량이 칸 이름을 가리거나 카메라를 여러 방향으로 옮기면 이 재등록이 어려워질 수 있습니다.



ArUco는 고유 ID가 있는 사각형 기준표입니다. 검출된 ID와 네 모서리를 실제 배치의 기준점으로 사용할 수 있습니다. 여러 마커의 상대 위치를 미리 정한 Board는 더 많은 대응점을 사용하고 일부 마커가 가려진 경우에도 위치 추정에 활용할 수 있습니다. [OpenCV 마커 검출](https://docs.opencv.org/5.0/tutorials/objdetect/aruco_detection/aruco_detection.html), [Board 설명](https://docs.opencv.org/5.0/tutorials/objdetect/aruco_board_detection/aruco_board_detection.html)



따라서 우리 프로그램에서는 **마커 위치와 A12/B16의 칸 경계를 한 번 등록 → 현재 화면에서 마커 검출 → 해당 화면의 모든 칸 좌표 계산 → 기존 번호/색/점유·품질·저장 처리**로 연결하는 것이 적합합니다. 이는 코드 구조에 근거한 설계 판단이며 실제 작업시간 단축률은 아직 측정하지 않았습니다.



| 작업 | 예상되는 효과 / 한계 |

|---|---|

| A/B 주차장 선택 | 서로 겹치지 않는 마커 ID 묶음과 등록된 판 배치로 식별 가능. 두 판의 마커가 섞이면 자동 확정하지 않도록 설계 |

| 카메라 이동 후 ROI | 화면에 기준점이 충분하면 등록된 주차칸 좌표를 새 구도로 변환 가능 |

| ㄷ자·사선 주차선 | 미리 등록한 실제3면/가상 입구 좌표를 함께 변환하므로 모양을 매번 닫힌 사각형으로 찾을 필요가 줄어듦 |

| 차량이 바닥 칸 이름을 가림 | 마커가 보이면 미리 연결한 칸 명칭/위치를 사용할 수 있음. 최초 칸 배치 검수는 필요 |

| 번호·스티커색·점유 | 기존 OCR/색/점유 모델과 품질 검사가 계속 필요. 마커가 차량 정보를 자동으로 읽어 주지는 않음 |

| 천장 고정 촬영 | 처음 맞춘 뒤 구도 감시·카메라 흔들림 확인에 활용. 시점 변경이 잦을 때보다 재등록 절감 효과는 작을 수 있음 |

| 실제 촬영 자세/각도 | 보정된 카메라 내부값과 실제 마커 배치가 있으면 pose 추정 검토 가능. 사용자 시점 선택과 동일한 정보라고 바로 간주하지 않음 |



## 2. 권장 설치와 등록



첫 적용안은 각 주차판 테두리에 **4~6개의 서로 다른 마커를 넓게 분산**하는 것입니다. 예를 들어 A판은 ID0~5, B판은 ID10~15처럼 구분할 수 있습니다. 이는 우리 보드에 대한 제안이며 ArUco의 보편적인 최소 개수 규칙은 아닙니다. 네 모서리 주변과 중간 지점에 배치하여 한쪽의 작은 영역에만 몰리지 않게 합니다.



마커는 주차면과 같은 평면에 고정하고 주차칸/스티커를 가리지 않게 둡니다. 마커의 위치가 판에 대해 움직이면 등록한 좌표 관계도 잘못됩니다. 인쇄 크기는 실제 촬영 높이·거리·해상도에서 검출 가능한지 시험한 뒤 정해야 하며 지금 고정된 cm 값을 보장할 수는 없습니다. 흰 여백과 검은 테두리가 잘 보이도록 출력해야 합니다. [마커 생성·검출 안내](https://docs.opencv.org/5.0/tutorials/objdetect/aruco_detection/aruco_detection.html)



A/B 각각 처음 한 번 마커 ID·모서리의 판 기준 좌표와12/16칸의 다각형, 실제3면, 입구, 명칭/종류를 저장하고 실제 주차선과 맞는지 확인합니다. 이후 촬영에서는 그 기준을 화면 좌표로 투영합니다. 임의 마커를 붙이는 것만으로 각 칸의 이름과 경계를 처음부터 알게 되는 것은 아닙니다.



## 3. 반드시 유지할 품질 조건



평면 변환은 같은 평면의 점을 연결하는 방법입니다. 주차면의 좌표 변환과 바닥보다 높은 차량/스티커의 투영은 같은 정확도를 보장하지 않으므로, 차량 높이로 생기는 어긋남을 주차위반으로 바로 확정해서는 안 됩니다. 보드가 휘거나 렌즈 왜곡이 크면 경계 오차가 생길 수 있습니다. [OpenCV 평면 변환 설명](https://docs.opencv.org/5.0/tutorials/features/homography/homography.html)



실제 적용에서는 마커 ID 충돌/다른 판 혼입, 관측점의 분산, 변환 오차, 화면 밖으로 나간 칸, 비정상 다각형, 이전 프레임과의 급격한 변화, 작은/흐린 마커를 확인해야 합니다. 부족하면 수집을 보류하고 그 사유를 보여줘야 합니다. 한 마커의 네 모서리로 수학적인 계산이 가능하더라도 전판 좌표를 신뢰할지는 별도 기준으로 판단합니다.



정밀한 렌즈 보정에는 ChArUco도 검토할 수 있습니다. 공식 문서는 ChArUco가 마커의 식별성과 체스보드 코너의 정밀도를 결합해 카메라 보정에 유용하다고 설명합니다. 실제 적용 시 화면/해상도별 보정값과 좌표계를 일치시켜야 합니다. [OpenCV ChArUco 설명](https://docs.opencv.org/5.0/tutorials/objdetect/charuco_detection/charuco_detection.html)



## 4. 현재 환경에서 확인한 것



- 설치 OpenCV **5.0.0**, `cv2.aruco.ArucoDetector`와 마커 생성 API, `findHomography` 사용 가능. 이번 확인을 위해 패키지를 설치하거나 바꾸지 않았습니다.

- 1200×900 합성 평면에 마커4개를 생성한 뒤 정면·원근·평면 회전·마커1개 가림의4조건에서 검출/좌표 복원을 확인했습니다.

- 시험용 내부 점12개의 최대 오차는 각 조건에서 약0.061/0.166/0.080/0.982px였습니다. 이상적인 합성 평면에 대한 수치이며 실제 카메라 정확도로 해석하지 않습니다.

- 마커1개만 남긴 경우, 이 시험의 보수적인 전판 기준(분산 배치 마커3개 이상)에 따라 보류했습니다. 공식 최소 검출 조건을 뜻하지 않습니다.

- 마커 검출의 소규모 실행 측정은 약2.15~2.51ms 범위의 조건별 중앙값이었습니다. OCR·저장·UI·실제 카메라를 포함한 속도나 비교 성능은 아닙니다.



원본 시험 결과는 `ARUCO_FEASIBILITY_V30.json`, 재현 스크립트는 작업 폴더의 `verification_v30/aruco_feasibility.py`에 있습니다. 실제 인쇄/반사/가림/거리/심한 기울기 조건은 아직 검증하지 않았습니다.



## 5. 실제 프로그램 연결 시 필요한 변경



1. A/B 마커 배치와 판 기준 ROI를 저장하는 설정·최초 등록 흐름.

2. `automatic_setup`에 마커 검출/좌표 변환 경로와 근거 부족 시 보류 처리.

3. `layouts`의 등록 근거 검증과 `dashboard.Worker`의 매 분석 장면 구도 검증 연결. 새 method 이름만 추가해 기존 검증을 건너뛰면 안 됨.

4. 원본 프레임별 ROI 사본과 마커 ID/코너/변환/오차 근거를 함께 고정해 저장. 다음 프레임의 좌표가 이전 결과를 바꾸지 않게 함.

5. UI에 마커 검출 수·좌표 유효/보류·A/B 판 식별·수집 상태 표시. 기존 천장 우선 시점·번호/색/점유·원본 보존·한글 JSON/학습 전달 유지.

6. 실제 A/B 판에 출력 마커를 붙인 자료로 등록 시간, 성공률, 수동 개입 횟수, 칸 모서리 오차, 마커 부족 시 안전한 보류를 기존 방식과 비교.



**권장 판단:** 우리처럼 같은 두 판을 여러 각도에서 촬영하는 작업에는 유망합니다. 가장 큰 기대 효과는 주차칸 재등록 자동화입니다. 번호·색 인식의 완벽함이나 차량 외곽 위반 기능이 완성되는 효과로 계산하지 않으며, 실제 적용 전후 성능 수치는 실측으로 확인해야 합니다.
