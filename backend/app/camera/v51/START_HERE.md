# V51 사용 설명서 — RealSense 두 대 동시 측정

**공개 제출본 안내.** 설치는 README의 `requirements-v51.txt` 절차를 따른다. 실제 촬영 전 카메라 시리얼을 설정하고, 팀 Drive의 도면 특징·스티커 참고 자료를 README에 적힌 로컬 위치로 복원한다. 검증 JSON은 경로·시리얼을 익명화한 이력이다. 이번 공개 파일 검사 범위는 PUBLICATION_CHECK.json에서 확인한다.

## F5로 바로 수집하기



**프로그램을 실행하고 F5를 누르세요.** 저장된 카메라 배정으로 장치를 연결하고, 준비된 두 영상을 분석해 원본·칸별 사진·JSON을 자동 저장합니다. 기본 저장 위치는 실행 폴더의 `datasets`이며 화면 아래에 실제 경로와 완료 수량이 표시됩니다.



| 키 | 동작 |

|---|---|

| F5 | 자동 연결 후 연속 수집·저장 |

| Space | 자동 연결 후 유효한 두 프레임을 한 번 분석·저장 |

| Esc | 수집 중지. 이미 쓰기 시작한 파일은 마무리 |



키는 주차장 창이 활성화된 상태에서 사용하세요. Space는 입력란이나 버튼에 초점이 있을 때 해당 입력·버튼의 기본 동작을 따릅니다. 확인 대화상자가 열린 동안에는 단축 수집을 실행하지 않습니다. 초기 자료 검사 중 누른 수집 키는 검사가 끝나면 이어서 처리합니다. 같은 키를 반복해서 눌러도 촬영 요청을 중복 생성하지 않습니다.



**설정·검수**를 펼치면 저장 폴더, 카메라 배정, 빈 기준 등록, 기존 1회 측정, 검수·내보내기 버튼을 사용할 수 있습니다. 기존 자료는 여기서 **저장 폴더 선택**으로 사용하던 `datasets`를 한 번 지정하세요. 이후에는 F5로 수집할 수 있습니다.



빈 기준 없이 시작하면 스티커 관측과 실제 도면의 위치를 함께 수집합니다. 빈칸·선 침범 비교가 필요하면 설정·검수에서 두 빈 사진을 확인하고 기준을 등록하세요. 차량을 놓은 사진이 자동으로 빈 기준에 등록되는 과정은 없습니다.



## V51의 측정 보류 수정



같은 연결·주차장·시점에서 도면 위치가 달라지면 현재 사진에서 실물 도면을 다시 찾습니다. 두 줄의 주차선이 충분히 맞고 이동·크기·변환 오차 검사를 통과하면 확인한 빈 기준을 현재 좌표에 맞춰 측정합니다. 화면의 **실물 도면 재정합**과 저장 JSON의 `빈기준도면재정합`에서 적용 여부를 확인할 수 있습니다. 기준 원본과 측정 원본은 별도로 보관하며, 저장 자료를 다시 읽을 때에도 변환 근거를 대조합니다.



이동이 크거나 주차선 근거가 부족하면 두 빈 기준을 다시 등록하세요. 카메라 재연결, 주차장·시점 변경도 재등록 대상입니다. 반사로 밝기만 바뀌고 새로운 물체의 윤곽을 확인하기 어려운 칸은 **밝기 변화와 물체 구분 보류**로 기록합니다. 보류 칸이 포함된 저장 사진은 검수 화면에서 확인하세요.



## 커진 사각형 번호 라벨



원형과 사각형 라벨을 자동으로 구분합니다. 사각형에서는 종이 테두리 안쪽 색을 측정하고 숫자 전체를 네 방향으로 읽습니다. 검정 테두리와 주변 차체가 숫자에 섞이는 현상을 줄였습니다. 면적 4~5배는 같은 모양에서 지름·가로세로 약 2~2.24배입니다. 별도의 크기 입력은 필요하지 않습니다.



사용자가 제공한 새 Intel 사진 2장에서 11·49·23·34·77의 번호와 색을 직접 판독했습니다. 흰색 87은 28로 읽히는 반대 방향 근거와 충돌해 번호를 보류했고, 칸 위치와 흰색은 저장했습니다. 인식 범위는 10~99입니다. 번호 23도 범위 안에서 처리합니다. 이 여섯 번호를 강제로 배정하는 목록은 사용하지 않습니다.



현재 시험 범위는 저장된 사진 재생과 모의 입력입니다. 이번 V51 작업의 추가 USB 촬영은 실시하지 않았습니다. V50의 5분 실장치 시험 이력은 `VALIDATION_V50.json`과 `HARDWARE_5MIN_V50.json`에 보관합니다.



카메라 1은 **A주차장(직사각형 12칸)**, 카메라 2는 **B주차장(사선 16칸)**이 기본입니다. 두 시점 모두 천장에서 시작합니다. 카메라 채널 A/B와 주차칸 이름 A-01/B-01은 별개입니다.



## 전기차·장애인 구역 수집



| 주차장 | 전기차 구역 | 장애인 구역 | 일반 구역 |

|---|---|---|---|

| A주차장 (12칸) | A-05, A-06 | B-06 | 나머지 9칸 |

| B주차장 (16칸) | A-07, A-08 | B-07, B-08 | 나머지 12칸 |



카메라 화면 위에서 실제 촬영 대상인 **주차장**을 선택하세요. 두 카메라가 서로 반대쪽 주차장을 보거나 같은 주차장을 볼 때도 이 선택을 따릅니다. **가상선 · 실물판 자동 결합**을 켜면 현재 영상과 선택한 도면을 맞춰 각 칸의 좌표를 찾습니다. 두 화면의 **도면 구역** 열과 전용칸 안내 글씨에서 전기차·장애인 구역을 확인할 수 있습니다. 예를 들어 B-06은 A주차장에서 장애인 구역이고 B주차장에서는 일반 구역입니다. 차량 스티커가 가려져도 등록된 칸의 종류는 도면에서 가져옵니다.



실물판을 찾은 촬영에서는 주차장·칸·구역과 차량 관측을 함께 저장합니다. 파란 가상선만 보이면 구역 이름은 배치 안내로 쓰이고 실물 위치는 미확인으로 기록됩니다. 실물 전용구역 점유를 수집할 때는 초록 실물선과 칸 이름이 현장에 맞는지 확인하세요. 칸 한글 JSON의 `주차장`·`주차칸명`·`주차칸종류`, 승인한 학습 사진 목록의 `lot_id`·`space_id`·`주차칸종류`로 분류할 수 있습니다. 현장 정답표에도 구역 종류가 자동으로 채워집니다. 기존 정답표에 이 필드가 없으면 측정 당시 등록한 칸에서 구역을 가져옵니다.



## 보드 없이 차량 번호와 스티커색부터 수집하기



**두 대 미리보기 → 두 대 측정 시작**을 누릅니다. 기본 설정인 **가상선 · 실물판 자동 결합**에서는 빈 보드 등록을 건너뜁니다. 두 카메라 각각에서 파란 가상선 안에 차량의 원형 스티커를 놓으세요. 실물 도면이 인식된 카메라에는 초록색 실물선이 표시됩니다. 미리보기는 배치 안내이고, 파일에는 측정한 프레임에서 다시 판정한 결과가 들어갑니다.



- **보드 없이 수집.** 칸 번호는 화면상 배치 위치입니다. `sticker_only/collected/<주차장>/<시점>/<칸명>/`의 PNG와 JSON에 위치근거, 가상배치칸, 실물칸확인=false, 번호, 스티커색, 추정 여부가 기록됩니다. 실물주차칸은 null입니다. 양쪽 모두 가상이며 스티커 후보가 없으면 자동으로 다음 프레임을 기다립니다.

- **한쪽만 보드가 있는 경우.** 같은 측정 ID에서 한 채널은 실물 칸, 반대 채널은 가상 칸으로 각각 저장합니다. 다음 프레임에 실물판이 들어오면 재등록 없이 현재 영상의 도면에 맞춥니다.

- **수동으로 등록한 구도를 쓸 때.** 기본 자동 결합은 제공된 A·B 사진 도면과 등록된 ArUco 마커를 현재 영상에서 찾습니다. 별도의 수동 ROI와 고정 구도 기준을 이용하려면 측정을 정지하고 **가상선 · 실물판 자동 결합**을 끈 뒤 **ROI·마커 기준 등록** 또는 **두 빈 주차장 기준 등록**을 사용하세요.

- **빈 보드를 이용한 점유·오주차 측정.** 아래 ‘처음 실행’의 빈 기준 등록까지 진행합니다. 차량이 들어오기 전후를 비교할 수 있습니다. 가상 모드로 돌아갈 때는 측정을 정지하고 자동 결합 체크를 켭니다.

- **밝기와 검수.** 실물판 통로나 확인한 빈 기준에 맞춰 밝기를 조정한 경우 각 칸의 JSON에 배율과 이동값을 기록합니다. 가상 촬영은 스티커 안의 국소 대비로 숫자를 읽습니다. 보정으로 되살릴 근거가 없는 반사, 66과 99의 방향 충돌은 번호를 보류할 수 있습니다. 추정 후보는 사람이 원본을 보고 승인·수정한 뒤에 학습 자료로 전달합니다.

- **파일 전달.** 하단 **두 카메라 사진·JSON 내보내기**는 기본으로 완료된 측정 전체를 전달합니다. 장면 전체가 통과하고 사람이 승인한 학습 크롭은 **통과·승인 학습 내보내기**로, 일부 칸만 통과한 경우에는 **통과한 칸만 학습 내보내기**로 전달합니다. 가상 데이터의 학습 과제는 번호와 스티커색입니다. Geti 가져오기를 시험할 때는 무표시 크롭과 학습 manifest를 사용하세요. Geti 설치판의 실제 가져오기는 별도로 확인해야 합니다.

- **현장 검증.** 하단 **현장 정답 대조**에서 `dual_measurements/<측정ID>.json`을 선택하면 `field_checks/<측정ID>/현장정답표.json`이 생깁니다. 자동 판독 결과를 보지 않고 실제 조명·배치를 입력한 뒤 같은 버튼에서 작성한 파일을 선택합니다. 정답표에 같은 JSON 필드가 두 번 들어가면 중복 항목을 바로잡은 뒤 다시 대조하세요. 번호·스티커색의 직접 일치, 추정 일치, 오답, 보류를 따로 셉니다. 가상 촬영의 주차선은 ‘미평가’로 둡니다. 학습 manifest의 데이터 루트 기준 상대경로를 넣으면 번호 사진의 정답·승인 근거·승인 좌표 픽셀도 대조합니다.



**한 칸에 스티커 두 개가 보일 때** 프로그램이 서로 다른 두 스티커의 판독 근거를 찾으면 번호를 보류합니다. 양쪽 화면이 모두 가상이어도 해당 측정의 두 원본과 검수용 기록을 저장합니다. 칸별 판독 후보와 원본을 열어 두 위치를 확인하고, 차량을 한 칸에 한 대씩 놓아 다시 촬영하세요. 가상 칸의 실제 점유와 오주차는 미평가로 둡니다.



가상선 내부를 좁혀 다시 읽다가 두 위치가 나타나거나 같은 위치에서 다른 번호가 나오면 검수 기록에 근거가 남습니다. 해당 칸의 번호를 비운 채 원본 이미지를 대조하세요.



## 반사나 숫자 방향 충돌로 보류될 때



칸별 JSON의 **번호판독영상진단**에서 검사 범위를 먼저 확인하세요. `sticker_polygon`은 찾은 스티커 안쪽, `bay_polygon`은 칸 전체입니다. 스티커 위치를 찾지 못한 장면에서는 칸 전체 통계만 제공합니다.



- `raw`와 `analysis`는 같은 영역에서 측정한 원본과 판독용 영상입니다. `white_clip_ratio`는 세 색 채널이 모두 250 이상인 픽셀의 비율이고, `contrast_p90_p10`은 밝기의 상·하위 백분위 차이입니다.

- `raw_saturated_without_detail`이 표시되면 원본에서 해당 영역을 확대해 숫자 획을 확인하세요. 획이 사라졌다면 조명의 반사각이나 노출을 조정해 다시 촬영하세요. 구도가 달라지면 빈 기준을 다시 등록하세요.

- `correction_lost_detail`이면 보정 전 원본을 확인하세요. `highlight_present`인 흰 스티커에서는 숫자 획이 선명할 수도 있습니다. 진단 수치는 검수 참고값이며 학습 전달에는 기존 품질 검사와 사람이 승인한 정답을 사용합니다.

- 모양과 획이 뒷받침하는 번호가 원본 OCR의 선택과 다르면 근거를 대조해 보류합니다. 정반대 방향에서 세 전처리가 모두 모양과 같은 번호를 읽은 경우에는 낮은 점수도 보류 판단에 쓰며, 그 번호를 자동 정답으로 올리지는 않습니다. 66/99, 68/89, 86/98처럼 돌리면 다른 번호로 읽히는 경우에는 양쪽 방향의 근거가 충돌하면 색만 남을 수 있습니다. 실제 배치와 스티커의 방향을 확인한 뒤 검수 창에서 승인하세요. 방향 확인이 어려운 스티커는 사람이 위아래를 구분할 수 있게 표시해 다시 촬영하세요.



**추정 번호의 원본 크기.** 번호 추정 영역의 높이가 24픽셀보다 작으면 칸의 검토 사유에 원본 너비와 높이를 표시합니다. 판독이 어려우면 숫자의 위아래가 보이게 하고 초점·거리를 조절해 다시 촬영하세요. 측정 중 이동을 보정할 주차선 근거가 부족하면 두 빈 기준을 다시 등록하세요. 여러 판독에서 서로 다른 번호가 나온 칸은 원본과 색을 확인한 뒤 승인하세요.



## 처음 실행



1. 이전 버전에서 진행 중인 측정·저장을 마치고 카메라 연결을 해제한 뒤 창을 닫으세요. `smart-parking-v51.zip`을 새 폴더에 풀고 **run_windows.bat**를 실행하세요. 실행기는 기존 가상환경·OCR 모델을 재사용합니다. 기존 촬영을 이어갈 때는 **저장 폴더 선택**에서 사용하던 데이터 루트(원본 `raw`와 측정 기록이 들어 있는 상위 폴더)를 지정하세요.

2. 두 RealSense를 USB로 연결하고 **장치 검색**을 누릅니다. 이전 설치 기록의 D435 시리얼은 1번 `<serial>`, 2번 `<serial>`이며 기본값에 반영했습니다. 다른 장비를 사용하거나 두 영상이 반대라면 연결을 해제하고 각 화면에서 해당 시리얼을 선택하세요. 연결 후 배정은 `dual_cameras.json`에 저장됩니다.

3. **두 대 미리보기**로 양쪽 영상을 확인하세요. 이 상태에서는 촬영 장면을 저장하지 않습니다. 실제 장치 위치와 A/B 화면이 맞는지 확인하고, 필요하면 **연결 해제** 후 시리얼을 바꾸세요. 한 대만 감지되면 같은 카메라를 두 번 쓰지 않고 대기합니다.

4. 각 영상 위에서 실제 주차장과 시점을 선택합니다. 같은 주차장을 두 시점에서 보고 싶으면 양쪽의 주차장을 같게 하고 시점을 각각 선택하세요. 해상도/FPS는 두 장치에 공통 적용되며 변경 전에 연결을 해제해야 합니다. USB 연결이 불안정하면 상태 사유를 보고 두 장치가 지원하는 낮은 해상도나 FPS를 시험하세요. 재연결 후에는 새 연결에서 들어온 두 프레임을 기다립니다. 1회 측정을 누른 순간 화면에 있는 사진이 이전 연결의 것이면 새 미리보기를 확인한 뒤 다시 누르세요. 100ms는 PC가 두 영상을 받은 시각 차이이며 센서 노출 시각의 차이는 따로 측정해야 합니다. 해상도를 바꾼 뒤에는 ROI·마커 기준과 번호 크기도 다시 확인해야 합니다.

5. **실물 점유와 경계를 비교할 때만** 두 주차장을 비우고 **두 빈 주차장 기준 등록**을 누르세요. 화면이 잠시 고정됩니다. 두 사진의 칸 이름·경계와 실제 빈 상태를 확인하세요. 칸이 빠졌다면 아래의 ROI·마커 기준 등록을 먼저 진행합니다. 기준을 만들기 어려우면 스티커 근거나 등록된 점유 모델로 수집할 수 있고, 근거가 부족한 빈칸은 관측 보류로 남습니다.

6. 기본값인 **구역 확정 후 자동 측정**을 켜 두면 승인 직후 등록선이 미리보기에 표시되고 연속 수집을 시작합니다. 차량을 놓으면 PC 수신 시각 차이가 기본 100ms 이내인 두 원본을 묶고, 빈 기준과 비교해 주차칸의 점유·위치 경고를 계산합니다. 현재 스티커에서 번호와 색을 읽어 결과 표를 갱신합니다. 한 번씩 시험하려면 빈 기준 확인 전에 자동 측정을 끈 뒤 **현재 두 화면 1회 측정**을 누르세요.



실제 차량 배치를 바꿨을 때만 **새 차량 배치**를 누르세요. 같은 데이터 루트에서 재실행하면 `dual_batches.json`의 배치 ID를 이어 씁니다. 기존 데이터 루트에서 이 파일을 처음 만들 때에는 새 배치가 시작됩니다. **기준을 찍을 때와 같은 카메라 연결·주차장·고정 시점**에서 사용합니다. 카메라를 옮기거나 재연결하거나 프로그램을 다시 실행하면 새 구도에서 빈 기준을 다시 등록하세요. 과거 기준 사진과 판독 근거는 데이터 루트에 보관됩니다.



## 검수 번호를 수정하고 학습용으로 전달할 때



1. **저장 검수·상세 보기**에서 장면과 칸을 선택합니다. **후보를 정답 초안으로** 가져와 원본에 보이는 두 자리 숫자와 원형 스티커 배경색을 대조하세요. `추정` 표시가 붙은 번호를 사람이 확인하면 자동 예측과 승인한 정답이 각각 보존됩니다.

2. 숫자 박스를 편집할 때 숫자를 가깝게 감싸세요. 현재 실물 규격에서는 숫자 박스 면적의 60% 이상이 등록한 스티커 안에 들어와야 승인됩니다. 숫자만 적고 박스를 생략하면 정답 표기는 보존하지만 숫자 학습 사진은 생성하지 않습니다.

3. **검수 저장 실패**이면 해당 칸의 초안에서 다시 저장하세요. 다른 창에서 검수가 변경됐다는 안내가 나오면 장면을 다시 열어 최신 값을 비교하세요. **검수 정답 저장 완료 · 표시사진·JSON 갱신 보류**이면 정답은 저장됐습니다. 파일 문제를 해결하고 **선택 장면 저장 복구**를 누르세요.

4. 기존 폴더를 열면 정상 승인 기록을 재사용합니다. 이전에 승인한 스티커와 숫자 박스가 어긋난 칸은 재검수 대기입니다. 해당 칸의 범위를 바로잡고 승인하면 새 표시사진과 학습 크롭을 확인할 수 있습니다.



현장 정답표에 학습 manifest를 지정해 대조하면 `미전달정답번호관측수`는 전달 목록에 없는 정답 칸 수, `검증통과번호관측수`는 독립 정답·당시 승인·원본 크롭 픽셀이 모두 일치한 칸 수입니다. 파일이 있어도 검증에서 탈락하면 `미검증정답번호관측수`에 포함됩니다. 예전에 전달한 크롭을 재검수하면 해당 전달 시점의 승인 이력으로 대조합니다.



## 빈 기준이나 저장이 보류될 때



- **빈 기준 보류** 옆에 카메라와 칸 이름이 나오면, 두 보드에서 차량과 가림을 치우고 다시 등록하세요. 숫자가 가려진 차량·손·새로운 물체는 자동 검사가 놓칠 수 있으므로 승인 창에서 두 사진을 확인하세요.

- 1회 측정에서 구도가 바뀌면 해당 프레임과 칸별 보류 사유를 볼 수 있습니다. 카메라를 옮겼다면 새 빈 기준을 등록하세요. 등록 중 **측정 정지**를 누른 경우 등록 저장이 끝나도 두 대를 다시 시작할 때까지 수집을 멈춥니다.

- **표시사진 PNG 검증 실패**가 나오면 **미완료 측정 확인**으로 이미 확보된 원본에서 다시 생성하세요. 기존에 완료된 자료의 손상은 **저장 검수·상세 보기**의 장면 복구에서 확인합니다. 하단의 완료 수량과 이번 내보내기 수량으로 복구 결과를 확인하세요.



- **촬영 복구 기록과 현재 예측이 다릅니다**라는 메시지가 나오면 해당 측정은 복구·내보내기에서 보류됩니다. 단독 촬영에서도 복구 기록이 남은 장면은 검수 저장·수집 자료·학습 크롭·CSV 내보내기가 보류됩니다. 이미 저장한 사진과 승인을 확인할 수 있습니다. 데이터 루트 전체를 먼저 백업하세요. 측정 ID로 두 원본과 저장된 예측, 복구 기록을 대조하고, 출처를 확인한 정상 백업에서 복구한 뒤 **미완료 측정 확인**을 다시 실행하세요. 정상 기록을 확인할 수 없으면 해당 측정을 보류하고 새로 촬영하세요.



## 실물 보드의 등록이 보류될 때



**버튼을 눌렀는데 번호·색이 대기일 때** 먼저 사진 아래의 **위치**와 **전체 경계**를 확인하세요. 예를 들어 A 8/12칸, B 13/16칸이면 일부 칸을 찾은 단계이며 **완료 동시측정 0쌍**일 수 있습니다. 1회 측정에서는 방금 분석한 사진에 등록선을 그리고, 누락된 행의 **검토 사유**에 칸 이름이나 경계 중 무엇을 확인해야 하는지 표시합니다. 보류된 측정의 원본과 `A_등록표시.png`, `B_등록표시.png`, `진단.json`은 하단 메시지에 나온 진단 폴더에서 확인하세요.



**다시 촬영하려면** 두 보드를 비우고 **두 대 미리보기**에서 네 모서리와 양쪽 끝 칸까지 보이도록 맞추세요. **두 빈 주차장 기준 등록**을 누르고 두 장에 가림이 없는지 확인해 승인하세요. 등록선이 보이면 차량을 배치합니다. 같은 칸이 계속 빠지면 해당 채널의 **ROI·마커 기준 등록**으로 모든 칸의 위치를 지정한 뒤 빈 기준 등록을 다시 진행하세요.



**끝 칸이 화면에서 잘렸을 때.** 두 대 미리보기에서 **현재 두 화면 1회 측정**을 누르세요. 일부 촬영된 끝 칸의 위치를 확인하면 해당 프레임이 표시되고 칸을 주황색으로 그립니다. 예를 들어 B주차장의 끝 칸 A-08이 잘렸다면 해당 행에서 `일부 촬영 · 위치 등록 · 학습 보류`를 확인하세요. 다시 촬영하려면 **두 대 미리보기**를 누르세요. 연속 측정 도중에는 **최근 측정·등록선 보기**에서 해당 등록 프레임을 열 수 있습니다.



**위치 등록과 학습 수집.** 위치 카운터에는 부분 등록 칸이 포함됩니다. 부분 등록은 사진 속 글씨와 선으로 본 위치를 저장한 것입니다. 두 실물 보드의 빈 기준을 등록하려면 양쪽의 전체 경계가 필요합니다. 부분 등록 칸은 학습에서 보류됩니다. 보드 없이 번호·색을 모으려면 기본 자동 결합에서 가상선을 사용하세요. 1회 측정이 보류되면 `diagnostics/held_pairs/<진단ID>/진단.json`의 해당 카메라 아래 `부분등록칸`을 확인하세요. `화면안_다각형_px`는 표시사진의 주황색 경계이고, `전체경계_추정_px`는 화면 밖 교점을 포함한 추정값입니다. 면적비율은 계산한 전체 칸 중 화면에 들어온 비율입니다. 단순히 이름만 보이거나 사선 근거가 부족하면 위치도 보류합니다.



**빈 보드인데 등록이 적을 때** 먼저 미리보기에서 보드의 네 모서리, 양쪽 줄의 첫 칸과 끝 칸이 화면에 들어오는지 보세요. 끝까지 보이는 범위에서 보드를 크게 담고, 흰 칸 이름과 흰 선에 초점을 맞추세요. A는 12/12, B는 16/16이 빈 기준 등록의 목표입니다. B의 일부만 확대해서 찍은 사진에서는 보드 전체를 등록할 수 없습니다.



**구도와 해상도.** 기본 설정은 두 대 모두 1920×1080, 30 FPS입니다. 끝 경계가 잘리면 카메라를 보드 중앙 위에 맞추고 양쪽 끝이 화면에 들어오는 높이에서 초점을 조정하세요. 기존 D435의 해상도·선명도별 촬영 기록은 [장비 시험 기록](LIVE_RGB_TRIAL_V38.json)에서 볼 수 있습니다.



재판독에 성공하면 진단 JSON의 `등록기준_재판독칸명`에 해당 칸이 나옵니다. 등록 시도 JSON의 `검출근거`에는 `local_reads`로 원본 문자, 점수, 원본 좌표가 두 건씩 들어갑니다. 보류 진단의 등록 근거가 없는 채널은 해당 목록이 null이고, 글씨를 전혀 읽지 못했던 등록 시도는 빈 목록입니다. 입구를 점선으로 그린 칸은 녹색 실선 세 면이 실제 주차선입니다.



**이미 차량을 놓았다면** 양쪽 보드 전체를 표시하고 **현재 두 화면 1회 측정**을 누르세요. 마지막 저장 장면을 보고 있었다면 **두 대 미리보기**로 돌아가세요. 버튼을 누를 때 실제로 표시한 두 원본으로 분석합니다. 한쪽 화면이 오래됐거나 수신 시각 차이가 허용값을 넘으면 사유가 표시됩니다. 새로운 영상이 들어왔을 때 다시 누르세요.



빈 기준 없이 시작해도 양옆 이름과 실제 세 주차선이 확인되는 중간 칸은 찾을 수 있습니다. 예를 들어 B-02의 글씨를 차가 가리면 B-01과 B-03의 위치·입구 방향과 B-02의 실제 선을 비교합니다. 복원한 칸은 결과 표와 칸별 JSON의 `칸명확인에_사용한_양옆칸`에서 확인하세요. 끝칸·연속 두 칸이 가려지거나 선까지 사라져 보류되면 카메라를 고정한 채 차를 잠깐 치우고 두 빈 기준을 등록한 다음 차를 원위치에 놓으세요. 기준을 다시 만들 때 프로그램이 글씨 가림을 발견하면 해당 칸 이름을 안내합니다. 두 사진의 전체 빈 상태는 촬영자가 확인하세요.



실물 번호의 입력 범위는 **10~99**입니다. 결과는 직접 판독·추정·보류로 구분합니다. 원형 라벨의 가장자리 안쪽에서 흰색·초록·파랑을 판별하므로 같은 번호에도 다른 스티커색을 쓸 수 있습니다. RealSense RGB의 기본 설정은 자동 노출·자동 화이트밸런스입니다. 직접 판독이 어려우면 제공한 여섯 사진의 숫자 모양과 일반 두 자리 모양을 사용합니다. 등록한 도면의 중앙 통로 밝기 분포가 일관되게 달라지면 인식용 영상의 밝기를 보정하고 값이 적용된 경우 한글 JSON에 기록합니다. 화면의 **추정**과 JSON의 **추정차량번호**는 검수할 후보입니다. 유사도 점수는 정답일 확률을 뜻하지 않습니다. 번호만 불확실한 경우에는 스티커색만 남을 수도 있습니다. 과거 D-39 설정으로 촬영된 자료는 그때의 범위와 배정표로 검증합니다.



**최근 측정·등록선 보기**에서 표와 같은 프레임의 숫자·배경색·위치 경고를 대조하세요. **저장 검수·상세 보기 → 후보를 정답 초안으로**에서 추정 번호와 숫자 영역을 불러오고 원본과 대조해 수정·승인할 수 있습니다. **두 카메라 사진·JSON 내보내기**에서 품질 통과 조건을 끄면 검토할 쌍도 복사됩니다. 학습용 전달에는 품질·승인 조건이 적용됩니다.





**보류를 재현하려면** 하단 경로의 `diagnostics/held_pairs/<진단ID>/진단.json`을 여세요. 두 원본, 두 등록 표시사진, 시리얼, 프레임 번호, 수신 차이, 등록 좌표와 실패 사유를 함께 볼 수 있습니다. 수집을 시작한 뒤 처음 분석 보류된 한 쌍, 또는 명시적으로 1회 측정해 분석 보류된 짝마다 기록합니다. 프레임 대기·동기화 거절 단계에는 분석한 두 원본이 없습니다. 완료·학습·내보내기 수량은 실제 저장된 측정에서만 집계합니다.



- 각 장면에서 실제로 칠한 ㄷ자 세 변과 열린 입구를 구분해 A 12칸/B 16칸을 찾습니다. 각 카메라에 등록된 ArUco 기준이 있으면 해당 프레임의 좌표로 보정합니다. 칸이 부족하면 두 장면을 완료 처리하지 않습니다.

- 최초 등록이 어렵다면 **측정 정지 → 현재 분석 완료 → 해당 카메라의 ROI·마커 기준 등록**을 사용하세요. 주차칸을 모두 지정해야 합니다. 마커 기준은 칸 바깥에 보드를 둘러싸도록 배치한 마커가 필요합니다. 마커 없는 고정 구도는 다음 촬영에서 영상 특징이 맞는지 다시 검사합니다. [ArUco 배치 안내](ARUCO_GUIDE.md)

- 두 영상 아래의 표는 완료 측정에서는 점유·번호·스티커 배경색·검토 사유를, 부분 등록 프레임에서는 칸별 등록 상태를 표시합니다. **최근 측정·등록선 보기**에서 표에 대응하는 프레임 번호와 좌표를 확인하세요.

- 카메라 위치만 바꿀 때는 정지한 뒤 시점만 변경합니다. 차량 배치가 바뀌면 **새 차량 배치**를 누르세요. 같은 주차장을 동시에 보면 두 시점에 같은 배치 ID를 부여합니다. 새 측정은 시작 후에 수신된 프레임만 사용합니다.

- **저장 검수·상세 보기**에서 개별 원본·주차칸·판독 근거·품질·사람 승인을 확인할 수 있습니다. 카메라는 통합 창에서 소유합니다. 예전 단일 카메라 수집 화면만 별도로 사용하려면 **run_single.bat**를 실행하세요. 같은 장치를 두 프로그램에서 동시에 열지 마세요.



## 저장과 전달



| 확인할 항목 | 저장 위치 또는 UI |

|---|---|

| 원본 두 장 | 데이터 루트의 `raw/A/<촬영시점>/`, `raw/B/<촬영시점>/`. 원본에는 글씨를 그리지 않습니다. |

| 빈 주차장 기준 | `references/dual/<빈기준ID>/`에 확인한 두 원본 PNG와 `reference.json`을 함께 저장합니다. 이 기준으로 판독한 칸별·전체 한글 JSON에서 기준 ID, 시리얼, 시각, 기준 원본 해시를 찾을 수 있습니다. |

| 실물 칸별 표시사진·한글 JSON | `collected/<주차장>/<촬영시점>/<칸명>/`. 같은 이름의 PNG/JSON에 칸 위치·명칭, 점유, 번호, 스티커색, 경고가 연결됩니다. 두 채널이 같은 칸을 찍어도 사진 ID가 다릅니다. |

| 가상 칸별 표시사진·한글 JSON | `sticker_only/collected/<주차장>/<촬영시점>/<가상칸>/`. 화면의 배치와 번호·색을 확인하세요. |

| 어떤 두 장이 한 측정인지 | `dual_measurements/<측정ID>.json`. 두 카메라의 시리얼·사진 ID·프레임·주차장·시점·배치·수신 시각·수신 차이가 들어갑니다. 칸별·장면별 한글 JSON에도 카메라 ID, 시리얼, 동시측정 ID, 수신 차이(ms)가 표시됩니다. |

| 저장 수량 | 기본 창 하단에 완료된 측정 짝, 연결 장면, 카메라별 칸 사진/JSON 짝, 미완료 수를 표시합니다. **완료는 두 장면 저장 완료**이며, 품질 통과와 다릅니다. 각 장면의 품질 통과/보류는 마지막 저장 결과에서 확인합니다. |

| 사진 전달 | 기본은 완료된 두 장면의 측정 자료 전체입니다. 품질 통과 장면만 원하면 해당 체크를 켜세요. 보류 원인을 검토하려고 후보 전체가 필요할 때는 체크를 해제하세요. 기본 A/B 측정 1쌍에는 칸별 PNG·JSON 28짝이 있습니다. 빈 기준까지 사용한 첫 쌍은 기준 사진 2장·기록 1개를 포함해 이미지 34개·데이터 JSON 31개입니다. 여러 측정이 같은 기준을 쓰면 한 번만 복사합니다. `내보내기_결과.json`의 `빈기준파일수`와 `EXPORT_STATUS.json`의 완료 상태를 확인하세요. |

| 학습 전달 | **통과·승인 학습 내보내기**: 완료된 측정에 속하는 자료 중 장면 품질 통과와 칸별 사람 승인 조건을 충족하는 과제별 크롭을 전달합니다. 표시에 쓴 글씨가 있는 사진을 학습 원본으로 사용하지 않습니다. |



한쪽을 쓰다 디스크 오류가 나면 이미 기록한 원본을 유지하고 해당 측정을 미완료로 표시합니다. **미완료 측정 확인** 또는 다음 시작에서 복구합니다. 두 원본과 두 장면의 유효한 저장 자료가 남아 있으면 짝의 완료 기록을 복구하고, 없는 쪽을 다른 시각의 사진으로 채우지 않습니다. 원본이 없다면 새로 두 대를 측정하세요.



**기존 자료 이어 쓰기.** **저장 폴더 선택**에서 기존 `datasets` 폴더를 선택하세요. 이전 측정은 원래의 판독 설정으로 읽습니다. 누락·부분 등록·추정 장면은 **저장 검수·상세 보기**에서 원본과 함께 확인하세요. 새 촬영을 시작할 때는 현재 연결과 구도에서 빈 기준을 다시 등록하세요. 기존 단일 촬영 자료의 학습 내보내기는 **저장 검수·상세 보기**에서 사용할 수 있습니다.



**장치나 구도가 바뀔 때.** 양쪽 빈 기준을 등록한 뒤 한 카메라가 재연결되거나 설정된 주차장·시점이 바뀌면 새 분석을 중지합니다. 두 카메라의 구도를 맞추고 **두 빈 주차장 기준 등록**을 다시 누르세요. 양쪽 모두 칸 등록에 실패하면 화면 하단에서 각 채널의 사유를 확인할 수 있습니다.



**장치 검색에 Windows I/O 취소(0x800703e3)가 표시될 때.** 이전 버전이나 RealSense 뷰어에서 현재 카메라를 열고 있는지 확인하세요. 촬영 중이라면 저장이 끝난 뒤 연결을 해제하고, V51에서 **장치 검색 → 두 대 미리보기**를 다시 실행하세요.



## 완료 수량이 예상보다 적을 때



**화면에 ‘영상이 너무 어둡습니다’가 뜰 때** 해당 카메라의 조명, 렌즈 가림과 노출 설정을 확인하세요. 평균 밝기가 8/255 미만이고 밝기 24 미만 픽셀이 99% 이상이면 해당 프레임의 등록을 보류합니다. 화면에 평균 밝기를 표시하며, 측정 보류 진단 JSON의 `저조도측정`에서 두 수치를 확인할 수 있습니다.



**저장 중 디스크 오류나 강제 종료가 있었을 때** 공간·권한 문제를 해결하고 **미완료 측정 확인**을 누르세요. 측정 시 두 원본과 판독 기록부터 저장합니다. 둘 다 정상이라면 남은 칸 사진, 한글 JSON과 완료 기록을 복구할 수 있습니다. 원본 자체가 없거나 해시가 다르면 해당 쌍을 보류합니다. 크롭 사진 픽셀이나 크롭 좌표만 손상된 경우에는 검수 창에서 해당 장면을 복구한 다음 두 카메라 측정을 다시 검사하세요.



1. **미완료 측정 확인**을 누르세요. 원본, 칸·스티커 크롭, 표시사진, 한글 JSON과 해당 판독·검수 기록을 양쪽에서 대조합니다. 데이터가 많으면 읽는 데 시간이 걸립니다. 작업이 끝나면 완료·보류 수량과 첫 오류 사유가 창 하단에 표시됩니다.

2. 연결 기록만 유실됐다면 양쪽 장면의 측정 ID·멤버 정보와 파일이 모두 맞을 때 자동으로 복구됩니다. 표시사진·라벨·크롭이 손상됐다면 **저장 검수·상세 보기**에서 해당 장면을 선택하고 저장 복구를 실행한 다음 다시 확인하세요. 원본 해시까지 다르면 원본 백업을 복원하거나 새로 촬영해야 합니다.

3. 사진 전달 후 창 하단의 저장 완료 수량은 **데이터 루트 전체에서 파일 검사를 통과한 측정**입니다. 복사 완료 수량은 **이번 내보내기의 조건을 충족해 목적지에서 검증한 파일**입니다. 예를 들어 한쪽이 품질 보류이면 저장 1쌍이어도 ‘두 장면 모두 품질 통과만’의 전달 결과는 0쌍입니다. 전달 폴더에서 `내보내기_결과.json`의 제외 사유와 `EXPORT_STATUS.json`의 완료 상태를 확인할 수 있습니다.



이전 버전과 호환되는 진단 필드 `찾은칸수`와 `못찾은칸`은 전체 경계 기준입니다. 끝 칸의 위치까지 확인하려면 같은 JSON의 `위치등록칸수`와 `부분등록칸`을 함께 보세요.



## 발표와 현장 검증



두 카메라 통합 수집·검수·저장 복구·학습 자료 내보내기를 구현했다. 실제 D435 두 대의 5분 수신과 표본 저장·재열람을 확인했고, 기존 사진과 모의 입력으로 판독을 재검증했다. 신규 실물 환경의 인식률과 장시간 운전, Geti 가져오기·학습 효과는 추가 검증 예정이다.



1. **새 실물 번호 24대.** 촬영 전 차량마다 식별표를 붙이고 번호·색·위치를 기록하세요. **현장 정답 대조**에서 만든 JSON의 `차량식별표`에 적습니다. 같은 차량이 두 카메라에 보이면 같은 식별표를 씁니다. 차량 관측칸 수, 서로 다른 번호 수, 식별표상 고유 차량 수가 별도로 표시됩니다. 차량 행에 식별표가 빠지면 고유 차량 수는 미확인입니다. 이전 정답표도 다시 열 수 있습니다.

2. **조명·방향별 독립 정답 대조.** 기본광·저조도·반사와 스티커 방향을 바꾸고 같은 조건명을 기록하세요. 자동 결과를 보기 전에 번호·색과 실제 차체 위치를 적습니다. 한 칸의 주차선 위반이 둘이면 `"주차선": ["선침범", "입구돌출"]`처럼 입력하세요. `주차선유형별대조`에 적중·오경보·놓침·보류가 구분됩니다. 가상 칸은 주차선을 미평가로 둡니다. 실물 점유는 `실물점유대조`, 점유와 독립적인 번호·색 성적은 `스티커번호색대조`, 번호만의 직접·추정 일치/오답과 색 정답은 `번호와색_개별대조`를 보세요. 차량 행의 `스티커방향_도`에는 화면에서 똑바로 선 방향을 0으로 한 시계 방향 각도(0~359)를 적으세요. 모르면 null로 두면 `방향별_번호대조`에서 미기록으로 집계합니다. 번호·색·점유를 함께 맞힌 차량 관측은 `위치근거별_차량관측대조`를 보세요.

3. **장시간 연속 수집을 추가로 확인할 때.** 이전 V50 시험은 실장치 2대, 1920×1080·30fps 설정, 300.092초였다. 30분 검증이 필요하면 다음 절차를 사용하세요. 두 장치를 연결해 **두 대 측정 시작**을 누르고 실제 시간으로 30분 이상 운전한 뒤 정지하세요. `diagnostics/continuous_runs/*.json`에서 종료 상태와 `측정활성_초`가 1,800초 이상인지 확인한 뒤 완료 쌍, 시작과 끝을 포함한 활성 시간의 최장 저장 공백(`측정활성_최장저장공백_초`), 보류·실패, 채널별 최근 수신과 연결회차 변경을 확인하세요. `정지후마무리_초`는 정지 요청 뒤 분석·저장을 마친 시간이며, `실제경과_초`는 두 시간을 합친 값입니다. 기존 `최장저장공백_초`는 정지 후 저장·마무리까지 포함합니다. 이전 운전 기록의 활성 시간 공백은 별도 계측값이 없으면 미측정으로 두세요. `분석보류쌍`, `스티커대기쌍`, `정지로해제한분석쌍`은 서로 다른 결과입니다. 실행 시간과 함께 두 채널의 완료 쌍·저장 공백을 확인하세요. 30초마다 기록하며 강제 종료 시 마지막 기록은 ‘진행 중’으로 남을 수 있습니다. 짝 선택 대기 수는 관측한 프레임 조합 기준이며 센서 프레임 유실률은 별도 측정 대상입니다. 연속 모드는 채널마다 최근 4장 중 수신차가 가장 작은 유효 쌍을 고르고 동률이면 최신 쌍을 씁니다. 1회 측정은 화면에 표시한 두 장을 사용합니다. 기본 100ms는 **PC 수신 시각 차이**입니다.

4. **Geti 가져오기·학습.** 전달하거나 복사한 뒤에는 **학습 폴더 전체 검사**에서 해당 폴더를 선택하세요. 완료 수는 번호·색·점유 과제별 사진 수입니다. 폴더 내 모든 파일의 목록과 사진의 SHA-256·길이·RGB PNG 디코딩을 검사하고, 동일한 크롭이 과제 안에서 서로 다른 정답이나 분할에 들어가면 위치를 표시합니다. Geti 설치판에 맞는 과제와 가져오기 형식으로 변환하고 별도 시험 배치로 평가하세요. `EXPORT_STATUS.json`이 완료인 학습 폴더에서 과제별 이미지·라벨 수와 `manifest.json`의 `과제별_라벨_분할수`를 확인하세요. 같은 과제에서 보정 전 또는 내보낼 크롭의 픽셀이 다른 분할과 정확히 겹치면 전달이 중단됩니다. 같은 분할에서도 동일한 과제·픽셀에 서로 다른 정답을 승인하면 두 파일 경로를 표시하고 내보내기를 실패로 기록합니다. 두 번호·색·점유 라벨 중 원본에 맞는 값을 확인해 검수를 바로잡고 다시 내보내세요. 실패 폴더에 일부 이미지가 남을 수 있으므로 완료 기록이 있는 폴더만 가져오세요. 오류에 적힌 두 장면을 검수 창에서 대조하고, 반복 촬영한 행의 중복 승인을 해제하거나 독립 배치로 다시 수집하세요. 유사 사진이나 같은 실물 차량의 다른 사진은 사람이 분할을 확인해야 합니다. 대상 Geti 설치판에서 가져온 수와 분할을 재확인하고, 학습 전후를 고정 시험 세트에서 비교하세요. 앱에 연결할 수 있는 외부 모델은 점유·빈칸 2분류입니다.



새 현장 대조 보고서의 `자료규격`은 `동시측정현장대조-v3`입니다. `번호색점유_실물차량칸수`가 종합 일치율의 분모입니다. 실물 차량 칸이 0이면 `차량칸_번호색점유_일치율`은 null(미평가)입니다. 가상 차량은 스티커 번호·색을, 가상 빈 배치는 스티커 관측 여부를 대조합니다. 예전 v2 종합값에는 가상 칸이 포함될 수 있으므로 비교하려면 같은 정답표를 다시 대조해 새 보고서를 만드세요. 가상 칸 행에는 `실물칸확인=false`, `자동점유=null`, `자동전용칸판정=null`을 기록하고 스티커 관측은 `화면관측`에 적습니다. 기존 정답표는 그대로 다시 대조할 수 있습니다.



**카메라 시각을 읽는 방법.** 동시측정 기록의 `info.members.A`와 `B`에서 `received_ns`는 PC가 받은 시각입니다. 차이가 허용 범위 안인 두 장을 선택합니다. 지원하는 RGB 프레임에는 `sensor_frame`에 SDK 프레임 번호, 시각(ms), 시계 종류를 기록하고 노출시간을 제공하면 `exposure_us`(µs)도 저장합니다. 이번 표본 12장은 모두 `system_time`이었고 프레임별 노출시간은 제공되지 않았습니다. 두 센서의 실제 노출 시차는 미측정입니다. 이전 촬영은 기존 PC 수신 기록으로 읽습니다.



**빈 기준 사진과 수신 시각.** 새로 등록할 때에는 카메라별 PNG를 다시 열어 고정 화면의 RGB 픽셀과 대조합니다. 저장한 기준에는 두 카메라의 PC 수신 시각(ns)·허용차·실제 차이를 함께 남깁니다. 등록 후 검증이 보류되면 두 고정 화면과 기록을 확인하고 빈 기준을 다시 등록하세요. 과거 기준은 저장된 사진·좌표·파일 해시로 읽고 새 수신 시각을 소급해서 채우지 않습니다.



**학습 전달 대조.** 학습 manifest의 파일·배치와 과제별 라벨 분할 집계를 대조합니다. 선택한 측정의 번호 크롭은 길이와 해시, 승인 당시 번호·좌표와 실제 픽셀까지 확인합니다. 전달 목록이 서로 다르면 원본 데이터 폴더에서 다시 내보내고 새 manifest로 대조하세요.



**빈 기준 등록 시 재확인.** 약한 스티커 후보가 있으면 승인 창에 카메라와 칸 이름이 표시됩니다. 실제로 빈칸인지 확인한 뒤 승인하세요. 새 기준은 그때 확인한 칸 목록의 해시도 저장합니다. 저장된 목록이 바뀌어 불일치하면 원본 두 장을 확인하고 다시 등록하세요. 과거에 해시 없이 저장한 기준은 기존 원본·좌표 검사를 사용합니다. 뚜렷한 후보가 남으면 등록을 보류합니다. 같은 실물 도면을 다시 확인해 정합 조건을 통과하면 보정하고, 주차선 근거가 부족하면 점유·선 침범 판독을 보류합니다. 손이나 가려진 차량, 국소 그림자는 사람이 두 사진을 확인해야 합니다.
