# V28 천장 우선·다섯 시점 수집 및 저장 복구 심층 분석



V27 → V28. 천장 촬영 데이터셋을 최우선으로 두고, 오른쪽·왼쪽·위쪽·아래쪽 촬영을 보완 자료로 수집하는 프로그램입니다. 기본 UI 시점은 천장입니다. 실제 위치를 옮긴 다음 현재 시점을 바꾸면 새 주차칸 좌표로 재등록하고 시점별 폴더에 저장합니다.



## 1. 목표와 실제 구현의 구분



목표는 최종 천장 설치에서 A12/B16 전체 주차칸·점유·D39 번호·스티커 배경색을 인식하고, 다른 시점에서도 성능을 유지하는 것입니다. 여러 시점 자료 수집/정답 작성/학습 전달/평가는 구현했지만 실제 다섯 시점 차량 자료로 모델을 새로 학습한 것은 아닙니다. 파일 분류만으로 모델이 새로운 각도를 학습하지 않습니다.



고정 기능 평가표 `parking-goal-20-v1`은 20개 중19개 충족, 95%입니다. V26는75%, V27는85%였습니다. 이는 동일 가중치의 기능 수용 기준 개수이며 실차 인식률·완벽함·현장 배포 준비율이 아닙니다. 남은 R18은 실제 차량 외곽을 이용한 선침범/다중칸 점유 판정과 정답 대조입니다. 다섯 시점/천장 우선 요구는 추가 항목으로 따로 기록하며 기존 분모를 바꾸어 점수를 올리지 않았습니다.



## 2. 천장 우선 UI와 촬영 시점



- 기본 선택/첫 항목은 **천장**이고 수집량 표시도 천장이 먼저입니다. 오른쪽·왼쪽·위쪽·아래쪽은 보완 시점입니다.

- 위쪽/아래쪽은 주차장 평면에서 바라보는 방향이고, 천장은 위에서 내려다보는 설치입니다. 사용자 선택을 기록하며 yaw/pitch/roll 각도를 측정하거나 영상에서 정확한 설치 방향을 자동 추정하지 않습니다.

- 같은 주차장의 시점 변경은 기존 ROI·표시 장면·오래된 추론을 무효화합니다. 자동 수집 중 변경했다면 준비 시간 후 자동 등록을 다시 시도합니다. 등록/번호 작업의 늦은 결과가 새 시점을 덮어쓰지 않도록 기존 세대 토큰을 사용합니다.

- 저장·검수·복구 중에는 변경을 거부하고 선택 표시를 되돌립니다. 재시작 복구 중 조작도 현재 주차장/시점과 다르게 표시되지 않게 합니다.

- 시점별 구도 기준 파일을 분리합니다. 같은 시점이라도 실제 구도가 달라졌으면 ORB 대조가 이전 좌표 재사용을 막고 이름/주차선을 다시 등록합니다. 촬영 때 모든 칸 이름과 ㄷ자 경계가 확인되어야 자동 전칸 수집을 시작합니다.

- 같은 차량 배치를 여러 시점에서 촬영할 때 `batch_id`는 유지합니다. 차량 배치를 실제로 바꾸면 **새 촬영 배치**를 누릅니다. 재시작은 새 그룹으로 시작하므로 동일 배치의 중복 수집을 시험셋으로 섞지 않도록 새 배치를 구성하거나 그룹을 점검해야 합니다.

- UI는 범위별/시점별 장면 수·통과·보류 및 파일 오류를 표시합니다. 사람 정답이 있는 경우 시점별 점유/번호/색의 비교 수·일치율·보류를 보여줍니다. 정답이 없으면 자료 없음/null입니다. 범위를 바꾸거나 저장 내용을 갱신하면 오래된 평가 표시를 지웁니다.



## 3. 파일과 데이터 계약



```text

datasets/

  raw/A/천장/<사진ID>.png

  spaces/A/천장/A-01/<사진ID>.png

  stickers/천장/<사진ID>_A-01.png

  collected/A/천장/A-01/A-01__<시각>__<사진ID>.png

  collected/A/천장/A-01/A-01__<시각>__<사진ID>.json

  scenes/A/천장/A주차장__<시각>__<사진ID>.png

  scenes/A/천장/A주차장__<시각>__<사진ID>.json

  manifests/<사진ID>.json

  predictions/<사진ID>.json

  selection/<사진ID>.json

  reviews/<사진ID>.json

  capture_journal/<사진ID>.json   미완료 촬영의 복구 기록

  .writer.lock                   동시 쓰기 잠금 경로

```



raw의 A는 카메라 ID이고, collected/spaces/scenes의 A는 주차장 ID입니다. 카메라 한 대를 A/B 주차장에 옮겨 씁니다. B 주차장 또는 다른 시점에서는 해당 폴더가 바뀝니다. 번호·색은 차체색이 아닌 기존 스티커 배경색 흰색/초록/파랑입니다.



한글 라벨은 `촬영시점`, `촬영시점코드`, `촬영시점근거`, `촬영배치`, `품질선별`, 원본좌표·번호 정수/null·색·점유·원본/표시사진 상대경로·해시를 포함합니다. 사진에도 시점과 번호/색/품질 상태를 표시합니다. 원본과 학습 크롭에는 표시 글자를 그리지 않습니다.



기존 자료의 시점을 사진만 보고 임의로 추측하지 않습니다. `capture_view`가 없으면 미지정으로 읽고 기존 경로를 유지합니다. 새로운 시점 필드는 촬영 설정과 일치해야 하며 검수·복구·품질 판정에서 불변 촬영 문맥으로 대조합니다. D39 계약, 기존 prediction/collection/export 규격과 설치의 기본 pose 값을 제품 번호만으로 변경하지 않았습니다. 시점별 구도 구분에는 기본 pose에 `__view-ceiling` 같은 접미사를 붙입니다.



## 4. 품질 선별과 학습 내보내기



V27의 전칸/정보 완성/번호색 일관성/중복/해상도/선명도/노출 규칙을 유지합니다. 주차칸 짧은변32px, 스티커 짧은변16px, 라플라시안 분산60, 극단 암/명 픽셀 비율0.98은 초기 기본값입니다. 실제 천장 차량 자료로 보정한 수치가 아니며 모든 반사·가림·오인식을 걸러낸다는 뜻은 아닙니다.



장면 전체 통과는 전칸 등록과 각 칸의 판정 통과가 필요합니다. 한 칸이라도 점유/필요 번호·색이 미확인이라면 보류합니다. 스티커 근거 방식에서 스티커가 없는 칸은 빈칸으로 단정하지 않으므로, 점유 모델이나 확인된 빈 기준/사람 정답이 없으면 통과 장면이 적을 수 있습니다. 보류 원본도 보존합니다.



**품질 통과 자료 내보내기**는 정상 완성된 통과 장면의 원본·표시사진·한글 JSON을 복사합니다. **통과·승인 학습 내보내기**는 통과 장면의 사람 승인 라벨만 원본/무표시 크롭으로 전달합니다. 품질 통과를 자동 사람 승인으로 바꾸지 않습니다. 자동 후보만 있는 통과 장면은 학습 정답으로 내보내지 않습니다.



기존 전체 후보 전달과 승인 표시사진 전달도 가능합니다. 개발 API `export_training(..., selected_only=False)`는 종전 전체 승인 동작을 유지하나 UI 학습 내보내기는 `selected_only=True`를 사용합니다. 오래된 품질 미판정 자료는 통과 전용에서 제외되므로 **선택 장면 저장 복구**로 판정해야 합니다.



학습 내보내기는 호환성을 위해 작업/분할/클래스 폴더 구조를 유지하고 manifest의 각 샘플에 시점 정보를 넣습니다. 배치 단위로 분할하므로 같은 배치의 다른 각도 사진을 학습과 시험으로 흩뿌리지 않습니다. 미리 모아 둔 데이터가 모두 같은 배치라면 독립 시험셋을 확보한 것이 아닙니다. 다양한 실제 차량 배치를 별도로 수집해야 합니다.



## 5. 동시 쓰기와 재시작 복구



`dataset_lock.dataset_write`는 데이터 루트별 스레드 RLock과 운영체제 파일 잠금을 사용합니다. 같은 프로세스의 중첩 작업은 재진입하고 서로 다른 스레드는 순서대로 진행합니다. 다른 V28 프로세스가 같은 루트에 쓰는 중이면 새 쓰기는 사유를 표시하고 거부합니다. 다른 루트는 별도로 작업할 수 있습니다. 저장/검수/복구/자동 등록/내보내기/레거시 분석 등의 쓰기 경계에 적용했습니다.



잠금 파일은 정상 해제 후에도 삭제하지 않습니다. 프로세스가 강제 종료되면 OS가 잠금을 회수합니다. 파일 존재만으로 잠금 상태를 판단하지 않으며 수동 삭제할 필요가 없습니다. V27 이하 프로그램·외부 편집기·OneDrive가 이 잠금 규칙을 따르는 것은 아니므로 그런 작성자까지 차단한다고 보장하지 않습니다. 네트워크 파일시스템·클라우드 경쟁은 미검증입니다.



새 촬영은 원본 쓰기 전에 `capture-journal-v1`에 촬영 문맥·원본 예상 해시·예측 스냅샷을 기록합니다. 완성 후 복구 기록을 제거합니다. 최초 manifest 저장 실패 시에도 원본을 지우지 않습니다. 프로그램 시작/저장 폴더 변경 시 복구 기록이 있으면 I/O 작업자가 자동으로 확인합니다.



복구는 해시·크기·디코딩이 맞는 원본과 유효한 기록만 사용합니다. 기존 manifest가 다른 문맥이면 덮어쓰지 않고, 이미 저장된 예측/검수도 검증합니다. 예측 스냅샷이 실제로 남아 있는 경우에만 유실 예측을 복구합니다. 원본이 없거나 잘렸거나 필요한 예측이 없으면 복구 보류로 남기고 **오류 상세**에 이유를 표시합니다. 구버전의 문맥 없는 고아 사진은 임의 복구/삭제하지 않습니다.



## 6. 검증과 범위



정확한 시험 개수·중단 지점 수는 `TEST_RESULTS_V28.json`, `VALIDATION.json` 및 네 가지 fault 보고서에 기록했습니다. 실제 별도 프로세스를 종료하는 시험, 같은/다른 루트 쓰기 경쟁, 종료 후 잠금 해제, 복구 반복/원본 보존/예측 누락 보류를 포함합니다. SystemExit 및 os._exit 시험은 실제 디스크 정전/클라우드 동기화 검증과 다릅니다.



제공한 A/B 빈 주차장 사진의28개 ㄷ자 경계와 현재 저장/복사/이동 후 상대경로를 확인합니다. 사진 OCR은 V23 CPU 관측35회의 동일 입력 재사용이고 신규 OCR 실행은0회입니다. 다섯 시점 차량 인식 정답률, 실제 천장 카메라, 새 학습 모델, GPU/Geti/실서버, 장시간 수집은 이번 검증 대상이 아닙니다. Tk 시험은 창을 숨긴 자동 흐름 시험이며 실제 화면/DPI 육안 검수가 아닙니다.



## 7. 실제 수집·학습·발표 순서



1. 천장 설치 장비가 준비되면 높이·초점·노출을 고정하고 A12/B16의 모든 칸과 스티커가 읽히는 구도를 확보합니다. 준비 전 보완 시점에서 찍을 때는 실제 방향에 맞게 시점을 바꿉니다.

2. 차량 번호/색/칸/점유 조합과 차량 배치를 다양하게 바꾸며 자동 수집합니다. 같은 배치의 여러 시점 촬영은 같은 그룹으로 유지합니다.

3. 보류 사유를 보고 가림·반사·작은 스티커·흔들림을 수정해 재촬영합니다. 알 수 없는 값을 채우거나 품질 기준을 낮추는 것으로 수집 성과를 만들지 않습니다.

4. 사람 정답을 작성하고 통과·승인 학습 크롭을 내보낸 뒤, 실제 데이터로 모델을 학습하여 프로그램에 연결합니다. 모델 파일 없이 수집 프로그램 변경만으로 딥러닝 재학습이 완료되지는 않습니다.

5. 학습에 쓰지 않은 새 차량 배치를 천장 조건에서 시험하고, 보완 네 시점도 따로 평가합니다. 비교 수·일치 수·보류 수를 함께 발표합니다. 전체 평균만으로 성능이 약한 시점을 숨기지 않습니다.



평가셋은 운영 조건을 대표해야 한다는 [Google의 데이터 분할 안내](https://developers.google.com/machine-learning/crash-course/overfitting/dividing-datasets), 같은 그룹의 분리를 방지하는 [scikit-learn 그룹 분할](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupShuffleSplit.html), 대표성 있는 라벨 자료로 학습하는 [Geti 안내](https://docs.geti.intel.com/docs/user-guide/quick-start/training-your-first-model)를 참고한 수집 운영안입니다. 위 UI/파일 동작은 해당 외부 도구가 대신 구현하는 것이 아니라 이 프로젝트의 코드로 구현했습니다.
