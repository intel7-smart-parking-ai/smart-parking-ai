# V51 ArUco 설치·수집 안내



마커를 기준으로 실물 주차칸 좌표를 등록하고, 분석할 때마다 현재 프레임에서 좌표를 갱신합니다.



마커가 주차칸과 겹치면 등록을 보류합니다. 좌표를 검증한 뒤 활성 기준을 저장합니다.



두 대를 쓸 때 마커 번호는 **카메라 이름이 아니라 실제 주차장** 기준입니다. A주차장 0–5, B주차장 10–15입니다. 두 카메라가 같은 보드를 보더라도 각 영상의 실제 ROI로 따로 등록합니다. 카메라 2 기준은 데이터 루트의 camera_alignment/B 아래에 저장합니다.



## 1. 출력과 부착



1. UI의 **마커 인쇄·배치 안내** 또는 인쇄 파일 (`PRINT_MARKERS.html`, 별도 보관 이력)을 엽니다. A4 세로, 100%, 머리글/바닥글 끄기로 출력합니다. 검은 정사각형의 한 변이 48mm인지 자로 확인합니다. 흰 여백까지 포함하면 64mm입니다. 이는 시작용 크기이며 실제 촬영 높이에서의 검출 보장값이 아닙니다. 충분히 크게 보이지 않으면 더 크게 출력해야 합니다.

2. **A주차장에는 ID 0~5, B주차장에는 ID 10~15**를 사용합니다. 사전은 `DICT_4X4_50`입니다. 다른 사전의 같은 숫자는 같은 마커가 아닙니다. 한 주차장에 같은 ID를 두 번 붙이지 않습니다.

3. 각 판의 외곽 네 모서리에 4개, 양쪽 중간에 2개를 분산 배치하는 것을 권장합니다. 처음 등록할 때는 6개 모두 보이게 하면 좋습니다. 최소 4개가 필요하며 검출 마커의 외곽이 모든 주차칸을 둘러싸야 합니다. 기준을 만들 때 보이지 않았던 ID는 나중에 계산에 추가하지 않으므로, 추가 마커를 설치했으면 기준을 다시 등록합니다.

4. 마커는 **주차면과 같은 높이의 단단한 평면**에 고정합니다. 칸 내부/번호 스티커 위에 붙이지 않고, 흰 여백을 남깁니다. 별도 받침을 쓴다면 보드와 같은 높이에 고정합니다. 마커만 따로 움직이거나 판이 휘면 기준을 다시 등록해야 합니다. 반사 코팅·접힘·큰 렌즈 왜곡도 오차 원인이 됩니다.



마커를 어느 ID부터 어느 모서리에 놓을지는 자유입니다. 처음 등록한 실제 위치와 방향을 기억합니다. 이후 ID와 위치의 관계를 유지하세요. A/B 주차장 선택은 사용자가 하며 다른 주차장 ID가 섞이면 보류합니다.



## 2. 처음 한 번 등록



**권장 자동 흐름**



1. 차량이 없는 판을 준비하고 모든 칸 이름·ㄷ자 주차선·마커가 선명하게 보이게 촬영합니다.

2. A 12칸 또는 B 16칸, 현재 촬영 시점을 선택하고 **자동 수집 시작**을 누릅니다. 사진이면 **사진 자동 등록·수집**을 사용합니다.

3. 처음에는 기존 이름/주차선 인식으로 전체 ROI를 만듭니다. 올바른 마커가 4개 이상 함께 보이고 배치 조건을 만족하면 마커 기준도 자동 저장합니다. 이미 검증된 같은 구도 기준이 있는 경우에도 마커 기준 등록을 시도합니다.

4. 화면의 모든 칸 경계와 명칭이 실제 판과 맞는지 확인하세요. 최초 등록이 잘못되면 이후 마커가 그 잘못된 ROI도 그대로 옮기므로 이 확인은 중요합니다.



**자동으로 전체 칸을 못 찾는 경우**



수집 정지 → **고급/수동 설정 → 사진 열기 또는 카메라 연결 → ROI 네 모서리**에서 A 12칸/B 16칸을 정확히 지정 → **현재 ROI를 마커 기준으로 등록**. 저장된 장면 재열기 상태에서는 새 기준을 만들지 않습니다. 현재 마커로 이미 투영한 ROI를 새 기준으로 재등록하는 것도 막습니다. 실제 선 기준의 ROI를 새로 지정하세요.



계산 ROI는 네 꼭짓점으로 닫힌 영역을 사용하지만, 자동으로 검출한 ㄷ자 ROI는 **실제 선 3면과 가상 입구를 따로 유지**합니다. 손으로 입력한 네 점에는 실제 어느 세 면에 선이 있는지 근거가 없으므로 자동 ㄷ자 검출 근거를 만들어 붙이지 않습니다.



## 3. 이후 수집



같은 카메라·해상도를 사용하고 자동 수집을 시작하면 **등록된 마커 → 현재 칸 좌표 → 번호/스티커색/점유 → 품질 검사 → 저장**으로 진행합니다. 매 분석 프레임마다 좌표를 계산합니다. 칸 이름 OCR을 매번 재등록에 사용하지 않아 구도 변경과 이름 가림에 대한 반복 작업을 줄입니다. 차량 번호 OCR은 계속 필요합니다.



- 처음에는 **천장** 시점을 우선합니다. 다른 시점으로 카메라를 옮긴 뒤 실제 방향을 선택하세요. 시점을 바꾸어도 같은 차량 배치의 그룹은 유지합니다.

- 기준 마커가 **3개 이상 넓게 분산되어 보여야** 합니다. 세 개가 모두 한쪽에 몰리면 개수가 충족되어도 보류합니다. 이는 이 프로그램의 품질 조건이며 ArUco 자체의 보편적인 최소 검출 개수가 아닙니다.

- 검출 마커의 짧은 변이 **20px 이상**, 전체 대응점 최대 오차 **3px 이하**, 한 마커를 빼고 나머지로 예측한 최대 오차 **5px 이하**여야 합니다. 초기 보수적 기준이며 실제 정확도를 보증하는 수치가 아닙니다.

- 중복/다른 판/처음 기준에 없는 ID, 이동한 개별 마커, 부족한 분포, 영상 밖 칸, 겹친/뒤집힌 ROI, 카메라·해상도 변경은 보류합니다. 잘못된 마커 하나를 버리고 나머지만 통과시키지 않습니다.

- 자동 수집 중 마커가 부족하면 분석/저장을 중지하고 사유를 표시하며 5초 후 재시도합니다. 마커가 다시 보이면 같은 기준으로 재개합니다. 부족한 상황에서 과거 좌표나 과거 구도 기준으로 자동 후퇴하지 않습니다.

- 번호/색/점유/화질이 미확인인 장면은 기존대로 후보·품질 보류 자료로 저장될 수 있습니다. **마커 좌표 자체가 불확실한 프레임은 저장 단계까지 보내지 않습니다.**



자동 수집은 모델이 있으면 점유 분류, 없으면 스티커 근거 모드를 사용합니다. 마커가 있다고 빈칸을 자동 확정하지 않습니다. 수동으로 빈 기준 비교 모드를 선택한 상태에서 카메라가 움직이면 이전 빈 기준은 다른 좌표이므로 무효가 되어 판정이 보류될 수 있습니다. 새 빈 기준을 등록하거나 검증된 점유 모델을 사용하세요.



## 4. 저장과 내보내기



데이터 루트 안의 `marker_boards/A.json`, `marker_boards/B.json`에 각각 현재 기준을 저장합니다. 기준 사진은 `marker_boards/references/<기준해시>.png`에 별도 보존합니다. 기준 사진을 먼저 완성하고 마지막에 JSON을 원자적으로 교체합니다. 중단 때문에 남은 참조되지 않는 사진은 자동 삭제하지 않습니다.



각 촬영 manifest의 `roi.marker_evidence`에는 기준 ROI/마커/기준해시, 현재 마커 ID·모서리, 변환행렬, 오차 수치, 프레임 번호·시각·연결구간·원본 픽셀 SHA256을 보존합니다. 이 복사본으로 과거 자료를 검증하므로 나중에 현재 기준 파일을 바꾸거나 옮겨도 이미 저장된 장면의 근거가 바뀌지 않습니다. 현재 기준이 없으면 새 마커 촬영은 시작할 수 없습니다.



칸별 한글 JSON에는 **마커등록근거**로 ID 목록, 검출수, 좌표, 행렬, 두 오차, 기준해시와 원본 픽셀 해시를 기록합니다. 전체 표시사진에는 마커 외곽과 ID도 표시합니다. 사진의 검토용 표시는 학습 원본에 덧그리지 않습니다. ㄷ자 선 지지비율은 **최초 기준 장면에서 측정한 값**임을 별도로 적습니다. 현재 선을 다시 측정했다는 의미가 아닙니다.



기존 `collected/<주차장>/<시점>/<칸명>/`과 같은 이름의 사진·JSON, `scenes/`의 통합 장면, `raw/`의 무표시 원본을 유지합니다. UI의 내보내기 완료 수량도 기존과 동일하게 장면/칸별 짝/이미지/JSON으로 집계합니다. 기준 등록 파일은 촬영 장면 수나 학습 샘플 수로 세지 않습니다.



**새 촬영도 다른 PC에서 계속할 때**는 데이터 루트 전체와 `marker_boards`를 함께 복사하세요. 수집 결과 내보내기는 검토/학습 자료 전달용입니다. 사진 가져오기용 `IMPORT` 기준을 실제 카메라 기준으로 재사용할 수 없으며 카메라/해상도가 바뀌면 실제 새 입력으로 다시 등록해야 합니다. 이전 측정 자료는 기존 데이터 루트에서 열 수 있습니다.



## 5. 인식 성능과 남은 현장 검증



ArUco는 평면의 기준점을 제공하며, 주차장 좌표를 다른 화면으로 연결하는 데 사용합니다. 보정된 내부 파라미터 없이 실제 카메라 기울기 각도를 측정했다고 표시하지 않습니다. [OpenCV 마커 검출](https://docs.opencv.org/5.0/tutorials/objdetect/aruco_detection/aruco_detection.html)



바닥보다 높은 차량/스티커에는 시차가 생길 수 있습니다. 바닥 평면 변환으로 차량 외곽 침범이나 가려진 번호를 해결할 수 없습니다. 렌즈 왜곡·보드 휘어짐·롤링셔터·심한 기울기는 실제 사진으로 확인해야 합니다. [OpenCV 평면 변환](https://docs.opencv.org/5.0/tutorials/features/homography/homography.html)



합성 평면·마커 기준 등록 중단 시험의 과거 결과를 참고할 수 있습니다. 실제 인쇄 마커를 부착한 두 주차장에서의 등록 성공률과 시간 단축률은 현장 검증 항목입니다. [마커 시험 결과](ARUCO_VALIDATION_V35.json)



1. 실제 인쇄 후 ID 검출, 가장 먼 마커 크기, 모든 칸 모서리와 표시선 일치.

2. 천장 고정 촬영에서 번호/스티커색/점유를 사람 정답과 비교.

3. 마커 1개 가림과 2개만 보임, 개별 마커 이동 시 정상 보류/재개.

4. 실제 차량 높이를 포함한 옆 시점의 칸 귀속, 왜곡, 번호 크기와 선명도.

5. 기존 방식 대비 최초 등록 시간·구도 변경 후 재개 시간·수동 개입 횟수. 전체 FPS는 OCR·모델·카메라·저장 장치까지 포함해 따로 측정.
