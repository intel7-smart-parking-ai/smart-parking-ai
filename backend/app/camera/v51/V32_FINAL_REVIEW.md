# V32 수집·저장·내보내기 심층 검수



2026-11-05. V31을 보존하고, 격리된 시험 데이터에서 재현한 **네 가지 오류 경로를 수정한 V32**입니다. 실제 사용자 촬영 파일에서 오류가 발견됐다는 뜻은 아닙니다. 정상 흐름뿐 아니라 잘못된 메타데이터·공유 파일·마커 배치·검사 실패 상황을 만들어 확인했습니다.



## 1. 재현한 문제와 수정



| 문제 | V31 재현 결과 | V32 처리 |

|---|---|---|

| 한글 JSON 값과 원래 근거의 연결 누락 | 번호 표기는 미확인인데 숫자 번호23, 사람검수완료true, 정보완성true로 바뀐 JSON을 전체/칸별 양쪽에 넣고 파일 해시를 갱신하면 완료 자료로 읽고 내보냄 | 저장 예측과 재검증한 사람 정답에서 기대값을 다시 계산하여 대조. 값뿐 아니라 정수/실수/불리언도 구분 |

첫 문제는 무작위 파일 손상을 주장한 것이 아닙니다. V31에도 파일 해시, 사진/JSON 연결, 핵심 품질 라벨 지문이 있었습니다. 그 지문에 포함되지 않은 **숫자형 번호·사람 승인 여부·정보완성 표시**와 일부 안내 수치가 일관되지 않더라도 별도의 근거 대조가 빠져 있음을 재현했습니다. 기존 번호 문자열/색을 바꾸는 시험은 기존 품질 지문 검사에서 거부되었고, 그 검사를 우회하는 가정을 붙여 오류를 꾸미지 않았습니다.



네 재현은 [V31_REPRODUCTIONS.json](V31_REPRODUCTIONS.json)에 기록했습니다. 작업 폴더 `verification_v32/reproduce_v31.py`는 배포된 V31을 읽되 시험 데이터는 별도 임시 폴더에만 작성합니다.



## 2. 수집에서 저장까지의 흐름



현재 실행 경로는 `run_windows.bat → main.main → Dashboard`입니다. 카메라 한 대와 A12/B16, 천장 우선/다섯 시점, D39 번호와 흰색·초록·파랑 **스티커 배경색**이라는 방향을 유지합니다. B는 사선/ㄷ자 실제 세 면과 가상 입구를 구분합니다.



자동 등록은 기존 마커 기준이 있으면 그 기준을 검사하고 현재 프레임의 칸 좌표를 계산합니다. 기준이 없으면 주차선/이름 인식 또는 사람이 확인한 전체 ROI에서 최초 기준을 만듭니다. 마커 ID는 A0~5/B10~15, 처음 최소4개·추적 최소3개와 충분한 분산, 크기/오차/전체 ROI 기하 조건을 유지합니다. 마커가 부족하거나 배치가 맞지 않으면 과거 좌표로 저장하지 않고 보류/재시도합니다.



V32는 마커 검정 영역이 주차칸 내부와1픽셀²를 넘게 겹치면 거부합니다. 수치상 테두리만 닿는 것은 내부 침범으로 계산하지 않습니다. 인쇄 흰 여백·설치 오차까지 고려하여 실제로는 충분히 떨어뜨려 배치해야 합니다. 마커를 차량 스티커/점유 학습 영역 안에 포함하지 않기 위한 검사입니다.



`marker_setup.enroll`은 기준 구성과 검증, 실제 `locate` 경로의 전체 성공을 먼저 확인합니다. 그 뒤 참조사진을 저장하고 활성 기준 JSON을 원자적으로 교체합니다. 처음 등록 실패 시 활성 파일이 생기지 않고, 재등록 실패 시 기존 활성 기준과 참조사진 목록을 유지하는 것을 시험했습니다. 디스크 쓰기 실패·저장 중단 시에도 이전 계약을 지킵니다.



분석용 작업자는 원본 `FramePacket`에 대해 새 ROI를 계산하고 작업 token도 같은 ROI로 바꿉니다. 번호 OCR·화면·저장이 해당 프레임과 ROI를 함께 전달받습니다. 프레임 번호/시각/연결구간/픽셀 SHA256을 확인하며, 주차장/시점 변경이나 마커 소실 후 도착한 오래된 분석은 버립니다. 이 V31 경로를 V32의 전체 회귀에서 다시 확인했습니다.



번호/색/점유 판독 알고리즘과 품질 수치는 이번 버전에 맞춰 임의로 완화하지 않았습니다. 마커 성공이 번호 정답이나 빈칸 확정을 의미하지 않습니다. 모델이 없으면 스티커 근거 후보를 사용하며, 원본과 후보·사람 승인을 분리합니다.



## 3. 사진·JSON·승인 근거 검증



`collection_output.expected_scene_labels`는 저장된 예측과 사람이 편집할 수 있는 정답 필드를 읽습니다. 검수 행은 현재 원본/칸/운영번호 규칙으로 다시 검증한 다음 표시값을 계산합니다. 저장 검수 파일의 파생 필드만 그대로 믿어 값을 만들지 않습니다.



핵심 대조 항목은 점유, 숫자형 번호, 번호 표기, 스티커색, 차량종류, 번호/스티커 좌표, 사람검수완료, 라벨출처, 자동정보완성입니다. 판독 상태·점유/번호 점수·화질·전용칸 비교·위치 경고 등 안내 값도 해당 필드가 있으면 대조합니다. 과거 유효 자료에 없던 부가 안내 항목은 무조건 필수로 만들어 막지 않습니다.



`validate_collection_label`은 칸별 JSON과 전체 장면의 각 칸을 모두 검사합니다. 정수23과 실수23.0, 불리언false와 정수0도 서로 다른 형식으로 판단합니다. 사진ID·주차장·칸·배치·시각·경로/해시·마커 근거 등 기존 연결 검사도 유지합니다.



`read_collection`의 검증 경로, UI의 `DatasetIndex`, 전체 후보 전달과 품질 선별/학습 전달에서 이 대조를 사용합니다. 잘못된 값을 정상 정보완성 수량이나 정상 사진/JSON 쌍으로 계산하지 않습니다. 원래 예측·검수·원본이 정상이면 **선택 장면 저장 복구**가 그 근거로 파생 사진/JSON을 다시 만듭니다. 없는 원본이나 없는 예측을 새로 추정해 채우지 않습니다.



기존 저장 흐름은 `persist_scene → save_capture`에서 최초 저장 저널·원본·촬영 manifest를 만들고, 칸 크롭/예측/표시사진/한글 JSON/품질 결과를 연결합니다. 수정 전에 pending을 기록하며 완료 영수증으로 마무리합니다. 원본은 덮어쓰지 않고, 재저장은 같은 장면의 원본 픽셀을 대조합니다. 복구·검수·내보내기는 같은 데이터 루트의 OS 잠금을 유지합니다.



## 4. 실제 파일 수량과 내보내기



`export_collection`은 정상 원본·촬영 기록·예측·검수·품질·한글 JSON·파일 해시를 대조한 뒤 목적지로 복사합니다. 실패한 원본 장면은 제외 사유를 기록하고, 목적지 쓰기 도중 오류는 전체 내보내기 실패로 처리합니다. `ExportTransaction`의 파일목록/해시 재검사와 완료 상태가 끝나야 UI에 완료 수를 알립니다.



V32는 복사 동작 횟수 대신 **목적지의 고유 경로**로 원본/이미지/데이터 JSON 수량을 계산합니다. 동일한 픽셀이어도 경로가 다른 두 파일은2개입니다. 반대로 두 장면이 같은 파일을 공유하면 원본은1개입니다. 장면 수와 칸별 사진/JSON 짝은 관측 자료 수이므로 두 장면을 그대로 보존합니다.



저장 UI의 집계도 **촬영장면 / 원본 파일**을 따로 표시합니다. 검증된 파일 경로별로 크롭·표시사진·JSON 수를 계산하고, 이미지 바이트를 중복 합산하지 않습니다. 캐시를 재사용하는 두 번째 집계에서도 같은 결과가 나오는지 시험했습니다. 데이터 루트에 방치된 미참조 파일이나 내보낸 복사본까지 본 수집 자료 수로 더하지 않습니다.



품질 통과 전달은 현재 품질 기준을 충족해야 하며, 학습 전달은 사람 승인도 필요합니다. 표시사진은 검토용이고 학습에는 무표시 원본/크롭을 사용합니다. 동일 배치의 시점을 같은 분할에 유지하는 조건과 동일 원본의 분할 누수 차단도 유지했습니다. 내보내기는 원본 삭제가 없는 복사입니다.

과거 마커 기준에 칸 내부 마커가 포함되어 있다면 보류될 수 있습니다. 마커를 칸 밖 같은 평면에 옮긴 뒤 실제 선으로 전체 ROI를 확인하고 기준을 다시 등록하세요. 저장된 과거 좌표를 임의로 바꾸지는 않습니다. 번호·승인 등 JSON 근거 불일치는 원본 예측/검수부터 확인해야 합니다.



## 7. 남은 현장 확인



카메라 하드웨어와 실제 인쇄 마커, 현행 D39 차량의 천장/여러 시점 자료가 없어 실제 번호·색·점유 정확도와 시간 절감률은 미측정입니다. 평면 변환은 높은 차량의 시차·가림·렌즈 왜곡·휘어진 보드를 해결하지 않습니다. 차량 외곽을 이용한 선침범 확정 모델과 새 딥러닝 학습도 아직 없습니다.



실장비 장시간 연속 수집, 실제 정전·OneDrive 경쟁, GPU/Geti/실서버, 실제 인쇄 크기와 육안 UI는 이번 검증 범위에 포함되지 않습니다. 소프트웨어 시험에서 확인한 범위와 현장 조건을 구분하여 자료 수집을 진행해야 합니다.
