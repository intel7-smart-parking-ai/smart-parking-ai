# V27 자동 품질 선별·통과 자료 내보내기 심층 검수



V26 → V27. V26는 화질 수치를 참고용으로 저장했지만 자동 품질 통과/보류와 통과 전용 전달 경로가 없었습니다. V27는 두 기능을 추가했습니다. 고정 평가표 20개 중 17개 충족으로 기능 구현율 85%입니다. 실차 정확도·완벽함·실사용 준비율을 뜻하지 않습니다.



## 실제 변경과 흐름



1. 기존 입력 → 전칸 등록 → 점유/번호/색 후보 → 원본 저장 흐름을 유지합니다.

2. `render_collection`이 승인된 사람 값 또는 자동 후보로 한글 라벨을 만든 뒤 `quality_selection.evaluate`를 호출합니다.

3. A12/B16 전칸 등록, 입력 출처, 점유 확인, 점유 차량 번호·스티커색·영역, D39 번호/색 일관성 및 중복, ROI 내부 화질을 검사합니다. 전용칸 불일치 경고 자체는 불량 사진 사유가 아니므로 위반 사례도 수집 가능합니다.

4. 한 칸이라도 보류되거나 전칸이 없으면 장면은 보류입니다. 보류 자료도 원본·사진·JSON을 저장합니다. 통과라고 사람 승인 정답으로 바꾸지 않습니다.

5. `selection/<사진ID>.json`에 한국어 사유·수치·정책·입력 지문을 저장합니다. `bundles`가 판정 파일 SHA256을 기록합니다. 칸별/전체 JSON에는 `품질선별`을 내장하고 사진에 선별 상태를 표시합니다.

6. 원본 해시·촬영/ROI 문맥·정책·예측/검수 지문·라벨 근거를 연결합니다. 판정 또는 라벨이 오래됐거나 손상됐으면 선별 통과를 재사용하지 않습니다. DatasetIndex의 캐시 서명에도 판정 파일을 포함합니다.

7. `품질 통과 자료 내보내기`는 정상 완성 묶음 중 현재 통과 장면만 복사합니다. 보류/미판정/손상은 사유와 함께 제외합니다. 기존 모든 후보 내보내기와 승인 학습 크롭 내보내기는 별도 유지합니다.

8. 검수를 저장하거나 장면을 복구하면 재판정합니다. 기존 기록의 촬영 당시 정책을 사용하므로 새 config를 바꾸어 과거 기준을 몰래 바꾸지 않습니다.



## 초기 수치 기준



| 설정 | 기본값 | 의미 |

|---|---:|---|

| min_bay_short_side | 32 | 주차칸 영역 최소 짧은 변, px |

| min_sticker_short_side | 16 | 스티커 영역 최소 짧은 변, px |

| min_sharpness | 60 | 내부 라플라시안 분산 최소값 |

| max_dark_ratio | 0.98 | 명도40 미만 픽셀 비율 최대값 |

| max_bright_ratio | 0.98 | 명도245 초과 픽셀 비율 최대값 |



측정은 원본 다각형 내부를 사용하고 테두리/흰색 크롭 여백을 제외합니다. 수치는 초기 휴리스틱이며 실제 D39 데이터로 보정하지 않았습니다. 흰 스티커·어두운 바닥을 단순 밝기만으로 무조건 배제하지 않도록 극단 노출 기준을 사용합니다. 점수가 있다고 모든 반사·초점·가림 문제를 검출한다는 뜻은 아닙니다. 사진마다 threshold를 임의 조정해 통과율을 올리는 것은 정확도 개선이 아닙니다.



## 실제 검증



- 누적 286개 회귀시험 통과, 실패/오류/건너뜀 0개. V27 추가 27개이며 새 규칙·저장·판정 변경·보류 제외·UI 작업자 경로를 포함합니다.

- 최초 저장17, 재저장17, 검수13, 전체 후보 내보내기10, 승인 학습6, 승인 표시7, 통과 내보내기30: 총100지점의 쓰기 직후 SystemExit 중단 시험 통과. 실제 정전/OneDrive 동시 쓰기 시험은 아닙니다.

- 생성한 A12 기준 영상에서 자동 빈칸 후보만으로 통과·내보내기 작동을 확인했습니다. 사람 검수 파일을 생성하지 않았습니다. 생성 시험 영상이므로 실측 인식 정확도로 계산하지 않습니다.

- 제공한 A12/B16 사진은 총28개 ㄷ자 좌표·원본 보존·표시사진/JSON·다른 경로의 파일 연결을 확인했습니다. 숫자/색/점유 미확인은 그대로 유지하고 두 장면 모두 품질 보류, 통과 내보내기0개입니다.

- 사진 OCR은 V23에서 실행한 실제 CPU 관측35회를 동일 픽셀/옵션으로 재사용했고 이번 신규 OCR은0회입니다. 신규 모델 성능 시험이 아닙니다.

- V21/V23/V24/V25/V26 기존 데이터849파일과 V26 배포 소스199파일·ZIP 해시를 보존했습니다. 기존 데이터에 자동 일괄 변환을 수행하지 않았습니다.

- Tk 창을 숨긴 상태에서 통합 동작을 시험했습니다. 실제 사용자 화면/DPI를 육안 확인한 것은 아닙니다.



## 기존 데이터와 사용법



새 폴더에 V27를 풀고 `run_windows.bat`를 실행합니다. `저장 폴더 선택`으로 과거 데이터 루트를 지정할 수 있습니다. 기존 원본·ROI·계약·설치 pose·한글 라벨/collection/export 규격은 바꾸지 않았습니다. 품질 판정은 별도 `주차품질선별-v1` 파일과 선택 필드로 추가했습니다.



이전 묶음은 정상 읽기와 전체 후보 내보내기가 가능합니다. 판정이 없으면 미판정이며 통과 전용에서는 제외합니다. 필요 장면을 열고 `선택 장면 저장 복구`하면 보존된 근거로 판정과 표시사진을 다시 만듭니다. 원본이나 필수 예측이 유실된 경우에는 먼저 해당 근거를 복구해야 합니다.



품질 통과는 사람 정답 승인과 별개입니다. 학습 정답용 내보내기는 기존 승인 절차를 사용하세요. 내보낸 폴더 전체와 `EXPORT_STATUS.json`을 전달합니다. UI의 데이터 JSON 수량은 내보내기 결과/상태 보조 JSON을 제외합니다. 원본은 삭제하지 않습니다.



## 남은 개발과 검증



고정 평가표 R19(프로세스 간 동일 데이터 쓰기 충돌 방지), R20(최초 저장 프로세스 종료 후 재시작 복구)을 다음 수정에서 진행합니다. 현재 같은 데이터 루트를 여러 프로그램으로 동시에 쓰지 마세요. R18(차량 외곽 기반 선침범/다중칸 위반)은 실제 차량 외곽 근거와 정답 평가가 필요합니다.



현재 자료만으로 차량 번호·스티커색·점유·위반의 현장 정확도는 산출할 수 없습니다. 현행 D39 차량 정답사진, 실제 카메라, 학습 모델, GPU/실서버/Geti, 장시간 촬영/실제 정전/클라우드 동기화는 이번 미검증입니다. 85%는 고정된 기능 체크리스트 점수이며 85% 인식 성공률이라는 뜻이 아닙니다.
