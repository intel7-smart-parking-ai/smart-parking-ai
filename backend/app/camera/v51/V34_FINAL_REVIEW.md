# V34 코드 검수 — 두 RealSense의 동시 측정



기존 V33은 카메라 허브가 여러 장치를 열 수 있어도 기본 UI가 첫 번째 장치만 선택했습니다. V34는 **한 허브가 서로 다른 두 시리얼을 각각 한 번 열고, 한 측정에 속하는 두 원본을 함께 분석·저장**합니다. 기본 배치는 1번 A주차장 12칸, 2번 B주차장 16칸입니다. 주차장·시점은 각각 선택할 수 있습니다.



## 장치와 측정 시각



[통합 UI](dual_dashboard.py)는 실시간 영상 두 개, 카메라별 칸 판독표, 마커 기준 등록, 품질과 저장/복사 수량을 표시합니다. [측정 로직](dual_capture.py)은 실제 입력의 채널 ID·시리얼·연결 구간·프레임과 수신 시각을 검사합니다. 기존 장치가 사라졌을 때 다른 시리얼을 그 카메라로 자동 대체하지 않습니다.



두 프레임 모두 **시작 이후의 새 관측**이어야 합니다. 선택 시 1초를 넘긴 영상, 이미 사용한 한쪽 프레임, 서로 다른 시리얼이 아닌 경우, 수신 시각 차이 초과는 보류합니다. 기본 허용 차이 100ms는 운용 설정값입니다. 공통 PC의 단조 시계로 수신 차이를 계산하며 **하드웨어 트리거나 센서 노출 동기화를 구현한 것은 아닙니다**. 분석과 디스크 기록에 걸린 시간으로 두 사진을 짝짓지 않습니다.



## 인식과 저장



- 각 카메라 분석은 별도 작업 스레드에서 수행합니다. 칸·번호·스티커색 규칙은 V33 것을 사용합니다. 카메라 2의 마커/구도 기준은 별도 경로이며, 같은 주차장이라도 카메라 1의 기준을 덮어쓰지 않습니다. CPU/GPU OCR 모델은 두 벌 올리지 않고 읽기 호출만 순서대로 수행합니다. 두 장치의 영상 수신은 계속됩니다. 실제 처리 FPS 증가율은 측정하지 않았습니다.

- 양쪽 ROI·예측이 준비된 경우에만 [저장 함수](dataset19.py)에 전달합니다. 저장 전 측정 명세를 pending으로 기록하고, 두 원본·표시 사진·한글 JSON 및 장면 기록이 완성된 뒤 complete로 마감합니다. 저장 중단 후에는 유효한 원본이 있는 것만 검증합니다. 한 장만 살아 있는 측정은 학습/완료 짝 전달에서 제외하며 이전 원본은 보존합니다.

- [사진 내보내기](collection_output.py)는 양쪽의 묶음과 품질 조건을 먼저 검사하고, 복사본의 파일 목록과 해시를 확인합니다. 한쪽 입력 자료가 손상되면 해당 측정을 제외하고, 복사 도중 목적지 오류는 전체 내보내기 실패입니다. 최종 결과에는 측정 ID별 두 멤버와 실제 수량이 남습니다. 학습은 사진 짝의 완료 여부 외에 기존 품질·검수·분할 누수 검사도 유지합니다.

- 각 촬영 manifest의 `analysis_config.dual_measurement`와 동시측정 명세에 관계를 기록합니다. 전체·칸별 한글 JSON은 `동시측정ID`, `카메라ID`, `카메라시리얼`, `두프레임_수신차_ms`를 포함합니다. 옛 자료에는 이 값을 강제로 채우지 않습니다. 데이터 원본·기존 D39 규칙·설치 pose·품질 판정 revision은 변경하지 않았습니다. 새 동시측정 자료의 복구/전달에는 V34를 사용하세요.

## 장비 연결 후 확인할 사항



실제 SDK 장치 조회에서는 기존 **D435 한 대**가 나왔습니다. 실제 두 카메라의 동시 촬영, USB 안정성, 지속 수집 속도, 천장 높이에서 D39가 붙은 차량의 번호·스티커색 정답률은 미측정입니다. V33의 19/20(95%)은 당시 단일 카메라 기능표의 수치로, 이번 두 카메라의 성공률이 아닙니다.



현장에서는 두 대의 시리얼과 구도를 미리보기에서 확인하고, 실제 한 쌍을 저장하여 각 표의 주차장·칸·번호·색을 사람 정답과 대조하세요. UI에 나온 수신 차이와 품질을 함께 기록한 뒤 수집량을 늘리는 것이 다음 단계입니다. 차량 외곽에 근거한 오주차 확정과 새 딥러닝 학습은 이번 변경에 포함하지 않았습니다.
