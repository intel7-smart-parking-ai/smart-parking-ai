# V49 문제별 진단과 수정 결과



V48의 단독·두 카메라 촬영, 보정·판독, 수집 저장, 검수 이력, 복구, 학습·CSV 내보내기, 현장 보고서까지 따라가며 같은 데이터가 단계마다 어떻게 처리되는지 대조했다. 현장 정확도, 실제 장시간 안정성, Geti 학습 효과는 별도 시험 항목으로 남긴다.



## 확인한 문제와 조치



| 항목 | V48에서 확인한 문제 | V49 동작과 검증 |

|---|---|---|

| 1. 단독 촬영의 복구와 자료 전달 | 같은 장면의 두 판독 기록이 다르면 복구는 보류됐지만, 단독 촬영의 학습·수집·승인·CSV 내보내기와 감사는 그 장면을 계속 사용했다. 보류 중인 승인도 수정할 수 있었다. | 복구 기록이 남은 단독 촬영을 모든 전달 경로에서 제외한다. 원본과 기존 승인 이력을 보존하며 검수 저장을 막는다. 같은 사례에서 수집 장면 1→0, 학습 크롭 3→0, 검수 결과 1→0, CSV 칸 2→0, 감사 번호 비교 1→0이었다. 시험 복사본의 정상 기록을 복구하면 다시 1장면·3크롭이 전달됐다. |

| 2. 가상선 내부 재판독과 번호 근거 | 최초 검사에서 번호를 찾지 못하고 좁은 영역에서 복수 스티커가 보이거나 같은 위치에서 서로 다른 번호가 읽히면 후속 근거가 사라질 수 있었다. 저장된 OCR에서는 선택된 숫자 상자만 스티커 안에 있어도 다른 위치의 판독을 합의 근거로 받아들였다. | 재판독의 복수·충돌 근거를 보존한다. 직접 번호에 합의한 영상들의 숫자 영역이 같은 스티커에 속하는지 확인한다. 보류된 칸에 선택 번호 근거가 남거나 추정 상태에 추정값이 빠지면 기록을 거부한다. 강제 충돌 회귀와 실제 OCR 사진 재생을 분리해 시험했다. |

| 3. 반사·과노출 진단 | 저장된 진단에서 픽셀 포화율·대비와 ‘정상/포화’ 상태가 모순돼도 형식 검사를 통과했다. | 진단 생성·읽기가 같은 수치 판정식을 쓴다. 완전히 포화된 테스트 영상의 상태를 정상으로 바꾼 기록을 거부했다. 기존 사진을 밝힌 초록 11은 보류했다. 흰색 66/99의 16개 방향·모드 조합은 색만 남기고 번호를 보류했다. |

| 4. 가상 배치가 포함된 현장 점수 | 가상 차량만 있는 정답표에서 번호·색이 맞으면 실물 점유를 포함한 종합 지표가 100%가 됐다. 빈 가상 구역에서 스티커를 관측하면 실제 빈칸의 오점유처럼 집계될 수 있었다. 같은 JSON 필드를 두 번 쓴 정답표도 마지막 값으로 처리됐다. | 새 보고서 v3은 실물 차량 칸만 종합 일치율 분모로 쓴다. 가상 차량만 있으면 미평가(null)다. 실물 차량 한 칸은 보류, 가상 차량 한 칸은 일치한 예에서 50%였던 실물 종합값은 0/1이다. 가상 스티커 일치 및 빈 가상 구역의 관측은 별도로 센다. 중복 필드가 있는 정답표는 다시 작성하도록 안내한다. |

| 5. 카메라 연결과 장시간 운전 기록 | 1회 측정은 수신 시각이 최근이면 재연결 전 표시 사진을 분석 대기열에 넣을 수 있었다. 운전 기록의 최장 저장 공백에는 정지 후 마지막 저장까지 걸린 시간도 포함됐다. | 1회 측정은 화면의 두 이미지가 현재 연결에서 온 것인지 확인한다. 현재 화면의 사진을 유지하고 오래된 연결이면 새 미리보기를 기다린다. 전체 공백과 측정 활성 시간의 공백을 분리한다. 모의 시계에서 활성 9초·정지 후 51초인 실행은 활성 최장 공백 5초, 전체 공백 55초로 기록됐다. |

| 6. 실물 빈 기준의 저장 근거 | 저장기가 다른 픽셀의 유효한 PNG와 그 파일의 올바른 해시를 반환해도 빈 기준이 등록됐다. 두 기준 사진의 PC 수신차는 등록 시 검사했지만 이후 파일에서는 시각과 허용치를 다시 확인할 수 없었다. | 두 기준 PNG를 발행 전에 디코딩해 촬영자가 확인한 프레임과 픽셀을 비교한다. 원본 파일·RGB 해시와 두 PC 수신 시각·허용차·실제 차이를 보존한다. 의도적으로 잘못된 PNG를 넣었을 때 기준 폴더가 발행되지 않았다. 한계 초과·모순된 수치·옛 기준 호환을 기존 및 새 시험으로 확인했다. |

| 7. 학습 자료와 Geti 전달 전 대조 | 학습 크롭이 올바르더라도 manifest의 배치별 분할·라벨별 수량, 파일의 바이트 수, 실물/가상 표시, 디코딩한 원본 픽셀 해시의 모순이 번호 감사에 걸리지 않을 수 있었다. | 학습 manifest의 전체 샘플 경로·신고 해시와 완료 기록을 맞추고 배치와 과제·라벨별 분할 수를 다시 센다. 선택한 측정의 번호 사진은 실제 파일 길이·해시, 원본·승인 좌표 픽셀, 카메라·위치 근거, 독립 정답을 대조한다. 중복과 잘못된 집계·위치·해시를 각각 넣어 거부를 확인했다. 실제 Geti의 가져오기·학습은 다음 현장 시험에서 확인한다. |



## 번호 판독 시험



| 입력과 판정 기준 | 직접 일치 | 추정 일치 | 오답 | 보류 |

|---|---:|---:|---:|---:|

| 기존 실물 사진의 차량 11칸 | 2 | 9 | 0 | 0 |

| 기존 합성 24개 | 15 | 3 | 0 | 6 |

| 기존 추가 합성 72개 | 42 | 9 | 0 | 21 |

| 이전에 별도로 둔 합성 24개 | 19 | 3 | 0 | 2 |

| 이번에 별도로 만든 합성 24개 | 15 | 5 | 0 | 4 |



이번 추가 합성은 서로 다른 번호 24개, 두 글꼴(Arial Bold·Tahoma Bold), 네 각도(6°, −18°, 68°, 106°)의 같은 픽셀을 V48·V49에 입력했다. 번호와 스티커색이 모두 맞아야 일치로 셌다. 각 버전의 이미지 해시와 칸별 정답·선택값을 첨부했다. 같은 차량의 반복 관측이 있는 기존 사진과 합성 시험은 각각 해석해야 한다.



기존 복수 스티커 6장에서는 실물판용·가상선용 판독 모두 한 번호로 단정한 사례가 0건이었다. 같은 스티커를 하나씩 놓은 12장은 모두 직접 일치했다. 이 결과와 기존 실물 11칸의 판독은 V48 재생 결과와 같다. 신규 실물 번호·폰트·광택에서 같은 성능이 나오는지는 독립 배치로 확인해야 한다.



## 복구·호환·배포



- RealSense 대신 메모리 영상을 공급하는 두 수집 스레드를 운전하고 B 채널 연결 중단을 한 번 주입했다. 실제 시계로 측정한 활성 시간은 62.938초였다. 915회 프레임 쌍을 선택했고 재연결 후 이전 회차를 선택한 사례는 0건이었다. 15초 간격으로 저장한 5쌍·원본 10장·140칸을 다시 읽고 내보냈다. 이 시험은 RealSense 두 대의 실제 30분 운전은 별도 현장 시험으로 남는다.

- 두 원본이 기록된 직후 시험용 저장 프로세스를 강제 종료했다. 정상 대조군은 한 쌍·28칸으로 복구됐다. 유효한 두 판독이 충돌한 대조군은 내보내기 0쌍, 원본·복구 기록 보존을 확인했다. 시험용 복사본의 원래 판독을 복원하고 복구를 두 번 실행한 뒤에도 한 쌍·28칸이었다.

- 저장된 빈 보드 사진에서는 A-03이 사람의 재확인 대상이었다. A 영상을 수평으로 0·1픽셀 이동한 경우 빈칸 12개·경고 0개, 2·4·6·12픽셀 이동 및 재연결은 보류였다. 손·새 물체·번호가 가려진 차량, 실제 카메라 이동의 모든 양상을 이 시험으로 평가할 수는 없다.

- V48에서 만든 촬영 자료를 V49에서 열고 내보냈다. 기존 자료 102개는 SHA-256이 같았고, 한 쌍의 두 원본과 28칸이 전달됐다. 기존 정답표로 실물 28칸을 다시 대조했다. V48에서 실제로 작성한 빈 기준 두 장도 V49에서 기존 원본 해시와 일치했다. 기존 사진·승인·설치 구도·학습 분할 규칙을 이어 쓴다. 현장 대조 결과 형식은 v3이며 기존 v2와 수치를 비교할 때는 같은 정답표로 다시 생성한다.

- 전체 회귀 671개(기존 645개, 신규 26개)가 모두 통과했다. 실패·오류·건너뜀은 각각 0이다. 이번 26개 시험의 기대 결과를 충족한 수는 V48 2개, V49 26개다. 수정 중 첫 전체 회귀에서 예전 재판독 입력의 상태 필드가 생략됐을 때 예외가 발생했다. 선택 번호와 같은 위치를 확인하는 기존 경로가 동작하도록 바로잡고 최종 소스로 전체 시험을 다시 실행했다. 새 보고 값과 같은 결함을 확인하는 여러 경로도 포함돼 있으므로 이 차이를 고유 버그 수나 현장 인식률로 계산할 수 없다.



## 남은 현장 문제와 확인 순서



1. **새 실물 차량 24대**를 동시에 배치하고 번호·색·차량 식별표를 독립적으로 작성한다. 직접 일치·추정·오답·보류를 각각 집계한다.

2. **조명·방향·실제 주차선 침범**을 조건별로 대조한다. 반사로 획이 사라지거나 회전 방향을 독립적으로 정할 수 없는 경우 노출·조명을 바꾸거나 방향이 보이도록 재촬영한다. 빈 기준 등록 전 두 사진을 사람이 확인한다.

3. **두 실물 카메라로 30분 연속 수집**하고 활성 시간, 완료 쌍, 활성 시간의 최장 공백과 재연결 건수를 기록한다. 기본 100ms는 PC 수신차이며, 움직이는 차량에서의 센서 노출차는 별도 계측 대상이다.

4. **대상 Geti 설치판에서 가져오기와 학습**을 수행한다. 과제별 사진·라벨·분할 수를 대조하고, 겹치지 않는 실물 시험 세트를 고정해 학습 전후를 비교한다.



이번 작업 중 RealSense SDK 장치 검색은 0대였다. 현장 성능 지표는 미측정으로 둔다.
