# V19 → V20



작성일: 2026-11-04. 제품 버전: V20. V19의 심층 분석에서 재현된 오류를 수정한 별도 배포다.



## 수정 이유와 변경



파일 유실·불일치 예측을 놓치는 문제, OCR 실패 시 색 후보도 사라지는 결합, 번호 승인 수와 크롭 수의 혼동, 느린 OCR과 전송 취소·입력 출처·내보내기 범위 문제를 보완했다.



1. 독립 스티커색 후보를 추가하고 밝은 바닥 안의 흰 스티커 윤곽 누락을 수정했다.

2. 점유·색 Worker와 번호 OCR Worker를 분리하고 이전 장면 번호의 늦은 전송을 막았다.

3. 예측 계약 검사, 필수 자산/완료 예측 유실 검출, 초기 저장 pending 표식을 추가했다.

4. 라벨 승인/크롭 가능 수를 분리하고 최근 목록을 실제 촬영 시각으로 정렬했다.

5. lot/session 범위를 두 내보내기에 적용하고 숫자 박스 없는 번호 자료의 제외 사유를 기록했다.

6. 전송 취소 세대 번호, video/import/synthetic 출처와 운영 송신 차단을 추가했다.

7. 기존 장면 재저장 시 예측·스티커 자산 보존, 모델 파일 교체 감지, 장면별 batch/session 고정, 손상 검수 로드 검사를 보강했다.



## 실행한 검사와 결과



- 최종 회귀 83개 통과(52개 기존 + 31개 신규), 실패/오류/건너뜀 0. 실제 카메라와 실제 HTTP 요청은 사용하지 않았다.

- B 사선 16칸 분석→저장→검수→내보내기 회귀와 Tk 작업 종료 시험 포함.

- `main.py --check` 통과. Python/JSON/버전명/원본 버전 보존/ZIP 대조는 VALIDATION.json 및 PACKAGE_CHECK_V20.json 참조.

- 실제 EasyOCR CPU: 작은 초록 23은 번호 실패(8로 읽어 보류), 점유·초록색 유지. 큰 흰 23은 윤곽 수정 뒤 occupied/23/white 반환. 시험 중 실패도 OCR 기록과 심층 보고서에 보존했다.

- Torch DLL은 샌드박스 접근 제한이 있어 승인된 로컬 실행으로 시험했다. 기존 로컬 모델만 사용했다.



## 미검증·이전 자료



실물 RealSense, 실제 스티커 정확도, GPU 성능, 학습된 B안 모델, Geti 설치판 가져오기, 실제 서버, 장시간 수집, 해상도별 UI 육안 확인은 미검증이다. 색 후보는 휴리스틱이며 차량 마스크나 자동 주차선 검출을 구현하지 않았다. 항목별 독립 승인과 전체 평가셋 보고서도 향후 범위다.



V19 폴더/ZIP은 변경하지 않는다. 가중치·가상환경·촬영 자료는 복제하지 않는다. V20에서 기존 데이터 루트를 지정해 이어 쓸 수 있으며 데이터 계약과 pose는 유지한다. 예측 schema 확장 및 자산 pending 기록은 START_HERE.md 8절을 참고한다. 이전 변경 이력은 history/CHANGELOG_V19.md에 보존한다.
