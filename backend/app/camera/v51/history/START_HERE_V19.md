# V19 실행 및 촬영 설명서



## 1. 실행



1. ZIP을 별도 폴더에 풉니다. V18 폴더를 덮어쓰지 않습니다.

2. `smart_parking_v19/run_windows.bat`를 더블클릭합니다.

3. 기본 저장 폴더는 이 프로그램 아래 `datasets`입니다. 화면의 **저장 폴더 선택**으로 바꿀 수 있습니다.



실행기는 `SMART_PARKING_PYTHON` 환경변수 → 이 폴더의 `.venv` → 기존 `<local-path>` 순서로 Python을 찾습니다. 기존 V10 모델 폴더가 있으면 OCR 가중치도 재사용합니다. 실행 환경과 모델은 ZIP에 복제하지 않았습니다.



다른 환경은 `SMART_PARKING_PYTHON`에 Python 실행 파일, `SMART_PARKING_MODEL_DIR`에 기존 EasyOCR 모델 폴더를 지정합니다. `config.json`의 `model_directory`가 있으면 환경변수보다 우선합니다. 실행 환경이 없다면 별도 가상환경을 만든 뒤 `requirements.txt`를 설치하세요. Intel GPU 설치는 기존 `install_intel_gpu.bat`를 참고하되 V19에서는 GPU 성능을 재검증하지 않았습니다. CPU만 쓰려면 `config.json`의 `device`를 `cpu`로 설정합니다.



번호 OCR을 켜면 EasyOCR 모델이 로드됩니다. 모델이 없고 `download_models: true`이면 EasyOCR가 다운로드를 시도합니다. 오프라인에서는 기존 모델을 연결하고 `download_models`를 `false`로 지정하세요. 첫 모델 로딩은 평소 분석보다 오래 걸릴 수 있습니다.



## 2. 카메라 1대로 A → B 촬영



1. A를 선택하고 **카메라 1대 연결**을 누릅니다. 카메라 A/B와 주차장 A/B는 다른 개념입니다. 이 버전은 카메라 A 한 대만 사용합니다.

2. A의 12칸 전체와 각 차량 스티커가 원본에서 읽히도록 설치합니다. `cameras.json`은 기존 RealSense RGB 1920×1080, 30 FPS 설정을 유지합니다. 장치가 정확히 한 대 감지되면 현재 시리얼을 사용합니다.

3. **ROI 네 모서리**에서 각 칸 ID를 선택하고 테두리 네 모서리를 순서대로 찍습니다. 누락·겹침·잘못된 사각형을 수정합니다.

4. **위치 확인**을 누릅니다. 전체 12칸이 등록되어야 분석·수집할 수 있습니다.

5. 아래 A안 또는 B안을 설정하고, **번호 OCR·색 후보**를 필요에 따라 켭니다. **1회 분석**으로 결과와 원본이 같은 장면인지 확인합니다.

6. **실시간 시작** 후 **분석 후 자동 저장**을 켜거나, 원하는 장면에서 **정지/장면 고정 → 현재 장면 저장**을 누릅니다. 저장 완료 전에는 수량이 늘지 않습니다.

7. 차량 배치가 실제로 달라졌을 때 **새 촬영 배치**를 누릅니다. 같은 배치의 연속 장면은 같은 그룹으로 유지해야 학습/시험 누수를 줄일 수 있습니다.

8. 카메라를 B로 옮기고 B를 선택합니다. 사선 16칸을 **실제 네 모서리 그대로** 등록하고 위치와 빈 기준을 새로 확인합니다. A의 ROI·빈 기준을 B에 재사용하지 않습니다.



카메라 재연결·해상도 변경·주차장 변경 후에는 위치 확인이 필요합니다. 카메라가 물리적으로 움직였지만 프로그램이 감지하지 못한 경우에도 직접 정지하고 ROI·빈 기준을 다시 등록해야 합니다.



## 3. 점유 분석 방법



**A안 빈 기준:** 등록한 모든 칸이 비어 있는 상태에서 **빈 기준 등록**을 누릅니다. `A안 빈 기준`을 선택합니다. 기준 대비 변화가 작으면 빈칸, 크면 점유 후보, 중간이면 보류입니다. 초기 변화 임계값은 35, 빈 비율은 0.025 미만, 점유 비율은 0.12 초과입니다. 차량뿐 아니라 손·그림자·조명도 변화에 포함되므로 현장 검수가 필요합니다. 기준은 세션 메모리에 유지되고 증빙 원본은 `references/`에 저장합니다. 재시작 후 자동 재승인하지 않습니다.



**B안 분류:** 학습된 점유 2분류 OpenVINO 모델을 준비한 뒤 `requirements_openvino.txt`의 선택 의존성을 설치합니다. `occupancy_model.example.json`을 복사해 모델 경로·입력 크기·색 순서·정규화·출력 순서·점수 의미를 **실제 학습 모델에 맞게** 바꾸고 **B안 모델 설정**에서 선택합니다. 예시의 수치는 설명용이며 실제 모델 전처리 값이라는 보장은 없습니다. IR 모델은 XML과 BIN을 함께 둡니다. 설정 파일의 상대 모델 경로는 해당 JSON 폴더 기준입니다. UI에서 선택한 모델 설정은 현재 실행에 적용되며, 재시작 후에도 쓰려면 `config.json`의 `occupancy_model`에 같은 설정을 넣습니다.



OpenVINO 호출 방식은 [공식 Python 추론 문서](https://docs.openvino.ai/2023.3/openvino_docs_OV_UG_Python_API_exclusives.html)를 참고했습니다. 현재 구현은 입력 하나·출력 하나의 점유 2분류용 연결부입니다. 임의의 Geti 검출/다중 출력 모델을 그대로 지원한다는 뜻은 아닙니다. 실제 학습 모델 및 이 PC의 OpenVINO 실행은 아직 검증하지 않았습니다.



모델이 없거나 오류가 나면 **보류**와 원인을 표시합니다. B안에서 A안으로 자동 변경하지 않습니다. 수동 검수 모드에서는 점유도 사람이 입력합니다.



## 4. 번호·스티커색·이상 주차



번호는 OCR 후보이며 실제 스티커에서 읽히는지 확인합니다. 색은 OCR 주변의 스티커 색 영역 후보를 찾아 측정하고 애매하면 미확인으로 둡니다. 흰색=일반, 초록=전기차, 파랑=장애인 구분이며 차체색은 사용하지 않습니다.



D-39 운영 번호 24개를 적용합니다. 초록 23·42·57·85, 파랑 14·32·55·75, 흰색 10·11·12·20·21·22·24·30·33·34·40·41·43·44·58·88입니다. 예비 13·31·77·78·87은 아직 승인 대상이 아닙니다. 예전 49 등은 원본/과거 기록을 보존하되 새 정답 승인에는 쓰지 않습니다.



전용칸과 스티커 유형이 다르면 종류 불일치 의심을 표시합니다. 빈 기준의 변화 영역이 여러 칸에 걸치거나 밖으로 나가면 주황 테두리와 경계 후보를 표시합니다. 이 변화 영역은 차량 마스크가 아니므로 불법주차를 확정하지 않습니다. 전용칸 번호와 종류는 팀이 정한 `layouts.py` 배치와 실물 배치를 대조해야 합니다.



## 5. 한 화면에서 검수



1. 정지한 장면을 저장하고 칸 카드 또는 원본의 해당 칸을 클릭합니다.

2. 오른쪽의 원본 크롭과 AI 후보를 봅니다. 화면이 작으면 오른쪽 스크롤바를 사용합니다.

3. **후보를 정답 초안으로**를 누르거나 점유·번호·색을 직접 입력합니다.

4. 색을 승인하려면 **스티커 내부 지정**, 번호 크롭을 학습에 쓰려면 **번호 박스 지정**으로 근거 영역을 확인합니다.

5. 검수자 이름을 확인하고 **선택 칸 승인**을 누릅니다. 다른 칸은 자동 승인되지 않습니다. **초안 저장**은 승인하지 않습니다.

6. 승인한 칸은 카드에 정답이 표시됩니다. 선택 칸에서 자동 후보와 정답의 불일치를 확인합니다.



번호를 못 읽어도 차량이 보이면 점유 정답을 남길 수 있습니다. 색이나 번호를 모른다는 이유로 빈칸으로 바꾸지 않습니다. 빈칸 승인 시 번호·색·영역은 비웁니다. 선명도/밝기/번호 높이 지표는 참고용이며 완벽한 품질을 인증하지 않습니다. 원본 확대와 사람 확인이 마지막 선정 기준입니다.



## 6. 저장 파일과 실제 수량



| 폴더 | 의미 |

|---|---|

| `raw/A/` 또는 `raw/IMPORT/` | 원본 PNG. IMPORT는 사진 입력이며 카메라 관측으로 송신하지 않음 |

| `manifests/` | 장면 ID, 주차장, ROI, 촬영 시각, 카메라, 배치, 원본 해시 |

| `spaces/<주차장>/<칸 ID>/` | 사선 바깥을 흰색 마스킹한 칸 크롭 |

| `stickers/` | 자동 스티커 후보가 잡힌 경우의 크롭 |

| `predictions/` | 같은 장면의 자동 예측. 정답과 별도 |

| `prediction_history/` | 같은 장면 재분석 전 예측 이력 |

| `reviews/` / `reviews/history/` | 사람 검수 정답 / 수정 이력 |

| `assets/` | 크롭 파일별 해시와 완료·부분 실패 증빙 |

| `references/` | 빈 기준 원본과 등록 기록 |

| `exports/` | 승인 자료 내보내기 결과 |



하단에서 전체·현재 주차장·현재 세션별로 유효 원본, 칸 파일, 스티커 파일, 라벨 파일/행, 항목별 승인 수, 이미지 용량, 디스크 여유를 봅니다. 같은 장면 저장 재시도·수정 이력·내보내기 복사본은 원본 수량에 합산하지 않습니다. 집계는 메타데이터에 연결된 파일과 해시를 대조합니다. 폴더 안에 수동으로 추가한 무관한 파일·고아 파일은 포함하지 않습니다. 이미지 용량은 집계 대상 원본/크롭의 합계이고 전체 폴더 디스크 점유량은 아닙니다.



최근 파일은 최대 200개를 표시합니다. 파일 대조는 모든 대상 메타데이터를 읽고 변경된 이미지 해시만 다시 확인하므로 첫 대조가 가장 오래 걸립니다. **파일 대조/새로고침**은 해시를 강제로 재검사합니다. 삭제·손상·검수 JSON 오류는 **오류 상세**에 나옵니다. 이전 후보 스티커가 바뀌면 현재 자산 목록에 없는 과거 크롭은 집계하지 않으며 자동 삭제하지 않습니다.



## 7. 승인 자료 내보내기



- **검수 원본·표시사진 내보내기:** V18에서 이어 온 JSONL, 원본 복사본, 승인 라벨을 그린 확인용 이미지입니다. 확인용 이미지 자체를 학습 원본으로 사용하지 않습니다.

- **학습용 작업별 크롭 내보내기:** `occupancy`, `number`, `color` 아래 `train`, `validation`, `test`와 클래스별 폴더 및 `manifest.json`을 만듭니다. 점유는 승인 칸, 번호는 번호와 박스가 있는 승인 칸, 색은 색과 스티커 다각형이 있는 승인 칸만 포함합니다.



동일 촬영 배치는 동일 분할로 묶습니다. 비율은 해시 기반 약 70/15/15라서 소량 배치에서는 세 분할이 모두 생기지 않을 수 있습니다. 같은 원본이 여러 분할에 있으면 `FAILED.json`을 남기고 실패합니다. Geti 설치판의 가져오기 호환성과 독립 시험 배치 확보는 별도 확인해야 합니다. 차량 전체 마스크·스티커 검출용 전체 박스 라벨은 이 내보내기에 없습니다.



## 8. V18 자료 이어 쓰기



V18 프로그램과 ZIP 및 촬영 자료는 그대로 보존합니다. 먼저 해당 자료 폴더를 백업하거나 복사한 뒤 V19의 **저장 폴더 선택**에서 그 데이터셋 루트를 지정하세요. 이전 원본은 이동하지 않습니다. V19는 같은 루트에 새 장면과 크롭·예측을 추가할 수 있습니다. V18 프로그램을 같은 데이터셋에 동시에 쓰는 방식은 피하세요.



기존 A/B 원본·메타데이터를 열 수 있습니다. 이전 규격 승인은 재검수 대상으로 내려가며 다시 승인해야 합니다. 데이터 계약 `20261104-d39-v3` 변경은 D-39 운영 번호와 D=64 배치 규칙을 반영한 것입니다. 제품 버전만으로 pose 값이나 기존 원본을 바꾸지 않습니다. C/D 가상 자료는 이번 UI의 선택 범위가 아닙니다. 특히 이전 D=10 배치는 새 D=64와 호환된다고 가정하지 말고 V18에서 원본을 확인해 별도 변환해야 합니다.



## 9. 선택 기능: 서버 전송



기본은 꺼짐입니다. 코드만 포함하며 실제 서버에는 전송하지 않았습니다. 팀 담당자와 이벤트 스키마, 카메라 ID, `confidence`/`bbox_xyxy`의 null 허용을 확인한 경우에만 사용하세요. V19에는 차량 검출 박스나 검증된 통합 신뢰도가 없어 두 필드를 null로 보냅니다.



`config.json`에 `api_contract_confirmed: true`, `api_nullable_bbox: true`, `api_nullable_confidence: true`, `api_camera_ids: {"A": "합의한 카메라 ID"}`를 설정하고 환경변수 `API_BASE_URL`, `VISION_TOKEN`을 지정합니다. 토큰은 config나 로그에 적지 않습니다. 화면 체크박스는 실행할 때마다 기본 꺼짐입니다.



실시간 카메라 결과만 `/api/v1/internal/vision-events`에 보냅니다. 사진·보류 점유·기본 2초를 넘은 관측은 보내지 않습니다. 내부 `electric`은 `ev`로 변환합니다. HTTP 202는 접수이고 상태 확정이 아닙니다. 네트워크/5xx는 같은 event_id로 1회 재시도, 401 등은 재시도하지 않습니다. 최신 대기 장면 1개만 유지하고 리디렉션은 따르지 않습니다. 서버 상태·주차 세션을 조회해 확정 결과를 맞추는 기능은 아직 없습니다.



## 10. 검증·체험



`run_windows.bat --check`는 설정만 검사합니다. Python 실행기로 `run_tests.py`를 실행하면 V19 전용 테스트 52개가 실행됩니다. 실제 장비와 인터넷 없이 합성 자료·모의 HTTP를 사용합니다. 반복 Tk 테스트의 화면 객체는 메인 스레드에서 정리합니다.



Python 실행기로 `demo.py`를 실행하면 합성 B 사선 주차장의 통합 화면을 볼 수 있습니다. 저장하면 `.demo_output`에만 기록하며 실물 학습 데이터로 사용하지 않습니다. OCR·서버 전송은 기본 꺼짐입니다. 실제 실행과 저장·검수는 본 프로그램을 사용하세요.
