# V21 실행·자동 수집·내보내기 설명서



V20에서 스티커 판독·근거 검증을 보완하고, **칸 자동 등록 → 번호·스티커색 분석 → 칸명 표시사진·한글 JSON 저장 → 내보내기 수량 표시**를 연결한 V21입니다.



## 1. 실행과 준비



1. `smart-parking-v21.zip`을 새 폴더에 풀고 `smart_parking_v21/run_windows.bat`를 실행합니다. 기존 버전 폴더를 덮어쓰지 않습니다.

2. 화면 위에서 주차장 A 또는 B를 선택합니다. **A주차장 12칸은 직사각형, B주차장 16칸은 사선형**입니다. 카메라는 A 한 대를 두 곳으로 옮겨 사용합니다.

3. 저장 위치를 바꾸려면 **저장 폴더 선택**을 사용합니다. 기본값은 프로그램 아래 `datasets`입니다.

4. **자동 수집 시작**을 누릅니다. 카메라 연결, 준비 대기, 이전 구도 검사 또는 칸 등록, OCR 활성화, 실시간 분석, 저장을 순서대로 진행합니다.

5. 종료할 때 **자동 수집 정지**를 누릅니다. 실행 중인 저장은 마무리하고 파일을 유지합니다.



매 장면마다 ROI·위치 확인·OCR·저장·검수를 따로 누를 필요가 없습니다. 고급/수동 설정은 기본 화면에서 접혀 있습니다. 자동 수집/자동 라벨 내보내기에는 사람 승인이 필요하지 않습니다. 사람이 승인한 학습 정답을 만들 때만 검수 기능을 사용합니다.



실행기는 `SMART_PARKING_PYTHON` → 현재 폴더 `.venv` → 기존 `<local-path>` 순서로 Python을 찾습니다. 기존 V10 모델 폴더가 있으면 재사용합니다. 환경·가중치는 ZIP에 포함하지 않습니다. 다른 환경에서는 Python 경로와 `SMART_PARKING_MODEL_DIR`를 지정합니다. `config.json`의 `model_directory`가 있으면 우선합니다. 필요한 패키지는 `requirements.txt`, 선택적 OpenVINO 패키지는 `requirements_openvino.txt`를 참고합니다.



`device: cpu`로 CPU 실행을 선택할 수 있습니다. `download_models: true`이며 모델이 없으면 EasyOCR가 다운로드를 시도합니다. 오프라인이면 기존 모델을 연결하고 false로 지정합니다. 첫 모델 로딩은 시간이 더 걸립니다. 시험에서는 기존 로컬 모델만 사용했습니다. 표시사진에는 Windows 맑은 고딕 또는 Linux 나눔고딕 글꼴이 필요합니다.



## 2. 자동 등록이 가능한 촬영 조건



- 원본 화면에 A는 12칸, B는 16칸 전체가 들어와야 합니다.

- 각 칸의 **실제 이름**이 화면에서 읽혀야 합니다. A주차장은 A-01~A-06 / B-01~B-06, B주차장은 A-01~A-08 / B-01~B-08입니다. 주차장 ID와 칸 앞의 A/B 구역 문자는 다릅니다.

- 칸 이름은 카메라 기준으로 읽기 좋은 방향과 크기로 배치합니다. 자동 칸 이름 판독은 정방향 이름을 대상으로 합니다. 90도 회전된 이름을 자동으로 모두 해결한다고 보장하지 않습니다.

- V21 초기 자동 등록은 윤곽에서 **닫힌 볼록 사각형**을 찾습니다. 직사각형과 평행사변형을 지원합니다. 입구가 열린 U자 선, 끊긴 선, 가려진 이름은 자동 등록에 실패할 수 있습니다. 도면의 의미를 영상만 보고 임의로 추측하지 않습니다.

- 차량 스티커가 작거나 반사로 날아가면 번호를 보류합니다. 번호색은 차체색이 아니라 흰색/초록/파랑 스티커 배경색입니다.



전칸 이름과 경계가 맞아야 수집을 시작합니다. 부족하면 화면에 찾은 칸 수·누락 이름을 표시하고 5초 후 재탐색합니다. 최신 실패 진단은 `setup_attempts/latest_주차장_카메라.png/.json`에 남깁니다. 이 파일은 진단용 최신 상태이며 촬영 원본을 덮어쓰는 파일이 아닙니다. OCR 자체가 실패하면 UI 오류 사유를 확인합니다.



한 번 성공한 구도는 `calibration_anchors`에 저장합니다. 재시작 시 시리얼·주차장·해상도·pose·해시를 확인하고 주차선/칸 이름의 ORB 특징을 비교해 재사용합니다. 자동 ROI를 사용하는 **매 분석 장면에서도** 같은 구도인지 검사합니다. 특징 부족이나 이동이면 현재 분석을 보류하고 자동 등록을 재시도합니다. 조명·가림·반복 무늬가 심한 실제 현장에서는 추가 검증이 필요합니다.



닫힌 경계를 만들 수 없는 도면에서는 **고급/수동 설정 → ROI 네 모서리 → 위치 확인**으로 최초 등록할 수 있습니다. 수동 ROI도 분석 후 자동 저장이 가능합니다. 수동 ROI를 자동으로 승인된 anchor처럼 취급하지 않습니다.



## 3. 점유·번호·색이 나오는 방식



| 항목 | V21 동작 | 의미 |

|---|---|---|

| 칸 위치·명칭 | 선의 사각형과 실제 칸 이름 OCR 대조 | 전칸 등록 후 수집 시작 |

| 번호 | 스티커를 바로 펴고 원본색/명도/이진 영상에서 판독 | 최소 2개 처리 영상이 같은 유효 번호를 반환해야 후보 채택 |

| 스티커색 | 독립 색·형태 탐색 및 영역 검증 | 원형/사각형 흰색·초록·파랑 후보 |

| 점유 모델 등록됨 | 설정된 OpenVINO 2분류 모델 | 모델 임계값에 따라 occupied/vacant/unknown |

| 점유 모델 없음 | 인쇄 흔적이 있는 스티커가 있으면 점유 후보 | 스티커가 없으면 **관측 보류**, 빈칸으로 단정하지 않음 |

| 종류 불일치 | 일반/전기차/장애인 칸과 스티커 종류 비교 | 로컬 의심 경고, 법적 위반 확정 아님 |

| 칸 경계 걸침 | 빈 기준 방식에서 변화 영역 후보 | 차량 마스크 기반 위반 확정 기능은 없음 |



자동 수집의 초기 점유 방식은 등록된 B안 모델, 없으면 스티커 근거 방식입니다. 자동으로 모든 칸이 비어 있다고 가정하여 빈 기준을 만들지 않습니다. 전체 빈칸까지 자동 판단하려면 검증된 점유 모델을 연결해야 합니다. 모델 없는 스티커 방식에서는 빈칸으로 보이는 칸도 관측 보류입니다.



운영 D-39 번호는 `23,42,57,85,14,32,55,75,10,11,12,20,21,22,24,30,33,34,40,41,43,44,58,88`입니다. 예전 사진의 49를 현재 번호로 바꾸어 맞추지 않습니다. 번호 판독 충돌, 한 처리 영상만 성공, 여러 칸의 같은 번호, 이웃 칸의 스티커는 보류합니다. 알려진 배정표 색은 실제 색 판독을 대체하지 않습니다.



## 4. 저장 구조와 이름



```text

datasets/

  raw/A/<사진ID>.png                         변경하지 않은 카메라 원본

  manifests/<사진ID>.json                    기계용 촬영·구도·해시 기록

  predictions/<사진ID>.json                  자동 예측과 OCR 근거

  spaces/A/A-01/<사진ID>.png                  글자를 그리지 않은 칸 크롭

  stickers/<사진ID>_A-01.png                  무표시 스티커 크롭

  collected/A/A-01/

    A-01__<촬영UTC>__<사진ID>.png             칸명·경계·번호·색 표시사진

    A-01__<촬영UTC>__<사진ID>.json            같은 이름의 한글 라벨

  collected/B/A-01/...                       B주차장의 A-01칸은 별도 폴더

  scenes/A/A주차장__<촬영UTC>__<사진ID>.png   전체 장면 표시사진

  scenes/A/A주차장__<촬영UTC>__<사진ID>.json  전체 칸을 모은 한글 결과

  assets/<사진ID>.json                       무표시 자산 완료 기록

  bundles/<사진ID>.json                      표시사진·JSON 쌍과 해시 완료 기록

  reviews/<사진ID>.json                      선택적으로 작성한 사람 정답

  calibration_anchors/...                    자동 등록 기준과 해시

  setup_attempts/...                         자동 등록 진단

  reports/audit-<ID>.json / .md               범위별 품질·정답 대조

  exports/automatic-<ID>/...                  내보내기 복사본

```



한글 JSON의 주요 값은 `주차장`, `주차칸명`, `주차칸종류`, `촬영시각_UTC`, `프레임번호`, `주차칸꼭짓점_px`, `점유상태`, `차량번호`, `스티커색`, `번호영역_xyxy_px`, `스티커꼭짓점_px`, `점유판단근거`, `번호판독점수`, `영상품질`, `자동정보완성`, `사람검수완료`, `라벨출처`, `원본사진파일`, `표시사진파일`, `한글라벨파일`, 각 SHA256입니다. 숫자 23은 문자열만 저장하지 않고 `차량번호: 23` 정수도 기록합니다. 미확인 번호는 null이며 임의의 0/가짜 번호로 채우지 않습니다.



모든 꼭짓점과 번호 박스는 **원본 전체 영상의 좌상단 (0,0)을 기준으로 한 픽셀 좌표**입니다. 칸 크롭 시작점도 별도로 기록합니다. 표시사진에는 설명 여백이 추가되므로 표시사진의 크기를 원본 좌표 기준으로 사용하면 안 됩니다. 초록 테두리는 칸, 주황은 스티커, 하늘색은 번호 영역입니다. 표시는 원본의 복사본에만 그립니다.



기존 영어 키의 기계용 JSON은 호환성과 상세 근거 보존을 위해 유지하고, 사용자용 한글 JSON을 추가합니다. 자동 후보에는 `사람검수완료: false`와 `자동 생성 후보 · 미검수`가 표시됩니다. 사람 정답 저장 시 해당 칸 사진과 한글 JSON을 다시 생성하지만 원래 예측과 원본은 보존합니다.



## 5. 파일 수량과 내보내기



UI는 디스크 기록과 해시를 대조해 원본·무표시 크롭·스티커·표시사진·한글 JSON·정상 짝·승인 라벨·학습 가능 수를 구분합니다. 정보완성은 필요한 값이 존재한다는 뜻이며 정확도 100%라는 뜻이 아닙니다. 미확인 수와 화질주의 수도 따로 표시합니다.



**칸별 사진·JSON 내보내기**는 현재 집계 범위(전체/현재 주차장/현재 세션)에 맞는 완성 묶음을 `exports/automatic-<ID>`로 복사합니다. 미검수 자동 후보도 포함되며 각 JSON에 출처가 남습니다. 원본을 삭제하거나 이동하지 않습니다. 복사가 끝나면 UI에 장면 수, 칸 사진·JSON 쌍, 이미지 수, 원본 수, JSON 수, 제외 수, 경로가 나옵니다. 제외 사유와 해시는 `내보내기_결과.json`에 기록됩니다. 파일 유실·해시 불일치·부분 실패 묶음은 제외합니다. 복사 중 오류는 완료로 표시하지 않습니다.



| 전칸 장면 수 | 칸별 쌍 | 이미지 합계 | 데이터 JSON | 별도 결과 기록 |

|---|---:|---:|---:|---:|

| A 1장 | 12 | 14 = 칸12+전체1+원본1 | 13 = 칸12+전체1 | JSON 1개 |

| B 1장 | 16 | 18 = 칸16+전체1+원본1 | 17 = 칸16+전체1 | JSON 1개 |

| A+B 각1장 | 28 | 32 | 30 | 같은 내보내기 묶음이면 JSON 1개 |



따라서 마지막 행의 폴더에서 파일 확장자만 세면 JSON은 **31개**입니다. UI의 30개는 데이터 JSON만 센 값이며 결과 기록 1개는 별도입니다. 원래 수집 폴더에는 manifests/predictions/assets/bundles 등 내부 JSON도 있어 단순 확장자 개수와 같지 않습니다.



아래 **승인 자료·표시사진 내보내기**, **승인 학습 크롭 내보내기**는 사람이 검수한 자료를 내보내는 기존 기능입니다. 자동 수집본 내보내기와 용도가 다릅니다. 번호 정답이 있어도 번호 영역 박스가 없으면 번호 학습 크롭은 제외합니다. 표시 글자가 그려진 사진은 발표·검토용이며, 학습에는 무표시 원본·크롭과 좌표 라벨을 사용합니다.



## 6. 품질과 정답 대조



`영상품질`은 라플라시안 선명도 분산·어두운 픽셀 비율·밝은 픽셀 비율·주의사항을 숫자와 한글로 제공합니다. 초기 화질 지표는 현장 정답률을 보증하지 않습니다. 초점/거리/반사를 조정하고, 정보가 없는 칸은 재촬영 대상으로 확인합니다. 미확인 사진도 원본 증거로 보존하여 실패를 숨기지 않습니다.



**현재 범위 품질·정답 대조**는 저장된 자동 예측과 사람 승인 정답을 비교합니다. 점유·번호·색 각각 비교 수, 일치 수, 보류 수, 예측한 경우의 일치율, 보류 포함 일치율, 예측 커버리지를 제공합니다. 승인 정답이 없으면 평가 자료 없음/null이며 100%로 표시하지 않습니다. 유실·손상 예측은 비교 제외 수로 따로 기록합니다. 칸/색/번호/배치/출처의 수집 커버리지도 보고합니다. 자동 라벨끼리 같은 값을 보인다고 실제 정확도로 계산하지 않습니다.



## 7. 고급/수동 방식



자동 등록이 불가능한 구도는 고급/수동 설정에서 기존 ROI 네 모서리 편집을 사용할 수 있습니다. 전칸 등록과 위치 확인 후 `실시간 시작` 및 `분석 후 자동 저장`으로 수집합니다.



**A안 빈 기준**은 모든 칸이 실제 비어 있을 때 등록합니다. 기본 변화 임계값 35, 빈 비율 0.025 미만, 점유 비율 0.12 초과입니다. 손·그림자·조명 변화도 포함하므로 점유 후보와 경계 걸침 후보를 실제 위반 확정으로 쓰지 않습니다. 기준은 세션 메모리와 references 증빙으로 관리되며 재시작 후 자동 빈칸 승인은 하지 않습니다.



**B안 모델 설정**은 검증된 OpenVINO 점유 2분류 모델의 경로·입력 크기·색 순서·정규화·출력 순서·임계값을 받습니다. `occupancy_model.example.json` 수치는 예시입니다. 선택한 설정은 현재 실행에 적용하며 재시작 후에도 쓰려면 config.json의 occupancy_model에 넣습니다. 임의의 Geti 다중 출력 모델을 그대로 지원하는 연결부는 아닙니다.



서버 전송은 기본 꺼짐입니다. 실제 카메라 출처, 현재 구도, 만료되지 않은 결과만 대상으로 합니다. 사진/합성/녹화는 운영 전송하지 않습니다. 정지·구도 변경·주차장 변경 시 대기 전송과 재시도는 취소합니다. 이미 나간 HTTP는 회수할 수 없고 202 응답은 접수일 뿐 최종 서버 상태를 뜻하지 않습니다. 이번 검증에서 실제 HTTP를 보내지 않았습니다.



## 8. 이전 데이터·버전 호환



V20과 기존 데이터는 그대로 둡니다. V21에서 기존 저장 루트를 지정해 이어 쓸 수 있지만, 같은 루트를 여러 버전으로 동시에 수정하지 마세요. 기존 데이터는 V21으로 열 수 있는 범위에서 검수/재분석하며 새 촬영부터 칸명 사진·한글 JSON을 생성합니다. 이전 파일이 자동으로 전부 새 산출물로 변환되는 일괄 마이그레이션 기능은 없습니다. 자동 내보내기에 필요한 bundle이 없는 이전 자료는 제외 사유를 남깁니다.



D-39 데이터 계약 `20261104-d39-v3`, 설치 pose, A/B 칸 정의는 유지했습니다. 제품 버전은 V21입니다. 새 예측은 `prediction-v21-1`, 표시사진 묶음은 `korean-collection-v1`, 자동 ROI 근거는 `roi-registration-v2`입니다. V21은 V19/20 예측을 검증하며 읽지만, 기존 오류 자료는 거부할 수 있습니다. V20은 V21 자동 ROI와 새 예측을 이해하지 못하므로 V21 생성 자료를 V20에서 수정하지 마세요.



## 9. 시험 범위와 알려진 한계



회귀시험 152개 통과. `main.py --check` 통과. 실제 로컬 EasyOCR CPU로 합성 A12/B16 자동 등록과 칸별 저장/내보내기를 확인했습니다. 현행 D39 실물 A/B 사진은 사용자 확인상 없으므로 실제 촬영 정답률은 측정하지 못했습니다.



별도 D39 합성 24대 시험에서는 V20 번호16/24 → V21 번호20/24가 맞고 4개는 보류했습니다. 이 시험에서 채택한 잘못된 번호는 없었으나 다른 영상까지 보증하지 않습니다. 작은 초록 23 실패 사례를 수정했고, 과거 실물 원형 파랑49는 파랑색을 찾되 현행 번호로 인정하지 않았습니다. 세부 근거는 `OCR_VALIDATION_V21.json`에 있습니다.



RealSense 실기기 연결, 현재 D39 실물 영상, 현장 조명·가림·열린 주차선, 장시간 성능, GPU, 실제 학습 모델, Geti 가져오기, 실제 서버, 화면 크기별 UI 육안 확인은 미검증입니다. 카메라 30 FPS 설정은 OCR 처리속도 30 FPS를 의미하지 않습니다. 모든 칸의 정확한 빈칸/차량 점유와 차량 마스크 기반 잘못된 위치 판정을 완성하려면 실제 데이터와 검증된 모델이 필요합니다.
