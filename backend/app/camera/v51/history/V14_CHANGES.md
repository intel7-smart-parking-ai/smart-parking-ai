# V13 → V14 카메라 조정·원본 확대·화질 확인



## 무엇을 바꿨나



기존 V13은 카메라 화질 설정을 JSON에서 수정하고 다시 연결하는 방식이었고 화면에서 실제 설정값을 조회하거나 지역 화질을 비교할 수 없었습니다. V14는 카메라 A/B별 ‘화질·카메라 설정 / 원본 확대’ 버튼을 추가했습니다.



- 노출·게인·화이트밸런스의 자동/수동 전환, 샤프니스와 플리커 값 조정.

- 현재 실제값과 센서가 반환한 최소/최대/단계값·읽기 전용 여부 조회. 단위는 장치 기준이며 임의의 고정 단위를 가정하지 않습니다.

- ‘적용만’과 ‘적용 후 설정 저장’ 구분. 정상 적용 결과를 조회한 뒤 카메라별 camera_quality.json에 저장합니다. 다음 연결에도 저장한 값이 사용됩니다.

- SDK 조작은 카메라 수신 스레드에 요청합니다. UI가 카메라를 두 번 열거나 SDK 센서를 다른 스레드에서 직접 조작하지 않습니다.

- 모든 입력을 미리 범위 검사합니다. 하드웨어 적용 도중 실패하면 일부 값이 바뀔 수 있어 실패 안내와 실제값 재조회를 요구합니다. 자동 롤백을 보장하지 않습니다.

- 전체 프레임의 선명도·어두운 픽셀·밝은 픽셀 참고 지표를 표시합니다.

- ‘현재 사진 원본 확대·영역 화질’은 현재 유효 프레임을 고정해 확인합니다. 원본 1:1, 휠 확대/축소, 오른쪽 드래그 이동을 지원합니다. 두 점으로 지정한 작은 영역의 지표를 따로 확인합니다.

- 촬영 manifest에 quality_advisory를 추가해 원본 전체의 지표를 보존합니다. 카메라 설정 요청 이후의 실제값 조회 기록도 프레임의 camera_options에 포함됩니다. 자동 노출이 변하는 경우 이는 최근 조회 시점 값이며 정확한 촬영 순간 메타데이터는 아닙니다.

- 설정 창을 열면 수집을 일시정지하고 해당 카메라 위치 확인을 해제합니다. 창을 닫고 위치 확인을 다시 해야 수집합니다.



주요 파일: camera_tools.py(설정·실시간 확인 UI), quality.py(장치 조회/입력 검사/화질 지표), camera_hub.py(수신 스레드 요청 및 실제값 기록), widgets.py(읽기 전용 원본 확인 모드), main.py(버튼 연결), pipeline.py(촬영 화질 기록).



## 실행 준비



1. ZIP을 새 V14 폴더에 풉니다. V10 환경을 재사용한다면 해당 폴더를 지우거나 이동하지 마세요.

2. 기존 models를 V14로 복사하면 재다운로드를 줄일 수 있습니다. cameras.json, camera_quality.json, configs의 현재 설정·ROI도 백업 후 복사할 수 있습니다.

3. 데이터는 datasets를 복사하거나 config.json의 dataset_directory에 기존 자료의 절대 경로를 지정해 이어 씁니다. 같은 데이터 경로로 여러 버전을 동시에 실행하지 마세요.

4. V14의 main.py가 있는 폴더에서 PowerShell을 열어 실행합니다.



```powershell

& '<local-path> .\main.py

```



새 환경이 필요할 때만 install_intel_gpu.bat를 사용합니다. 기본 번호는 01~99 및 100, 자료 규칙은 1103-sticker-100-v2입니다. 기존 V13 승인 자료는 UI 변경 때문에 재승인할 필요가 없습니다.



## 카메라 조정 순서



1. 카메라·조명을 고정하고 가장 가까운 칸과 먼 칸에 흰색·초록·파랑 스티커 차량을 놓습니다. 한 번에 보이는 가장 먼 스티커도 확인해야 합니다.

2. ‘카메라 연결’을 누르고 해당 카메라 아래 ‘화질·카메라 설정 / 원본 확대’를 엽니다. 카메라 A/B는 각각 조정합니다.

3. ‘현재 실제값 조회’로 센서 범위를 확인합니다. 처음에는 자동 노출·자동 화이트밸런스를 켜고 ‘적용만’을 누른 뒤 영상이 안정될 때까지 기다립니다.

4. 다시 ‘현재 실제값 조회’를 눌러 자동 설정 결과를 확인합니다. 이 값은 수동 설정의 출발점이며 최적값을 보장하지 않습니다.

5. ‘현재 사진 원본 확대·영역 화질’을 엽니다. 정지 사진이므로 뒤에서 설정을 바꾸더라도 이 창은 갱신되지 않습니다. 바뀐 결과를 보려면 닫고 다시 엽니다.

6. ‘원본 1:1’을 눌러 스티커를 확인하고 휠·오른쪽 드래그로 위치를 맞춥니다. 스티커 주변 왼쪽 위와 오른쪽 아래 두 점을 클릭한 뒤 ‘선택 영역 화질 확인’을 누릅니다. 이 선택은 학습 라벨로 저장되지 않습니다.

7. 숫자 획·색상·반사를 눈으로 확인합니다. 너무 어두우면 조명을 먼저 보완하고, 움직임 흐림이나 반사가 있으면 촬영 조건과 노출을 조정합니다. 한 번에 하나의 조건을 바꾸며 같은 영역을 비교하세요.

8. 일정한 조명에서 고정하려면 자동 노출·자동 화이트밸런스를 해제하고 조회했던 수치를 기준으로 수동 값을 조정합니다. 수동 노출은 노출·게인을 둘 다 입력합니다. 미지원/읽기 전용 옵션은 적용할 수 없습니다.

9. ‘적용만’으로 시험하고 실제값을 확인한 뒤 ‘적용 후 설정 저장’을 누릅니다. 저장 완료 안내를 확인하세요. 저장 파일은 camera_quality.json, 실제값 기록은 logs/camera_A_quality_actual.json 또는 B 파일입니다.

10. 창을 닫고 주차칸 ROI와 화면이 맞는지 확인한 뒤 ‘위치 확인’ → ‘한 장 저장’ → ‘OCR 시작 / 재시도’로 번호·색 결과를 비교합니다. 색은 기존처럼 스티커 내부를 검수에서 지정해야 합니다.



카메라 위치를 옮겼다면 ROI를 다시 등록하세요. 전 칸을 담느라 숫자 자체가 너무 작아지면 노출값 조정으로 해결되지 않을 수 있습니다. 카메라 담당 구역 분할, 촬영 거리, 스티커 크기를 함께 조정해야 합니다.



## 화질 수치 해석과 한계



초기 참고 기준: Laplacian 분산 60 미만은 선명도 낮음 가능성, 회색 밝기 40 미만 픽셀이 35% 초과면 어두운 영역 많음, 245 초과 픽셀이 20% 초과면 밝은 영역/반사 가능성입니다. 현장 정답률로 보정되지 않은 경험적 경고이며 OCR 합격 판정이 아닙니다.



검은 바닥이 많은 전체 화면은 어두움 경고가 자연스럽게 나타날 수 있고, 흰 스티커는 밝은 픽셀 경고가 날 수 있습니다. 그래서 같은 크기의 스티커 영역을 선택해 설정 전후를 비교해야 합니다. 원본 1:1은 이미지 한 픽셀을 캔버스 한 픽셀로 표시하는 배율이며 Windows DPI 배율에 따른 물리 크기는 다를 수 있습니다. 확대는 흐릿한 원본을 복원하지 않습니다. 경고가 있어도 원본 수집을 막거나 삭제하지 않습니다.



V14는 자동 스티커 검출/차량 점유 모델을 추가한 버전이 아닙니다. 카메라 조정으로 모든 번호·색의 확실한 인식을 보장하지 않습니다. 자동 노출 고정 버튼이나 센서 범위를 무시하는 임의 최적값도 적용하지 않습니다. 실제 최적 수치는 현장에서 정답 번호·색과 비교해 선택해야 합니다.



## 검증



총 88개 시험 통과: 기존 79개 + 신규 9개, 실패·오류·건너뜀 0. 밝기·선명도 지표, 입력 범위/단계/NaN 차단, 자동 해제 순서와 실제값 조회, 카메라 작업 스레드 처리, 원본 배율과 읽기 전용 창, 설정 창 조회/타이머 정리를 검사했습니다. Python 구문·main.py --check 통과, ZIP CRC 및 포함 파일 일치 확인.



테스트는 가짜 SDK 센서·합성 영상·실제 Tk 위젯으로 진행했습니다. 실제 D435 설정 적용·장시간 연결·장치별 범위·최적 노출·색상 정답률은 미검증입니다. 기존 사용자 로그에서 확인된 V10의 B390 GPU 시작 성공과 V14 카메라 설정 실측은 별개의 검증입니다.
