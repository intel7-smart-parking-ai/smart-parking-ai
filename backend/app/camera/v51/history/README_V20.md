# V20 주차장 통합 수집 프로그램



V19에서 확인된 **예측·파일 검증 누락, OCR과 색 후보의 결합, 점유 처리 지연, 전송 취소, 수량·범위 표시 문제를 수정한 V20**입니다. 카메라 한 대로 A 직사각형 12칸과 B 사선 16칸을 순서대로 촬영합니다. 색은 스티커 배경색입니다.



**실행:** `run_windows.bat` 더블클릭. 촬영·검수 사용 설명서 (`START_HERE.md`, 별도 보관 이력) · [코드 심층 검수 및 수정 보고서](V20_DEEP_CODE_REVIEW.md).



- OCR을 끄거나 번호를 못 읽어도 스티커색 후보를 별도로 탐색합니다. 밝은 바닥 위 흰 스티커의 중첩 윤곽 누락도 수정했습니다.

- 점유·색 후보와 번호 OCR을 서로 다른 작업 스레드에서 처리합니다. 화면은 각 결과의 실제 원본·시각에 고정되며, 늦은 번호 결과가 최신 점유 관측을 덮어 전송하지 않습니다.

- 파일 유실·손상과 예측 필드 오류를 표시하고, 승인 라벨 수와 학습 크롭 조건을 충족한 수를 나눠 보여줍니다.

- 최근 파일은 촬영 시각 순서로 표시하며, 현재 주차장·세션 범위가 내보내기에도 적용됩니다.

- 정지·주차장 변경·전송 해제 시 대기 및 재시도 전송을 취소합니다. 사진·녹화·합성 영상은 운영 카메라 이벤트로 전송하지 않습니다.



**검증:** 최종 회귀시험 83개 통과. 실제 EasyOCR CPU 합성 시험에서 큰 흰 스티커는 점유·번호 23·흰색을 함께 반환했습니다. 작은 초록 스티커는 번호 인식에 실패했지만 점유·초록색을 유지했습니다. 이 실패를 숨기지 않고 [시험 기록](OCR_CPU_SMOKE_V20.json)에 남겼습니다. 실물 정확도나 FPS를 보장하지 않습니다.



학습된 B안 모델, 자동 주차선 검출, 차량 마스크 기반 위반 확정, 서버 최종 상태 조회는 포함하지 않습니다. 자동 후보는 사람이 검수해 승인해야 합니다. V19의 코드·ZIP·촬영 자료는 보존했고 데이터 계약과 설치 pose는 변경하지 않았습니다.
