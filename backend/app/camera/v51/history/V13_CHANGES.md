# V12 → V13: 한 사진의 여러 차량·주차칸 분석과 데이터셋 묶음



## 현재 동작과 수정 이유



V12도 등록된 ROI를 모두 순회해 OCR을 수행했습니다. 그러나 최근 분석 검수는 한 번에 한 칸만 보여줘 전체 차량의 처리 상황을 확인하기 어려웠습니다. 이번 버전은 여러 칸의 결과와 모든 텍스트 후보를 한 사진 단위로 관리하고, 승인 라벨도 사진별로 묶습니다.



## 변경 내용



- ‘여러 차량 결과’ 버튼을 수집/저장 자료 탭에 추가했습니다. 저장 자료에서 사진을 선택하면 그 사진, 선택이 없으면 최근 분석 사진을 보여줍니다.

- 한 사진의 등록된 모든 칸을 표로 표시합니다. 번호 후보, 보류 상태, 같은 칸의 복수 글자 후보를 모두 확인할 수 있습니다.

- 표의 칸을 선택하고 ‘선택 칸 검수’를 누르거나 더블클릭하면 해당 칸의 검수로 이동합니다.

- analysis JSON에 frame_summary와 frame_revision=multi-slot-v1을 추가했습니다. 전체 등록 칸 수, 번호 후보가 있는 칸 수, 검수 필요 칸 수, 모든 OCR 글자 후보의 원본 좌표·점수를 보존합니다.

- 여러 칸에서 같은 번호가 나오면 계속 중복 보류합니다. 한 칸에 복수 후보가 있어도 모두 기록하고 단일 차량 번호로 자동 확정하지 않습니다.

- 승인 내보내기의 기존 칸별 JSONL 옆에 *.frames.jsonl을 추가합니다. 동일 image_id의 모든 승인 칸을 annotations 배열로 묶어 한 장에서 여러 객체/영역을 학습 자료로 관리할 기반을 제공합니다.

- 과거 분석 파일에 사진 단위 요약이 없으면 다음 OCR 실행에서 재분석합니다. 기존 검수 규칙과 contract_revision=1103-sticker-100-v2는 유지합니다.



주요 파일: multi_vehicle.py(사진 단위 요약/내보내기), pipeline.py(분석 결과 연결·재분석), main.py(전체 결과 UI), review.py(묶음 내보내기).



## 정확한 범위와 한계



‘한 번에 분석’은 원본 한 장을 제출하면 모든 등록 칸을 분석한다는 의미입니다. 내부에서는 ROI를 순서대로 처리하며, 모든 칸의 연산을 동시에 병렬 실행하는 방식은 아닙니다. 현재 인식 단위는 보통 한 칸에 한 대인 주차 차량의 번호입니다.



아직 차량 검출 모델은 없습니다. 따라서 OCR 후보 수를 차량 대수로 사용하지 않으며 vehicle_count는 null입니다. 번호가 가려지거나 스티커가 너무 작으면 차량이 있어도 번호를 읽지 못할 수 있습니다. 통로/미등록 칸 차량, 한 칸의 여러 차량을 자동으로 개별 추적·분리·확정하는 기능은 구현하지 않았습니다. 주차칸 바닥 문자나 차체 문양이 텍스트 후보가 될 수도 있습니다.



스티커색은 사진별 스티커 내부 네 점을 지정해 검수합니다. 여러 차량의 스티커색을 자동 분할하는 모델은 포함하지 않았습니다. 확대 편집은 V12 기능을 유지합니다.



frames.jsonl은 사진별 승인 칸 라벨이며 차량 검출용 바운딩박스 정답을 새로 만들어낸 것이 아닙니다. annotation_scope에 human_reviewed_parking_spaces_not_vehicle_boxes를 기록합니다. 번호판 박스와 스티커 폴리곤은 사람이 등록한 경우에만 포함됩니다. all_objects_in_image_annotated=false를 유지하므로 일부 승인 자료를 사진 전체 정답 완료로 취급하면 안 됩니다. Geti 전용 가져오기 형식으로의 변환과 실제 모델 학습은 별도입니다.



## 여러 차량 수집 방법



1. 카메라를 고정하고 보이는 각 주차칸에 고유 ROI를 등록합니다. 차 한 대가 아니라 사진에 있는 전체 칸을 등록해야 전체를 분석합니다.

2. 여러 칸에 차량을 배치하고 ‘한 장 저장’ → ‘OCR 시작 / 재시도’를 실행합니다.

3. 분석 후 ‘여러 차량 결과’를 엽니다. 원하는 사진이 있으면 저장 자료 탭에서 먼저 사진을 선택하세요.

4. 번호 후보가 없는 칸이나 중복·복수 후보가 있는 칸을 우선 검수합니다. 미인식을 빈칸으로 승인하지 마세요.

5. 각 차량의 실제 번호·점유·스티커색과 영역을 확인하고 승인 저장합니다.

6. ‘승인 자료 내보내기’를 실행하면 기존 *.jsonl과 사진 단위 *.frames.jsonl이 함께 생성됩니다.



데이터 수집에는 빈칸/한 대/여러 대, 서로 다른 배치, 겹침·가림·조명 변화도 포함하세요. 같은 사진 또는 같은 연속 배치의 칸들을 학습/평가로 따로 흩어 넣으면 누수가 생길 수 있으므로 image_id와 batch_id로 함께 관리하세요. 이를 바탕으로 후속 차량/스티커 검출 모델을 학습·검증해야 모든 차량 자동 인식으로 확장할 수 있습니다.



## 실행과 이전



V13 ZIP을 별도 폴더에 풀고 main.py가 있는 폴더에서 실행합니다.



```powershell

& '<local-path> .\main.py

```



기존 models, 카메라 설정, configs의 등록 ROI를 V13으로 복사해 재사용할 수 있습니다. 데이터는 datasets를 복사하거나 config.json의 dataset_directory에 기존 자료 경로를 지정하세요. 동일 자료 경로로 여러 버전을 동시에 실행하지 마세요. 기존 실행 환경 폴더를 삭제하면 위 Python 경로는 사용할 수 없습니다.



## 검증



기존 73개 + 신규 6개, 총 79개 시험 통과. 세 칸의 12·49·100 모의 OCR 결과와 원본 좌표 연결, 같은 칸 복수 후보 보존, 칸 사이 중복 번호 보류, 미인식 점유 unknown, 세 칸 승인 자료의 한 사진 묶음, 실제 Tk 전체 결과 창을 검사했습니다. Python 구문과 main.py --check 통과. 실제 여러 차량 영상의 인식률·GPU 처리 속도·Geti 학습·서버 연동은 미검증입니다.
