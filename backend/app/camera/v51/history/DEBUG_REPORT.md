# V8 → V9 전체 디버깅 결과



작성일: 2026-11-03. V8 소스와 ZIP을 보존하고 `smart_parking_v9`에서 수정했습니다. 실행 파일은 `main.py`, 배포 파일은 `smart-parking-v9.zip`입니다.



## 무엇을 고쳤는가



| 문제 / 재현 조건 | V9 동작 | 주요 파일 |

|---|---|---|

| 다른 시리얼 또는 해상도의 프레임에 이전 ROI가 연결되어도 저장됨 | 저장 전 카메라·시리얼·해상도·ROI 설치 키를 검사. 현재 화면에 남은 과거 프레임 대신 허브의 최신 유효 프레임으로 촬영 | `records.py`, `layouts.py`, `pipeline.py`, `main.py` |

| 한 카메라의 ROI 오류가 다른 패널 갱신을 막음 / 종료 직전 저장 오류 누락 | 카메라별 예외 처리. 종료 중 새 촬영 차단, 저장 결과와 카메라 스레드 종료까지 대기. 저장 실패 알림 및 파일 기록 | `main.py`, `camera_hub.py` |

| BOM 포함 카메라 JSON 로딩 실패 / 상대 영상 경로가 실행 위치에 따라 달라짐 / 소수 해상도가 정수로 잘림 | UTF-8 BOM 지원, 설정 파일 위치 기준 상대 경로, 정수 해상도 검사. NaN·불리언 간격·잘못된 설정 타입도 시작 전에 거부 | `camera_hub.py`, `settings.py` |



승인 영역 기준은 **선택 칸과 75% 이상 겹침, 다른 칸 각각 20% 미만 겹침**입니다. 실제 차량이 칸을 걸치거나 카메라 원근 때문에 스티커 위치가 ROI 밖이면 자동 연결을 확정하지 않고 ROI를 확인하거나 승인을 보류합니다. 이 검사는 스티커를 자동 검출한다는 의미는 아닙니다.



## 실제 검증



1. 수정 전 V8의 기존 32개 테스트 통과를 확인했습니다.

2. V8 소스를 그대로 복사한 상태에서 새 오류 재현 사례 9개를 실행해 6개 실패·3개 오류를 확인했습니다. 원시 결과는 `V8_REPRODUCTION.txt`입니다. 경로에 V9가 표시되는 이유는 수정 전 복사본에서 시험했기 때문입니다.

3. 수정 후 기존 32개와 신규 24개, **총 56개 테스트 통과**: 실패 0, 오류 0, 건너뜀 0. 이 중 GUI 시험은 7개입니다.

4. 모든 배포 Python 파일 구문 검사 통과. `python main.py --check`로 일반 설정·도면·카메라 설정 검사 통과.

5. V8의 기준 파일 25개와 V8 ZIP의 SHA-256을 작업 전 기록과 비교해 변경이 없음을 확인했습니다. `V8_BASELINE_HASHES.json`에 기준값을 보존했습니다.



| 시험 범위 | 방법 |

|---|---|

| 가나다라 도면·전용 칸·카메라/주차장 분리 | 50칸 구성 및 합성 프레임 저장 |

| 번호·색상 | 가짜 OCR 결과, 합성 스티커/바닥 이미지. 01~24 엄격 검증, 스티커 내부 마스크, 가상 번호판 분리 |

| 저장·검수·내보내기 | 임시 파일에 손상 JSON·잘못된 ID·영역·중복 승인 등을 넣어 결과 확인 |

| OCR 재시도·오류 격리 | 모델 로더/분석 함수 모의, 오류 상태 기록 실패 및 알림 큐 경쟁 상황 주입 |

| 실제 Tkinter 창 동작 | 합성 프레임으로 촬영→검수, 중복 창, 종료 취소, 영역 편집, 오류 패널 격리, 종료 대기 확인 |



시험 환경: Windows, Python 3.13.15, OpenCV 5.0.0, NumPy 2.5.4, Pillow 13.0.0, Tk 8.6. 기존 로컬 가상환경을 사용했으며 새 PC의 의존성 설치는 별도로 시험하지 않았습니다. 시험 환경에는 EasyOCR이 설치되어 있지 않아 실제 모델 추론을 하지 않았습니다.



다시 실행하려면 의존성 설치 후 V9 폴더에서 다음 명령을 사용합니다.



```powershell

python main.py --check

python -m unittest discover -s tests -v

```



임시 디렉터리 접근이 제한된 실행 환경에서는 Python `tempfile.tempdir`을 쓰기 가능한 폴더로 지정해야 합니다. 이번 자동 시험은 V9 아래 `test_temp`를 사용했습니다. GUI 시험은 데스크톱 세션이 필요하며 화면이 없는 환경에서는 건너뛸 수 있습니다.



## 유지한 규칙과 남은 현장 확인



- 원본을 일정 간격으로 저장하고 OCR은 별도 처리합니다. D435 요청 해상도/프레임률 및 카메라 화질 설정은 V8 기준을 유지했습니다. 카메라 움직임 자체를 자동 감지하지는 않습니다.

- 흰색=일반, 초록=전기차, 파랑=장애인. 색은 사진별로 지정한 스티커 내부에서만 측정합니다. 번호별 색 배정표는 추정하지 않습니다.

- 점유 자동 판정은 여전히 `unknown`입니다. 사람 검수와 자동 후보를 분리합니다.

- 제품 버전만 V9로 증가했으며 `contract_revision=1103-sticker-v1`은 유지합니다. 승인 JSONL은 Geti 전용 가져오기 형식이 아닙니다.

- **실제 D435 촬영, EasyOCR 정확도, RTX 3050 CUDA 실행, Geti 가져오기/학습, 서버 API 연동은 미검증입니다.** 이번 수정은 데이터 연결과 오류 처리의 안정성 개선이며 인식률 향상을 실측한 것은 아닙니다.

- 대량 데이터셋 성능 및 여러 프로그램이 같은 데이터셋을 동시에 수정하는 작업은 검증하지 않았습니다. V8/V9를 같은 데이터 경로로 동시에 실행하지 마세요.

- 다음 현장 시험은 고정 카메라에서 각 한 칸을 등록한 뒤 흰색·초록·파랑 스티커를 하나씩 촬영하고 원본·OCR 후보·수동 검수 결과를 비교하는 순서입니다. 다시 실제 수정본을 전달하면 V10으로 올립니다.



## 발표용 설명



> V8에서 주차칸 ROI, 번호, 스티커색, 검수를 한 프로그램으로 통합했다. V9에서는 잘못된 카메라·ROI 연결, 손상 파일로 인한 내보내기 중단, 검수 결과 덮어쓰기 등을 재현해 수정했다. 기존 32개에 24개의 검증을 추가해 총 56개 테스트를 통과했으며, 실제 장비에서의 인식 성능은 다음 현장 시험으로 확인한다.
