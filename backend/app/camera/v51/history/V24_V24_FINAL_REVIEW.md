# V24 전체 코드 심층 분석·검수 보고서



날짜: 2026-11-05 (한국). 기준 배포: V23. 결과물: 별도 smart_parking_v24 및 smart-parking-v24.zip.



## 검수 결론



V23의 표시·수집·인식·검수·저장·복구·내보내기·설정 경로를 코드로 추적하고, 재현된 오류를 V24에서 수정했습니다. 전체 회귀231개, 별도 저장 중단28곳, 기존 데이터340파일 읽기 보존, A12/B16 원본 사진 재검증을 수행했습니다. 검사한 소프트웨어 경로에서 최종 실패는 없었습니다. 모든 환경에서 오류가 없거나 실차 결과가 완벽하다는 의미는 아닙니다.



기존의 카메라1대·A 직각12칸·B 사선16칸·스티커 배경색·ㄷ자 실제3면과 가상입구 분리는 유지했습니다. D39 운영번호, 설치pose, 제품과 별개인 데이터 규격도 변경하지 않았습니다.

## 2. 입력 전환과 자동 등록 경쟁



V23 connect는 hub가 이미 있을 때만 can_leave/clear_context를 호출했습니다. 사진을 먼저 열고 처음 카메라를 연결하면 scene이 사진에 묶인 채 input_mode만 camera가 됐습니다. get_packet은 정지 scene을 우선하기 때문에 화면과 입력 출처가 혼동되고, 미저장 검수도 전환 확인을 건너뛸 수 있었습니다.



V24는 두 연결 경로 모두 can_leave를 거치고, 새 hub를 구성한 뒤 clear_context로 raw·scene·ROI·상세·예측·confirmed_epoch와 비동기 세대를 초기화합니다. 카메라 사양 읽기에 실패하면 기존 사진을 유지하고 오류를 알립니다. 물리 카메라를 연결하지 않고 모의 Hub와 숨긴 Tk에서 재현·검증했습니다.



사진 자동 등록이 진행 중일 때 고급 1회 분석이 이전 ROI로 제출될 수 있었습니다. 현재는 calibrating 검사에서 즉시 거부하고, 등록 완료가 처리된 뒤 자동 사진 분석 한 번을 진행합니다. 취소·등록 실패·연결된 카메라와 사진 분리 등 V23의 시험도 유지됩니다.



## 3. 예측 근거가 사라졌을 때의 저장 오류



V23 재저장은 prediction_status가 complete이면 없는 예측을 거부했으나 pending이면 없는 값으로 진행했습니다. 또 save_review는 예측 파싱/검증 오류를 pass로 무시한 뒤 None으로 표시사진을 생성했습니다. 결과적으로 사람 정답 일부는 정상이어도 나머지 자동 근거가 사라진 묶음이 complete가 될 수 있었습니다.



V24 records.load_prediction으로 읽기 규칙을 통일했습니다. 파일이 있으면 prediction 계약과 원본 장면을 검사하고, complete/pending이 약속된 파일이 없으면 오류입니다. 과거 수동 자료처럼 예측을 약속하지 않은 자료는 None을 허용합니다. persist_scene·복구·저장장면 로더·수량 검사와 collection 검증에서 같은 규칙을 씁니다.



새 예측을 명시적으로 제공한 재분석은 검증 후 다시 저장할 수 있습니다. 원본 프레임·시각·연결구간·ROI와 픽셀 일치를 먼저 검사하므로 다른 사진으로 덮어쓰지 않습니다. 예측이 없는 상태에서 자동으로 값을 만들어 복구하지 않습니다.



## 4. 사람 정답과 표시사진 완성 상태



사람이 입력한 유효한 정답은 먼저 저장합니다. 이후 예측 파일 유실/손상으로 표시사진 갱신을 완료할 수 없으면 사람 정답을 취소하지 않고 bundle/manifest를 partial로 남깁니다. 원본과 정답은 보존되고 UI 파일 대조에서 오류가 보입니다.



문제를 해결하려면 원래 예측 파일을 복구하거나 같은 원본을 다시 분석해 유효한 예측을 제공해야 합니다. 이후 선택 장면 저장 복구로 같은 사진ID의 파생 사진/JSON을 다시 생성합니다. 복구가 원본 개수를 늘리거나 승인 정답을 초기화하지 않는 것을 시험했습니다.



입력 SHA256이 일치한다는 사실은 예측 내용이 올바른 형식이라는 뜻이 아닙니다. V24 read_collection은 예측 자체의 계약도 확인하고 prediction_status=pending이면 내보내기를 거부합니다. 따라서 V23에서 이미 만들어진 잘못된 complete 묶음도 새 검증에 걸립니다. 정상 V23 자료는 같은 형식으로 계속 읽습니다.



## 5. 후속 OCR과 점유 후보의 일관성



빠른 단계의 independent_sticker가 못 찾더라도 칸 전체 OCR 제안→국소 스티커 위치→복수 처리 영상 번호 합의에서 나중에 스티커를 찾을 수 있습니다. V23는 이 경우 번호/색만 채우고 점유는 unknown으로 유지했습니다.



V24는 스티커 근거 모드에서 유효한 번호와 국소 스티커 근거가 채택되면 occupied 후보를 반영하고 점유 사유와 전용칸 종류 비교를 갱신합니다. 가짜 확률을 만들지 않아 occupancy_score는 null입니다. 모델/빈기준/수동 모드의 점유 결과를 OCR이 덮어쓰지는 않습니다. 번호 중복은 기존처럼 보류합니다. 이는 스티커 기반 차량 후보이며 차량 분할 모델을 새로 구현한 것은 아닙니다.



## 6. 좌표와 모델 설정의 선검사



자동 칸 이름 bbox는 실제 배열 잘라내기에 사용됩니다. V23에서 0.25 같은 소수 좌표가 계약을 통과하면 static_markings의 NumPy 슬라이싱 단계에서 오류가 날 수 있었습니다. 이제 원본 정수 픽셀 좌표를 요구합니다.



자동 ㄷ자 ROI를 수동 확인 상태로 바꾸더라도 세 면/입구와 polygon의 관계는 유지되어야 합니다. V24는 registration_method 이름만 보고 검사하지 않고 open_u 메타데이터가 있는 모든 칸에 같은 일치 검사를 적용합니다.



점유 모델 설정은 model 경로 문자열, labels 두 클래스, NCHW/NHWC, RGB/BGR, 양의 정수 size, 유한한 비영 scale, 유한한 mean과 양수 std, logits/probabilities, 0~1의 threshold, device 문자열을 먼저 검사합니다. boolean/NaN/무한대도 숫자 설정으로 통과시키지 않습니다. 모델 파일의 실제 실행·정확도는 별도이며 이번에는 OpenVINO 모의 모델만 시험했습니다.



## 7. 색상 처리 비용 감소



색 판독 기준을 바꾸지 않고 작업 영역만 줄였습니다. 기존 color_candidate는 호출마다 전체 이미지 크기의 마스크와 HSV를 생성했습니다. 새 구현은 스티커의 바깥상자와 실제 영상 1픽셀 여백만 처리합니다. 이 여백으로 내부 마스크 침식이 전체 영상 방식과 같게 유지됩니다. 이미지 가장자리에서도 원래 영상의 경계 조건을 보존합니다.



합성4000×3000 영상, 네 스티커 좌표, 각5회 측정에서 색 이름·비율·유효 픽셀 수 등 출력이 같았습니다. 네 호출의 중앙값은 V23 약492ms, V24 약1.10ms였습니다. 이것은 **색상 함수만의 로컬 측정**이며 전체 OCR·카메라 처리율이 그만큼 빨라진다는 뜻이 아닙니다. 상세 수치는 COLOR_BENCHMARK_V24.json에 있습니다.

V23 결함 재현의 5개 오류는 잘못된 임계값이 모델 파일 접근까지 전달됐기 때문에 새 테스트가 기대한 사전 ValueError 대신 파일 오류를 받은 경우입니다. V24에서는 이 조건들이 사전 검사에서 거부됩니다. 수치가 서로 다른 테스트 메서드/하위 사례를 혼합해 결함 수로 읽히지 않도록 구분했습니다.



물리 보드의 OCR은 이번에 새 CPU/GPU 모델로 재측정한 것이 아닙니다. 원본·구도·인식후처리·저장·내보내기는 V24를 실제 실행했고, 동일 픽셀·인자의 번호/이름 판독 관측만 V23 캐시를 사용했습니다. 두 빈 보드의 모든 칸은 번호null·색unknown·점유unknown이며 추론오류0입니다. 현행 차량+D39 정답률은 측정하지 않았습니다.



## 9. 호환성·보존과 운영 방법



V23 배포 소스150파일과 ZIP 해시를 보존·대조합니다. .venv, 모델, 촬영 데이터, 로그, 임시시험, __pycache__는 복제하거나 새 ZIP에 넣지 않습니다. V24에서는 저장 폴더 선택으로 기존 데이터 루트를 이어 사용합니다. 원본 사진과 기존 자료를 일괄 재작성하지 않습니다.



계약20261104-d39-v3, prediction-v21-1, ROI등록v2/v3, korean-collection-v2, 한글 라벨v1, 설치pose는 그대로입니다. 새 형식 변환은 없습니다. 예측 유실/손상 때문에 과거에 잘못 complete였던 묶음만 더 엄격하게 거부하며 오류 사유를 제공합니다. 정상 자료의 이름·수량·경로 의미는 같습니다.



UI 실행은 run_windows.bat, 데모는 run_demo.bat입니다. 사진 자동 등록·수집과 카메라 자동 수집 시작의 구분도 유지합니다. 수집 데이터는 자동 후보이고 사람이 승인한 정답은 별도입니다. 내보내기는 원본 삭제를 동반하지 않는 복사입니다.



## 10. 남아 있는 검증 범위와 한계



실제 차량이 있는 D39 사진, RealSense 장치, GPU, 학습된 점유·차량 외곽 모델, 실제 서버·Geti, 장시간 실행, 물리 정전과 OneDrive 동시쓰기 충돌은 이번 시험 범위에 없습니다. 전용칸 종류 비교와 배경 변화 경고를 차량 위치 위반 확정으로 사용하지 않습니다.



한 저장 루트에 여러 프로그램이 동시에 쓰는 잠금은 제공하지 않습니다. 과거 자료 전체 자동 변환과 유사사진 자동 삭제도 없습니다. 카메라 프레임 설정은 OCR 처리율 보장이 아닙니다. 첫 등록에는 이름·주차선이 충분히 보여야 하고 조명·가림·반사에서 보류될 수 있습니다.



이번에는 실제 창을 열어 마우스로 조작하는 검사는 하지 않았습니다. 숨긴 Tk에서 전환·등록·저장 경로를 시험했습니다. V23의 화면 조작 중단 이력은 history에 남기며 V24에서 재검사한 것으로 표기하지 않습니다.
