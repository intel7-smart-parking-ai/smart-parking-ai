# V24 실행·ㄷ자 등록·자동 수집·저장·내보내기 설명서



V23에서 사진→카메라 전환, 예측 유실/손상 자료의 완료 처리, 후속 스티커 점유 반영을 수정한 V24입니다. 카메라 한 대·A12/B16·ㄷ자 세 면·스티커 배경색·통합 수집 흐름을 유지합니다.



## 1. 실행과 두 입력 방식



1. `smart-parking-v24.zip`을 새 폴더에 풀고 `run_windows.bat`를 실행합니다. V22를 덮어쓰지 않습니다.

2. 상단 **A · 직사각형 12칸 / B · 사선 16칸**에서 주차장을 고릅니다. 영상이 없으면 칸 배치 안내가 나타납니다. 이 배치는 촬영 좌표로 자동 사용되지 않습니다.

3. 제공한 사진을 적용하려면 **사진 자동 등록·수집**을 누르고 A에서는 `20261103_143356.jpg`, B에서는 `20261104_171431.jpg`를 선택합니다. 파일명으로 주차장을 추측하지 않으므로 A/B 선택을 맞춥니다.

4. 사진은 칸 이름·주차선 등록, 번호·색 분석, 한 장 저장을 순서대로 수행합니다. 불완전하면 사유와 진단을 표시하고 멈춥니다. 카메라 재탐색처럼 사진 한 장을 계속 반복 저장하지 않습니다.

5. 실제 카메라는 **자동 수집 시작** 한 번으로 연결·등록/구도 대조·OCR·자동 저장을 진행합니다. 정지 시 이미 저장한 파일을 보존합니다. 주차장을 옮기면 A/B를 바꾼 뒤 다시 시작합니다.

6. 기존 자료는 **저장 폴더 선택 → A/B 선택 → 선택 주차장 저장 장면 보기**로 엽니다. 저장 장면을 보고 있는 동안 A/B를 바꾸면 그 주차장의 최신 읽을 수 있는 장면을 찾습니다. A 자료가 없으면 B를 대신 보여주지 않습니다.



`run_demo.bat`는 카메라·모델 없이 A/B 화면을 확인하는 합성 예제입니다. 기본 A12에서 B16으로 전환할 수 있습니다. 번호 OCR은 꺼져 있으며 출력은 `.demo_output`에만 저장합니다. 실제 촬영 정확도 시험으로 사용하지 않습니다.



실행기는 `SMART_PARKING_PYTHON` → 현재 `.venv` → 기존 `<local-path>` 순서로 Python을 찾습니다. 기존 모델 폴더 또는 `SMART_PARKING_MODEL_DIR`를 재사용할 수 있습니다. config의 model_directory가 있으면 우선합니다. 환경·가중치·촬영 데이터는 ZIP에 넣지 않았습니다. 패키지는 requirements.txt, 선택 OpenVINO는 requirements_openvino.txt를 사용합니다.



CPU는 config의 `device: cpu`로 선택합니다. 모델이 없고 download_models가 true이면 다운로드를 시도하므로 오프라인에서는 기존 모델을 지정하고 false로 설정하세요. V23에서는 기존 로컬 CPU OCR 모델을 사용했고, 이번 V24 사진 검증은 그 관측 캐시를 재사용했습니다. 한글 사진 표시에는 맑은 고딕 또는 나눔고딕이 필요합니다.



## 2. ㄷ자 주차선과 이름 자동 등록



| 항목 | A주차장 | B주차장 |

|---|---|---|

| 실제 사진 | 20261103_143356.jpg | 20261104_171431.jpg |

| 전체 칸 | 12 | 16 |

| 명칭 | A-01~06 / B-01~06 | A-01~08 / B-01~08 |

| 주차선 | 직각 ㄷ자 | 사선 ㄷ자 |

| 전기차 칸 | A-05, A-06 | A-07, A-08 |

| 장애인 칸 | B-06 | B-07, B-08 |



주차장 A/B와 각 주차장 안의 A/B 구역은 서로 다른 구분입니다. 데이터의 키는 **주차장+칸명**입니다.



화면에 모든 칸 이름과 선이 보여야 합니다. 처음에는 빈 주차장을 등록해 이름 가림을 줄이고, 이후 같은 카메라 구도에서는 저장 기준을 대조해 재사용할 수 있습니다. 사진의 고정 좌표를 코드에 넣은 방식이 아닙니다.



1. 영상의 밝고 채도가 낮은 선을 찾습니다. 노란 스토퍼와 녹색/파랑 바닥을 흰 주차선으로 취급하지 않습니다.

2. 서로 대응하는 측면 두 개와 뒤쪽 선을 연결해 ㄷ자를 만듭니다. 선 끊김 허용 정도를 두 가지로 검사해 작은 틈과 긴 가림을 구분합니다.

3. 칸 이름 OCR은 0/270/90/180도 순서와 두 크기를 검사하고 원본 좌표로 돌립니다. 이름의 중복·누락, 이웃 이름과 간격, 선 지지 정도, 칸 겹침을 검사합니다.

4. 실제 선 3면은 실선으로 표시합니다. 열린 입구 끝점 사이는 **주황 점선인 가상 경계**입니다. 영역 면적·크롭·귀속 계산에는 네 꼭짓점이 필요하지만 이를 실제 페인트 선이라고 주장하지 않습니다.

5. 전칸이 검증돼야 수집합니다. 부족한 카메라 영상은 5초 후 재등록을 시도하고, 가져온 사진은 보류 사유를 보여주고 멈춥니다.



닫힌 선이 실제로 있는 옛 자료도 지원합니다. 수동 ROI는 고급 설정에서 네 점으로 지정할 수 있습니다. 자동 ㄷ자 등록이 완료된 칸을 수동으로 다시 그리면 해당 칸은 사람이 지정한 영역으로 바뀝니다.



`setup_attempts`에 진단 사진/JSON, `calibration_anchors`에 기준 사진/ROI/해시를 저장합니다. 같은 주차장·카메라·시리얼·해상도·pose인지 확인한 뒤 ORB 특징으로 구도를 비교합니다. 매 자동 분석도 구도 대조를 거칩니다. 이동·가림·특징 부족이면 보류합니다.



빈 바닥의 A-01 같은 인쇄 글자를 차량 스티커로 오인하지 않도록, 등록 때 확보한 이름의 작은 명도 패치를 현재 영상과 비교합니다. 외관이 그대로인 글자 영역의 스티커 후보만 제외합니다. 나중에 차량이 그 영역을 덮어 외관이 달라지면 제외가 해제됩니다. 해당 위치 전체를 영구적으로 가리는 방식은 아닙니다.



첫 등록은 회전 OCR과 모델 로딩으로 시간이 걸립니다. 같은 구도의 기준 재사용은 OCR 등록 반복을 줄입니다. 검증 중 이름 OCR 개별 호출은 약 5~10초였으며 모델 초기화와 나머지 처리는 별도입니다. 재사용 캐시 실행 시간을 현장 초기 등록 속도로 해석하지 마세요.



## 3. 점유·번호·색이 나오는 방식



| 항목 | V24 동작 | 의미 |

|---|---|---|

| 칸 위치·명칭 | ㄷ자 세 면·가상 입구와 실제 칸 이름 OCR 대조 | 전칸 등록 후 수집 시작 |

| 번호 | 스티커를 바로 펴고 원본색/명도/이진 영상에서 판독 | 최소 2개 처리 영상이 같은 유효 번호를 반환해야 후보 채택 |

| 스티커색 | 독립 색·형태 탐색 및 영역 검증 | 원형/사각형 흰색·초록·파랑 후보 |

| 점유 모델 등록됨 | 설정된 OpenVINO 2분류 모델 | 모델 임계값에 따라 occupied/vacant/unknown |

| 점유 모델 없음 | 인쇄 흔적이 있는 스티커가 있으면 점유 후보 | 스티커가 없으면 **관측 보류**, 빈칸으로 단정하지 않음 |

| 종류 불일치 | 일반/전기차/장애인 칸과 스티커 종류 비교 | 로컬 의심 경고, 법적 위반 확정 아님 |

| 칸 경계 걸침 | 빈 기준 방식에서 변화 영역 후보 | 차량 마스크 기반 위반 확정 기능은 없음 |



자동 수집의 초기 점유 방식은 등록된 B안 모델, 없으면 스티커 근거 방식입니다. 자동으로 모든 칸이 비어 있다고 가정하여 빈 기준을 만들지 않습니다. 전체 빈칸까지 자동 판단하려면 검증된 점유 모델을 연결해야 합니다. 모델 없는 스티커 방식에서는 빈칸으로 보이는 칸도 관측 보류입니다.



운영 D-39 번호는 `23,42,57,85,14,32,55,75,10,11,12,20,21,22,24,30,33,34,40,41,43,44,58,88`입니다. 예전 사진의 49를 현재 번호로 바꾸어 맞추지 않습니다. 번호 판독 충돌, 한 처리 영상만 성공, 여러 칸의 같은 번호, 이웃 칸의 스티커는 보류합니다. 알려진 배정표 색은 실제 색 판독을 대체하지 않습니다.



## 4. 저장 구조와 이름



```text

datasets/

  raw/A/<사진ID>.png                         변경하지 않은 카메라 원본

  manifests/<사진ID>.json                    기계용 촬영·구도·해시 기록

  predictions/<사진ID>.json                  자동 예측과 OCR 근거

  spaces/A/A-01/<사진ID>.png                  글자를 그리지 않은 칸 크롭

  stickers/<사진ID>_A-01.png                  무표시 스티커 크롭

  collected/A/A-01/

    A-01__<촬영UTC>__<사진ID>.png             칸명·경계·번호·색 표시사진

    A-01__<촬영UTC>__<사진ID>.json            같은 이름의 한글 라벨

  collected/B/A-01/...                       B주차장의 A-01칸은 별도 폴더

  scenes/A/A주차장__<촬영UTC>__<사진ID>.png   전체 장면 표시사진

  scenes/A/A주차장__<촬영UTC>__<사진ID>.json  전체 칸을 모은 한글 결과

  assets/<사진ID>.json                       무표시 자산 완료 기록

  bundles/<사진ID>.json                      표시사진·JSON 쌍과 해시 완료 기록

  reviews/<사진ID>.json                      선택적으로 작성한 사람 정답

  calibration_anchors/...                    자동 등록 기준과 해시

  setup_attempts/...                         자동 등록 진단

  reports/audit-<ID>.json / .md               범위별 품질·정답 대조

  exports/automatic-<ID>/...                  내보내기 복사본

```



한글 JSON의 주요 값은 `주차장`, `주차칸명`, `주차칸종류`, `촬영시각_UTC`, `프레임번호`, `주차칸꼭짓점_px`, `점유상태`, `차량번호`, `스티커색`, `번호영역_xyxy_px`, `스티커꼭짓점_px`, `점유판단근거`, `번호판독점수`, `영상품질`, `자동정보완성`, `사람검수완료`, `라벨출처`, `원본사진파일`, `표시사진파일`, `한글라벨파일`, 각 SHA256입니다. 숫자 23은 문자열만 저장하지 않고 `차량번호: 23` 정수도 기록합니다. 미확인 번호는 null이며 임의의 0/가짜 번호로 채우지 않습니다.



모든 꼭짓점과 번호 박스는 **원본 전체 영상의 좌상단 (0,0)을 기준으로 한 픽셀 좌표**입니다. 칸 크롭 시작점도 별도로 기록합니다. 표시사진에는 설명 여백이 추가되므로 표시사진의 크기를 원본 좌표 기준으로 사용하면 안 됩니다. 초록 실선은 칸의 실제 세 면, 주황 점선은 가상 입구, 주황 실선은 스티커, 하늘색은 번호 영역입니다. 표시는 원본의 복사본에만 그립니다.



ㄷ자 칸 JSON에는 `주차선형태`, `실제주차선_3면_px`, `입구가상경계_px`, `주차선지지비율`도 포함됩니다. 선 지지비율은 픽셀 근거이며 정답 확률이 아닙니다. 경계가 겹치지 않도록 계산 ROI는 검출선에서 원본 기준 2 px 안쪽으로 둡니다.



기존 영어 키의 기계용 JSON은 호환성과 상세 근거 보존을 위해 유지하고, 사용자용 한글 JSON을 추가합니다. 자동 후보에는 `사람검수완료: false`와 `자동 생성 후보 · 미검수`가 표시됩니다. 사람 정답 저장 시 해당 칸 사진과 한글 JSON을 다시 생성하지만 원래 예측과 원본은 보존합니다.



## 5. 파일 수량과 내보내기



UI는 디스크 기록과 해시를 대조해 원본·무표시 크롭·스티커·표시사진·한글 JSON·정상 짝·승인 라벨·학습 가능 수를 구분합니다. 정보완성은 필요한 값이 존재한다는 뜻이며 정확도 100%라는 뜻이 아닙니다. 미확인 수와 화질주의 수도 따로 표시합니다.



**칸별 사진·JSON 내보내기**는 현재 집계 범위(전체/현재 주차장/현재 세션)에 맞는 완성 묶음을 `exports/automatic-<ID>`로 복사합니다. 미검수 자동 후보도 포함되며 각 JSON에 출처가 남습니다. 원본을 삭제하거나 이동하지 않습니다. 복사가 끝나면 UI에 장면 수, 칸 사진·JSON 쌍, 이미지 수, 원본 수, JSON 수, 제외 수, 경로가 나옵니다. 제외 사유와 해시는 `내보내기_결과.json`에 기록됩니다. 파일 유실·해시 불일치·부분 실패 묶음은 제외합니다. 복사 중 오류는 완료로 표시하지 않습니다.



| 전칸 장면 수 | 칸별 쌍 | 이미지 합계 | 데이터 JSON | 별도 결과 기록 |

|---|---:|---:|---:|---:|

| A 1장 | 12 | 14 = 칸12+전체1+원본1 | 13 = 칸12+전체1 | JSON 1개 |

| B 1장 | 16 | 18 = 칸16+전체1+원본1 | 17 = 칸16+전체1 | JSON 1개 |

| A+B 각1장 | 28 | 32 | 30 | 같은 내보내기 묶음이면 JSON 1개 |



따라서 마지막 행의 폴더에서 파일 확장자만 세면 JSON은 **31개**입니다. UI의 30개는 데이터 JSON만 센 값이며 결과 기록 1개는 별도입니다. 원래 수집 폴더에는 manifests/predictions/assets/bundles 등 내부 JSON도 있어 단순 확장자 개수와 같지 않습니다.



아래 **승인 자료·표시사진 내보내기**, **승인 학습 크롭 내보내기**는 사람이 검수한 자료를 내보내는 기존 기능입니다. 자동 수집본 내보내기와 용도가 다릅니다. 번호 정답이 있어도 번호 영역 박스가 없으면 번호 학습 크롭은 제외합니다. 표시 글자가 그려진 사진은 발표·검토용이며, 학습에는 무표시 원본·크롭과 좌표 라벨을 사용합니다.



## 6. 품질과 정답 대조



`영상품질`은 라플라시안 선명도 분산·어두운 픽셀 비율·밝은 픽셀 비율·주의사항을 숫자와 한글로 제공합니다. 초기 화질 지표는 현장 정답률을 보증하지 않습니다. 초점/거리/반사를 조정하고, 정보가 없는 칸은 재촬영 대상으로 확인합니다. 미확인 사진도 원본 증거로 보존하여 실패를 숨기지 않습니다.



**현재 범위 품질·정답 대조**는 저장된 자동 예측과 사람 승인 정답을 비교합니다. 점유·번호·색 각각 비교 수, 일치 수, 보류 수, 예측한 경우의 일치율, 보류 포함 일치율, 예측 커버리지를 제공합니다. 승인 정답이 없으면 평가 자료 없음/null이며 100%로 표시하지 않습니다. 유실·손상 예측은 비교 제외 수로 따로 기록합니다. 칸/색/번호/배치/출처의 수집 커버리지도 보고합니다. 자동 라벨끼리 같은 값을 보인다고 실제 정확도로 계산하지 않습니다.



## 7. 고급/수동 방식



자동 등록이 불가능한 구도는 고급/수동 설정에서 기존 ROI 네 모서리 편집을 사용할 수 있습니다. 전칸 등록과 위치 확인 후 `실시간 시작` 및 `분석 후 자동 저장`으로 수집합니다.



**A안 빈 기준**은 모든 칸이 실제 비어 있을 때 등록합니다. 기본 변화 임계값 35, 빈 비율 0.025 미만, 점유 비율 0.12 초과입니다. 손·그림자·조명 변화도 포함하므로 점유 후보와 경계 걸침 후보를 실제 위반 확정으로 쓰지 않습니다. 기준은 세션 메모리와 references 증빙으로 관리되며 재시작 후 자동 빈칸 승인은 하지 않습니다.



**B안 모델 설정**은 검증된 OpenVINO 점유 2분류 모델의 경로·입력 크기·색 순서·정규화·출력 순서·임계값을 받습니다. `occupancy_model.example.json` 수치는 예시입니다. 선택한 설정은 현재 실행에 적용하며 재시작 후에도 쓰려면 config.json의 occupancy_model에 넣습니다. 임의의 Geti 다중 출력 모델을 그대로 지원하는 연결부는 아닙니다.



서버 전송은 기본 꺼짐입니다. 실제 카메라 출처, 현재 구도, 만료되지 않은 결과만 대상으로 합니다. 사진/합성/녹화는 운영 전송하지 않습니다. 정지·구도 변경·주차장 변경 시 대기 전송과 재시도는 취소합니다. 이미 나간 HTTP는 회수할 수 없고 202 응답은 접수일 뿐 최종 서버 상태를 뜻하지 않습니다. 이번 검증에서 실제 HTTP를 보내지 않았습니다.





## 8. 기존 데이터와 예측 유실·손상 복구



V23 소스·ZIP·원본은 보존했습니다. V24 기본 datasets는 새 위치이므로 **저장 폴더 선택**에서 기존 데이터 루트를 지정하세요. 과거 V21 합성171파일과 V23 실물 보드사진169파일을 읽어 총340파일 해시가 변하지 않았음을 확인했습니다.



D39 계약20261104-d39-v3, prediction-v21-1, 자동 ROI v2/v3, korean-collection-v2, 한글라벨v1과 설치pose는 V23와 같습니다. 정상 V23 자료는 변환 없이 읽습니다. V21의 collection-v1 묶음은 종전처럼 선택 장면 저장 복구가 필요합니다. 한 저장 루트는 한 프로그램에서만 수정하세요.



필수 예측 파일이 유실되거나 잘못됐으면 V24가 완성 묶음으로 내보내지 않습니다. 검수 정답은 저장해 보존하지만 파생 사진/JSON은 partial로 남을 수 있습니다. 원래 예측을 복구한 뒤 **선택 장면 저장 복구**를 사용하세요. 예측을 복구할 수 없다면 원본을 사진 입력으로 다시 분석하여 새 장면 후보를 만들 수 있으나, 이것은 기존 정답의 자동 이전이나 유실된 예측의 원상 복구가 아닙니다. 원래 자료는 보존하고 새 결과를 검수해야 합니다.



복구는 검증된 원본·예측·사람 정답으로 같은 사진ID의 파생 자료를 다시 만듭니다. 원본 수량과 촬영 시각을 바꾸지 않습니다. 원본 자체가 손상됐으면 복구를 거부하며 없는 값을 만들어내지 않습니다.



## 9. 저장·내보내기 완료의 의미



수집은 변경 전 pending 기록 → 원본·예측·자산·표시사진·한글 JSON 쓰기 → 최신 입력 해시 확인 → 완료 기록 순서입니다. 이전 버전의 중단 방어를 유지했습니다. 중단/유실/해시 불일치 자료는 완성본으로 세거나 내보내지 않습니다. 원본은 보존하고 선택 장면 복구로 다시 생성합니다.



UI 수량은 현재 선택 범위의 실제 파일·해시를 검사한 결과입니다. 자동 후보와 사람 정답, 파일 완성과 인식 정확도는 구분합니다. 내보내기는 원본을 지우는 이동이 아니라 복사입니다. 완료 후 경로·장면·칸별쌍·이미지·데이터JSON·제외 수량을 표시하고 별도 결과 JSON을 남깁니다.



저장/분석/등록/복구 중 다른 입력으로 바꿀 수 없는 상태는 안내합니다. 이전 작업의 늦은 결과가 새 주차장 화면을 덮어쓰지 않도록 세대 토큰을 검사합니다. 저장 실패를 성공으로 표시하지 않습니다.



## 10. V24 검증과 설정 안내



전체231개 회귀시험, 별도28곳 저장중단 시험을 통과했습니다. A12/B16 원본 사진의 기하·인식후처리·저장·내보내기는 V24로 실행하고 OCR35회는 V23 실제 CPU 관측 캐시를 재사용했습니다. 결과는 칸28쌍, 이미지32·데이터JSON30·원본2입니다. 빈 보드의 모든 번호/색/점유는 미확인/관측보류이며 추론오류0입니다.



사진을 보다가 최초 카메라 연결을 눌러도 이전 사진·ROI·확인상태가 초기화됩니다. 미저장 정답이 있으면 전환 확인을 거칩니다. 자동 칸 등록 중에는 고급 1회 분석을 시작할 수 없습니다. 스티커 근거 모드에서 후속 OCR이 스티커와 유효 번호를 찾으면 점유 후보도 함께 반영합니다.



점유 모델을 설정할 때 threshold는0~1, size는양의정수2개, std는양수, scale/mean은유한한수이며 scale은0일 수 없습니다. 잘못된 설정은 파일 로드/UI 적용/추론 전에 거부합니다. 예시 설정 파일은 학습된 모델을 포함하지 않습니다.



색 분석은 전체 사진 대신 스티커 주변만 처리하도록 개선했습니다. 같은 출력인지 영상 가장자리까지 검증했습니다. 로컬4000×3000 네영역 색함수 시험의 중앙값 약492ms→1.10ms는 전체 OCR 처리율을 뜻하지 않습니다.
