# V10 → V11: 번호 100까지 지원 및 수집 UI 개선



## 변경 내용



- 실물 번호 허용 범위: 01~99 및 100. 49와 100도 OCR 후보·검수 승인·JSONL 내보내기에서 사용합니다. 한 자리 1을 01로 자동 변환하지 않습니다. 00, 101 이상, 001 등은 승인하지 않습니다. 가상 번호판 규칙은 별도입니다.

- 수집 화면 상단에 ① 연결 → ② 주차장 → ③ ROI → ④ 위치 확인 → ⑤ 촬영 → ⑥ OCR → ⑦ 검수 순서를 표시했습니다.

- 주차칸 ROI 버튼에 용도를 명시하고, 한 장 저장 버튼을 연속 수집보다 앞에 배치했습니다.

- 검수 화면에 이전/다음 칸 버튼을 추가했습니다. 이동 중 입력은 메모리에 유지되며 저장 버튼으로 파일에 저장합니다.

- ‘승인 저장 → 다음 칸’은 현재 칸을 승인 검증하고 저장한 다음 이동합니다. 오류가 있으면 이동하지 않고 안내합니다. 마지막 칸에서는 저장 완료를 표시합니다.

- Ctrl+S로 검수/초안을 저장합니다. 성공 팝업 대신 화면에 완료 메시지를 표시해 반복 검수를 줄였습니다.

- 번호 라벨을 ‘번호 01~100’으로 수정했습니다. 스티커 영역 없이 색만 지정하면 여전히 저장할 수 없습니다. 스티커 내부 네 점을 먼저 지정하세요.



## 실행과 기존 데이터



V11은 별도 폴더에 풀어주세요. 이미 설치된 V10의 XPU 환경을 재사용할 수 있습니다. V11의 main.py가 있는 폴더에서 PowerShell을 열고 아래를 실행하세요.



```powershell

& '<local-path> .\main.py

```



V10의 models 폴더를 V11로 복사하면 모델 재다운로드를 줄일 수 있습니다. 카메라 설정 cameras.json, camera_quality.json과 실제 등록 ROI가 든 configs 폴더도 백업 후 복사할 수 있습니다. 기존 촬영 자료는 datasets를 복사하거나 config.json의 dataset_directory에 기존 데이터 절대 경로를 지정하세요. 두 프로그램을 같은 데이터 경로로 동시에 실행하지 마세요.



번호 규칙 변경에 따라 contract_revision을 1103-sticker-100-v2로 올렸습니다. 과거 OCR은 OCR 시작 시 재분석합니다. 이전 규칙의 검수는 재검수 후 승인해야 내보낼 수 있습니다. 원본 이미지와 과거 검수 파일은 재저장 전까지 유지됩니다. 49가 들어간 사진은 재분석 후 후보를 확인하세요.



## 검증



총 69개 테스트 통과(기존 64개 + 신규 5개), 실패/오류/건너뜀 0. 01~100 전체 번호 경계, 49/100 모의 OCR, 100 승인 내보내기, 실제 Tk 창의 승인 버튼 저장 및 잘못된 번호의 승인 차단을 검사했습니다. main.py --check 통과.



번호 범위 확장은 허용 규칙 변경입니다. 흐릿한 사진의 인식률 향상을 의미하지 않습니다. 사용자가 제공한 V10 로그에서는 B390 XPU OCR 시작 시험 성공을 확인했으며, V11의 실제 카메라 인식률/장시간 GPU 운용은 별도 현장 확인이 필요합니다.
