# V21 → V22 변경 이력



날짜: 2026-11-04. V21을 복사한 별도 V22 수정본입니다. 이전 배포 소스와 ZIP은 덮어쓰지 않았습니다.



## 수정 이유와 결과



1. 재저장/검수 정답 갱신 중 중단되면 이전 complete 표시사진 묶음이 내보내질 수 있었습니다. 갱신 전 manifest와 bundle을 pending으로 만들고 마지막에 완료 처리하도록 수정했습니다.

2. 표시사진이 최신 예측/검수 파일을 반영하는지 확인할 방법이 없었습니다. korean-collection-v2에 입력 SHA256 지문을 추가하고 읽기/내보내기에서 검사합니다.

3. 승인 번호 ` 23 `이 정답 표기에는 23으로 보이지만 한글 JSON 숫자에는 null로 저장되었습니다. 공백을 정규화하고 검증된 display_number를 사용합니다.

4. 자동 ROI 등록 중 새 촬영 묶음을 만들면 결과가 폐기되어 등록 상태에 정체했습니다. 작업 중 변경을 막고 자동 상태·체크박스를 함께 해제합니다. 편집 대화상자와 저장 장면 열기 전 실시간 처리를 멈춥니다.

5. 저장 실패 후 파생 자료를 복구할 경로를 추가했습니다. 선택 장면 저장 복구는 원본/예측/검수 검증 후 같은 ID로 다시 생성합니다. 원본 손상·필수 예측 유실·잘못된 검수는 거부합니다.

6. 내보내기 중복 실행과 저장 루트 변경을 막고, 진행/실패 상태가 이전 성공 수량과 혼동되지 않게 했습니다. 저장·검수·복구 오류 후 디스크 집계를 갱신합니다.

7. 화면의 긴 칸 라벨을 두 줄로 표시하고, 작은 창에서 저장 현황·안내·칸 카드에 공간을 우선 배정했습니다.

- reproduce.py를 V21/V22에 실행: 오래된 장면 내보내기 1→0, 검수 숫자 null→23, 등록 중 묶음 변경 allowed→blocked.

## 규격과 호환



제품V22. D39 계약 20261104-d39-v3, prediction-v21-1, roi-registration-v2, 설치 pose/칸 정의 유지. 표시자료 bundle만 입력 지문을 추가한 korean-collection-v2. V21 묶음은 저장 복구 후 자동 내보내기. 일괄 변환 없음. 원본은 유지하며 같은 데이터 루트는 한 프로그램에서만 수정합니다. V22 자료를 V21로 편집하지 않습니다.



## 미검증·남은 조건



이번 V22에서 실제 OCR/카메라/실제 서버를 실행하지 않았습니다. V21 실제 CPU OCR 합성 시험은 history의 과거 근거로만 보존합니다. 현행 D39 실물 A/B 정답률, 실기기·GPU·장시간·실제 점유 모델·Geti·실제 정전/동기화는 미검증입니다. 자동 등록에는 읽히는 칸 이름·닫힌 사각형이 필요합니다. 모델 없이 스티커가 없으면 빈칸이 아닌 보류이며 차량 마스크 기반 위치 위반 확정은 아직 없습니다. 자동 중복 사진 제거·다중 프로그램 쓰기 잠금·구자료 일괄 변환은 포함하지 않습니다.
