1. 카메라·조명을 고정하고 가장 가까운 칸과 먼 칸에 흰색·초록·파랑 스티커 차량을 놓습니다. 한 번에 보이는 가장 먼 스티커도 확인해야 합니다.

2. ‘카메라 연결’을 누르고 해당 카메라 아래 ‘화질·카메라 설정 / 원본 확대’를 엽니다. 카메라 A/B는 각각 조정합니다.

3. ‘현재 실제값 조회’로 센서 범위를 확인합니다. 처음에는 자동 노출·자동 화이트밸런스를 켜고 ‘적용만’을 누른 뒤 영상이 안정될 때까지 기다립니다.

4. 다시 ‘현재 실제값 조회’를 눌러 자동 설정 결과를 확인합니다. 이 값은 수동 설정의 출발점이며 최적값을 보장하지 않습니다.

5. ‘현재 사진 원본 확대·영역 화질’을 엽니다. 정지 사진이므로 뒤에서 설정을 바꾸더라도 이 창은 갱신되지 않습니다. 바뀐 결과를 보려면 닫고 다시 엽니다.

6. ‘원본 1:1’을 눌러 스티커를 확인하고 휠·오른쪽 드래그로 위치를 맞춥니다. 스티커 주변 왼쪽 위와 오른쪽 아래 두 점을 클릭한 뒤 ‘선택 영역 화질 확인’을 누릅니다. 이 선택은 학습 라벨로 저장되지 않습니다.

7. 숫자 획·색상·반사를 눈으로 확인합니다. 너무 어두우면 조명을 먼저 보완하고, 움직임 흐림이나 반사가 있으면 촬영 조건과 노출을 조정합니다. 한 번에 하나의 조건을 바꾸며 같은 영역을 비교하세요.

8. 일정한 조명에서 고정하려면 자동 노출·자동 화이트밸런스를 해제하고 조회했던 수치를 기준으로 수동 값을 조정합니다. 수동 노출은 노출·게인을 둘 다 입력합니다. 미지원/읽기 전용 옵션은 적용할 수 없습니다.

9. ‘적용만’으로 시험하고 실제값을 확인한 뒤 ‘적용 후 설정 저장’을 누릅니다. 저장 완료 안내를 확인하세요. 저장 파일은 camera_quality.json, 실제값 기록은 logs/camera_A_quality_actual.json 또는 B 파일입니다.

10. 창을 닫고 주차칸 ROI와 화면이 맞는지 확인한 뒤 ‘위치 확인’ → ‘한 장 저장’ → ‘OCR 시작 / 재시도’로 번호·색 결과를 비교합니다. 색은 기존처럼 스티커 내부를 검수에서 지정해야 합니다.



카메라 위치를 옮겼다면 ROI를 다시 등록하세요. 전 칸을 담느라 숫자 자체가 너무 작아지면 노출값 조정으로 해결되지 않을 수 있습니다. 카메라 담당 구역 분할, 촬영 거리, 스티커 크기를 함께 조정해야 합니다.



## 화질 수치 해석과 한계



초기 참고 기준: Laplacian 분산 60 미만은 선명도 낮음 가능성, 회색 밝기 40 미만 픽셀이 35% 초과면 어두운 영역 많음, 245 초과 픽셀이 20% 초과면 밝은 영역/반사 가능성입니다. 현장 정답률로 보정되지 않은 경험적 경고이며 OCR 합격 판정이 아닙니다.



검은 바닥이 많은 전체 화면은 어두움 경고가 자연스럽게 나타날 수 있고, 흰 스티커는 밝은 픽셀 경고가 날 수 있습니다. 그래서 같은 크기의 스티커 영역을 선택해 설정 전후를 비교해야 합니다. 원본 1:1은 이미지 한 픽셀을 캔버스 한 픽셀로 표시하는 배율이며 Windows DPI 배율에 따른 물리 크기는 다를 수 있습니다. 확대는 흐릿한 원본을 복원하지 않습니다. 경고가 있어도 원본 수집을 막거나 삭제하지 않습니다.



V14는 자동 스티커 검출/차량 점유 모델을 추가한 버전이 아닙니다. 카메라 조정으로 모든 번호·색의 확실한 인식을 보장하지 않습니다. 자동 노출 고정 버튼이나 센서 범위를 무시하는 임의 최적값도 적용하지 않습니다. 실제 최적 수치는 현장에서 정답 번호·색과 비교해 선택해야 합니다.

# V12 → V13: 한 사진의 여러 차량·주차칸 분석과 데이터셋 묶음



## 현재 동작과 수정 이유



V12도 등록된 ROI를 모두 순회해 OCR을 수행했습니다. 그러나 최근 분석 검수는 한 번에 한 칸만 보여줘 전체 차량의 처리 상황을 확인하기 어려웠습니다. 이번 버전은 여러 칸의 결과와 모든 텍스트 후보를 한 사진 단위로 관리하고, 승인 라벨도 사진별로 묶습니다.



## 변경 내용



- ‘여러 차량 결과’ 버튼을 수집/저장 자료 탭에 추가했습니다. 저장 자료에서 사진을 선택하면 그 사진, 선택이 없으면 최근 분석 사진을 보여줍니다.

- 한 사진의 등록된 모든 칸을 표로 표시합니다. 번호 후보, 보류 상태, 같은 칸의 복수 글자 후보를 모두 확인할 수 있습니다.

- 표의 칸을 선택하고 ‘선택 칸 검수’를 누르거나 더블클릭하면 해당 칸의 검수로 이동합니다.

- analysis JSON에 frame_summary와 frame_revision=multi-slot-v1을 추가했습니다. 전체 등록 칸 수, 번호 후보가 있는 칸 수, 검수 필요 칸 수, 모든 OCR 글자 후보의 원본 좌표·점수를 보존합니다.

- 여러 칸에서 같은 번호가 나오면 계속 중복 보류합니다. 한 칸에 복수 후보가 있어도 모두 기록하고 단일 차량 번호로 자동 확정하지 않습니다.

- 승인 내보내기의 기존 칸별 JSONL 옆에 *.frames.jsonl을 추가합니다. 동일 image_id의 모든 승인 칸을 annotations 배열로 묶어 한 장에서 여러 객체/영역을 학습 자료로 관리할 기반을 제공합니다.

- 과거 분석 파일에 사진 단위 요약이 없으면 다음 OCR 실행에서 재분석합니다. 기존 검수 규칙과 contract_revision=1103-sticker-100-v2는 유지합니다.



주요 파일: multi_vehicle.py(사진 단위 요약/내보내기), pipeline.py(분석 결과 연결·재분석), main.py(전체 결과 UI), review.py(묶음 내보내기).



## 정확한 범위와 한계



‘한 번에 분석’은 원본 한 장을 제출하면 모든 등록 칸을 분석한다는 의미입니다. 내부에서는 ROI를 순서대로 처리하며, 모든 칸의 연산을 동시에 병렬 실행하는 방식은 아닙니다. 현재 인식 단위는 보통 한 칸에 한 대인 주차 차량의 번호입니다.



아직 차량 검출 모델은 없습니다. 따라서 OCR 후보 수를 차량 대수로 사용하지 않으며 vehicle_count는 null입니다. 번호가 가려지거나 스티커가 너무 작으면 차량이 있어도 번호를 읽지 못할 수 있습니다. 통로/미등록 칸 차량, 한 칸의 여러 차량을 자동으로 개별 추적·분리·확정하는 기능은 구현하지 않았습니다. 주차칸 바닥 문자나 차체 문양이 텍스트 후보가 될 수도 있습니다.



스티커색은 사진별 스티커 내부 네 점을 지정해 검수합니다. 여러 차량의 스티커색을 자동 분할하는 모델은 포함하지 않았습니다. 확대 편집은 V12 기능을 유지합니다.



frames.jsonl은 사진별 승인 칸 라벨이며 차량 검출용 바운딩박스 정답을 새로 만들어낸 것이 아닙니다. annotation_scope에 human_reviewed_parking_spaces_not_vehicle_boxes를 기록합니다. 번호판 박스와 스티커 폴리곤은 사람이 등록한 경우에만 포함됩니다. all_objects_in_image_annotated=false를 유지하므로 일부 승인 자료를 사진 전체 정답 완료로 취급하면 안 됩니다. Geti 전용 가져오기 형식으로의 변환과 실제 모델 학습은 별도입니다.



## 여러 차량 수집 방법



1. 카메라를 고정하고 보이는 각 주차칸에 고유 ROI를 등록합니다. 차 한 대가 아니라 사진에 있는 전체 칸을 등록해야 전체를 분석합니다.

2. 여러 칸에 차량을 배치하고 ‘한 장 저장’ → ‘OCR 시작 / 재시도’를 실행합니다.

3. 분석 후 ‘여러 차량 결과’를 엽니다. 원하는 사진이 있으면 저장 자료 탭에서 먼저 사진을 선택하세요.

4. 번호 후보가 없는 칸이나 중복·복수 후보가 있는 칸을 우선 검수합니다. 미인식을 빈칸으로 승인하지 마세요.

5. 각 차량의 실제 번호·점유·스티커색과 영역을 확인하고 승인 저장합니다.

6. ‘승인 자료 내보내기’를 실행하면 기존 *.jsonl과 사진 단위 *.frames.jsonl이 함께 생성됩니다.



데이터 수집에는 빈칸/한 대/여러 대, 서로 다른 배치, 겹침·가림·조명 변화도 포함하세요. 같은 사진 또는 같은 연속 배치의 칸들을 학습/평가로 따로 흩어 넣으면 누수가 생길 수 있으므로 image_id와 batch_id로 함께 관리하세요. 이를 바탕으로 후속 차량/스티커 검출 모델을 학습·검증해야 모든 차량 자동 인식으로 확장할 수 있습니다.



## 실행과 이전



V13 ZIP을 별도 폴더에 풀고 main.py가 있는 폴더에서 실행합니다.



```powershell

& '<local-path> .\main.py

```



기존 models, 카메라 설정, configs의 등록 ROI를 V13으로 복사해 재사용할 수 있습니다. 데이터는 datasets를 복사하거나 config.json의 dataset_directory에 기존 자료 경로를 지정하세요. 동일 자료 경로로 여러 버전을 동시에 실행하지 마세요. 기존 실행 환경 폴더를 삭제하면 위 Python 경로는 사용할 수 없습니다.



## 검증



기존 73개 + 신규 6개, 총 79개 시험 통과. 세 칸의 12·49·100 모의 OCR 결과와 원본 좌표 연결, 같은 칸 복수 후보 보존, 칸 사이 중복 번호 보류, 미인식 점유 unknown, 세 칸 승인 자료의 한 사진 묶음, 실제 Tk 전체 결과 창을 검사했습니다. Python 구문과 main.py --check 통과. 실제 여러 차량 영상의 인식률·GPU 처리 속도·Geti 학습·서버 연동은 미검증입니다.





# V11 → V12 스티커 편집 개선



## 확인된 V11 문제



1. 전체 영상을 화면 크기로 축소해 보여주고 확대·이동 조작을 제공하지 않았습니다. 작은 스티커는 클릭 오차가 생기기 쉬웠습니다.

2. 선택한 점을 빨간 원으로만 표시했습니다. 클릭 번호와 연결선이 없어 순서나 교차 여부를 보기 어려웠습니다. 잘못된 영역 검사는 완료를 누른 뒤에만 나타났습니다.

3. 스티커 편집에도 주차칸 등록 안내를 재사용해 ‘등록 0/12칸 · 현재 A-01’이 나왔습니다. 이 표시는 잘못된 UI 안내이며, 그 자체가 검수 대상 칸을 A-01로 바꾸는 것은 아닙니다.

4. 스티커 위치와 주차칸 전체 위치를 같은 축척으로 다뤄 사진마다 작은 점 네 개를 반복 지정해야 했습니다. 원본이 흐릿하면 확대하더라도 세부 정보가 새로 생기는 것은 아닙니다.



## V12 수정



- 스티커 편집을 열면 검수 중인 주차칸 주변을 자동 확대합니다. ‘선택 칸 확대’로 되돌릴 수 있습니다.

- ‘확대 +’, ‘축소 −’, ‘전체 보기’ 버튼 및 마우스 휠 확대/축소를 추가했습니다.

- 오른쪽 마우스 버튼을 누른 채 드래그하면 확대된 화면을 이동합니다.

- 화면 표시 크기와 원본 좌표를 분리했습니다. 확대·이동 중 클릭해도 원본 이미지 좌표를 저장하며 기존 점은 화면 배율을 바꿔도 유지됩니다. 전체 확대 비트맵 대신 고정 크기 화면 영역을 렌더링합니다.

- 점마다 1~4 번호와 주황색 연결선을 표시합니다. 네 점이면 마지막 점에서 첫 점까지 닫습니다.

- 스티커 편집은 ‘스티커 내부 선택점 n/4’, 번호판 박스 편집은 ‘번호판 박스 선택점 n/2’, 주차칸 편집은 해당 칸 등록 안내로 구분했습니다.

- 네 점이 교차하거나 유효하지 않으면 하단에 오류를 표시합니다. 저장 전 영역 검증도 유지합니다.



주요 수정 파일: widgets.py(편집·좌표 변환·검수 연결), main.py(V12 제목), tests/test_v9_gui.py(회귀 시험). 번호 01~99 및 100, Intel XPU 경로, 스티커 내부 색 측정 규칙은 동일합니다. 자료 규칙은 1103-sticker-100-v2이며 UI 변경만으로 올리지 않았습니다.



## 사용 순서



1. 검수 화면에서 해당 칸을 선택하고 ‘스티커 내부 네 모서리 지정 + 색 측정’을 누릅니다.

2. 선택 칸 주변이 확대되어 보입니다. 스티커 위에 마우스를 놓고 휠을 올려 추가 확대하세요.

3. 위치가 벗어나면 오른쪽 버튼을 누르고 드래그하세요. ‘전체 보기’로 사진 전체를 다시 볼 수 있습니다.

4. 바닥·차체를 제외하고 스티커 테두리 안쪽을 시계 방향 또는 반시계 방향으로 네 번 클릭합니다. 연결선이 교차하지 않도록 하세요.

5. 잘못 찍었으면 ‘점 취소’로 마지막 점부터 되돌립니다. 네 점과 연결선을 확인한 뒤 ‘완료’를 누릅니다.

6. 검수 화면에서 대상 칸·측정 색·번호를 확인하고 승인 저장합니다. 완료 버튼만으로 최종 검수 파일이 승인 저장되는 것은 아닙니다.



## 설치와 데이터 이전




가상환경 경로의 폴더를 삭제/이동하면 위 명령이 실패합니다. 새 환경이 필요할 때만 install_intel_gpu.bat를 사용하세요.



기존 models를 V12로 복사하면 모델 재다운로드를 줄입니다. 기존 cameras.json, camera_quality.json과 configs 폴더를 복사하면 장치 설정과 등록 ROI를 이어 쓸 수 있습니다. datasets를 복사하거나 config.json의 dataset_directory를 기존 자료 절대 경로로 지정하면 기존 사진·검수를 이어갑니다. 프로그램을 같은 데이터셋으로 동시에 실행하지 마세요. V11과 V12의 규칙은 같으므로 버전 변경만으로 기존 검수의 재승인을 요구하지 않습니다.

# V10 → V11: 번호 100까지 지원 및 수집 UI 개선



## 변경 내용



- 실물 번호 허용 범위: 01~99 및 100. 49와 100도 OCR 후보·검수 승인·JSONL 내보내기에서 사용합니다. 한 자리 1을 01로 자동 변환하지 않습니다. 00, 101 이상, 001 등은 승인하지 않습니다. 가상 번호판 규칙은 별도입니다.

- 수집 화면 상단에 ① 연결 → ② 주차장 → ③ ROI → ④ 위치 확인 → ⑤ 촬영 → ⑥ OCR → ⑦ 검수 순서를 표시했습니다.

- 주차칸 ROI 버튼에 용도를 명시하고, 한 장 저장 버튼을 연속 수집보다 앞에 배치했습니다.

- 검수 화면에 이전/다음 칸 버튼을 추가했습니다. 이동 중 입력은 메모리에 유지되며 저장 버튼으로 파일에 저장합니다.

- ‘승인 저장 → 다음 칸’은 현재 칸을 승인 검증하고 저장한 다음 이동합니다. 오류가 있으면 이동하지 않고 안내합니다. 마지막 칸에서는 저장 완료를 표시합니다.

- Ctrl+S로 검수/초안을 저장합니다. 성공 팝업 대신 화면에 완료 메시지를 표시해 반복 검수를 줄였습니다.

- 번호 라벨을 ‘번호 01~100’으로 수정했습니다. 스티커 영역 없이 색만 지정하면 여전히 저장할 수 없습니다. 스티커 내부 네 점을 먼저 지정하세요.
