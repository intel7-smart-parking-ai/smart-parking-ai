# V33 최종 검수 — 주차장 촬영 배치와 학습 데이터 중복



V32를 기준으로 한 대의 카메라 입력에서 주차칸 등록, 분석, 화면에 표시한 프레임 저장, 검수, 학습 자료 전달까지 연결해 점검했습니다. 이번 변경의 목적은 **어떤 촬영에서 나온 정답인지 보존하고, 같은 사진으로 학습과 성능 평가를 동시에 하지 않도록 하는 것**입니다. 실차 번호·색 인식 모델이나 점유 임계값을 변경한 작업은 아닙니다.



## 1. 무엇을 재현하고 고쳤는가



다음 결과는 사용자 데이터가 아닌 임시 데이터셋에서 확인했습니다. [같은 시나리오의 두 버전 결과](FIX_VERIFICATION_V33.json)와 [V32 재현 기록](V32_REPRODUCTIONS.json)을 함께 제공합니다.



| 조건 | V32에서 일어난 일 | V33의 결과 |

|---|---|---|

| 사진 저장 → 새 촬영 배치 → 이전 사진이 그대로인 상태에서 저장 | 이전 사진 ID와 이전 배치가 재사용됨 | 이전 사진을 해제합니다. 배치 시작 전 수신한 카메라 프레임도 보류하고 새 입력부터 새 배치에 저장합니다. |

| 저장 함수에 다른 배치 또는 세션의 기존 사진 ID 전달 | 요청 그룹과 다른 기존 기록을 갱신함 | 원본·검수·파생 파일을 쓰기 전에 거절합니다. 거절 전후 입력 파일 해시가 동일했습니다. |

| 프레임 1의 저장이 끝나기 전에 시각과 ROI가 같은 프레임 2를 표시 | 프레임 2에 프레임 1의 저장 ID가 연결됨 | 카메라·일련번호·프레임·시각·연결 구간·출처·ROI·배치·세션·시점·저장 위치를 대조합니다. 화면에 잘못된 저장 ID를 연결하지 않습니다. 늦은 번호 결과의 실시간 전송 여부도 관측 단위로 검사합니다. |

| 공통 저장 함수에 카메라 프레임과 이전 사진 가져오기 설정을 전달 | 출처가 사진으로 저장되고 같은 프레임의 재시도가 실패함 | 카메라로 저장하고 이전 사진 이름·해시를 가져가지 않습니다. 같은 사진의 재시도는 같은 ID가 됩니다. 출처가 맞는 가져온 사진의 이름·해시는 유지합니다. |

| 같은 A주차장 12칸 원본을 압축 설정만 달리한 PNG 두 개로 저장하고 서로 다른 분할의 두 배치에서 전칸 승인 | 같은 픽셀의 칸 24개가 학습·검증에 나뉘어 완료 처리됨 | 두 원본의 크기·픽셀이 같아 내보내기가 실패합니다. 완료 학습 샘플 0개이며 사유에 충돌한 사진 ID·배치·분할이 나옵니다. 한 분할 안의 같은 사진은 허용합니다. |



## 2. 현장에서의 수집 흐름



1. 실제 보드와 UI의 주차장·촬영 시점을 맞춥니다. A주차장은 양쪽 6칸씩 직사각형 12칸, B주차장은 양쪽 8칸씩 사선 16칸입니다. 두 보드 모두 A/B 구역명을 포함합니다. 기본 시점은 천장이며 오른쪽·왼쪽·위쪽·아래쪽은 촬영자가 선택합니다.

2. 실제로 칠한 ㄷ자 세 변과 칸 입구를 구분합니다. 표시는 실제 선을 따르고, 칸 귀속과 자르기에는 네 꼭짓점을 사용합니다. ArUco가 등록된 보드는 현재 프레임에 맞게 칸 좌표를 갱신합니다. 필요한 마커가 가려지거나 카메라·해상도가 기준과 다르면 보류합니다.

3. 전체 칸의 점유 후보, D39 번호, 흰색·초록·파랑 **스티커 배경색**을 분석합니다. 번호를 읽지 못하면 미확인으로 남깁니다. 전용 구역의 차종 비교·경계 후보는 참고 경고이며, 차량 외곽을 측정한 위반 확정이 아닙니다.

4. 차량 위치나 배치 자체를 바꿨을 때 **새 촬영 배치**를 누릅니다. 카메라 상태에서는 다음 프레임, 사진 상태에서는 새로 선택한 사진이 필요합니다. 차량 배치는 같고 카메라 방향만 바꾸는 경우 **현재 촬영 시점**만 바꿉니다. 같은 배치의 여러 시점이 학습·검증·시험으로 흩어지지 않게 하는 조건입니다.

5. 원본, 칸 크롭, 표시 사진·한글 JSON, 전체 표시 장면·JSON, 품질 판정과 검수를 같은 장면에 연결합니다. 새 배치를 만들었다고 이전 배치의 파일을 이동하거나 수정하지 않습니다. 저장 재시도에는 V32와 같은 사진 ID 계산식을 사용합니다.

6. UI에서 촬영 장면·고유 원본 파일·칸별 짝·품질 통과/보류·승인 수량을 확인합니다. 전체 후보 전달과 품질 선별 전달은 다릅니다. 학습 전달은 품질 통과와 사람 승인을 요구하며, 동일 원본의 분할 충돌이 있으면 완료 수량에 포함하지 않습니다.



## 3. 코드 경계와 저장 호환성



| 위치 | 확인한 책임 |

|---|---|

| [dashboard.py](dashboard.py) | 촬영 배치 시작 시 남아 있던 입력과 칸 상세를 해제합니다. 배치 시작 이후 프레임인지 수신 시각으로 검사합니다. 저장 완료는 요청 당시 문맥이 현재 화면과 같을 때만 연결합니다. 세션 동안 모든 저장 ID를 쌓던 메모리 사전을 없앴습니다. |

| [dataset19.py](dataset19.py) | 화면과 저장 함수가 같은 방식으로 사진 ID를 계산합니다. 기존 ID의 배치·세션 불일치를 쓰기 전에 거절합니다. 승인된 학습 장면마다 디코딩된 원본을 한 번 지문으로 계산해 분할 간 충돌을 검사합니다. |

| [records.py](records.py), [pipeline.py](pipeline.py), [main.py](main.py) | 프레임이 입력 출처를 결정합니다. 종류가 맞을 때만 부가 정보를 복사하며, 저장 설정에도 같은 출처를 남깁니다. 과거 가져오기 UI에서 명시한 가상 이미지 같은 출처도 프레임에 기록합니다. |

| [capture_recovery.py](capture_recovery.py), [collection_output.py](collection_output.py), [export_integrity.py](export_integrity.py) | 미완료 기록, PNG/JSON 짝 대조, 내보내기 상태와 복사본 해시 검증이 계속 적용되는지 통합 시험했습니다. 원본 복사가 끝났다는 것과 내보내기 전체가 완료됐다는 것을 구분합니다. |



촬영 스키마, ROI·마커 등록 규격, D39 규칙, 설치 pose, 품질 판정 기준은 유지합니다. 학습 manifest의 샘플에는 기존 파일 해시와 함께 선택 항목 `raw_pixels_sha256`이 추가됩니다. BGR8·너비·높이를 접두부에 넣은 뒤 행 순서대로 픽셀 바이트를 SHA-256으로 계산합니다. **완전히 동일한 픽셀**을 검사하므로 화면을 다시 찍거나, JPEG 재압축·리사이즈·회전 등으로 픽셀이 달라진 유사 사진까지 판별하지는 않습니다. 독립된 차량 배치로 평가 세트를 구성해야 합니다.



V33을 새 폴더에 풀고 **저장 폴더 선택**에서 기존 데이터 루트를 지정하면 됩니다. 기존 기록의 배치·출처를 일괄로 추정하거나 재분류하지 않습니다. 충돌한 학습 자료는 오류에 나온 두 원본과 배치를 확인하고 독립된 촬영 자료로 다시 구성한 후 내보내세요. 실패 폴더의 일부 크롭은 학습 자료로 사용하지 않습니다.

- 중단 모의 시험: 재저장·검수 30, 최초 저장·전달 41, 선별 자료 전달 30, 선별 학습 전달 15, 마커 기준 등록 4. 합계 120가지입니다. 실제 전원 차단이나 USB 분리가 아닌 프로그램의 쓰기 경계에서 중단을 주입한 결과입니다.

- [ArUco 시험](ARUCO_VALIDATION_V33.json): 합성 보드에서 A/B 각 6개 마커로 좌표 갱신, 칸별 저장·전달, 기준 등록 중단을 확인했습니다. [구버전 호환](PREVIOUS_DATA_REUSE_V33.json): 기존 검증용 데이터 11개 루트에서 1,894개 파일의 점검 전후 해시가 동일했습니다.

- 실제 천장 카메라·출력 마커·현재 D39 차량으로 점유·번호·색 정답률은 측정하지 않았습니다. 장비 도착 뒤에는 천장부터 독립 배치로 촬영해 주차칸 귀속, 번호·색 일치, 보류율을 사람 정답과 대조한 다음 다른 네 시점에 같은 검사를 적용하세요. 새 딥러닝 학습, 실제 Geti 전달, 장시간 카메라·동기화 경쟁 시험도 이번 범위에서 실시하지 않았습니다.
