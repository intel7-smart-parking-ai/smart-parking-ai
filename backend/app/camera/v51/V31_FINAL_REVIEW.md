# V31 ArUco 통합 및 전체 흐름 심층 검수



2026-11-05. **V30의 수집·선별·검수·내보내기 흐름에 ArUco 기준 등록과 프레임별 주차칸 좌표 갱신을 실제로 연결한 V31**입니다. V30은 적합성 분석/분리된 합성 실험 단계였고, V31은 실행 프로그램에 들어간 기능 수정입니다. 기존 배포본은 덮어쓰지 않았습니다.

## 2. 실제 실행 흐름과 검수 결과



### 진입·입력·작업 분리



`run_windows.bat → main.main → Dashboard`가 현재 통합 UI입니다. `main.py`에 남아 있는 이전 `App` 클래스는 현재 기본 진입점에서 생성하지 않습니다. 설정/카메라·레이아웃 검사는 `main.py --check`, 모델 확인은 별도 옵션입니다. V31 설정 검사에는 ArUco API 유무도 추가했습니다. 실행 환경의 OpenCV는 5.0.0이고 요구 버전 하한은 4.7입니다. 이번 작업에서 패키지나 모델을 설치하지 않았습니다.



카메라/사진 입력은 `FramePacket`으로 식별됩니다. 카메라 ID, 시리얼, 프레임 번호, 시각, 재연결 구간, 원본 BGR 영상, 출처가 분리되어 있습니다. UI는 빠른 분석/번호 OCR/입출력 작업자를 나눕니다. Tk 위젯은 메인 스레드에서만 갱신합니다. 주차장/시점 변경·중단 시 generation을 바꾸어 늦은 결과를 버리는 기존 구조를 유지했습니다.



### 최초 기준 등록



`automatic_setup.prepare_auto_scene`는 데이터 루트의 `marker_boards/<lot>.json`을 먼저 확인합니다. 기준이 있으면 검증 후 `marker_setup.locate`를 사용합니다. 기준이 손상되거나 현재 마커가 부족하면 오류를 반환하며 과거 ROI/ORB 기준으로 자동 후퇴하지 않습니다.



기준이 없을 때는 V30의 주차선/칸 이름 인식과 동일 구도 재사용 흐름을 유지합니다. 전체 칸의 유효한 ROI와 4개 이상의 마커가 함께 보이면 `enroll`로 처음 기준을 저장합니다. OCR이 전체 칸을 못 찾는 경우에는 사람이 전체 ROI를 먼저 지정한 후 UI의 등록 버튼을 사용할 수 있습니다. 마커만으로 처음부터 각 칸의 명칭을 추정하지 않습니다.



처음 기준은 전체 A12/B16의 실제 좌표·타입·경계 메타데이터, 검출 ID와 모서리, 카메라/해상도, 원본 픽셀 해시로 구성됩니다. 기준 자체의 canonical JSON SHA256을 저장합니다. 마커 기준으로 투영한 ROI를 새 원본 기준으로 반복 등록하지 못하게 하여 오차 누적을 방지했습니다.



### 마커 검출·평면 좌표 변환



`marker_setup.py`는 `DICT_4X4_50`을 사용하며 A에는 0~5, B에는 10~15를 배정합니다. ID 중복/다른 판/미지정 ID를 거부합니다. 처음 등록에는 최소 4개와 모든 칸을 둘러싸는 배치가 필요합니다. 추적에는 기준에 등록된 최소 3개의 넓게 분산된 마커가 필요합니다.



각 마커 4개 모서리의 전체 대응점을 이용합니다. 일부 마커만 남겨 강제로 통과시키는 이상점 제거를 하지 않습니다. 전체 재투영 최대 3px, 한 마커를 제외한 교차 예측 최대 5px, 최소 변 길이 20px, 기준 대비 관측점 분포를 검사합니다. 모든 칸이 원본 안에 있고, 순서가 뒤집히지 않고, 볼록하고 서로 겹치지 않아야 합니다.



원본 사진을 정면 사진으로 바꾸어 저장하지 않습니다. 바닥 ROI·세 면·가상 입구의 좌표만 현재 원본으로 변환합니다. 마커 등록의 의미가 달라 새 `roi-registration-aruco-v1`을 도입했으며 제품 버전을 이유로 기존 데이터 schema, `number-pixels-v1` 품질 개정, 기본 설치 pose를 바꾸지 않았습니다.



### 프레임별 분석·표시 연결



V30의 분석 작업자는 이름/선 등록에 대해서만 구도 검사를 했습니다. 새로운 method를 추가하고 이 검사를 지나치게 하면 이동 후 이전 좌표를 사용할 수 있으므로 V31에서는 ArUco 전용 재검증 경로를 명시적으로 추가했습니다.



`Worker`가 분석 대상 프레임의 마커를 새로 검출하고 ROI를 계산한 뒤 **작업 token의 ROI도 같은 값으로 교체**합니다. 예측 검증, 번호 OCR 작업, 화면 게시, 저장이 이 token을 전달받습니다. 화면용 옛 좌표와 저장용 새 좌표가 갈라지지 않도록 한 변경입니다. 분석 전 UI의 준비 검사는 재추적을 허용하지만 실제 분석·저장은 매 프레임 근거를 반드시 검사합니다.



마커 근거에는 프레임 번호/시각/재연결 구간/원본 픽셀 SHA256을 고정합니다. `records.validate_capture`는 다른 프레임이나 다른 픽셀에 좌표를 재사용하는 것을 거부합니다. `validate_record`와 `load_original`도 저장된 근거와 원본을 대조합니다. 자동 수집 도중 마커가 사라지면 generation을 갱신하여 이전 OCR 결과가 나중에 도착해도 저장되지 않습니다. 추적되지 않은 최신 생영상에 과거 마커 좌표를 덧그리는 화면 경로도 막았습니다.



### 번호·스티커색·점유



`vision19`, `analysis`, `prediction_contract`, D39 운영번호/색 계약과 품질 판정은 유지됩니다. 차량 번호 OCR을 마커 ID로 대신하지 않습니다. 마커가 있다고 차량이 있다는 뜻도 아닙니다. 자동 수집은 점유 모델이 있으면 분류, 없으면 스티커 근거 후보를 사용합니다. 미검출을 빈칸 정답으로 만들지 않습니다.



카메라가 움직여 ROI가 달라진 경우 이전 빈 기준 비교 영상은 사용하지 않습니다. 그 상태에서 빈 기준 모드를 명시적으로 선택하면 미확인으로 남을 수 있으므로 새 빈 기준 또는 검증된 점유 모델이 필요합니다.



`static_markings`는 원래 칸 이름과 비슷한 흰 스티커를 혼동하지 않도록 기준 외관을 대조합니다. ArUco 이동 뒤에는 최초 이름 영역을 현재 화면에 투영하여 외관을 비교합니다. 현재 차량 이미지를 새로운 바닥 글자 기준으로 학습하지 않으며, 내용이 가려졌거나 달라지면 그 위치를 무조건 제외하지 않습니다.



### 저장·검수·품질



`dataset19.persist_scene → pipeline → capture_recovery`의 기존 쓰기 계약을 유지했습니다. 최초 촬영 저널, 원본, manifest/예측, 무표시 칸 크롭, 표시사진/한글 JSON, 품질 선별과 완료 영수증을 연결합니다. 원본은 보존하며 후보와 승인 정답을 구분합니다.



새 ROI에는 당시의 기준 사본과 현재 검출 근거가 포함됩니다. 따라서 현재 `marker_boards` 파일을 교체하거나 파일을 다른 PC로 옮겨도 과거 장면 검증에 현재 기준을 강제로 적용하지 않습니다. 마커 기준 파일 자체는 수집 장면/라벨 수로 집계하지 않습니다.



한글 JSON의 `마커등록근거`와 촬영 manifest의 값이 일치하는지 읽기/내보내기에서 대조합니다. 파일 해시만 다시 계산해서 다른 수치를 넣은 사례도 거부합니다. ㄷ자 선 지지비율은 최초 등록 당시 값임을 명시했고, 현재 마커 변환 오차와 구분했습니다.



새 마커 기준은 참조 사진을 먼저 쓰고 활성 JSON을 마지막에 원자적으로 교체합니다. 중간 중단이면 기존 활성 기준을 유지하거나 새 기준 전체가 남습니다. 근거 없는 반쪽 기준을 활성화하지 않습니다. 참조되지 않는 사진은 보존합니다. 기존 데이터 루트 잠금을 사용하므로 다른 V28 이상 작성자와 동시에 무단 수정하지 않습니다.



### 내보내기·복구



칸별 전체 후보 복사, 품질 통과 사진/JSON, 사람 승인 자료, 품질 통과+사람 승인 학습 크롭의 조건을 유지했습니다. ArUco 등록 성공만으로 품질 통과나 사람 승인을 만들지 않습니다. `quality_selection`의 번호 자체 선명도·노출·16px 기본 크기·스티커 겹침·과거 판정 재검사도 유지합니다.



내보내기는 원본을 지우는 이동이 아니라 검증된 복사입니다. 완료 영수증/파일 해시/장면·칸쌍·이미지·JSON 수를 확인합니다. 마커 장면에서 저장 중단 복구, 기준 파일이 없는 과거 장면 열기/복사, 승인 후 선별/학습 전달을 추가로 시험했습니다. 사용자 데이터 루트의 파일은 자동 이전하거나 재라벨링하지 않았습니다.

중간 검증 이력도 남깁니다. 최초 신규 시험25개와 전체394개가 통과한 뒤 저장 근거/복구/교차 검증/UI 지연 결과 시험을 추가하여 404개 통과 뒤 바닥 글자의 투영 외관/가림 시험2개를 추가하여 최종406개를 실행했습니다. 인쇄 생성 도구에서 OpenCV5 ID 반환 배열이 1차원인 경우를 수정해 12개 생성/재검출을 완료했습니다. 실제 사진 검증은 처음 ROI만 실행해 과거 OCR7회가 재사용되어, 35회를 요구한 포장 검증이 실패했습니다. 이 결과를 별도로 보존한 뒤 번호 OCR 경로까지 과거 관측을 재생해35회·28쌍 검증을 마쳤습니다. 사용자 촬영 자료나 판정 기준을 이 실패에 맞춰 변경하지 않았습니다.

## 5. 호환성과 현장 한계



- V31에서 이전 V30 데이터 루트를 선택하여 읽기/검수/수집할 수 있습니다. 기존 자료는 마커 근거가 없더라도 기존 계약으로 검증합니다. 새 마커 장면은 해당 근거를 모르는 V30에서 지원하지 않으므로 같은 신규 데이터에 구버전으로 쓰기를 계속하지 마세요.

- 현재 카메라/시리얼/해상도와 다른 기준은 거부합니다. 다른 입력 장치나 해상도에서는 전체 기준을 다시 만듭니다. `IMPORT` 사진용 기준과 실제 카메라 기준은 구분됩니다.

- 최초 전체 ROI 확인은 필요합니다. 잘못된 첫 경계를 마커가 알아서 수정해 주지 않습니다. 모든 마커를 보드와 함께 움직이는 것은 허용하지만 개별 마커의 상대 배치를 바꾸면 재등록해야 합니다.

- 실제 인쇄 마커·현재 D39 차량·천장 카메라·여러 실제 시점 사진이 없어 현장 정확도와 속도 개선율은 미측정입니다. 20/3/5px 초기 기준은 현장 샘플로 평가해야 합니다.

- 평면 변환은 차량 높이/가림/심한 왜곡/휘어진 판을 해결하지 않습니다. 실제 각도 측정, 렌즈 보정/ChArUco, 차량 외곽 기반 위반 모델, 딥러닝 학습은 추가되지 않았습니다.

- 장시간 카메라 연속 운영, GPU/Geti/실서버, 실제 정전·OneDrive 경쟁, 실제 인쇄 크기와 육안 UI/DPI 검수는 미검증입니다. 이번 시험은 검증된 범위의 소프트웨어 회귀이며 현장 완벽성 인증이 아닙니다.



다음 현장 단계는 [ArUco 안내](ARUCO_GUIDE.md)의 설치 후 검증 항목을 사용하여 천장 자료부터 정답을 확보하는 것입니다. 자동 등록 성공과 번호·색·점유 정답률을 분리해 기록하고, 보류 이유별로 카메라 거리·빛·인쇄 크기를 조정해야 합니다.



## 6. 참고와 재현 근거



설치·수집은 [START_HERE.md](START_HERE.md), 새 기능 상세는 [ARUCO_GUIDE.md](ARUCO_GUIDE.md), 시험 수치는 [VALIDATION.json](VALIDATION.json)과 각 `*_V31.json`을 확인합니다. `run_tests.py`로 회귀를 재실행할 수 있습니다. 작업 폴더 `verification_v31`에는 중단 시험, 실제 사진 재생, 마커 합성/지연 측정, 배포 검증 스크립트와 실행 로그를 보존했습니다.



ArUco ID/코너/생성 API는 [OpenCV 공식 마커 문서](https://docs.opencv.org/5.0/tutorials/objdetect/aruco_detection/aruco_detection.html)를 참조했습니다. 평면 대응과 내부 파라미터를 이용한 pose 해석은 [공식 homography 문서](https://docs.opencv.org/5.0/tutorials/features/homography/homography.html)를 참조했습니다. 수집 중 최소 마커 개수와 오차 문턱은 이 프로그램에서 정한 정책이며 공식 문서의 보편적 요구값으로 주장하지 않습니다.
