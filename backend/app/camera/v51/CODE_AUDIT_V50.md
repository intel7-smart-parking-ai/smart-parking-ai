# V50 일곱 항목 코드 진단



## 1. 번호를 직접 읽은 경우와 추정한 경우



`round_sticker.identify`가 국소 OCR에서 서로 다른 번호를 읽고도 인쇄 모양이나 여섯 차량 참고 사진으로 추정하던 경로를 재현했다. 이제 `conflicting_views`가 나오면 관측한 후보와 스티커색을 남기고 번호를 보류한다. `vision19`는 높이 24px 미만의 추정 영역에 원본 픽셀 크기를 표시한다. 기존 두 사진의 11칸은 직접 2·추정 9였다. 추정 영역은 너비 8~13px, 높이 10~12px였다. 아홉 스티커에 국소 OCR을 강제로 적용한 별도 실험에서 다중 영상 합의는 0건이었다. 같은 차량을 반복 촬영한 자료가 포함되어 있다.



새 합성 24개는 그림을 만들기 전에 번호·색·폰트·방향을 고정하고 V49와 V50에 같은 픽셀을 입력했다. V49는 직접 일치 15·추정 일치 5·추정 오답 1·보류 3, V50은 직접 일치 15·추정 일치 1·오답 0·보류 8이었다. 26을 28로 제시한 오류와 37·79·92·95의 맞는 추정이 함께 보류로 바뀌었다. 빈 구역의 오번호는 두 버전 모두 0이었다. 이 변경은 사람이 다시 볼 칸을 늘리는 대가로 근거가 충돌하는 추정을 줄인다.



## 2. 반사·과노출·회전



기존 사진의 원본 및 변환 영상을 판독하고 저장 라벨과 대조했다. 어둡게 변환한 11칸은 직접 1·추정 10, 밝게 변환한 11칸은 직접 1·추정 9·보류 1이었다. 밝은 초록 11이 보류됐다. 77번의 숫자 영역을 흰색으로 완전히 가린 조건에서도 번호가 보류됐다. 흰색 66·99에 대해 네 각도와 실물·가상 처리 경로를 조합한 16건은 모두 흰색을 보존하고 번호를 보류했다. 실제 반사의 정도와 조명별 인식률은 독립 정답이 있는 현장 시험이 필요하다.



## 3. 가상 안내선과 실물 위치



실장치 표본은 모두 가상 안내선 모드였다. 저장된 네 측정의 칸 JSON 112개를 직접 열어 모두 `실물칸확인=false`, `실물주차칸=null`, 사람 승인 전 상태임을 확인했다. 이 가운데 번호 관측은 미확인 108칸, 검토할 추정 4칸이었다. 같은 B-06의 반복 관측이며 고유 차량 4대로 집계할 근거가 없다. 실제 주차 위치와 선 침범 평가는 실물 칸을 등록하고 별도 정답과 대조해야 한다.



지정 구역은 주차장과 칸 이름의 조합으로 찾는다. A주차장의 A-05·A-06은 전기차, B-06은 장애인 구역이다. B주차장의 A-07·A-08은 전기차, B-07·B-08은 장애인 구역이다. 기존 도면과 한글 칸 JSON에는 이미 이 배정이 있었다. V50에서 두 카메라 표와 안내선, 표시사진의 설명, 현장 정답표·보고서와 승인한 학습 사진 목록까지 연결했다. 이전의 두 실물 사진에서 인쇄 도면을 찾아 A 12칸·B 16칸의 표시사진과 JSON을 저장했다. 전기차 4칸·장애인 3칸·일반 21칸이 일치했다. 모의 시험에서는 카메라 A에 B주차장, 카메라 B에 A주차장을 배정하고 28칸의 승인·학습 내보내기까지 대조했다. 새 학습 목록의 구역 누락·불일치는 전체 검사에서 거부한다. 실물판이 안 보이면 가상 위치 근거를 함께 기록한다.



## 4. 수신 시각과 실제 5분 측정



D435 두 대, 1920×1080, 30fps 설정, 허용 PC 수신차 100ms로 300.092초 측정했다. 운전 중 유효한 두 프레임을 고른 관측 2,792회, 다음 짝 대기 22회, 유효 관측의 최대 수신차 16.2122ms였다. 약 50초 간격으로 원본을 남긴 6쌍 중 4쌍은 정상 저장·재열람, 2쌍은 스티커 대기였다. 수신 확인 시 한 채널이 비어 있던 횟수, 연결 회차 변경, 저장 실패는 각각 0이었다. 12개 원본의 SHA-256과 디코딩 RGB를 검사했다. 최종 판독 코드로 12장을 다시 읽어 저장·대기 판단과 저장된 칸별 번호·색·상태의 일치도 확인했다.



`camera_hub`는 같은 RGB 프레임에서 SDK 프레임 번호·시각·시계 종류를 읽는다. 노출시간은 장치에서 제공한 프레임에만 보존한다. `pipeline`, `records`, `dual_capture`, 복구 및 재열람 경로가 이 값을 연결한다. 이번 표본의 SDK 시계는 모두 `system_time`이었고 프레임별 노출시간은 미제공이었다. 센서 노출 동기와 프레임 유실률은 별도로 측정해야 한다. 이번 측정의 분석 간격은 약 50초였으며, GUI 기본 저장 간격으로 5분 내내 저장한 처리량이나 30분 안정성은 미측정이다.



## 5. 빈 기준과 구도 변화



이전 실물 빈 보드 사진과 당시 검수한 28칸 좌표를 사용해 두 빈 기준을 다시 등록하고 사진을 재열람했다. A 사진의 수평 이동량 0·1px에서는 12칸 모두 빈칸, 2·4·6·12px에서는 구도 변경 보류였다. 연결 회차만 바꾼 재생도 재등록을 요구했다. 이 픽셀 수는 해당 사진과 구도의 관측값이다. 강한 스티커 후보 차단, 약한 후보 재확인, 변조된 기준 거부는 회귀 시험에 포함했다. 손이나 번호가 가려진 차량, 실제 차체가 선을 넘은 정도는 촬영자가 기준 원본 두 장과 실제 배치에서 확인해야 한다.



## 6. 학습 전달과 현장 성능



V49의 현장 대조는 선택한 측정의 번호 PNG를 검증했으나 다른 칸의 색·점유 파일이 손상되거나 사라져도 번호 검증이 통과했다. `field_check.inspect_training_folder`를 현장 대조와 **학습 폴더 전체 검사**에 함께 연결했다. 세 과제의 파일 목록·길이·SHA-256·RGB PNG 디코딩·배치 분할·과제/칸 중복을 검사한다. 다시 압축한 파일도 픽셀·크기·과제가 같으면 다른 분할 또는 라벨과 충돌하는지 확인한다. 선택한 측정의 번호는 당시 사람 승인·원본 좌표·독립 정답까지 추가로 대조한다. 로컬 폴더 검사는 Geti 서버의 가져오기와 학습 과정을 평가하지 않는다.



신규 실물 번호 24대의 독립 정답, 실제 조명·방향별 차체 경계 결과, Geti에서 가져온 자료 수와 독립 시험 배치의 모델 성능은 확보하지 못했다. 이 항목들은 미측정으로 기록했다.



## 7. 실행 지침·데이터 보존·회귀



시작 설명서와 기본 실행 화면에 V50을 표기했다. 설명서에는 5분 표본 설정, 수신 시각을 읽는 법, 재촬영과 빈 기준 재등록, 학습 폴더 검사를 추가했다. 과거 결과는 버전을 기재한 기록에서 찾을 수 있다. V49로 만든 장면을 V50에서 읽어 기존 파일 102개의 해시와 28칸 내보내기를 확인했다. 양쪽 원본 저장 후 작업 프로세스를 강제 종료한 시험에서는 충돌한 판독을 보류하고 원본을 보존했으며, 원래 판독 복원 후 28칸을 내보냈다.
