# V29 최종 코드 심층 검수 및 마무리 보고서



2026-11-05 · V28 → V29. 이번 검수는 새로운 기능을 계속 늘리기보다 수집→판정→저장→검수→내보내기의 연결에서 실제 오류를 재현하고 고치는 작업입니다. V28 소스와 ZIP을 보존한 별도 V29 배포본입니다.



## 1. 최종 판단과 확인 범위



확인한 프로그램은 **카메라 한 대로 A 직각12칸/B 사선16칸을 수집하고, 천장 촬영을 우선하며, 현재 시점을 바꾸어 보완 촬영하는 데이터 수집·검수 도구**입니다. 주차칸 명칭·ㄷ자 경계·점유·D39 번호·스티커 배경색 후보를 사진/한글 JSON으로 연결합니다. 차량이 있는 실제 다섯 시점 자료로 학습한 완성 모델을 새로 만든 것은 아닙니다.



최종 검수에서 세 결함을 V28에서 재현했고, 후속 회귀에서 기존 잠금 코드의 강제 종료 직후 일시적 잠금 거부도 관측하여 V29에서 함께 보완했습니다. 정해진 회귀·파일 대조·중단 시험은 통과했지만, 모든 환경에서 오류가 없다는 증명이나 실차 인식 정확도의 증명은 아닙니다. 고정 기능 수용 기준은 **19/20=95%로 유지**합니다. 남은 R18은 차량 외곽을 실제 검출한 선침범·다중칸 점유 판정 및 정답 대조입니다.

번호 기준은 `quality_selection.min_number_short_side`입니다. V29 배포 설정에는16이 명시됩니다. 한국어 품질 JSON에 번호 영역 `너비_px`, `높이_px`, `짧은변_px`가 기록됩니다. 이 수치는 최소 크기 필터이며 번호 판독 정확도를 보장하는 임계값이 아닙니다. 실제 천장 촬영 자료로 추후 보정해야 합니다.



과거 다섯 항목 품질 정책의 지문을 바꾸지 않도록 새 키가 없는 기존 정책은 그대로 읽습니다. 기존 통과 자료라도 번호 크롭이 새 최소 검사에 미달하면 통과 내보내기 전에 거부합니다. **선택 장면 저장 복구**로 판정을 갱신하면 원본을 유지한 채 보류로 표시됩니다. 정상 과거 정책·자료의 호환도 회귀 시험으로 확인했습니다.

## 4. 데이터 수집 조건과 방향성



천장이 기본/최우선 촬영입니다. 위쪽/아래쪽은 주차장 평면의 방향을 뜻하며 천장과 다릅니다. 시점은 사용자가 선택한 기록이고, 센서가 측정한 yaw/pitch/roll이나 영상에서 자동 추정한 정확한 각도가 아닙니다. 카메라 이동 뒤 선택 시점을 바꾸면 주차칸을 다시 등록합니다.



A 주차장: A-01~A-06, B-01~B-06의12칸. B 주차장: A-01~A-08, B-01~B-08의16칸. 주차장 ID와 내부 A/B구역, 카메라 ID는 서로 다른 개념입니다. 실제 ㄷ자 주차선은 세 면을 따라 표시하고, 열린 입구는 가상 점선으로 구분합니다.



번호는 현행 D39 운영 목록, 색은 스티커 배경의 흰색·초록·파랑입니다. 차체색이나 일반 실제 자동차 등록번호 전체를 새로 학습한 기능으로 해석하면 안 됩니다. 모든 칸/문자/스티커가 보이는 구도를 확보해야 자동 등록과 완성 자료 선별이 가능합니다. 보이지 않는 번호를 추정하여 정답으로 저장하지 않습니다.



여러 시점에서 자료를 저장하는 기능과 그 자료로 학습한 모델의 일반화 성능은 별개입니다. 같은 차량 배치의 다른 시점은 같은 batch로 유지하고, 차량 배치를 바꾸었을 때 새 배치를 만듭니다. 앱 재시작은 새 그룹이므로 동일 배치를 반복 촬영해 시험셋에 섞이지 않게 운영해야 합니다. 새 데이터로 실제 모델을 학습·연결한 후 독립 배치에서 평가해야 합니다.



## 5. 저장 파일과 검증 기준



```text

데이터 루트/

  raw/<카메라ID>/천장/<사진ID>.png               무표시 원본

  manifests/<사진ID>.json                       촬영 문맥

  predictions/<사진ID>.json                     자동 후보

  reviews/<사진ID>.json                         사람 정답

  selection/<사진ID>.json                       품질 정책·수치·사유

  collected/A/천장/A-01/A-01__<시각>__<사진ID>.png

  collected/A/천장/A-01/A-01__<시각>__<사진ID>.json

  scenes/A/천장/A주차장__<시각>__<사진ID>.png

  scenes/A/천장/A주차장__<시각>__<사진ID>.json

  assets/, bundles/                            완료 상태·자산 해시

  capture_journal/                             미완료 촬영 복구 기록

  exports/                                     전달용 복사본

  .writer.lock                                 운영체제 잠금 경로

```



천장/A/A-01 부분은 실제 시점·주차장·칸에 맞게 달라집니다. 과거 시점 없는 자료는 기존 경로를 유지합니다. 자료 규격 `korean-collection-v2`, `주차품질선별-v1`, `prediction-v21-1`, D39 contract_revision을 제품 버전만으로 올리지 않았습니다.



한국어 JSON에는 칸명·원본 좌표·ㄷ자 세 면/가상 입구·점유·차량번호 정수 또는 null·스티커색·촬영 시점/배치·라벨 출처·품질 수치와 사유·원본/표시사진 상대경로와 SHA256이 들어갑니다. 사진에는 경계·칸명·현재 값/미확인 상태를 표시합니다. 원본과 학습용 크롭에는 글자를 그리지 않습니다. 기계용 manifest/prediction의 기존 영문 키도 보존합니다.



파일 존재만으로 완성 처리하지 않습니다. 읽을 때 촬영 문맥, 필수 예측/검수 지문, 원본/파생 파일의 해시, 전체 장면 JSON과 개별 칸 JSON의 내용 일치를 검사합니다. 품질 판정도 당시 원본·ROI·설정·예측·정답 지문에 연결됩니다. 원본이 변경되거나 예측만 유실된 자료를 정상처럼 전달하지 않습니다.



원본 전에 복구 journal을 남기며 원본 저장은 기존 파일 덮어쓰기를 허용하지 않습니다. 최초 manifest 쓰기 실패 시 원본을 삭제하지 않고 재시작 복구 대상으로 남깁니다. 원본이 잘렸거나 필수 문맥/예측이 없으면 복구를 보류합니다. 과거 문맥 없는 고아 원본을 추측해서 복원하지 않습니다.

| 품질 통과·승인 학습 가능 점유/번호/색 | 정상 장면의 품질 통과 + 승인 크롭 조건을 모두 충족한 작업별 후보 수. 현재 UI 학습 내보내기와 같은 선별 기준 |

| 칸별 사진·JSON 내보내기 | 정상 저장된 전체 후보 묶음 복사 |

| 품질 통과 자료 내보내기 | 품질 통과 장면의 원본·표시사진·한글 JSON 복사. 사람 정답 승인과는 별개 |

| 통과·승인 학습 내보내기 | 통과 장면 안에서 사람이 승인한 점유/번호/색 무표시 학습 크롭 |

| 승인 자료·표시사진 내보내기 | 기존 승인 정답/표시사진 전달 기능. 품질 통과 전용과 다름 |

| 내보내기 완료 수 | 실제 복사 완료된 장면·주차칸 사진/JSON 짝·이미지·데이터 JSON 수. 상태/receipt 같은 보조 JSON은 데이터 JSON 수에서 제외 |



학습 수량은 작업별 크롭 수입니다. 한 차량 칸에서 점유·번호·색 세 작업이 준비되면3개 샘플이 될 수 있습니다. 집계 후 파일 변경, 디스크 오류, 분할 간 동일 원본 중복 등의 문제로 내보내기가 실패할 수 있으므로 최종 완료 수/상태가 전달 기준입니다.



학습 자료는 batch 해시를 이용한 train/validation/test 그룹 분할을 유지합니다. 동일 원본 SHA256이 다른 분할에 나타나면 완료를 거부합니다. 서로 다른 프레임의 매우 비슷한 장면까지 모두 탐지하는 의미적 중복 검사는 아니며 실제 배치 관리가 필요합니다. 독립 세 분할이 없으면 경고합니다.



내보내기는 이동/원본 삭제가 아닌 복사입니다. `EXPORT_STATUS.json`에 진행·실패·완료와 파일 목록/해시를 남깁니다. 출력 바이트와 최종 입력 지문을 재확인하고 완료를 기록합니다. 출력 폴더 전체를 전달해야 상대경로가 유지됩니다. 이 작업에서 임시 다른 경로로 복사한28쌍을 검증했지만 실제 USB/다른 PC/Geti 설치판으로 가져오기는 별도 검증 사항입니다.

## 8. 기존 자료 사용과 실제 마무리 조건



새 V29 폴더에서 실행하여 **저장 폴더 선택**으로 기존 데이터 루트를 지정하면 됩니다. 가상환경·모델·촬영 데이터는 배포 ZIP에 복제하지 않았습니다. 기존 데이터를 새 폴더로 일괄 변환하지 않습니다. 시점이 없는 저장 사진을 열면 미지정으로 보이며, 새 촬영 전에 실제 시점을 선택합니다. 기본 신규 실행은 천장입니다.



이전 자료에서 ‘번호 영역 해상도 부족: 선택 장면 복구로 품질 판정을 갱신하세요’가 나오면 해당 장면을 열어 **선택 장면 저장 복구**를 실행합니다. 원본은 유지하고 기존 근거로 표시사진/JSON/판정을 다시 만듭니다. 기준에 미달하는 자료는 보류로 남깁니다. 여러 프로그램이 같은 루트에 동시에 쓰지 않게 운영하고 `.writer.lock`을 수동 삭제하지 않습니다.



이번 코드 수정 묶음은 재현한 오류의 수정·회귀·파일 전달 검증까지 마무리합니다. 이후 필요한 작업은 실제 천장/D39 차량 자료 수집, 반사·가림·촬영 높이별 품질 기준 보정, 정답 검수, 모델 학습/연결, 독립 천장·다섯 시점 평가입니다. 차량 외곽 위반 모델도 그 자료로 구현·평가해야 합니다.



미검증 범위는 실제 물리 카메라와 천장 장비, 차량 인식률, 새 학습 모델, 장시간 운전, 실제 디스크 정전, OneDrive/외부 작성자 경쟁, 실서버/Geti, 화면 크기·DPI에 따른 육안 UI입니다. OS 잠금은 이를 따르는 프로그램 작성자 사이의 보호이며 외부 편집기/동기화 프로그램을 제어하지 않습니다. 따라서 현 단계의 정확한 설명은 **기능 검수95%·이번 자동 검증 통과·현장 인식률 미측정**입니다.
