# V26 최종 코드 분석·보완 검증



2026-11-05 한국. 기준 V25 → 수정본 V26. 기존 V25 소스183파일과 ZIP을 보존한 별도 작업입니다.



## 결론과 요구 방향



카메라 한 대, A 직각12칸/B 사선16칸, ㄷ자 실제3면·가상입구, 스티커 배경색과 D39 번호, 원본/표시사진 분리, 칸명 파일·한글수치JSON·수량 UI를 유지했습니다. 이번에는 저장과 검수의 시점 차이, 출력 해시의 기준, JSON과 촬영 자료의 연결을 강화했습니다.



전수 시험을 통과했다는 것은 시험한 소프트웨어 조건에서의 결과입니다. 실제 카메라/D39 차량의 인식 정확도, 완전 자동 고품질 선별, 차량 외곽 기반 선침범 확정은 여전히 검증/구현 완료 상태가 아닙니다. OCR 모델이나 ㄷ자 탐지 성능을 개선했다고 주장하지 않습니다.

## 1. 최초 예측 저장 약속



persist_scene은 빠른/번호 분석 결과를 검증한 뒤 save_capture로 원본과 촬영 기록을 만듭니다. V25에서는 첫 촬영 기록을 쓴 직후, 파생 자산 저장을 시작하기 전까지 예측 저장 예정 상태가 없었습니다. 이 지점에서 종료된 후 선택 장면 복구를 수행하면 예측이 원래 없던 장면으로 취급할 수 있었습니다.



V26는 prediction_expected를 save_capture에 전달합니다. 예측이 예정된 장면의 첫 manifest부터 prediction_status=pending입니다. 예측이 아직 없으면 rebuild_scene_assets가 값을 만들어 완료 처리하지 않습니다. 같은 프레임과 유효한 예측을 다시 제공하는 재시도는 V25의 안정된 사진ID로 이어 저장합니다. 처음부터 예측 없이 수동으로 저장한 장면은 계속 지원합니다.



이는 예측 데이터 유실의 탐지 강화입니다. 아직 디스크에 쓰지 못한 예측을 복원하는 기능이나 프로그램 재시작 뒤 metadata 없는 원본의 자동 복구는 아닙니다.



## 2. 내보내기 검증 기준 고정



승인 JSONL 내보내기는 원본을 복사하고 검증한 다음 장면별 JSONL을 만듭니다. V25는 장면별 결과를 확인할 때 목적지 원본의 현재 해시를 다시 계산하여 등록했습니다. 그 사이 목적지 파일이 바뀌면 새 해시로 기준을 바꿔서 완료할 수 있었습니다.



V26 ExportTransaction.verify는 같은 경로의 기대 해시가 바뀌면 거부합니다. review.export_reviewed는 최초 이미지 내보내기에서 검증한 raw_sha256을 그대로 사용하고 장면별 image_id/상대경로/해시도 대조합니다. 테스트에서는 그룹 JSON 생성 중 복사된 원본만 손상시켜 완료되지 않는지 확인했습니다. 촬영 원본은 보존됩니다.



완료 이후 별도 USB/클라우드 전송에서 생기는 손상을 상시 감시하는 것은 아닙니다. 내보낸 폴더에 남은 파일별 SHA256은 전달 후 대조에 사용할 수 있습니다.



## 3. 현재 촬영 기록과 검수 화면 일치



records.current_capture_record는 저장된 manifest와 화면에서 받은 record의 사진ID·카메라·시리얼·주차장·해상도·ROI·원본 경로/해시·촬영시각·프레임·연결구간·출처·배치·세션·계약·분석설정을 비교합니다. 달라졌으면 어떤 검수 파일도 쓰기 전에 오류를 돌려주고 최신 장면을 다시 열도록 안내합니다.



asset/collection/prediction의 완료 상태는 파일 작업 중 갱신될 수 있으므로 불변 촬영 필드에 포함하지 않습니다. 상태만 바뀐 정상 장면은 검수 저장을 계속 허용합니다. 이는 오래된 화면에서의 충돌 방어이며 여러 프로세스의 동시 쓰기 잠금을 추가한 것은 아닙니다.



## 4. 사진·한글 JSON·전체 결과의 의미 대조



collection_output.validate_collection_label을 파일 집계와 내보내기에서 함께 사용합니다. 사진ID/주차장뿐 아니라 촬영시각, 배치, 세션, 프레임, 출처, 칸 종류/좌표, 원본 크기/해시, 표시사진 경로/해시, ㄷ자 경계까지 연결합니다. 전체 장면의 칸 결과와 각 칸 JSON의 내용도 같아야 합니다.



테스트는 유효한 JSON을 편집한 뒤 그 파일의 해시까지 갱신하여 단순 바이트 검사만으로 부족한 경우를 만들었습니다. V26는 잘못된 연결을 제외하고 UI 디스크 집계에 partial/오류를 표시합니다. 정상적으로 생성된 기존 collection-v2 데이터의 형식은 그대로이며 일괄 변환하지 않습니다.



## 5. 전체 코드 흐름과 수정 범위



main/Dashboard 입력 → CameraHub/사진 프레임 → automatic_setup/open_boundaries/ROI 확인 → VisionEngine 점유·색 → 같은 프레임 번호 보강 → prediction 계약 검사 → persist_scene 원본/예측/크롭/표시자료 저장 → DatasetIndex 실파일 대조 → 사람 검수 또는 자동 후보 → export_integrity 목적지 검증 → 완료 UI.



수정 핵심 파일은 pipeline.py, dataset19.py, records.py, review.py, collection_output.py, export_integrity.py입니다. main/dashboard/demo/run_tests/dataset_audit의 제품 표기는 V26으로 맞췄습니다. 카메라/ROI 알고리즘/번호·색 인식/설정/전송 코드는 V25와 비교하여 변경하지 않았습니다. 일반 실행은 Dashboard이며 예전 App/--analyze-only 보조 경로는 현재 자동 수집 UI와 구분합니다.



수집 자료의 원본과 자동 후보, 사람이 승인한 정답, 검토용 표시사진은 계속 분리합니다. 상태 완료와 정보 완성은 실제 정답률을 의미하지 않습니다. 원본은 내보내기에서 삭제하지 않습니다.

## 7. 호환·사용·남은 한계



새 V26 폴더에서 run_windows.bat를 실행하고 저장 폴더 선택으로 기존 데이터 루트를 지정합니다. .venv/모델/촬영 자료/로그/임시시험 파일은 새 ZIP에 포함하지 않습니다. 기존 D39 계약·prediction schema·ROI v2/v3·collection-v2·한글 라벨·설치pose는 변경하지 않았습니다.



정상 V25 자료는 그대로 읽습니다. 촬영 metadata와 파생 JSON이 어긋난 자료는 자동 수정하지 않고 오류로 표시합니다. 원래 촬영 기록과 예측/검수 근거가 정상임을 확인한 뒤 선택 장면 저장 복구를 사용해야 합니다. 예측이 유실됐으면 먼저 원래 근거를 복원해야 합니다.



내보내기는 V25처럼 automatic-ID/training-ID/reviewed-ID 폴더를 통째로 전달하고 EXPORT_STATUS.json=완료를 확인합니다. A+B 한 장씩의 자동 내보내기는 이미지32·데이터JSON30, 보조 결과/상태JSON2개로 총64파일입니다. UI 데이터JSON30과 실제 JSON32의 차이는 의도된 집계 범위입니다.



물리 카메라·실차 D39 정답률·학습 점유/차량외곽 모델·GPU·실서버/Geti·장시간·실제 창 클릭/DPI·물리정전/동기화 경쟁은 미검증입니다. 품질 수치는 참고 경고이며 완전 자동 품질 합격 정책은 없습니다. 한 저장 폴더는 한 프로그램에서만 작성하고, 이전 고아 원본이나 중복 파일을 자동 삭제하지 않습니다.
