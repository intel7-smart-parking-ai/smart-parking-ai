# V47 일곱 항목 재검수



V46 배포 소스를 기준으로 판독에서 검수·저장·내보내기까지 점검했다. 수정에 사용한 합성 72개에서 직접 오답은 8건에서 0건으로, 보류는 11건에서 21건으로 바뀌었다. V46이 틀린 8건 중 7건은 번호가 보류됐고, 초록 93은 정답과 일치하는 추정으로 기록됐다. 보류에는 실제로 읽을 수 있는 스티커도 있다.

|---|---|---|

| 기존 합성 24종 | 19 / 3 / 0 / 2 | 15 / 3 / 0 / 6 |

합성 입력의 번호·색 정답은 생성할 때 정했다. 두 버전에 넣은 장면의 픽셀 해시를 대조했다. 추가 세트 ①은 −15°, 0°, 15°, 90°, 세트 ②는 −30°, 12°, 80°, 180°로 렌더링했다. 세트 ③은 고정 난수 4707과 −72°, −8°, 39°, 152°를 사용했다. 초록 36을 98로 직접 오독하는 원인을 여기에서 추가로 발견했다. 낮은 점수 때문에 버려졌던 세 전처리 모두가 같은 반대 방향에서 인쇄 모양과 같은 번호를 읽은 경우, 그 근거로 확정을 보류한다. 세트 ①~③은 오류 재현과 개선에 사용했다. 마지막 행은 최종 Python 파일 99개의 해시를 고정한 뒤 실시한 별도 시험이다. 고정 난수 4711로 24개 번호를 골라 Verdana·Cambria Bold와 −12°, 0°, 22°, 90°로 장면을 합성했다. 최종 코드에서 직접 일치 19건, 추정 일치 3건, 오답 0건, 보류 2건이었다. 각 칸의 정답과 판독값을 칸별 재생 결과에 기록했다. 두 OCR 단계는 같은 엔진으로 다른 전처리 영상을 읽는다. 여러 번 같은 번호가 나왔다는 사실은 전처리 간 일관성을 뜻한다. 실제 사진 차량 11칸에는 참고 사진과 같은 차량의 반복 관측이 있다. 이 표의 오답은 번호 또는 색 중 하나라도 다른 경우다.

## 검사한 코드와 자료 호환



- `round_sticker.py`, `sticker_ocr.py`, `vision19.py`, `prediction_contract.py`의 후보 선택·방향·번호와 색 근거·저장 계약을 추적했다.

- `field_check.py`, `review.py`, `collection_output.py`, `dataset19.py`에서 현장 정답, 사람 승인, 실물/가상 데이터, 학습 파일을 대조했다.

- `camera_hub.py`, `dual_capture.py`, `dual_dashboard.py`, `collection_run.py`, `empty_pair.py`의 수신차, 연결회차, 빈 기준, 정지 후 쓰기와 복구를 확인했다.

- V46에서 생성한 한 측정을 별도 프로세스에서 열어 완료 쌍 1개와 28칸을 내보냈고 기존 파일 102개의 SHA-256이 일치했다. 이전 독립 정답표로 새 실물 28칸 보고서도 생성했다. `동시측정현장대조-v2`의 가상 점유는 null이므로 보고서를 직접 읽는 도구에서는 화면 관측에 `화면관측`을 사용한다.

- 추가한 시험 22건을 두 버전에 같은 조건으로 실행했다. 새 보고서 항목을 포함해 V46은 16건 미충족, V47은 22건 통과였다. 전체 회귀시험은 627건 통과, 실패·오류·건너뜀은 각각 0건이다.
